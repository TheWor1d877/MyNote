gRPC 超时控制（Timeout / Deadline）。这是云原生和分布式存储系统中防止雪崩、保障 SLA 的核心机制。
超时控制的本质：Deadline 而非 Timeout

| 术语 | 含义 | 特点 |
|------|------|------|
| Timeout | 相对时间（如“3秒后超时”） | 客户端本地概念 |
| Deadline | 绝对时间（如“2026-05-28T10:55:00 前完成”） | 端到端传递，服务端也遵守 |

## Go 语言中的完整使用模式
客户端上传大文件（需较长超时）
```go
func uploadWithTimeout(client pb.FileServiceClient, fileData []byte) error {
	// 1. 根据数据大小动态设置超时（例如：1MB/s 速度估算）
	timeout := time.Duration(len(fileData)/1024/1024+1) * time.Second
	if timeout < 5*time.Second {
		timeout = 5 * time.Second // 最小 5 秒
	}
	
	ctx, cancel := context.WithTimeout(context.Background(), timeout)
	defer cancel() // ⚠️ 必须调用！否则 Context 泄漏

	stream, err := client.Upload(ctx)
	if err != nil {
		return fmt.Errorf("create stream failed: %w", err)
	}

	// ... 发送数据 ...
	
	// 2. 显式检查 Context 是否已超时（可选但推荐）
	select {
	case <-ctx.Done():
		return ctx.Err() // 可能是 context.DeadlineExceeded 或 context.Canceled
	default:
		// 继续处理
	}
}
```

服务端：如何响应超时？
```go
func (s *server) Upload(stream pb.FileService_UploadServer) error {
	for {
		// 检查 Context 是否已超时
		select {
		case <-stream.Context().Done():
			log.Println("Upload canceled:", stream.Context().Err())
			return stream.Context().Err() // 自动返回 DEADLINE_EXCEEDED 或 CANCELED
		default:
		}

		chunk, err := stream.Recv()
		if err == io.EOF {
			break
		}
		if err != nil {
			return err
		}
		// 处理 chunk...
	}
	return stream.SendAndClose(&pb.UploadStatus{Success: true})
}
```

## 注意：
所有RPC必须设置Deadline

根据业务场景动态设置超时：
Get 请求：100ms~1s
写入请求：1s~5s
批量操作：按数据量线性增加

链路超时传递
微服务 A → B → C 时，B 应使用 A 传来的 Context（含剩余 Deadline），不要重新设置固定超时！
