gRPC 客户端拦截器自动重试（生产推荐）
## 创建带有重试拦截器的客户端
```go
 import "github.com/grpc-ecosystem/go-grpc-middleware/v2/interceptors/retry"
 
 func fullJitterBackOff(base time.Duration) retry.BackoffFunc {
 	return func(ctx context.Context, attempt uint) time.Duration {
 		m := float64(base) * math.Pow(2, float64(attempt))
 		return time.Duration(rand.Float64() * m)
 	}
 }
 
 
conn, err := grpc.NewClient(
	"storage-service:50051",
	grpc.WithTransportCredentials(insecure.NewCredentials()),
	// 添加重试拦截器
	grpc.WithChainUnaryInterceptor(
		retry.UnaryClientInterceptor(
			retry.WithMax(3),                         // 最大重试 3 次
			retry.WithPerRetryTimeout(2*time.Second), // 每次重试超时 2s
			retry.WithCodes( // 只重试这些错误码
				codes.Unavailable,
				codes.DeadlineExceeded,
				codes.Aborted,
				codes.ResourceExhausted,
			),
			retry.WithBackoff(fullJitterBackOff(5*time.Second)), 
		),
	),
)
if err != nil {
	log.Fatal("Client create failed:", err)
}
```


## 重传机制策略设计
必须保证幂等性
等待时间设置

| 算法 | 公式 | 适用场景 |
|------|------|----------|
| 固定间隔 | `sleep(1s)` | 简单场景 |
| 指数退避 | `sleep(0.1 * 2^attempt s)` | 推荐（避免雪崩） |
| 指数退避+抖动 | `sleep(0.1 * 2^attempt + random(0,1)s)` | 生产必备（分散重试压力
## 重要场景
| 场景 | 重试策略 | 说明 |
|------|----------|------|
| etcd 写入冲突 | 重试 3 次 + 指数退避 | MVCC 冲突 (`ABORTED`) |
| Ceph OSD 临时不可用 | 重试 + 感知集群状态 | 结合 OSD map 更新 |
| 对象存储上传分片失败 | 仅重试失败分片 | 分片天然幂等 |
| 跨数据中心同步 | 重试 + 断路器 | 避免长时间等待 |
