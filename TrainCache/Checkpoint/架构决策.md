# Checkpoint 架构决策

| 项 | 决策 |
|---|---|
| 恢复形态 | 原生 sidecar，恢复完成后训练容器才启动 |
| 配置载体 | ConfigMap 存参数，Secret 存凭证 |
| 模块归属 | 新顶层模块 `checkpoint/`，二进制 `checkpointd` |
| 插件边界 | 独立二进制，同容器子进程，unix socket 通信 |

## 1. 恢复形态：原生 sidecar

checkpointd 以 initContainer 注入，`restartPolicy: Always`，排在插件预置 initContainer 之后、训练容器之前。

- 恢复在训练容器启动前完成，训练镜像不需要改代码或启动脚本。
- 启动顺序由 startupProbe 控制。恢复未完成时探针失败，训练容器不启动；恢复完成后探针通过。
- 同一个 checkpointd 继续执行保存阶段的目录监控、就绪判断和上传，不拆成两个容器。
- 集群需要支持原生 sidecar。仓库 e2e 使用 kind v1.37。

恢复失败按 5 次、初始 5s、线性退避重试。失败期间训练容器不启动，错误写入日志与 Pod 事件。

## 2. 配置载体：ConfigMap + Secret

- Pod annotation 只写配置名，不写后端参数。
- ConfigMap 存插件名、endpoint、bucket、prefix、分片大小、并发数、本地保留份数等非敏感项。
- Secret 存 accessKey 与 secretKey。
- 准入层读取 annotation 指向的 ConfigMap，把非敏感项与 Secret 的键注入 checkpointd 容器的环境变量。
- checkpointd 运行时只读环境变量，不访问 K8s API，不需要 RBAC。
- 本地工作目录不写入配置。准入层注入时确定路径，训练容器与 checkpointd 使用同一个环境变量。
- 配置在 Pod 创建时固化，改配置需要重建 Pod。首期不引入 CRD。

## 3. 模块归属：checkpoint/

- 新顶层 Go module `checkpoint/`，module path `traincache/checkpoint`，加入 `go.work`。
- 二进制 `checkpointd`，镜像 `ghcr.io/thewor1d877/traincache/traincache-checkpoint`，Dockerfile 放 `checkpoint/Dockerfile`。
- 包职责：

| 包 | 职责 |
|---|---|
| `cmd/checkpointd` | 启动、参数解析、信号处理 |
| `internal/sidecar` | 保存与恢复流程、生命周期 |
| `internal/plugin` | 插件契约、注册、子进程管理、RPC |
| `internal/plugin/s3` | S3 兼容后端插件 |
| `internal/plugin/local` | 本地目录插件 |
| `internal/manifest` | manifest 格式、校验清单 |
| `internal/config` | 环境变量配置 |
| `internal/obs` | 日志与指标 |

- 注入逻辑留在 `controller/internal/webhook`。checkpoint 模块不依赖 controller。
- 不并入 agent。agent 是节点级 DaemonSet，管 CAS 块与读路径；checkpoint 是 Pod 级，管整份 checkpoint 目录与后端版本。

## 4. 插件边界：独立二进制，同容器子进程

- 插件是独立可执行文件。内置 S3 与本地插件编进 checkpointd 镜像，第三方插件使用自己的镜像。
- 插件预置 initContainer 把二进制复制到共享 emptyDir 卷。checkpointd 只从该卷的固定目录启动插件，内置与第三方走同一条路径。
- 每次 Save 或 Restore 启动一个子进程，操作结束退出。插件不常驻，不跨操作保存状态。
- 子进程通过 unix socket 与 checkpointd 通信。协议带版本握手；请求包含操作类型、本地路径、任务标识、后端配置，响应包含进度、校验结果与错误分类。
- 插件崩溃只终止当前操作。checkpointd 读取退出码与错误分类，决定重试或返回失败。checkpointd 继续运行，下一次操作重新拉起子进程。
- 凭证由 checkpointd 通过环境变量传给子进程，不写配置文件或共享卷。
- 插件的资源占用受 checkpointd 容器限额约束，并发由配置控制。
- 插件只处理一份就绪的本地数据和一份后端配置，不判断保存时机，不感知训练框架。

插件 RPC 的具体编码（gRPC 或 JSON 分帧）另行确定，进程边界不变。
