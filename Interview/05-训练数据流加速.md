# 训练数据流加速

## 必会

1. 从一次训练 step 出发，数据从对象存储到 GPU 显存走哪条完整路径？把每一段可能阻塞的环节标出来。
2. GPU 每步都在等数据，你怎么判断瓶颈在 CPU 解码、内存、PCIe、网络、存储还是框架层？各用什么证据排除？
3. DataLoader 开多 worker 之后数据是怎么跨进程传回来的？num_workers 和 prefetch_factor 各控制哪一段？
4. DataLoader 里打开 pin_memory 改变了什么？它和后面的 H2D 拷贝是怎么接上的？
5. 异步预取要可控，你控哪几个量？预取深度和预算各防什么事？
6. 双缓冲和多缓冲在数据管道里怎么配合？缓冲份数由什么决定？
7. 预取器产得比 GPU 消费快，队列和内存会发生什么？这条管道的背压怎么设计？
8. 训练开始前怎么做数据预热？把热数据提前搬到 page cache 或本地 NVMe，各适合什么场景？
9. 训练数据的访问模式和在线服务不一样：按 epoch 扫、带 shuffle、多任务共读。缓存策略怎么针对它设计？
10. 数据分片怎么和节点、机架对齐？局部性没对齐时，多付的是哪一段带宽？
11. 调度器怎么知道哪个节点上有哪份数据的缓存？cache-aware 打分怎么设计，缓存位置信息从哪来、过期了怎么办？
12. 对象存储的 range 读是怎么支持分片并行读的？并发数和单次读取大小怎么配？
13. 数据分片不均衡是怎么造成慢节点的？一个 rank 读得慢，为什么全集群一起等？
14. checkpoint 写盘会和数据读取争什么资源？异步 checkpoint 把哪一段挪出了关键路径？
15. 海量小文件为什么要合并成大分片？顺序吞吐换来的同时，付出了什么？
16. 分片粒度怎么定？太大和太小各伤哪一头：顺序读、随机读、负载均衡？
17. 数据缓存的命中率怎么测？测出来的命中率虚高，通常是哪几种原因？
18. 数据管道要采哪些指标？延迟、吞吐、队列深度各看哪个位置，才能把「等数据」归因到具体环节？

## 加分

19. 数据集做了新版本，缓存怎么跟着失效？版本号不进缓存键会发生什么？
20. 「单写多读」的缓存一致性假设在训练场景什么时候失效？失效后拿什么补救？
21. 多租户集群里，怎么防止 A 租户的预取把 B 租户的数据读走？缓存键怎么设计，共享和隔离的边界划在哪？
22. range 读 64 并发乘 8MB 能打满带宽，换成 16 并发乘 32MB 反而掉一半，总在途字节明明一样。为什么？
23. 预取深度调大后，固定 shuffle 种子的基准涨了四成，换一种数据顺序就跌回原样。这是对什么的过拟合？评测怎么设计才不被数据顺序骗？
24. 小文件合并之后，随机访问单条样本和流式断点续读的代价各变成什么？描述一种不适合合并的访问模式。
25. 两千多万张 JPEG 加几十万段短视频，图像解码和视频抽帧各在哪执行、各产生多少读放大？把解码搬到 GPU 省掉的是哪一段拷贝？
26. 把变长样本拼成定长序列消掉了哪一项浪费？拼接之后跨样本的注意力为什么必须屏蔽？
27. 长上下文训练把多篇文档拼成一条序列，文档内可见、跨文档屏蔽的 mask 怎么构造？位置编码按文档重置还是整条连续，各付出什么？
28. 全局去重之后数据变少了，每步 GPU 时间为什么基本不变、loss 却可能变？设计一个实验，区分「数据变少」和「数据变差」。
29. GIL 保护了什么、不保护什么？DataLoader 为什么用多进程而不是多线程做解码？
30. 跨进程传 tensor 的序列化开销在哪？共享内存怎么把这段拷贝省掉，代价是什么？
