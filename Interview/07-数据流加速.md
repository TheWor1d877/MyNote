# 数据流加速（修订版）

面向大模型训练数据管道方向的面试题库，覆盖数据路径与瓶颈定位、GPU 拷贝重叠、解码预处理、数据格式与列存、缓存与数据局部性调度、Checkpoint 加载、网络传输与尾延迟可观测，共 105 题；★ 前缀为该方向面试必会题。

> **分层使用说明（2026-10-06 起生效）**
> - **★ = P0**：训练端到端数据路径、page cache 行为、本地缓存与调度、对象存储 range 读、可观测性与延迟建模——与 P1 项目直接咬合；
> - **P1 概念级**：数据格式（WebDataset/MDS/Arrow）、分布式文件系统缓存策略、预取/双缓冲/列存谓词下推——知道做什么用、对调度有什么影响即可；
> - **P2 跳过**：DALI/nvJPEG/NVDEC/音频/视频解码加速器（17–26）——GPU 侧解码不是平台岗主场，P1 §9.4 已明确概念边界，本节只需知道"DALI 把 CPU 解码移走、不影响跨网络取数"；

## 思考与取舍题

86. 预取深度调到 32 后，固定 shuffle 种子的基准吞吐提升 40%，换一种数据顺序就跌回原样甚至更差。为什么会出现"对 page cache 的过拟合"？如何设计一个不被数据顺序愚弄的评测方法？

87. 预取太浅喂不饱 GPU，太深又会挤占带宽和内存。同一台机器上"单任务独占"与"多任务共享"两种部署，为什么最优预取深度差很多？在线判断"喂不饱"还是"冲过头"该看哪个信号？

88. shuffle 越彻底模型质量越好，磁盘顺序 I/O 却越差。给出至少两种"保住全局 shuffle 又保住顺序读"的工程折中，并说明各自牺牲了什么。

89. 估算：图像数据集 5 亿张、平均 300KB（约 150TB），训练要把本地 NVMe 读带宽打满 6GB/s。全局均匀 shuffle 下，缓存池要占到数据集多大比例才能稳住 90% 命中率？"首轮训练"这个约束又如何改变结论？

90. cache-aware 调度把任务尽量钉在已有缓存的节点上，为什么在数据集远大于缓存池时反而制造热点过载与冷节点闲置？出现什么信号时，应该主动把任务派往零缓存的节点？

91. 弹性扩容在负载尖峰时才加节点，预热却要在训练开始前就把数据搬进本地盘，两者在时间轴上天然冲突。给出至少两种让扩容节点快速"变热"的折中，并指出各自的带宽代价。

92. 数据集从 v3 灰度升级到 v4，新旧任务并行期间同一份数据可能在缓存里存两套。以"版本号进缓存 key"为前提，双份缓存的成本该谁承担？什么情况下应该放弃灰度、强制全量失效？

93. 异步 checkpoint 把写压力挪到后台，但触发后的几分钟里数据读取 P99 明显恶化。列出 3 个候选原因并按可能性排序，并说明哪个原因决定了你应该把 checkpoint 写到另一块物理盘。

94. 把海量小文件合并成大分片换来了顺序吞吐，但"随机访问单条样本"与"流式断点续读"的代价会发生什么变化？描述一个明显不适合合并的访问模式。

95. 列存谓词下推省下的读取量，什么时候会被"按文件或 row group 粒度整块缓存"的浪费吃掉？缓存粒度应该跟着格式结构走，还是跟着访问模式走？

96. 给训练任务配了 io.max 限速后，平均带宽确实被保护了，但单步数据加载 P99 从 80ms 涨到 1s。解释限速器在什么工作模式下会把"平均限速"变成"脉冲式排队"，限速值该按平均速率还是峰值速率设？

97. GPUDirect Storage 与 DIO 绕过 page cache 后，内核预取随之失效，"预取"该由谁接手？用户态预读、存储侧缓存、GPU 侧三种承接方式的适用边界分别是什么？
