### S5 RDMA 传输臂（116–121，2026-10-20 新增）

116. ★ Soft-RoCE 功能能验证、性能不可信——为什么？`rdma_rxe` 是软件模拟协议栈，常常比 TCP 还慢；为什么你的 P2P 块传输原型（Step 5）用它验功能是正当的，但任何性能数据都不能进报告？跨子网 Soft-RoCE 丢包不重发会直接挂死——这个约束怎么在面试时诚实标注"没真到无损以太网"？
117. ★ 为什么"独立 C++ 传输组件 + 薄 C ABI"，而不是 cgo 直接把 libibverbs 链进 Go 热进程？三个原因：① cgo 切换开销（goroutine→C 线程 ~2–5μs）对 RDMA 完成路径不可接受；② CQ 轮询放 C 进程里跑更干净，不占 Go runtime 调度；③ Go GC 可能移动内存，传给 `ibv_reg_mr` 会炸。这三个原因分别怎么用最小复现实验证明（cgo 切换开销测 bench、CQ 轮询进程 CPU、GC 移动内存测试）？
118. ★ RDMA Write vs Send/Recv 在 P2P 拉取式场景的选型决策：P2P 块共享是"拉取式"——节点 A 要找 peer B 要块。Write 是单边操作（A 知道 B 的 rkey+addr 就能直接写过去，B 无感知），Send/Recv 是双边（B 要提前 post receive buffer）。gRPC 天然用 Send/Recv 语义（RPC 请求-响应），RDMA 用 Write 语义——两套传输栈的根本差异在哪？面试时能对比着讲吗？
119. ★ `ibv_reg_mr` 开销几百微秒到毫秒级——为什么？它要锁定物理页、建立虚拟到物理地址的映射、Pin 住页面防止 swap。为什么不能按需注册 4KB 小块（开销比 TCP 还大）？你的内存池设计是怎样的（C++ 侧大块预注册几 MB 槽位、Go 侧 `sync.Pool` 管理引用）？
120. CQ 轮询 vs 事件通知：Soft-RoCE 上事件通知经常丢事件导致请求挂起超时，轮询是被迫选择——这是你"真跑过 RDMA"的硬证据吗？真 Mellanox/NVIDIA 网卡上轮询延迟最低但 CPU 100%，事件通知 CPU 0% 但延迟高——这两个 tradeoff 怎么讲？你的实验数据里 Soft-RoCE 上两种方式的 CPU 占用差多少？
121. ★ RoCE 无损以太网三前提（PFC / ECN / MTU=4096）各自解决什么问题、怎么配合？InfiniBand 是端到端专用协议栈，RoCE 把它搬到以太网上——以太网天生会丢包，RDMA 假设包都到（丢包不重发），所以 PFC（暂停帧）+ ECN（拥塞标记）配合把以太网变"无损"。能白板画清楚 PFC 和 ECN 怎么配合吗？你的 Soft-RoCE 同网段能跑（不需要 PFC/ECN），但跨子网会丢包挂死——这个边界怎么讲？
