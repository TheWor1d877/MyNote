3. ★【对标】AIBrix v0.7+、llm-d、Production Stack 已经覆盖了软评分路由、KV 事件消费、KV offload、多副本 HA、P/D 分离。你的三重身份（工业方案的独立复现者、双模式机制的量化测量者、冷启动缺口的上游贡献者）里，哪一重最经得起追问？如果 AIBrix 明天把冷启动预热也做了，你还剩什么？
4. ★【复现】⏳ 一键复现 P2 需要 vLLM 版本、模型、GPU 型号、镜像 digest、负载 trace、seed。CPU 模式和 GPU 模式两套环境，面试官半小时内能跑到哪一步？如果他没有 GPU，你的最小复现集是什么（mock KV 事件 + 假后端 + 固定 trace）？
5. ★【上难度】⏳ 你主动制造过哪些故障：副本重启、端点摘除、上游 SSE 断流、KV 事件乱序/重复/丢失、扩缩容风暴。哪一件把你的索引打崩了？恢复后你怎么校验索引和真实缓存状态重新对齐，而不是“看起来恢复了”？
6. ★【天花板】⏳ 路由的理论上限是什么？所有请求都命中缓存时，TTFT 下界是 prefill 时间 + 网络 RTT；全不命中时，下界是完整 prefill。你的策略离这两个下界各有多远？冷启动协同的理论上限又是什么——新副本从 0 到公平份额，最快需要几个观察窗？
7. ★【复盘】如果写《我为什么放弃自研 KV 感知网关》，你会怎么写？哪个证据让你从“做一个更强的网关”退到“复现 + 测量 + 补缺口”？这篇复盘和你要给 AIBrix 提的 issue 是同一条证据链吗？
