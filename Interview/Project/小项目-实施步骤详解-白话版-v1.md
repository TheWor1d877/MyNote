# 小项目实施步骤详解（白话版）

这份文档把《小项目与微弹药实施详解 v5》里十个项目按执行顺序重新排一遍。v5 负责讲每一项做什么、验收什么，本文负责讲什么时候开始、先做哪一步、做到什么程度算过关。

## 先弄清楚：三类项目，三条时间轴

十个项目分成三类：

- S 类三项，独立仓库、独立验收：S1 mini-Raft、S2 RDMA 传输臂、S3 SLO 校准与回放台。
- M 类四项，挂在主项目上、不占名额：M1 io_uring、M2 eBPF、M3 GPU 实测、M4 外部口径校验。
- N 类三项，只产笔记：N1 DDP→ZeRO、N2 hostPath、N3 vLLM 精读。

它们挂在三条时间轴上：

1. P1 轴：M1、M2、S2 按 P1 的步骤 8、核心 1 完工、步骤 11 三个锚点接入；N2 随时。
2. P2 轴：N3 在 P2 开工前完成，S3 在 P2 主体有 trace 之后，M4 在 P2 引擎打点落地之后。
3. 独立轴：S1 与 P1 并行推进；M3 与 N1 共用一次租卡窗口。

固定依赖只有一条：N3 → P2 主体（含引擎打点）→ S3 → M4。其余项目按锚点接入，不互相等待。

## 名词小词典

| 名词 | 大白话解释 |
| --- | --- |
| Raft | 让多台机器对操作日志的顺序达成一致的算法。 |
| 任期 | 时间切成一段一段，每段叫一个任期，节点在任期内选主。 |
| 脑裂 | 出现两个 leader 各自写数据，一致性算法要防的事故。 |
| 线性一致读 | 读操作能看到最新写入。 |
| 对拍 | 同一串操作分别打到两个实现上，逐项比较结果。 |
| RDMA | 网卡直接读写对端内存，不经过对端 CPU 与内核。 |
| Soft-RoCE | 让普通以太网卡跑 RDMA 协议栈的内核模块，功能可验证、性能不可采信。 |
| PD / QP / CQ / MR | 保护域、队列对、完成队列、注册内存，verbs 编程的四个基本对象。 |
| io_uring | 一次提交一批读写、一次收割一批结果的异步 I/O 接口。 |
| O_DIRECT | 绕过页缓存直接读写磁盘，要求地址、长度、偏移对齐。 |
| eBPF | 在内核里挂小程序的机制，用来做观测。 |
| tracepoint / kprobe | 内核预留的观测点 / 挂在函数上的探针。 |
| CO-RE | 一次编译，跨内核版本运行。 |
| readahead | 内核提前把后面的数据搬进页缓存，会干扰归因。 |
| major fault | 数据不在内存、必须去磁盘拿的缺页。 |
| TTFT / ITL | 首 token 时间 / 相邻 token 间隔。 |
| SLO | 服务等级目标，例如 TTFT p99 不超过某个值。 |
| 校准 | 预测概率与实际发生频率对齐。 |
| Brier / ECE | 预测误差的两把尺子：平方误差平均 / 分桶后的校准误差。 |
| 漂移 | 数据分布随时间移动，使校准失效。 |
| 回放 | 按到达事件推进时间轴，把策略跑在历史数据上。 |
| uprobe | 挂在用户态函数上的 eBPF 探针。 |
| 口径 | 同一指标的两套测量方法。 |
| DDP / ZeRO | 每卡存全量参数与梯度 / 把状态按卡数分片。 |
| hostPath | 把宿主目录直接挂进 Pod，绕过存储接口与部分隔离。 |
| block_manager | vLLM 里管 KV block 分配、释放、淘汰、前缀查找的模块。 |
| 前缀命中深度 | 从第一个 block 起连续命中的块数乘块大小，断开即止。 |

## 步骤 0：开工闸门

这一步的目标：把十个项目的公共前提一次备齐，避免每开一项就重新踩一遍环境。

具体做什么：

1. 机器：确认 P1 集群（kind）与本地 Go、C++、liburing、clang、bpftrace 工具链可用；确认能租到单卡 GPU 与双卡训练机的窗口。
2. 版本：vLLM 版本、内核版本、CUDA 与驱动版本各记一行，写进一个公共的 `versions.md`。后面所有笔记与报告都引用这一行。
3. 目录：独立仓库放各自仓库；M 类放 P1 的 `experimental/` 或附录目录；N 类放笔记目录。每个项目 README 顶部写清截止日与止损日。
4. 三件套模板：每个项目开工时先建一个空表，列“设计取舍、踩过的坑、数据或对照表”三栏，做完当天填。

过关标准：`versions.md` 有内容；三类目录各有一个空项目骨架；租卡窗口有确定的预约方式。

## 步骤 1：N3 vLLM 引擎源码精读（P2 前置）

目标：把引擎内部的 block 生命周期、调度、前缀命中读清楚，给 P2 的打点位置与 S3 的特征字段定依据。

具体做什么：

1. 第一天写清版本与 commit。v0.x 用 `BlockTable` 二维数组，v1 用 BlockPool 加 Index，接口不同。
2. 读 `block_manager`：block 多大、token 怎么映射到 block index、in-flight 怎么判断、前缀命中深度怎么从 hash 链算。
3. 读 `scheduler`：continuous batching、chunked prefill、preemption 的调度逻辑；被抢占的请求在 V1 里走重算，代价落在 prefill。
4. 读 attention 与 KV 事件：块存取有事件，请求时间线与重算归因没有。这一条决定 P2 的打点要自己埋。
5. 写半页到一页笔记，每条结论标注文件与行号，推断的内容标“推断”。

过关标准：四条结论能直接给 P2 第 7 节的五个打点位置用；约束条件（只缓存满块、末尾重算）写清。

## 步骤 2：M1 io_uring 预取器（挂 P1 步骤 8）

目标：补 C++、异步 I/O、对齐与零拷贝这一格，同时为读 vLLM 的 C++ 代码做前置训练。

具体做什么：

1. 锁内核版本，跑通 liburing 官方 examples。io_uring、O_DIRECT、overlayfs 三个坑叠在一起，直接上手太陡。
2. 先用 Go 线程池版跑出基线，再用 C++ buffered 版隔离语言因素。
3. 写 O_DIRECT 加 io_uring：缓冲区地址、长度、偏移三重对齐；`posix_memalign` 对齐到 4K；overlayfs 上报 EINVAL 就换到宿主真实文件系统。
4. 提交与收割：`get_sqe`、`prep`、`submit_and_wait(N)`、批量收割 CQE，短读按 EOF 处理。
5. 做 registered files 与 registered buffer，队列深度 64 到 256 可配。
6. 参数矩阵：队列深度 × 块大小（4K / 64K / 1M）× 并发，记录吞吐、syscall 数、CPU 占用；先用 fio 测裸盘上限。

过关标准：syscall 数下降有数字；大块吞吐不变的解释成立；小文件臂 IOPS 有提升；三重对齐与 overlayfs 两个坑能各讲一段。

## 步骤 3：M2 eBPF 观测工具（P1 核心 1 完工后）

目标：补内核级观测，看到用户态看不到的部分。

具体做什么：

1. bpf2go 编译并加载 hello-world，确认 clang、内核头、vmlinux.h、CO-RE 就绪。
2. 块 I/O 延迟直方图：挂 `block/block_rq_issue` 与 `block/block_rq_complete`，按 request 指针配对，按 log2 桶在 per-CPU map 聚合，用户态周期拉取。
3. major fault：挂 `exceptions/page_fault_user`，区分 major 与 minor。
4. 预读归因：统计预读进来的页有多少被用上，给出“帮忙还是帮倒忙”的结论。
5. 对齐：文件事件、dataloader 打点、块 I/O、major fault 对到同一条时间线，做一张映射表。
6. 准备兜底：eBPF 挂不上时改用 `/proc/diskstats` 采样，标注两个口径的差异。

过关标准：四件事围绕同一轮 benchmark 出数；用户态与内核观测的停顿差有数字；预读归因单独成节；探针自身开销有量。

## 步骤 4：S1 mini-Raft（独立，3 周止损）

目标：把一致性从背下来的知识点变成能讲清楚的东西，同时回答 P1 为什么用 etcd。

具体做什么：

1. 单机 KV 加 WAL：先追加日志再改内存，记录带长度与前缀和；`currentTerm`、`votedFor`、`log[]` 三个字段必须落盘。
2. gRPC 骨架与选举：两个接口 RequestVote、AppendEntries；选举超时在 [T, 2T) 随机；term 小的立即让位。
3. 复制与提交：leader 追加本地日志、并行发 AppendEntries、多数派确认后提交；只提交当前任期的日志。
4. 快照与恢复：在 `lastIncludedIndex` 处截断日志；落后 follower 用 InstallSnapshot；恢复时先装快照再重放日志。
5. 故障注入：`kill -9`、三类分区、时钟跳变；随时杀任意节点再拉起。
6. 与 etcd 对拍：同一组操作、同一 kill 时机、同一种分区，比较返回值、日志顺序、恢复后数据。

过关标准：故障注入下已提交数据零丢失；三类分区行为表完整；对拍报告写完；P1 README 有一句元数据层对比结论。

## 步骤 5：S2 RDMA 传输臂（挂 P1 步骤 11）

目标：补 RDMA 数据面与跨语言桥接。高性能网络只留这一项。

具体做什么：

1. 环境闸门：两台 Linux 虚机，`modprobe softroce`，`rping` 双向跑通。不通就停。
2. 最小 verbs demo：跑通 RDMA Write；四个函数 `ibv_create_qp` 与状态迁移、`ibv_post_send`、`ibv_poll_cq`、`ibv_reg_mr`。
3. C ABI 封装：暴露四个函数，ibverbs 状态留在 C++；传给 C 的缓冲区由 C 侧分配并注册，Go 切片会被 GC 移动。
4. 接 P1 Transport 接口：写 `rdmaTransport`，实现 `SendChunk` / `ReceiveChunk`，gRPC 与 RDMA 可切换。
5. P2P 块传输原型：A 预注册 8 个 1MB 槽位并把地址与 rkey 发给 B；B 用一条 Write 写入 A 的槽位；A 轮询 CQ 通知 Go 侧。
6. 对比实验：Soft-RoCE、TCP、gRPC stream 三档，块大小 4KB / 256KB / 4MB，各 1000 次取 P50 与 P99；另测轮询与事件通知的 CPU 占用、注册耗时。
7. 可选云真值：按小时租 eRDMA 校准一次，数字不进简历，只用来标定结论边界。

过关标准：功能跑通；三档延迟吞吐表完整；桥接代码注释写清不用 cgo 链热进程的理由；PFC / ECN / MTU 机制能讲；注册耗时有实测。

## 步骤 6：M3 GPU 单卡实测（租卡窗口）

目标：补一页来自真卡的数字，供 P2 的预热与扩容叙事引用。

具体做什么：

1. 锁 vLLM 版本、卡型号、驱动与 CUDA 版本，写进 README 顶部；记下 `--gpu-memory-utilization` 与最大并发。
2. 并发扫 1、2、4、8、16、32，每档跑固定请求数，记录 TTFT、ITL、GPU 利用率、KV 块占用。
3. 显存账：`torch.cuda.max_memory_allocated` 与实际 block 数对照纸面值，差额归给权重、激活、碎片、CUDA context。
4. 时间去向表：分排队、prefill、decode、采样与调度开销，各给占比与随并发的变化。
5. 标出只有真卡出现的现象：OOM 落在 KV、功耗墙抖动、量化模型缺 kernel。
6. 测量有效性：两次吞吐差 20% 以上时的处理写清；为观测改掉的开关逐条登记。

过关标准：档 2 的表跑出来，没有表就不写进简历；每条数字标“实测 / 文档 / 论文”来源。

## 步骤 7：N1 DDP→ZeRO 显存账（与 M3 同窗口）

目标：补训练侧的显存公式、通信归因与边界条件。

具体做什么：

1. 控制变量：GPT-2 small 或 6 到 10 层 Transformer，BF16 加 AdamW，每卡 batch 与梯度累积固定。
2. 三组对照：DDP、ZeRO-1、ZeRO-2 或 FSDP FULL_SHARD，各跑 20 步以上取稳定值。
3. 测每卡峰值显存、稳定步耗时、通信时间占比、公式预测值。
4. 归因三件事：显存降幅为什么小于理论值；2 卡上 ZeRO-1 为什么可能更慢；卡数少且显存不紧时 DDP 更划算的边界。

过关标准：一张原始数据表、一份 profiler 记录、一页报告、可复现脚本。

## 步骤 8：N2 hostPath 隔离（随时）

目标：写清 P1 的挂载模型放弃了哪一层隔离，附在 P1 后面。

具体做什么：

1. 讲清破坏范围：hostPath 破坏挂载与文件系统可见性；PID、IPC、UTS、user、network 这些 namespace 不受影响，除非再开 hostPID 之类。
2. 复现一个隔离失效 case：触发条件、验证命令、实际现象。
3. 说明对 P1 意味着什么、为什么接受这个代价；换成 CSI 之后隔离边界变哪一部分、不变哪一部分。

过关标准：case 别人照步骤能跑出来；结论落在 P1 的挂载模型一节。

## 步骤 9：S3 SLO 校准与回放台（P2 主体之后）

目标：给 Pact 的预测与处置补实测数据。纯 CPU，独立仓库。

具体做什么：

1. 定口径：SLO 阈值、违约判定、预测时刻、成本口径四项写死。
2. 数据 schema：每请求一行，字段含到达时间、输入输出长度、命中深度、排队与分段 prefill、每步 decode、是否取消、副本 ID；公开 trace 缺字段时插值并标“推断”。
3. 标签：违约与否；右截断标签处理；类别不平衡重采样并记录前后分布；禁止时间泄漏。
4. 预测器：历史分位数与 Little 定律两条基线，分桶回归或 GBDT 输出概率，做特征组消融。
5. 校准：可靠性图、Brier、ECE、等距回归与 Platt 对比，分副本分负载切片。
6. 漂移：PSI 或 KL 滑窗，定阈值与重校准条件；人为漂移一次验证告警。
7. 回放器：事件驱动，四类动作各一个决策点，迟滞防抖，指标含违约率、拒绝率、单位 token 成本、扩容次数。
8. 结论：哪类动作在哪种负载下有效；预测误差 ±20% 时收益剩多少；一个失败案例。

过关标准：可靠性图与 Brier 前后对比、漂移告警表、四类动作对照表、敏感度曲线、一页结论。

## 步骤 10：M4 外部口径校验（P2 打点落地后，2 天）

目标：量两套口径的偏差，回答“不一致时信哪个”。

具体做什么：

1. 锁版本与符号：vLLM 版本、解释器版本、函数符号；CPU 与 GPU 后端分开登记。
2. 挂点：`Scheduler.schedule`、`execute_model`、每步输出处；bpftrace 记录进入与退出时间，采样率可配。
3. 对齐：按 request id 对到账本记录，算每阶段偏差 P50 与 P99，区分时钟源差异与插桩偏差。
4. 开销：开与关探针对 TTFT、ITL、吞吐的影响，采样率变化对开销与丢事件的影响。
5. 结论：给出判定规则；声明污染，例如关掉 async scheduling 会改变被测行为。

过关标准：偏差表、开销表、一条判定规则、一条不一致案例。

## 步骤 11：总装与回写

每个项目做完当天做三件事：

1. 填三件套：设计取舍、踩过的坑、数据或对照表。
2. 往 P1 或 P2 的 README 塞一句话或一张图，写清这个项目补了哪个位置。
3. 填复盘卡：计划与实际的偏差、砍了什么、下次怎么排。

过关标准：十个项目各有 README 或笔记；P1 与 P2 的 README 里能按编号找到对应条目；没有项目停在“代码跑通但没出数”的状态。

## 排期锚点与砍项顺序

顺序锚点：

1. 步骤 0 先做，公共前提一次备齐。
2. N3 最早做，它决定 P2 的打点位置。
3. P1 轴上 M1、M2、S2 按各自锚点接入，不单独占工期。
4. S1 与 P1 并行，3 周止损。
5. M3 与 N1 合并到一次租卡窗口。
6. S3 与 M4 跟在 P2 主体后面，按顺序做。

砍项顺序（从后往前砍）：

1. 先砍 M3 的档 2 之外的一切，只留时间去向表。
2. 再砍 S2，降级为读码与接口设计，保留“性能不可采信”的边界。
3. 再砍 S1 的选做实验，保留主流程与对拍。
4. 再砍 M1 的参数矩阵，只留一组对照。
5. 再砍 M4，改成读码笔记。
6. 最后砍 S3 的漂移与回放，只留校准报告。

N3 与 N2 不砍，它们是笔记，成本低且有接口价值。
