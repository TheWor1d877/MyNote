## 命名与判断口径

- S：独立仓库，独立验收，进简历项目栏。
- M：不单独成项，作为 P1 或 P2 的附加臂、附录，只在主项目 README 里回写。
- N：只产笔记，不开仓库，至少有一条能说出口的结论。
- 判断“大项目是否已经覆盖”，依据是 P1 实施步骤文档（14 步加支线任务）与 Pact 指南，不依据面试题。题单是问法，不是实现范围。

## 执行顺序

固定顺序只有一条：N3 精读 → P2 主体开工（含引擎打点）→ S3 校准台 → M4 口径校验。N3 决定打点位置，S3 吃打点的输出，M4 校验打点的可信度。

P1 线按接入时机走：

1. S1 独立推进，3 周止损，与 P1 并行。
2. M1 随 P1 步骤 8 前后推进，不另排工期。
3. M2 在 P1 核心 1 完工之后做，四件事围绕同一轮 benchmark。
4. S2 挂在 P1 步骤 11 之后，4 周止损。
5. N2 随时可写，P1 挂载模型定稿时收口。
6. M3 与租卡窗口合并，一次租用同时跑 P2 的负载台与单卡时间去向表。
7. N1 在云上双卡窗口跑一次，与 M3 的租用合并。

## 共用纪律

1. 每个项目 README 顶部写截止日与止损日，独立仓库放自己仓库，M 类放 `experimental/` 或附录目录，N 类写在笔记头部。
2. 每个项目攒齐三件：一个设计取舍、一个亲自踩过的坑、一张数据或对照表。笔记也要有一条能复述的结论。
3. 做完当天往 P1 或 P2 的 README 塞一句话或一张图，成果不停在本地目录。
4. 每个项目至少产出一条主项目能用的数字或结论；产不出来的降级成笔记，不算项目。
5. S 类三项全做，不做二选一；M 类不占名额，但每项都挂在主项目的某一步上。
6. 止损日到就砍功能，不砍质量。砍掉的写进复盘卡。

## S1 mini-Raft KV

互补关系：P1 用 etcd，不自研 Raft；P2 是单机服务层。S1 补分布式共识的工程经验，这是两个大项目都不覆盖的能力域。

做什么：Go 实现 3 节点 Raft，对外 Get/Put。目的把一致性从背下来的知识点变成能讲清楚的东西。

范围：选举、日志复制、快照、崩溃恢复的最小集；故障注入三类；与 etcd 同序列对拍。membership 变更与 Pre-Vote 不做，但要能白板讲。

### 步骤 1：单机 KV 加 WAL

1. 内存 KV，map 加锁。
2. 前置 WAL：先追加日志再改内存，记录格式 len ￨ crc32 ￨ entry。
3. 三个字段必须持久化：currentTerm、votedFor、log[]。votedFor 不落盘会在同任期投两票。
4. 启动重放 WAL，用 crc 识别损坏的尾部记录。

### 步骤 2：gRPC 骨架与选举

1. 两个接口：RequestVote、AppendEntries。
2. 三个角色由同一个 tick 驱动；选举超时在 [T, 2T) 随机化，T 取 500ms 左右。
3. 选举流程：超时转 candidate、自投、拉票、多数当选。
4. 每次 RPC 先比 term，term 更小立即让位。
5. 日志打印 term 变化与投票方向。

### 步骤 3：复制与提交

1. leader 追加本地日志，并行发 AppendEntries，多数派确认后提交并应用状态机。
2. 只提交当前任期的日志，能讲清论文 §5.4.2 的推导。
3. 日志不一致时按 prevLogIndex 与 term 回退 nextIndex；冲突项加速回退是加分项。
4. 集成进测试 harness，支持延迟、分区、重启注入。

### 步骤 4：快照与 kill -9 恢复

1. 在 lastIncludedIndex 处截断日志，快照保存状态机内容。
2. 落后 follower 用 InstallSnapshot。
3. 恢复顺序：先装快照，再重放后续日志。
4. 随时 kill -9 任意节点再拉起，验证不丢数据、集群自愈。

### 步骤 5：故障注入与对拍

1. 三类故障：kill -9、三类分区（多数派隔离、少数派隔离、leader 单向失联）、时钟跳变。
2. 与 etcd 对拍：同一组操作、同一 kill 时机、同一种分区，比较返回值、日志顺序、恢复后数据。
3. 选做：丢包率扫描、无主窗口分布、etcd 源码五差异笔记。
4. 选做：把 P1 元数据后端临时换成你的实现，跑一轮 benchmark。

验收：故障注入下已提交数据零丢失；三类分区行为表完整；对拍报告写完；P1 README 有一句“元数据层对比自研 Raft 与 etcd，结论见附录”。

弹药三件套：

- 取舍：自研与直接用 etcd 的边界。
- 坑：votedFor 不落盘、跨任期提交、时钟依赖。
- 数据：无主窗口分布、丢包扫描、与 etcd 的差异表。

## S2 RDMA 传输臂

互补关系：P1 主路径用 gRPC stream，RDMA 只是一行“永远不进主路径”。S2 把 Transport 接口的第二个实现写出来，补 RDMA 数据面与跨语言桥接。这是高性能网络方向唯一的落点。

做什么：两台 Linux 虚机用 Soft-RoCE 跑通 verbs，实现对标 P1 Transport 接口的块传输原型。

范围：Soft-RoCE 功能验证；不做 GPUDirect RDMA；不进 P1 主路径。

载体：旧口径是并进 P1 `experimental/`，这一版留待定。若走独立仓库，验收标准不变。

### 步骤 1：环境闸门（2 小时）

两台 Ubuntu 虚机，内核 ≥ 5.x，`modprobe softroce`，同网段 IP，`rping` 双向跑通。rping 不通就停。

### 步骤 2：最小 ibverbs demo（半天）

C++ 写 client/server，跑通 RDMA Write。四个函数：`ibv_create_qp` 与状态迁移 INIT→RTR→RTS、`ibv_post_send`、`ibv_poll_cq`、`ibv_reg_mr`。成功判据是对端内存被改写。

### 步骤 3：C ABI 封装与 Go 桥接（1–2 天）

C++ 侧封装 3–4 个函数：`rdma_init`、`rdma_write`、`rdma_poll`、`rdma_shutdown`。约束是 ibverbs 状态不暴露给 Go；传给 `rdma_write` 的缓冲区由 C 侧分配并注册，Go 的切片地址会被 GC 移动。

### 步骤 4：接 P1 Transport 接口（半天）

写一个 `rdmaTransport`，实现 `SendChunk` / `ReceiveChunk`，内部调 C ABI。P2P 模块运行时注入实现，gRPC 与 RDMA 可切换。

### 步骤 5：P2P 块传输原型（1 天）

A 预注册 8 个 1MB 槽位并把 rkey 与地址经 gRPC 发给 B；B 收到请求后用一条 Write 写入 A 的槽位；A 轮询 CQ，通知 Go 侧块就绪。

### 步骤 6：对比实验（半天）

Soft-RoCE、TCP、gRPC stream 三档，块大小 4KB / 256KB / 4MB，各 1000 次，取 P50 与 P99。另测 CQ 轮询与事件通知的 CPU 占用、`ibv_reg_mr` 的注册耗时随块大小的变化。

### 步骤 7：可选云真值（不占工期）

按小时租 eRDMA 云主机校准一次，量软件栈与真卡的差距。数字不进简历，只用来标定结论边界。

验收：功能跑通；三档延迟吞吐表完整；桥接代码注释写清不用 cgo 链进热进程的理由；PFC / ECN 机制能讲；注册耗时有实测。

回写 P1 README：Transport 下的第二条曲线，或一条明确的否定结论。

弹药三件套：

- 取舍：Write 与 Send/Recv；轮询与事件通知；cgo 与独立 C++ 组件。
- 坑：Go 内存被 GC 移动导致注册失效；Soft-RoCE 跨子网丢包不重发；按需注册小块的开销。
- 数据：三档延迟吞吐、注册耗时曲线、CPU 占用对比。

## S3 SLO 校准与回放台

互补关系：Pact 第 9 节给的是计算路径（特征、概率、校准、漂移），第 10 节给的是四类动作与代价表。两节都缺实测数据上的校准与策略回放。上游的 SLO 调度工作偏策略设计与仿真，没有面向“违约概率”的校准报告，也没有把准入、降级、扩容、路由放进同一个回放器。这一项补的就是这块。

做什么：读请求时间线，输出每请求的 TTFT/ITL 违约概率、可靠性图、Brier、ECE、漂移告警；再把四类处置按策略回放，输出违约率与成本。

范围：离线批处理，单机 CPU；不接在线控制面；不做训练框架；不碰 GPU。数据两档：自采的引擎账本 JSONL、公开 trace。

### 步骤 0：口径

1. SLO 定义：TTFT p99 ≤ X，ITL p99 ≤ Y，两个阈值分副本、分模型记录。
2. 违约判定：单请求超阈值计一次，聚合口径按窗口 p99。
3. 预测时刻：请求入队时给出概率，只用当时可见的信息。
4. 成本口径：拒绝的损失、降级后的质量折损、扩容单位成本、跨域路由的额外时延。

### 步骤 1：数据 schema

1. 每请求一行：到达时间、输入长度、输出长度、前缀命中深度、排队时长、每个 prefill 分块时长、decode 每步时长、是否取消、副本 ID、SLO 阈值。
2. 公开 trace 缺字段时用插值，并在报告里标“推断字段”。
3. 数据版本与来源写进 README，采样率与截断规则一并记。

### 步骤 2：标签

1. 标签是违约与否，窗口内还在跑的请求没有标签，做右截断处理。
2. 违约率低时按时间分桶重采样，报告里写清重采样前后的分布。
3. 禁止用未来信息构造特征，特征只用请求入队时刻可见的量。

### 步骤 3：预测器

1. 基线两条：历史分位数、Little 定律估算（并发乘服务时间）。
2. 主力模型：分桶回归或 GBDT，输出概率。
3. 分特征组消融：到达侧（并发、到达率）、请求侧（输入长度、命中深度）、引擎侧（排队与 prefill 分段）。

### 步骤 4：校准

1. 可靠性图：每个概率桶里预测均值与实际频率。
2. Brier 与 ECE，校准前后各一份。
3. 等距回归或 Platt 缩放，比较两种后处理的误差。
4. 切片：分副本、分负载类型、分命中深度三档，看校准在哪一档失效。

### 步骤 5：漂移

1. PSI 或 KL 散度滑窗，输入分布与时延分布各一条。
2. 阈值取校准误差开始上升的位置，给重校准的触发条件。
3. 造一次人为漂移（把到达率翻倍），验证告警能在多久内触发。

### 步骤 6：回放器

1. 事件驱动，时间轴按到达与完成事件推进。
2. 四类动作各自一个决策点：准入（拒绝或延后）、降级（降精度或降并发）、扩容（加副本并预热）、路由（换副本）。
3. 迟滞：动作触发与撤销各设阈值，避免抖动。
4. 指标：违约率、拒绝率、单位 token 成本、扩容次数、预热浪费的 KV。

### 步骤 7：结论

1. 哪类动作在哪种负载下有效，给一张对照表。
2. 预测误差敏感度：概率偏差 ±20% 时策略收益还剩多少。
3. 一个预测失败的案例，写清错在特征、标签还是漂移。

验收：可靠性图与 Brier 前后对比；漂移告警表；四类动作的违约率与成本对照；敏感度曲线；一页结论。

回写 P2 README：一张策略对照表，加一句预测误差对策略收益的影响。

弹药三件套：

- 取舍：概率校准与点预测；离线回放与在线试跑；等距回归与 Platt。
- 坑：右截断标签、类别不平衡、时间泄漏、公开 trace 字段缺失。
- 数据：Brier 与 ECE、四类动作对照、敏感度曲线、漂移触发时延。

## M1 C++/io_uring 预取器

互补关系：P1 与 P2 主力 Go，C++ 系统编程这一格空着。M1 补 C++、io_uring、O_DIRECT、对齐内存，同时是读 vLLM C++ 代码的前置训练。

定位：P1 文档的支线任务，步骤 8 前后，借 A 轨小文件数据推进；不占名额，不另排工期。

范围：只做本地写路径与提交模型；不做完整 S3 客户端。

### 步骤 0：锁环境

1. `uname -r` 锁定内核版本，registered files 与 buffers 的行为随版本变化。
2. 把 liburing 官方 examples 逐个跑通，io_uring、O_DIRECT、overlayfs 三个坑叠在一起，直接上手太陡。

### 步骤 1：Go 线程池基线

带线程池的 buffered 写入器，跑出第一组数字，作为后面所有版本的比较原点。

### 步骤 2：C++ buffered 版本

同逻辑用 C++ 写一遍，隔离语言因素。

### 步骤 3：O_DIRECT 加 io_uring

1. 写路径换 O_DIRECT 与 io_uring。
2. 三重对齐：缓冲区地址、长度、偏移；`posix_memalign` 对齐到 4K。
3. overlayfs 上 O_DIRECT 可能报 EINVAL，目标路径落到宿主真实文件系统。
4. 提交与收割：get_sqe、prep、submit_and_wait(N)，CQE 批量收割，短读按 EOF 处理。

### 步骤 4：registered 优化

`IORING_REGISTER_FILES` 与 registered buffer 消掉固定开销；队列深度 64–256 可配。

### 步骤 5：参数矩阵

1. 队列深度 × 块大小（4K / 64K / 1M）× 并发，记录吞吐、syscall 数、CPU 占用。
2. 用 fio 先测裸盘上限，贴着上限比。
3. 预期写进报告：4MiB 块经 HTTP 抓取受网络限速，省 syscall 对吞吐贡献接近零；io_uring 的战场是小文件高 IOPS。

验收：syscall 数量下降有数字、大块吞吐不变的解释成立、小文件臂 IOPS 提升有数字。

弹药三件套：

- 取舍：大块与小文件两条路径的收益边界。
- 坑：O_DIRECT 三重对齐、overlayfs 的 EINVAL。
- 数据：队列深度与块大小的矩阵、syscall 统计。

## M2 eBPF 观测工具

互补关系：P1 用用户态 inotify 观测。M2 补内核级观测，能看到用户态看不到的部分，例如预读造成的 major fault 不记在消费者进程名下。

定位：P1 核心 1 完工之后做。四件事围绕同一轮 benchmark：块 I/O 延迟直方图、major fault、预读归因、与 P1 指标对齐。只做只读观测；内核 ≥ 5.10；在宿主机跑。

### 步骤 1：hello-world

1. 挂 `block/block_rq_issue` 与 `block/block_rq_complete`。
2. 按 request 指针配对，算延迟。
3. 内核侧按 log2 桶聚合，用户态周期拉 per-CPU map。

### 步骤 3：major fault

挂 `exceptions/page_fault_user`，取 major/minor 位。read 字节量探针可选。

### 步骤 4：预读归因与对齐

1. 统计预读进来的页有多少被用上，给出“预读帮忙还是帮倒忙”的结论。
2. 文件事件、dataloader 打点、块 I/O、major fault 对到一条时间线，做映射表。
3. 同轮 benchmark 下比较用户态与内核观测的停顿差异。
4. 写清一条观测逻辑：缓存命中页缓存时不产生 block I/O，直方图天然区分命中与未命中。

弹药三件套：

- 取舍：tracepoint 与 kprobe；per-CPU map 与 ringbuf。
- 坑：预读归因错算到消费者进程；request 指针复用导致错配；容器权限。
- 数据：停顿差、预读命中与浪费比例、探针自身开销。

## M4 外部口径校验

互补关系：Pact 引擎侧在进程内打点。M4 从进程外用 uprobe 采 token 级时间，量两套口径的偏差与外部探针自身的开销。这一项回答“两个口径不一致时信哪个”。

### 步骤 1：锁版本与符号

1. vLLM 版本、Python 解释器版本、函数符号表。
2. CPU 后端与 GPU 后端分别登记，GPU 后端只挂宿主侧 Python 函数。

### 步骤 2：挂点

1. `Scheduler.schedule`、`execute_model`，以及每步输出处。
2. bpftrace 记录进入与退出时间，采样率可配。

### 步骤 3：对齐

1. 按 request id 或到达顺序对到账本记录。
2. 算每阶段偏差的 P50 与 P99，区分时钟源差异与插桩偏差。

### 步骤 4：开销

开与关探针对 TTFT、ITL、吞吐的影响；采样率变化对开销与丢事件的影响。

### 步骤 5：结论

1. 给出判定规则：在什么条件下用内部时间戳，什么条件下用外部观测。

## N3 vLLM 引擎源码精读

形态：笔记，版本锁定，P2 开工前完成。它是 S3 与 M4 的设计依据。

### 步骤 1：锁版本

第一天写清 vLLM 版本与 commit。v0.x 用 BlockTable 二维数组，v1 用 BlockPool 加 Index，接口不同。

### 步骤 2：block_manager

1. block 多大，token 怎么映射到 block index。
2. in-flight block 靠什么判断，没有显式 ref 的边界情况怎么兜。
3. 前缀命中深度怎么从 hash 链算出，为什么是连续匹配、断开即止。
4. 驱逐与抢占的关系：`EvictLRU` 跳过有引用的块，全池被引用时调用方怎么办。

### 步骤 3：scheduler

1. continuous batching、chunked prefill、preemption 的调度逻辑。
2. v1 怎么在同一张卡上平衡 prefill 与 decode 的 GPU 时间。
3. preemption 怎么选被驱逐的请求，V1 默认重算的代价。
4. 取消与超时请求怎么释放 block。

### 步骤 4：attention

1. paged attention 的内存布局，为什么分固定大小的 block。
2. KV 事件的产出位置与粒度：块存取有事件，请求时间线与重算归因没有。

验收：半页到一页笔记，每条结论标注出自哪个文件哪一行，或标“推断”。四条结论直接给 Pact 第 7 节的打点位置用。

弹药三件套：

- 取舍：显式 ref_count 与所有权语义。
- 坑：版本漂移导致结论失效。
- 数据：命中深度与 block 粒度的关系，供预热策略取参数。
