## 步骤 1：搭实验装置——负载台、网关与记录（指南第 4、11、16 节）

为什么第二步是它：后面每做完一段都要马上验证，验证靠轨迹与记录。装置不稳，所有数字都不可信。

具体做什么：

1. 模型选型先定口径。4060 的显存是 8 GB，8B bf16 权重约 16 GB，放不下。单机机制验证改用 1.5B 或 3B 模型，KV 每 token 字节数（按精度与结构算）与块大小按实际模型算，记进表口径。8B 的收益数字出自步骤 8 的 A100 窗口。两组口径分开报，不混用。
2. 负载台。轨迹参数含：共享前缀比例三档、输入长度分布三档、压力两档（低负载与高压力）、冷热态、KV 池容量、副本数。轨迹用 Mooncake 公开 agent trace 加合成数据补齐。真实 trace 的前缀比例不够时，按档位合成共享前缀段，拼到请求头部，合成段与真实段的比例写进轨迹元数据。分档参数写进轨迹文件名，换档不改代码。KVFerry 与对照组读同一份轨迹，两侧 KV 池容量与副本数取同一个值。
3. 薄网关。网关做四件事：接入请求、注入会话编号、执行 sticky 路由、摘除副本。会话编号按会话维度注入，同一会话的请求共享一个编号，保留与升温决策（步骤 5）靠它关联统计。网关不判断副本好坏，只按探针结果摘掉 endpoint 并改路。在飞请求带原 request id 改到其余副本，重新 prefill，改路事件记一条。这一步的路由目标是原生引擎副本，取回组件在步骤 5 挂上。
4. 记录落盘。四张表都按 request id 或块哈希关联。这一步定表结构与写入通路，决策服务后面填内容：

| 表 | 粒度 | 关键字段 |
|---|---|---|
| 决策记录 | 每请求一条 | 指南 7.5 字段：会话编号、命中深度、层位、动作、估计耗时、表版本、完成时刻、TTFT |
| 退回与降级事件 | 每次一条 | 时刻、类型、原因、表版本 |
| 驱逐事件 | 每块一条 | 块哈希、层位、原因 |
| 演练记录 | 每次一条 | 时刻、节点编号、手段、命中率曲线 |
5. 冷热态规程。冷态每轮重启副本，清空 KV 与存储层。热态先预热：按轨迹的共享前缀比例打一轮预热请求，命中率与 step 时间回到稳态后开始计数，预热轮不计入结果。两组数字分开报。两档压力的定义写进轨迹元数据。低负载取到达率低于单副本容量，高压力取到达率超过容量、队列持续积压。容量用原生基线的完成速率估算。
6. 一条命令拉起。单机进程级脚本拉起网关、原生副本与负载台，k8s 版在步骤 9。这一步先保证轨迹可复跑。
7. 原生基线。原生 vLLM 加本地前缀缓存跑一遍分档轨迹，这是 benchmark 六组里的第一组，后面所有对照以它为底。

过关标准：一条命令起全套；同一轨迹重跑两次，请求数、token 数、P50 TTFT 对得上；九档负载形状（前缀三档乘长度三档）各能生成轨迹，两档压力各跑一遍；原生基线入库。

常见坑：负载台的 CPU 或连接数先饱和时，测出来的是负载台上限，不是引擎上限，饱和轮次作废。冷热态混在一张表里，命中率数字没法解释。单机用小模型、对照用 8B，口径不一致，数字没法比。

## 步骤 2：标定工具与四张代价表——决策的输入（指南第 6 节）

决策算术、传输并发、干扰回路都要查表。表先有，步骤 3 起的实现才有输入。标定工具自带最小探针，覆盖异步拷贝、NVMe 直读或普通文件读、socket，不依赖产品引擎。

具体做什么：

1. 取回带宽表。行是来源层与路径：本地 DRAM 经异步拷贝，本地 NVMe 的 GDS 与 pinned 两条路径，以及 TCP。列是 8 MiB、64 MiB、256 MiB、1 GiB 四个字节档，每格记有效带宽与固定开销。两个数这样取：同一路径扫多个块大小，把传输耗时对字节数做线性拟合，斜率的倒数是有效带宽，截距是固定开销。单块档另直接测一次，用来验证截距。RDMA 行与 MR 注册时间留到步骤 8 的 A100 版补齐。NVMe 到 DRAM 的 staging 带宽按 8、64、256 MiB 三档另记。单机 TCP 走 loopback，口径标注「单机机制验证」，收益结论用双机表。列按字节档标，不假设块恒为 8 MiB。块字节由形态索引的每 token 字节数换算：FP16 换 FP8 折半，MLA latent 按压缩后的字节计。实际块字节小于最小档时按最小档查，介于两档之间取较低档。
2. 重算每 token 时间表。用引擎的 prefill 微基准测。输入长度分 1k、4k、16k、32k 四档，列分纯 prefill 批与 decode 混批两种，混批的 chunk 取 512、1024、2048、4096。微基准这样构造：按固定输入长度批量打请求进引擎。纯 prefill 列不混 decode。混批列按 chunk 档位配置 chunked prefill，同时持续发 decode 请求。每 token 时间 = prefill 段耗时 / 实际计算 token 数，命中段不计入分母。档内按实际 token 数线性插值，不外推档位之外的长度。表头带模型口径：参数量、层数、注意力结构、KV 精度。换模型或换精度时整表重标。
3. 干扰系数表。在飞块数取 1、2、4、8、16，decode 批大小取 1、8、32，两两组合成格。每格记两个数：计算负载下的取回带宽折扣，传输负载下的 decode step 时间增幅。计算负载由引擎持续 decode 产生，传输负载由步骤 0 的探针产生。
4. 决策与排队开销表。表里三项：查表加算术的耗时，取回组件回调与决策 RPC 的耗时，入队到出队的排队等待。排队直接测，不建模。前两项合计对照 step 时间的 1% 闸门。
5. 三个在线参数定值。迟滞系数默认 0.8：在同一轨迹上扫 0.6、0.7、0.8、0.9、1.0 五档，记决策翻转次数与 TTFT，取翻转少、TTFT 不劣的档。干扰闸门默认取 decode step 增幅 5%。传输并发上限默认每副本在飞 8 块，取带宽接近饱和、step 增幅又在闸门内的拐点。
6. 漂移探针。每 30 秒传一个 64 MiB 的固定块。实测耗时与表值偏差超过 20%，且连续三次，就触发重标定；重标定窗口内决策退回重算。探针在这一步跑通，接入决策在步骤 5。
7. 表带版本与口径，口径含 GPU 型号、网卡、PCIe 拓扑、驱动、引擎版本、模型、KV 精度与块大小。一条命令跑完四张表，冷热态分开，入库。换模型或换 KV 精度时，重标受影响的两张表：带宽表换块字节换算口径，重算表整表重标。硬件特性只进表不进代码。带宽、折扣、固定开销全部写进表，代码只认直连与中转两条路径，换机型只换表不换代码。
8. 形态与生命周期参数不进四张表，这一步只定默认值。形态索引随引擎配置在步骤 3 建索引时写入，记四项：页式块、会话状态、每 token 字节数、能否分块取回。三个生命周期参数先取默认值：保留层级与期限，活跃会话留 DRAM 1 小时；升温触发条件，同会话再活跃且预测收益超门槛；活跃度口径，统计最近 10 分钟内的请求。步骤 5 接入决策，实测后按轨迹调。后三件是预测口径，不是标定常数。再活跃间隔分布按周重估，漂移超阈值时升温退回不搬。

测量规程：

1. 每格预热后至少测五次，取中位数。
2. 带宽按完成时刻之差计算，不用发起时刻，发起时刻含排队。
3. 探针在独立进程里跑，与产品进程分开，避免互相干扰。
4. 干扰表的计算负载与传输负载同时起，两侧分别记录。

过关标准：四张表 4060 版齐全，每格有实测值与口径；同机重跑一次，表值偏差有数；三个参数各有扫描记录与选定值；人为制造探针偏差能触发重标定。

常见坑：固定开销混进带宽，小块档的取回耗时被低估。重算表只测纯 prefill 批，决策在混批里查错列。干扰表只记传输对计算的影响，漏了计算对带宽的折扣，两个方向都要记。

## 步骤 3：最小块存储——块读底座（指南第 10 节）

这一步的目标：块写得出、读得回、地址拿得到。节点坏了，服务不中断。压缩与去重不做，增量也不放在存储，存储只保证块读可靠。

具体做什么：

1. 块格式与键。块对齐引擎 KV block，默认 64 token、8 MiB，跟随引擎配置，单机小模型按实际块大小记口径。键用前缀哈希链 hash(父块哈希, 块内 token ids, 附加键)，附加键含 LoRA、缓存盐、多模态哈希，存储侧照单全收，不自行裁剪。
2. 存储节点服务。存储节点实现三个接口：块写入、块读回、清单上报，数据放在 DRAM 服务缓冲与 NVMe 文件里。NVMe 用一个大文件加偏移，每块占一段，偏移记进索引。不用每块一个文件，小文件的 inode 与目录开销会被放大。这一步用离线灌块做验证，取回组件的 save 对接在步骤 5。
3. 索引。索引存两样：块哈希到（层、节点、地址或偏移、长度）的映射，以及形态索引（KV 形态、每 token 字节数、能否分块取回、搬迁单位）。索引与决策服务同进程部署，这一步先独立跑。索引是软状态，靠三个动作维护：写入时登记，驱逐时注销，周期清单心跳。心跳默认 10 秒一次，周期写配置。心跳字段带节点编号、块哈希列表、各块层位与偏移、容量水位。进程重启后，索引从各节点最近一次清单逐条重建。重建完成前，命中查询一律按未命中返回，请求走重算，save 路径不受影响。形态索引随引擎配置下发，重启后从配置重建，不进软状态。
4. 放置与驱逐。HBM 逐出时，save 把块交给保留决策（步骤 5），决策给出落哪层或丢弃。DRAM 容量超阈值时按 LRU 下沉到 NVMe，NVMe 超阈值时丢弃，远端层在步骤 8 接上。读请求不提升层级。放置只做写入下沉与 LRU 驱逐，升温（步骤 5）是唯一把 KV 往近层搬的路径。每层容量写配置，驱逐事件带块哈希与原因。
5. 节点故障语义。存储节点失联后，索引把它的块标为不可用，命中查询跳过这些块，命中深度按剩余层位缩减，剩下的走重算。节点恢复后重新上报清单，索引恢复登记。
6. 对账抽查规程。每轮随机抽 1% 的块，不足一百块时抽一百块。抽到的块读回，重算哈希，与索引登记对照。已驱逐的块核对索引已注销，盘上的残留段核对已释放。

过关标准：随机抽块读回校验哈希，索引与数据对账一致；杀一个存储节点（这一步用双进程模拟），服务继续，命中率下降幅度有数；索引进程重启，重建窗口内请求全走重算，无错误命中；节点恢复后命中率回到故障前水平的时间有数。

常见坑：哈希口径与引擎不一致，漏了附加键（LoRA、缓存盐、多模态哈希），命中查询报命中，读回的块却对不上。索引做成硬状态，重启后登记与盘上的实际块不一致，错误命中比重算更贵。

## 步骤 4：传输引擎 TCP 路径——指令语义先冻结（指南第 8 节）

为什么 TCP 先做：4060 没有 RDMA 网卡。指令语义（块列表、优先级、期限）与完成事件先在 TCP 上冻结，步骤 8 的 RDMA 只换数据通道，决策层与重叠执行不用改。

具体做什么：

1. 指令与完成事件。决策层下发指令，指令带块列表、来源节点、优先级、期限。传输引擎每完成一块就回一条完成事件，事件带块 id 与时刻。这套语义 RDMA 与 TCP 共用，写成引擎内部接口，两条路径各实现一遍。
2. 地址交换（TCP 版）。控制消息按批打包，一次带一个请求的全部块哈希。存储节点回地址或偏移，未命中就回失败，决策改为重算。每块单发一条控制消息会把固定开销放大，打包能把开销摊薄。
3. 数据通道。NVMe 的块从文件直接发到 socket，DRAM 的块用零拷贝发送，不经用户态缓冲中转。控制通道与数据通道分开连接。控制消息小、数据消息大，混在一条连接上会互相阻塞。
4. 传输调度。块队列按期限排序，期限近的先发。期限已过的块撤读，整个请求改为重算。在飞块数上限默认 8，取值查干扰表。
5. 路径开关。配置切 TCP 或 RDMA，代价表切对应列。这一步 RDMA 侧是空实现，开关与表切换逻辑先跑通。

指令生命周期分五段，每段留记录：

| 阶段 | 执行者 | 触发条件 | 动作 | 判断条件 | 返回与后续 |
|---|---|---|---|---|---|
| 下发 | 决策层 | 决策层判定取回 | 下发块列表、来源节点、优先级、期限 | 无 | 进传输引擎队列 |
| 排队 | 传输引擎 | 并发额度有空位 | 按期限排序等待 | 期限未过 | 出队，进入发起 |
| 发起 | 传输引擎 | 地址交换成功 | 读块，NVMe 直读文件 | 期限未过 | 完成后出事件 |
| 完成 | 传输引擎 | 块读完成 | 每块一条完成事件，带块 id 与时刻 | 无 | 交给重叠执行 |
| 撤读 | 传输引擎 | 期限已过 | 未完成块取消，通知决策层 | 无 | 整请求改重算 |

撤读与完成可能竞态：撤读指令发出后完成事件仍会到达，引擎按请求当前状态丢弃迟到的完成事件，不能写进已改重算请求的 KV。

过关标准：同一轨迹 TCP 路径的取回成功率与期限错过率有数；期限撤读能演示，人为把期限压到取回耗时以下，请求改重算且记录对得上；指令与完成事件语义冻结成文档，步骤 8 照此实现；带宽复跑与步骤 2 表值偏差有数。

常见坑：期限排序只按下发时刻，不看剩余时间，晚下发的紧期限块会排在后面，最后错过期限。并发额度按请求数计而不是按在飞块数计，一个大请求占满额度，小请求拿不到额度。

## 步骤 5：决策服务与取回组件挂载——把账算起来（指南第 7、5 节）

这一步的目标：命中查询返回时，决策层按表算出取回、重算或不可取回，请求按结果走异步加载或正常 prefill。请求时点做确定性仲裁，逐出和再活跃做预测加策略表，两套机制分开。这一步把存储（步骤 3）、传输（步骤 4）、代价表与形态生命周期参数（步骤 2）接进请求路径。

具体做什么：

1. 决策算术。第一步查形态索引。命中 KV 的形态如果不支持分块取回，直接输出不可取回，不查带宽表。其余形态按下面的式子算：取回耗时 = 各块（字节数 / 折扣后带宽 + 固定开销）之和；折扣后带宽 = 6.1 的路径上限乘在线份额；重算耗时 = 命中 token 数 × 每 token 时间，查 6.2 的当前批组成列。在线份额指当前能用到的带宽占路径上限的比例，由队列长度与在飞块数决定，干扰区间查 6.3。取回耗时不超过重算耗时乘迟滞系数（默认 0.8）时输出取回，否则输出重算。来源层按带宽表取耗时最小的层，整段前缀只走一层。不可取回与退回分开记账：不可取回是正常裁决，退回是系统异常。
2. 期限。假设该请求立即重算，估计它开始 prefill 的时刻，取回必须在这个时刻之前完成。预计超时就输出重算，记一条期限不足事件。期限估计用队列长度与近期 step 时间。请求进入异步加载状态后，期限仍在计时。决策 RPC 设超时，超时按重算处理，记一条退回事件，请求路径不因决策服务抖动卡住。批组成从钩子与调度器状态读，决策服务不自己估算。
3. 取回组件实现。命中查询里调决策 RPC。决策输出取回时，返回命中 token 数加异步标记，请求进入远程 KV 等待状态。决策输出重算或不可取回时返回 0，请求走正常 prefill。传输引擎通过完成上报通知取回组件，取回组件再通知调度器，调度器这时才放请求进 prefill。save 回调在 HBM 逐出时把块交给保留决策，不固定写 DRAM。
4. 非核心钩子。引擎在 prefill chunk 边界与 step 推进时把进度传给决策层，供期限估计与干扰标定用。钩子带开关，关闭后期限估计只用队列长度口径。
5. 保留与升温是预测加策略表，和请求到达的查表仲裁分开。保留由 save 回调在逐出时触发。决策层用会话编号统计的再活跃间隔分布做先验，结合近层占用，输出留近层、沉远层或丢弃。分布不足以判断时沉远层，不丢块。置信档用来标注这条判断依据是否充足，一并记进决策记录。升温在会话再活跃时触发。同一会话编号的请求到达网关后，先查该会话的 KV 是否在冷层。在冷层且预测收益过门槛才搬，搬运字节受每副本升温带宽预算约束，预算用尽即停。预测落空时立即中止，记一条误判，浪费字节单列。预测落空指请求迟迟不到，或命中深度低于阈值。升温不阻塞请求，未完成时请求按当前命中深度走请求到达的决策。收益归因用反事实对照：同一轨迹强制开与强制关各跑一遍，报净 TTFT 与浪费字节，不只报命中率。升温与取回共用传输通路与代价表，各记各的记录。
6. 三类退回，各记事件带原因：

| 触发 | 判据 | 退回期间动作 |
|---|---|---|
| 代价表缺失或过期 | 表版本不在或超有效期 | 决策输出重算，save 照常 |
| 探针漂移超阈值 | 偏差超 20% 连续三次 | 触发重标定，窗口内决策输出重算 |
| 决策开销超闸门 | 决策与回调合计超 step 时间 1% | 决策输出重算，开销降下来后恢复 |

退回期间产品语义等于原生引擎加本地前缀缓存，save 路径不受影响，KV 照常写回。漂移探针（步骤 2）在这一步接入决策。
7. 决策记录。请求到达时每请求一条，字段按指南 7.5：会话编号、request id、命中深度、层位、动作（取回 / 重算 / 不可取回）、取回与重算的估计耗时、表版本、实际取回完成时刻、TTFT，写进步骤 1 定的表。逐出时记保留动作与层级，升温记搬回字节与耗时，两类单列。

请求从命中查询到 prefill 的路径如下，排查问题时按这张表定位卡在哪一段：

| 阶段 | 执行者 | 触发条件 | 动作与消息字段 | 判断条件 | 返回与后续 |
|---|---|---|---|---|---|
| 命中查询 | 取回组件 | 调度器扫描到该请求 | 调决策 RPC，带前缀哈希链、队列长度、批组成 | 索引返回命中深度与层位 | HBM 命中不进决策，未命中返回 0 |
| 决策 | 决策服务 | 收到查询 | 先查形态索引，再查四张表算取回与重算耗时，比迟滞，校期限 | 取回 ≤ 重算×0.8 且期限够 | 输出动作、来源层、块顺序与期限，记决策记录 |
| 异步等待 | 调度器 | 决策层输出取回 | 请求置远程 KV 等待状态 | 无 | 其余请求照常计算，重叠窗口开始 |
| 块读 | 传输引擎 | 拿到地址与偏移 | 按期限排序发起块读，完成事件交给重叠执行 | 期限未过 | 超期撤读，整请求改重算 |
| 完成报告 | 取回组件 | 全部块完成 | 完成上报，带请求 id | 无 | 调度器放请求进 prefill |
| 跳段计算 | 引擎 | 请求进 prefill | load 回调按块 wait event，prefill 只算未命中段 | KV 已 resident | 首 token 产出，TTFT 落记录 |

过关标准：指南 7.2 算例的三场景在实测表下决策方向一致。决策与回调开销合计不超过 step 时间的 1%。三类退回各演示一次，退回期间与原生引擎对照语义一致。不可取回事件与退回事件分开统计，两类各能演示一次。保留与升温各演示一次，决策记录条数与网关请求计数对账。保留决策的置信档分布有数。升温用强制开关在同一轨迹上开与关各跑一遍，净 TTFT 与浪费字节有数。

常见坑：HBM 命中也进决策，原生前缀缓存的命中就被重复记账。HBM 命中不进决策。重算耗时查纯 prefill 列，混批里就低估重算成本，取回被过度触发。退回时把 save 一起停了，存储层不再进新块，决策恢复后命中率回不来。不可取回混进退回统计，正常裁决与系统异常分不清。保留决策固定写 DRAM，冷 KV 占满近层，热会话的命中反而被挤掉。保留与升温沿用请求到达的算术，把预测当查表，升温落空没人记浪费。

## 步骤 6：重叠执行——取回与排队时间重叠（指南第 9 节）

这一步的目标：让取回和其余请求的计算重叠。请求被调度时，KV 已大部分或全部 resident，prefill 跳过命中段，取回耗时不全额算进 TTFT。

具体做什么：

1. stream 与 event。计算沿用引擎的 stream，传输用独立的 stream。pinned 中转缓冲在启动时分配，异步拷贝走传输 stream。每块完成时 record 一个 event，load 回调按块 wait event。
2. 隐式同步排查。传输路径上不做同步等待，也不把 GPU 数据拉回主机再推回去。用 profiler 确认传输与计算在时间轴上重叠，没有排成串行。判据是时间轴上取回拷贝与 decode kernel 有重叠区间，重叠区间占取回耗时的比例记进报告。比例接近零说明 stream 或 event 接错，回查同步点。
3. 干扰回路。在线监测 decode step 时间，按阈值动作：

| 监测量 | 阈值 | 动作 |
|---|---|---|
| decode step 增幅 | 超过 5% | 传输并发减半 |
| decode step 增幅 | 回落到 2% 以下 | 并发逐级恢复 |
| 降并发时未发起的取回 | 重算期限后不足 | 改重算，记期限不足事件 |
4. 等待位置确认。指南第 3 节核实过，load 回调在 CUDA Graph 断点处 eager 执行，prefill 被分段捕获也不冲突。这一步用 profiler 再验一次，确认等待点落在图外。

过关标准：同一轨迹预取重叠与串行取回对照，TTFT 差有数；传输活跃期间 decode step 增幅不超过闸门；pinned 与 pageable 两档带宽与 TTFT 分开报；人为把并发压到闸门以上，减半与恢复动作各记一条事件。

常见坑：wait event 写成同步等待，传输 stream 与计算 stream 串成一条，重叠收益归零。pinned 缓冲按请求临时分配，分配耗时进请求路径，要在启动时预分配。干扰回路只看带宽不看 step，计算被拖慢没人管。

## 步骤 7：单机主干验收——TCP 全流程闸门（指南第 4、7.5、8.6、9.4、10.5 节）

这一步的目标：4060 单机上产品全流程跑通，主干语义冻结。这一步不过，不进租机窗口。

具体做什么：

1. 全流程串联。标定、挂载、运行、降级、运维、复现六步（指南第 4 节）走一遍，每步留记录。运维这一步只做进程级重启与配置切换，k8s 版在步骤 9。
2. 决策误差复核。在同一轨迹上，把决策选出的动作与逐请求实测最优的动作对照，记选错边的请求占比与损失分布。实测最优这样取：同一请求分别强制取回和强制重算各跑一遍，取 TTFT 小的那个。强制动作用决策旁路开关实现，配置里指定动作、跳过查表，开关状态记进决策记录。这个开关同时供步骤 10 的静态全取回与静态全重算两组用。
3. 降级演示。切换路径开关、切换代价表列，各演示一次。三类退回各演示一次。摘掉取回组件配置，回到原生引擎，验证一键回退。
4. 决策分布自检。同一轨迹在 10 GbE 与 IB 两档各跑一遍。10 GbE 档取回占比低于 5%，重算占多数。IB 档取回占多数。低带宽档仍频繁取回，先查代价表与字节换算口径，判为表错，不进步骤 8。这两条验的是仲裁逻辑本身，与收益数字分开记。
5. 存储对账与故障复跑。抽块校验、杀存储节点、索引重启重建，按步骤 3 的过关标准复跑一遍，记录入库。
6. 主干验收报告，内容五项，随轨迹与表版本入库：

| 项 | 内容 |
|---|---|
| 决策分布 | 取回、重算、不可取回占比，按层位与负载档分 |
| 流量账 | 取回字节数、重算 token 数 |
| TTFT | P50 与 P99，对照原生基线 |
| 开销 | 决策与回调占 step 时间比例实测 |
| 事件 | 退回、降级、期限不足、不可取回、保留与升温清单 |

过关标准：指南 7.5、8.6、9.4、10.5 四处验收项全过；同一轨迹重跑两次，请求数、token 数、P50 TTFT 对得上；回退到原生引擎后行为与步骤 1 基线一致。

红灯处理：决策误差大到收益为负，先回步骤 2 查表值口径，再查期限估计；修不动就按指南第 14 节砍项顺序缩范围，决策、传输、重叠、存储、部署五件不动。

## 步骤 8：RDMA 路径与双机验证——租机窗口（指南第 3、6、8 节）

为什么排在这：主干语义已在 TCP 上冻结，RDMA 只换数据通道。租机窗口集中用：拓扑核实、verbs 引擎、A100 四张表、双机端到端，一次做完。

具体做什么：

1. 拓扑核实，进窗口第一件事（现勘第 3 条）。先看网卡与 GPU 是否在同一 PCIe switch 下，用 lspci 查拓扑树。两者挂在同一个 switch 下游，才满足 GPUDirect 条件。IB 带宽用标准带宽压测工具实测。NVMe 型号记档，GDS 可用性查直读接口与驱动。结论写进代价表口径，决定走 GPUDirect 还是 pinned 中转。
2. verbs 引擎。QP 用 RC 类型。KV 池与存储节点的服务缓冲在启动时预分配，MR 注册一次后缓存复用。控制通道按批打包，交换块地址与 rkey。数据通道走 RDMA READ，请求方网卡直接读远端内存。CQ 轮询线程取完成事件。指令与完成事件照步骤 4 冻结的语义实现。
3. GPUDirect 与中转。网卡与 GPU 同 switch 时，把 GPU 内存注册成 MR，RDMA READ 直落 HBM。注册方式优先用驱动原生直连通道，驱动不支持时回落到通用直连通道，两者都不可用就走 pinned 中转。不同 switch 也走 pinned 主机中转：RDMA READ 落到 pinned 缓冲，异步拷贝经传输 stream 进 HBM。本地 NVMe 层的 GDS 可用时直读进 HBM，不可用就走 pinned 中转加一次拷贝。两条路径的带宽差写进表。代码只认直连与中转两条路径，其余硬件差异全在表里。
4. 条带化与调度。64 MiB 以上的传输按 QP 数均分拆段，每段独立 post，完成事件按段聚合回块。期限排序、撤读、并发上限照 TCP 版语义。
5. 远端存储节点。远端 DRAM 服务缓冲注册 MR，用来响应地址交换。远端 NVMe 的块先 staging 到本节点 DRAM，地址交换等 staging 完成才回地址。staging 耗时计入取回估计，写进表的远端列。TCP 路径直读文件，不做 staging。
6. A100 四张表。标定工具在租机重跑，RDMA 行补齐，干扰表与重算表出 A100 版，模型换回 8B，三个在线参数按 A100 表重定。旧表保留供对照。
7. 双机端到端。副本机跑引擎与传输引擎的请求侧，存储机跑存储节点与传输引擎的服务侧，两机用 IB 直连或经交换机。网关与决策服务放副本机，负载台放存储机或第三台，避免负载台抢副本机的 CPU。远端取回全流程跑通后，同一轨迹按 RDMA 与 TCP 两套口径各跑一遍，决策分布与 TTFT 分开报。RDMA 副本与 TCP 副本并存的混合集群也顺带验证，各副本按本机表决策。
8. 窗口收尾。租机的数据全部存盘带回，四张表、profiler 记录、演练记录与双口径报告一起入库。退租前按清单核对，缺项在窗口内补测，退租后补不了。

过关标准：MR 注册确认一次性，传输路径上无注册调用；带宽表复跑偏差有数；负载下期限错过率有数；拓扑允许时 GPUDirect 与中转两档带宽差有数；双机全流程与单机主干语义一致。

红灯处理：GPUDirect 不可用，中转路径照跑，报告直连与中转的实测差。租机窗口拿不到或 IB 不可用，产品按 TCP 单路径交付，RDMA 数字标未测，soft-RoCE 的功能记录不进收益结论。

常见坑：MR 注册进了请求路径，每次取回付一次注册耗时。rkey 与地址按块单发，控制开销被放大。staging 没等完就回地址，RDMA READ 读到半块。

## 步骤 9：平台壳——能部署能运维（指南第 11 节）

平台侧只做壳，共三件：网关给请求注入会话编号，存储节点提供块读接口，k8s 清单负责拉起服务。决策与传输逻辑不进平台。

具体做什么：

1. 部署。k8s manifests 加一条命令拉起四类组件：薄网关、引擎副本、决策与索引服务、存储节点。单机 kind 集群跑 TCP 全流程，租机双节点跑 RDMA。kind 的 GPU 透传按顺序配：节点容器挂 /dev/nvidia* 与驱动库，装 nvidia device plugin，副本 Pod 声明 nvidia.com/gpu 资源，节点挂载传播用 rslave。不配 rslave，设备节点进不去容器。存储节点挂本地 NVMe。副本数、KV 池容量、块大小、路径开关都是显式配置项，benchmark 复现时随报告入库。
2. 健康与热更新。副本与存储节点都带就绪探针，探针周期与失败阈值写显式配置。检测延迟 = 周期 × 阈值，演练记录里报这个值。代价表版本、迟滞系数、干扰闸门、传输并发上限、路径开关支持热更新，不重启进程。探针失败的副本由网关摘除，在飞请求改路重算。热更新生效时刻记一条事件，决策记录带更新前后的表版本，供对照。
3. 滚动升级不冷缓存。存储节点逐台升级，块留在盘上。升级窗口内，该节点的块按不可用处理，命中查询跳过这些块，命中率短暂下降。进程拉起后上报块清单，索引重建后继续服务。存储不做复制，这段下降是设计内的代价，演练记录里单列。副本逐台升级时 HBM 缓存是冷的，命中由存储层接住，命中率回到稳态所需的请求数记录进报告。升级期间决策与传输照常，升级动作本身不进决策路径。
4. 故障演练。共三类，爆炸半径限定在一个节点，演练记录带时刻与节点编号：

| 演练 | 手段 | 核对 |
|---|---|---|
| 杀存储节点 | 停一个存储节点进程 | 服务继续，命中率下降与恢复曲线，索引标不可用事件 |
| 杀副本 | 停一个引擎副本 | 网关摘除与改路重算事件，其余副本照常 |
| 断网络 | 断网关到存储节点的网络 | 决策退回与改重算事件对得上，恢复后登记重建 |

过关标准：同一轨迹重跑两次，请求数、token 数、P50 TTFT 对得上；杀一个存储节点服务继续，命中率下降与恢复时间有数；滚动升级后命中率回到升级前水平，恢复请求数有数；热更新不重启进程，决策记录能看出表版本切换时刻。

常见坑：kind 集群没配 device plugin，GPU 副本起不来。存储节点升级把盘清了，不冷缓存就变成冷缓存。热更新只改配置不记事件，决策误差复核分不清是哪版表做的决定。

## 步骤 10：Benchmark 六组对照——收益数字（指南第 16 节）

具体做什么：

1. 六组定义。原生 vLLM（本地前缀缓存）、静态全取回（offload 常开）、静态全重算（offload 常关）、sticky 路由加静态 offload（生产默认）、vLLM OffloadingConnector（上游现状，静态字节预算）、KVFerry。六组读同一份轨迹，KV 池容量与副本数取同值。各组配置差异如下：

| 组 | 存储挂载 | 路由 | 取回/重算决策 |
|---|---|---|---|
| 原生 vLLM | 无，只有本地前缀缓存 | sticky | 无 offload |
| 静态全取回 | KVFerry 存储 | sticky | 旁路开关强制取回 |
| 静态全重算 | KVFerry 存储，save 照常 | sticky | 旁路开关强制重算 |
| sticky 加静态 offload | 分层存储常开 | sticky | 静态配置 |
| OffloadingConnector | vLLM 自带 CPU offload | sticky | 静态字节预算 |
| KVFerry | KVFerry 存储 | sticky | 在线查表决策 |
2. 分档跑。九档负载形状各配两档压力，每档单独出结论，不合并总均值。轨迹用步骤 1 的装置，Mooncake 公开 agent trace 加合成补齐。
3. 规程。每组至少跑七次，取中位数报区间。冷热态分开。客户端饱和的轮次作废，负载台的 CPU 与连接数曲线作附件。模型、引擎、镜像、机器、KV 池容量、副本数、代价表版本随报告入库，一条命令复现。复现命令的要素逐项列：轨迹文件名与版本、镜像 tag、模型与量化、KV 池容量、块大小、副本数、表版本、路径开关、随机种子，缺一项复现不成立。决策分布作正确性断言：10 GbE 档取回占比低于 5%，IB 档取回占多数。违反即判表错，该轮收益数字作废。
4. 双口径。RDMA 与 TCP 分开报，TCP 用双机表，不用单机 loopback 表。
5. 收益口径。同轨迹下看 TTFT P50 与 P99、窗口内完成请求数、取回字节数与重算 token 数，对照该档最优静态组。完成请求数指固定时长窗口里收到完整响应的请求数，超时与断连不计，窗口时长写进报告，口径与 MI300X 那组实测对齐，供外部对照。
6. 决策误差与开销各单列一节：

| 节 | 内容 |
|---|---|
| 决策误差 | 选错边占比、损失分布、按负载档分的决策翻转次数 |
| 开销 | 决策计算、取回组件回调、RPC 三项实测值与 step 时间占比 |

过关标准：六组数字能画在同一张图上，任一组一键复现；收益来自哪档负载能指出来；收益接近零的档照实报；OffloadingConnector 组与 KVFerry 组的决策分布差异能解释，静态字节预算对在线查表。

常见坑：对照组 KV 池容量与 KVFerry 不一致，命中率差异被容量差异掩盖。只报总均值，收益翻面的档被平均掉。拿单机 loopback TCP 数字当远端收益。

## 步骤 11：侧枝二层间流水——先做不动核心的（指南第 13 节）

为什么先做它：接口现成，按层等待回调在每层 attention 前调用，不动调度器核心，补丁面小。主干验收通过后开工。

具体做什么：

1. 层序交付。传输引擎按层的计算顺序排块：第 i+1 层的块排在第 i 层之后，层内按块期限排序。指令语义加一个层序号字段，完成事件按层聚合。计算进度用步骤 5 的非核心钩子报当前层号，传输引擎对着层号提前一层交付。交付进度落后于计算进度时，该层的等待暴露在 prefill 里，等待时长记进每层分布。
2. 等待接入。按层等待回调的调用点在 CUDA Graph 断点处，等待在这里 eager 执行。默认捕获模式下 prefill 被分段捕获，等待点落在图外，不需要改捕获模式。必要时挂载组件声明强制分段捕获，两种模式都兼容。decode 段不插等待，KV 在 prefill 结束时已全部 resident。
3. 干扰闸门照常。层间传输的并发受 5% 闸门约束，超限减半，回路照步骤 6。
4. 固定开销账。层粒度交付把一次整段传输拆成 32 次层传输，固定开销按层数放大。先用步骤 2 的表值算一遍，再实测验证。推算算例（8B、30K 前缀、32 层，数值为推算口径）：每 token 每层 KV 是 4 KiB，30K token 的单层 KV 约 120 MiB；单层计算时间约 3 s / 32 ≈ 94 ms。IB 折扣后 20 GB/s，取一层约 6 ms，小于 94 ms，等待接近零。10 GbE TCP 折扣后 0.77 GB/s，取一层约 164 ms，大于 94 ms，每层暴露约 70 ms 等待，流水收益被带宽吃掉。层 KV 字节数小、单块档固定开销占比高时同样不划算。这笔账决定该机型是否采纳层间流水。
5. 对照验收。同一轨迹对主干整请求预取做对照，短队列与长队列两档分开报 prefill 等待时间、TTFT、每层等待的分布。短队列是层间流水的收益来源，队列短时主干没有足够的重叠窗口。每层等待分布的读法：等待集中在前几层，说明交付起步慢，控制通道或首块延迟大；等待均匀分布在所有层，说明带宽不够，层 KV 字节数除以单层计算时间已超过可用带宽。两种情况修法不同，报告里分开写。

过关标准：短队列档 prefill 等待时间下降有数；长队列档收益接近零时照实报，标不采纳；降级开关关闭后回到主干整请求预取，主干验收复跑不受影响。

红灯处理：固定开销吃掉收益，整项标不采纳，不留半成品。

## 步骤 12：侧枝一块粒度混合执行——后做补丁面大的（指南第 12 节）

为什么后做：非连续命中要动调度器核心，回归测试是主要工作量。开工前先做现勘第 6 条：在指南 12.2 列出的七个补丁点上跑引擎原有的调度测试集，记失败项与修复方式，估回归工期。

具体做什么：

1. 补丁回归先行。七处补丁是命中掩码、调度记账、块分配、命中查找、请求状态、输入构造、失败回退，清单见指南 12.2 表。补丁按依赖顺序落。命中掩码与请求状态先落，这两处定义分段语义。调度记账、块分配、命中查找再落，这三处适配记账。输入构造与失败回退最后落，适配执行。每落一处，跑一遍原有的调度测试集，失败项当处修复或记录，不攒到最后。
2. 决策细化。决策单位从整段前缀换成块范围，每段各算取回与重算耗时，各自选耗时小的动作，期限按段独立计时。四张表与主干共用。块掩码用按块 id 的位图表达命中与动作。调度记账把「已计算 token 数」的单整数换成段列表，每段记起始块、块数、来源（本地命中、外部取回、重算）。调度器其余读点按段列表求和适配。
3. 三股流。远端取回与本地取回走传输引擎的两组队列，重算段进 prefill 批，三股流按块掩码对齐。prefill 只算未取回的范围，attention 的 slot mapping 跳过已 resident 的块。块掩码在调度器、传输引擎、计算图输入构造三处用同一份，掩码版本随请求走。传输完成时更新掩码，prefill 按掩码跳段。两处读到的掩码不一致时，以调度器版本为准，并记一条事件。
4. 失败回退。复用现成的失败块回退路径，按块改为重算。期限错过时保留已取回的部分，只重算未取回的范围，已取回的块不白付。
5. 一键回退。补丁带开关，关闭后调度器回到连续前缀语义，主干验收复跑。
6. 对照验收。同一轨迹对主干整请求决策做对照。跨层分布与期限边缘两类负载单独构造轨迹，单独出结论，报 TTFT P50 与 P99、取回字节数、重算 token 数。这两类是混合执行的收益来源，其余负载档收益接近零时照实报。

过关标准：原有调度测试集补丁后全绿，或失败项有记录与修复；两类收益负载档的收益有数；回退后主干语义与验收不受影响。

红灯处理：回归面修不动，整项标未做，主干不受影响；收益接近零，标不采纳。

常见坑：「已计算 token 数」从单整数改成段列表后，调度器的其它读点漏改，记账错乱。块掩码与 slot mapping 对不齐，attention 读到未 resident 的块。

## 步骤 13：交付与诚实清单（指南第 18、19 节）

交付物：薄网关（含会话编号注入）；决策与索引服务（含形态索引与保留升温决策）；传输引擎（RDMA 与 TCP 双路径，直连或中转）；重叠执行与取回组件挂载配置、非核心钩子；最小块存储；侧枝核心补丁（一键回退，未做标未做）；标定工具与按机器版本的四张代价表；形态与生命周期参数配置；k8s manifests 与一条命令拉起；benchmark 装置与六组对照报告；现勘报告（现状矩阵、拓扑结论、接口能力核实表、补丁回归记录）。

诚实清单逐条写进报告，按指南第 18 节二十一条：推算值不进收益结论；rxe 带宽数字不进结论与简历；单机与双机只做机制验证；突发到达时期限估计失真，该区间退回重算；干扰表换机型重测；GPUDirect 与 GDS 依赖拓扑与驱动；侧枝收益可能接近零；补丁回归风险是侧枝主要成本；存储是最小实现；副本故障在飞请求重算，迁移收益账未测；漂移窗口内无取回收益；1% 开销闸门是目标值；CUDA 与 PyTorch 停留在使用层；块大小与哈希口径跟随引擎配置；形态索引只覆盖页式块与会话状态两类，未登记形态按不可取回处理；保留与升温的收益账在单机规模未测全，活跃度口径与保留期限是默认值，按轨迹调参，调参记录随报告入库；仲裁器本身是代价比较，厚度在传输调度与重叠；保留与升温是预测问题，单机置信有限，收益带反事实对照；版本叙事靠接口语义不绑版本号；传输执行器可替换，自研支点在块级期限与协同回调。

报告按组分节，每节四件：配置与表版本、收益数字与区间、决策分布与误差、该档结论。侧枝两组单独成节，未做项标未做。诚实清单与现勘报告随附，第三方复核从现勘报告的接口能力核实表进入，对照部署版本重核。版本叙事只讲接口语义：版本号只出现在现勘表与表口径里，报告与答辩不写「某版本才成立」。

过关标准：交付物清单逐项有着落，未做项标未做；诚实清单随报告入库；第三方拿报告与一条命令能复现任一组数字。

1. 网关接入与摘除改路，会话编号注入验证。

3. 传输双路径与期限撤读。
4. 重叠的 profiler 记录。
5. 存储对账与节点故障。
6. 平台一条命令与三类演练。
7. benchmark 一键复现。
