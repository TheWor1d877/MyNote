# Pact 指南：推理服务契约层

## 1. 项目介绍

电梯陈述：把推理服务的延迟与可用性承诺做成可签约、可计量、可预测、可举证、可结算的对象，用同一套条款驱动引擎的显存与批次取舍，在固定算力下提高达标产出，并在副本故障时保住可用性条款。服务登记合同条款，对每个请求预测完成概率，在违约前处置，在违约后给出四段归因与证据包，按合同周期出账；副本失联或变慢时摘除并替换，在飞请求改路重算。

五重定位：

1. 承诺方。延迟与可用性指标写成条款，条款能被测量、被引用、被追责。
2. 测量方。每个请求的延迟拆成排队、prefill、decode、客户端与网络四段，每段带引擎内打点。
3. 结算方。按合同窗口出账，给出达标率、违约次数、赔付金额、归因占比。
4. 调度方。合同期限与违约概率进入引擎的让位选择、前缀保留与批组装，度量固定 KV 池容量下的达标 token 产出。
5. 保障方。副本故障检测、摘除与替换，可用性条款从事后赔付变成事中保障。

四类用户与各自关心的事：

| 用户 | 关心的事 | 在本产品里看到的东西 |
|---|---|---|
| 平台运维 | 违约率趋势、扩容时机、误拒率、显存产出率、副本故障与误杀 | 契约看板、处置记录、调度收益、副本健康、告警 |
| 租户 | 自己的请求是否达标、超标由谁造成 | 租户视图、归因占比 |
| 采购与财务 | 本期赔付多少、和账单对不对得上 | 结算单、对账结果 |
| 模型与算法 | 延迟分布随版本怎么变 | 版本对比、预测漂移 |

引擎侧改造是本项目的深度所在，占交付工作量的三成左右，单独成节（第 7 节）。显存调度策略改的是引擎调度器的选择逻辑，与打点共用同一批插入位置。副本容错的检测信号一半来自引擎的 step 时间分布，一半来自引擎外的硬件采集，动作接在处置器上（第 10 节）。

这个项目不做模型质量评估，不做训练侧，不做跨云调度，不做跨机模型并行，不改 attention kernel 与量化实现。

## 2. 问题与动机

### 2.1 外部事实

- 推理服务按 token 计费，延迟不进合同。云厂商用服务档位区分速度与价格，赔付条款没有进入推理服务的合同。
- 学术侧已有预测与准入。Scorpio 用预测器加 TTFT 与 TPOT 两个守卫处理异构 SLO；Cascade 用请求级延迟预算统一调度与 KV 管理；LLMVisor 给出多租户下的请求级延迟归因模型。
- 引擎侧只暴露聚合指标。vLLM 给出 TTFT 直方图、队列长度、KV 占用、命中计数，没有请求级的四段耗时。
- 引擎的显存取舍按到达顺序与 LRU 做。抢占选谁、前缀驱逐谁、chunk 取多大，三处都不看请求的延迟期限。
- 计费与监控各有一套口径。账单按 token 数，监控按请求数与时延分位，两套数字对不上时没有仲裁机制。
- 编排侧的健康检查只判进程存活。探针通过就继续接流量，算得慢的副本探针一样通过；硬件降频与 ECC 事件不进延迟归因，这部分违约被算进 decode 段。

### 2.2 仍然成立的问题

1. 没有产品把合同当成对象。条款、判定、归因、结算分散在监控、告警、账单三处，三处各用一套口径。
2. 预测的校准误差没有进入决策。预测器输出概率，处置按固定阈值触发，概率准不准无人测量。
3. 违约没有证据链。租户申诉时，平台拿不出「这一次违约发生在哪一段、由谁的流量造成」的可复核材料。
4. 固定算力下的产出没有合同口径的度量。吞吐按全部 token 算，违约请求的 token 也计入，平台提高吞吐的办法可以是牺牲长请求。
5. 可用性条款只有赔付没有保障手段。副本故障时网关靠探针摘除，探针证明不了副本算得快；慢副本继续接流量，违约集中出现，事后归因分不清是批次组成还是硬件降频。

### 2.3 需求强度

企业私有化部署把「P99 TTFT 低于 2s、TPOT 低于 50ms」写进采购合同，违约按次赔付。8B GQA 模型每 token 的 KV 是 128 KiB，30K 上下文占 3.8 GiB，80 GB 卡的 KV 池约 60 GB，同时放得下十五个请求。并发越过这条线，违约集中出现在长上下文与冷缓存请求上。

decode 每步读一遍权重供整批请求用，权重读取时间固定，批内请求越多，每个请求分摊到的那部分越少。批的上限由 KV 池容量决定，同一份池子在单位时间里服务完多少请求，取决于让位、前缀保留与批组装三处的选择。这三处是调度器里的策略代码，改动不涉及 kernel。

副本级分布式是推理侧的扩容方式，判据是权重单卡放得下就加副本，放不下才做模型并行。8B bf16 权重 16 GB，一张 80 GB 卡放得下，两个副本拿到两倍 KV 池且不付通信。跨机张量并行每层前向两次 all-reduce，32 层一步 64 次 collective，decode batch 8 时单次消息 8 × 4096 × 2 = 64 KB，属小消息延迟受限；按单次 collective 在普通云以太网上 50–100 µs 的量级推算，一步合计 3.2–6.4 ms，占 50 ms TPOT 条款的 6–13%，抖动全进 P99，IB 上同口径约 0.64 ms。70B bf16 权重 140 GB，单卡放不下，那时模型并行才是必需项。这组数是推算，实测留到多卡云窗口。

一个副本故障，它上面的在飞请求全部违约。R 个副本时损失 1/R 的流量，加上改路重算的 prefill 开销。恢复时间拆四段：进程拉起、权重加载、KV 池初始化与 CUDA Graph 捕获、前缀缓存重建。前三段能到秒级，第四段靠流量重新命中，共享前缀比例高时要几十个请求才回到稳态命中率。

赔付与出账是本产品的直接收入场景：平台按合同收费，赔付按合同扣减，两边都要有可复核的数字。固定算力下多服务出来的达标请求，是同一套条款带来的第二笔收益。可用性条款下的故障窗口违约次数减少，是第三笔收益，它直接改写赔付金额。

## 3. 产品形态与使用流程

部署形态：一个网关实例、一个契约服务、若干引擎副本，副本级分布式。单卡能跑通全流程，双卡验证副本间的路由、扩容、故障摘除与回插。副本之间不共享模型状态，一个副本故障不动其余副本的 KV 池。

使用流程六步：

1. 签约。录入合同：模型、SLO 分位、统计窗口、最小样本量、赔付公式、允许的降级档位、可用性条款与故障责任分档。
2. 接入。租户拿到密钥，请求经网关进入，网关写入 request id 与租户标识。
3. 运行。预测器按请求给出完成概率，处置器按阈值决定放行、降级、拒绝、触发扩容或摘除替换副本；引擎调度器按契约服务下发的参数做让位选择、前缀保留与批组装。
4. 计量。引擎返回的 token 用量写进流水表，缓存命中按合同约定决定是否计费。
5. 结算。统计窗口结束时出账，给出达标率、违约次数、赔付金额。
6. 举证。违约事件生成证据包，供争议时复核。

## 4. 架构总览

```
租户
  │
  ▼
网关（Envoy 或自写反代）
  ├── 鉴权与配额
  ├── request id 注入
  ├── 拒绝响应（带重试时间）
  ├── 路由：按副本余量与前缀命中选择
  └── 摘除执行：摘掉 endpoint，在飞请求改路
        │
        ▼
   引擎副本 ×N（vLLM）
        │  per-request trace（自研打点，第 7 节）
        │  批次快照与显存事件（自研打点，第 7 节）
        │  副本健康信号（探针、step 时间分布、XID 与降频，第 10 节）
        ▲  调度参数（按窗口下发）
        ▼
   流水表（请求、token、四段耗时、批次快照、显存事件、副本健康事件）
        │
        ├──► 契约服务
        │      ├── 契约登记与版本
        │      ├── 预测器
        │      ├── 处置器（含副本摘除与替换）
        │      ├── 显存调度器
        │      ├── 归因器
        │      └── 结算与对账
        │
        └──► Prometheus + Grafana
               └── 四块面板与七类告警
```

数据面与控制面分开：网关只做鉴权、路由、拒绝、摘除执行，不做预测计算；契约服务读流水与指标，算出的策略以参数形式下发给引擎调度器，按统计窗口更新，请求路径上不做同步计算。引擎调度器每步读当前参数做选择，参数缺失或过期时沿用上游默认策略，退回事件计数并进面板。副本摘除的判定在处置器，执行在网关，判定周期与统计窗口分开配，故障检测要秒级，策略下发按窗口。

处置器与显存调度器的边界：处置器按请求决定放行、降级、拒绝、扩容，按副本决定摘除与替换，作用在准入与副本粒度；显存调度器按调度步决定谁让出显存、哪个前缀留下、chunk 取多大，作用在引擎内部。网关的前缀路由决定请求进哪个副本，引擎的前缀保留决定该副本的池子里留下什么。副本被摘除后它内部的显存调度不再运行，在飞请求改路到其余副本重新 prefill。

## 5. 现勘与核实

动作清单：

1. 单卡跑通一主两从的副本组，锁定镜像与模型版本，把引擎与 KV 池的启动参数读成映射表。
2. 精读 Scorpio、Cascade、LLMVisor，逐条列出它们覆盖的机制，写进现状矩阵。
3. 核实云厂商推理服务的合同形态与赔付口径，记录公开可查的部分。
4. 在引擎调度路径上找打点位置，确认不改 kernel 也能拿到四段耗时。这一条决定归因是打点还是估计。
5. 在引擎调度器里找三处决策点：抢占候选的排序、前缀驱逐的排序、chunk 上限的选择。确认三处能读外部参数，确认插入位置与打点位置是否共用同一段代码。这一条决定第 13 节能否成立。
6. 实测设备到主机与主机到设备的传输带宽，扫四个块大小，与重算成本比较。换出比重算贵时机型不适用换出策略，这一条决定 13.1 走哪条分支。
7. 核实副本健康信号的可得性与延迟：编排侧探针的判据与周期、降频与 ECC 字段在容器里能不能读到、XID 从哪条路径采集、采集周期决定的检测延迟下限。这一条决定 10.3 的三条信号里有几条可用。

现状矩阵回答一件事：哪些环节属于复用，哪些属于自研。

| 环节 | 上游现状 | 本产品接的位置 |
|---|---|---|
| 违约预测 | 论文有预测器与守卫 | 校准指标与漂移检测，接进处置 |
| 请求级预算 | 论文有延迟预算调度 | 预算口径与合同口径一致 |
| 延迟归因 | 论文有归因模型 | 接进证据包与结算 |
| 合同与结算 | 无公开产品 | 自研，本产品的核心 |
| 请求级 trace | 引擎只有聚合指标 | 自研打点，归因与调度收益的测量来源 |
| 显存调度 | 抢占按到达顺序、前缀按 LRU 驱逐、chunk 上限取固定配置 | 合同剩余期限与保留收益进入三处排序 |
| 副本容错 | 编排侧探针判进程存活，摘除后靠重启策略拉起 | 慢副本判定、误杀门槛、回插与冷启动分段计时 |

头号风险：打点位置与调度决策点的可得性。引擎的调度路径是否允许插入钩子、异步执行下时间戳能否对齐、三处排序能否读外部参数，这三条决定第 7 节与第 13 节能否成立。第二风险是硬件信号的可得性：容器里读不到降频与 ECC 时，慢副本判定只剩 step 时间分布一条，10.3 按降级形态运行，报告里写明少了哪条信号。

## 6. 基座设计

### 6.1 网关

鉴权、配额、request id 注入、拒绝响应、路由、摘除执行六件事。SSE 转发与断连检测在这里做，断连要通知引擎取消，避免白算。摘除执行按处置器的判定摘掉 endpoint，在飞请求改路到其余副本；判定与执行分开，网关不自己判副本好坏。

### 6.2 负载台

合同场景由参数生成：模型、SLO 分位、共享前缀比例、输入与输出长度分布、突发形状、租户数量、缓存冷热、KV 池容量、副本数、故障注入类型与时刻。同一份轨迹同时喂给本产品与对照组，两侧的 KV 池容量与副本数取同一个值。

负载形状分档出结论：共享前缀比例与输入长度分布各取三档，每档单独报数，不合并成一个总均值。

故障注入四类，各对应一段恢复耗时与一条检测信号：

| 注入 | 手段 | 探针能不能判 | 考哪一段 |
|---|---|---|---|
| 杀副本进程 | kill 引擎进程 | 能 | 检测延迟与改路重算 |
| 网络分区 | 网关到副本丢包或断连 | 能，超时后判 | 探针周期与误杀门槛 |
| 慢副本 | cgroup 限 CPU 配额，或 `nvidia-smi -lgc` 锁低频 | 不能 | step 时间分布判定 |
| 冷启动失败 | 副本盘满或权重文件缺失 | 不能 | 恢复四段的第二段卡住 |

爆炸半径限定在一个副本，其余副本继续接流量。注入时刻、副本编号、注入手段随报告入库。锁频模拟的是降频的结果，不是温度或电源故障的成因，报告里按这个口径写。

### 6.3 存储与指标

流水表存请求级记录，按时间分区；批次快照与显存事件各存一张表，按 step 序号与 request id 关联；副本健康事件另存一张表，按副本编号与时刻关联，含探针结果、step 时间分布、降频与 ECC 信号、摘除与回插动作；契约与处置记录存关系库；指标走 Prometheus。流水表与指标库共用 request id，两边的数字可以互相回查。

## 7. 引擎侧改造

### 7.1 上游指标为什么不够

引擎给出的三类指标都不能回答合同问题：

1. TTFT 直方图只有分布，没有请求维度。一次违约要追到具体请求、具体租户，直方图给不出。
2. 没有 batch 组成记录。TPOT 随同批请求的 token 数变化，离开 batch 组成，TPOT 的差异无法解释。
3. chunked prefill 下「prefill 完成时刻」不是一个点。一个请求的前缀被切成多段推进，中间有多个块边界，聚合指标只报最后一段。

三条缺口都指向同一件事：需要请求级的时序记录。显存调度还要第四类记录：抢占、换出、换入、前缀驱逐四类动作的时刻与 token 数，聚合计数只给总量，给不出「这一次让位让谁付出了多少延迟」。

### 7.2 打点位置

五个位置，按时间顺序：

| 位置 | 记录的时刻 | 解决什么 |
|---|---|---|
| 入队 | 请求进入调度队列 | 排队起点 |
| 出队 | 被调度器选入 batch | 排队终点 |
| 每个 prefill 块结束 | 一个 chunk 算完 | prefill 分段 |
| 首 token | 第一个输出 token 产生 | TTFT 终点 |
| 结束或取消 | 生成完成、被抢占、被取消 | 总时长与结局 |

每个请求记录九项：

- request id 与租户标识。
- 入队时刻、出队时刻。
- prefill 的块数与每块 token 数。
- 前缀命中的 token 数。
- 首 token 时刻。
- 输出 token 数。
- 被抢占的次数与每次重算的 token 数。
- 换出与换入的次数、每次的 token 数与耗时。
- KV 块占用的峰值。

时间和 token 数都取自引擎内部，不由网关估算。网关的时间只用于对照与网络段拆分。

### 7.3 批次快照与显存事件

每个调度步记一条批次快照：batch 内各请求的 id、各自的阶段（prefill 或 decode）、各自的 token 数、当步 KV 占用、是否触发抢占。

快照的作用是把 TPOT 的波动归因到同批其他请求。同一步里别人的 token 数多，这一步就慢，责任落在批次组成上。多租户归因与让位选择的复核都用它作分母。快照按副本聚合出 step 时间分布，供 10.3 判定慢副本；聚合时按 batch token 数分桶，同桶内的副本之间相比。

批次快照全量记录，不随请求级采样率下降。请求级 trace 的采样策略：违约相关请求全量记录，正常请求按 1/32 采样，采样率写进配置，报告里标注。两者采样率不同的理由是归因分母要完整，单请求的时序可以抽样。

显存事件单独记一条，四类触发各一个事件名：抢占、换出、换入、前缀驱逐。字段含时刻、request id 或前缀哈希、token 数、耗时、触发原因（池占用超阈值、策略排序、上游默认）。策略退回上游默认时记一条退回事件，带退回原因。

### 7.4 开销与精度

开销：

- 每条记录约 200 字节，每请求五到八条，1k 请求占用不到 2 MB 缓冲区。批次快照按每步一条另计，步数与请求数的比值写进报告。
- 写入走环形缓冲，调度路径上不申请内存、不加锁。
- 落盘由独立线程批量导出，按 step 或按时间窗口触发。
- 开销用开关前后对照测：同一轨迹跑两遍，比较 P50 与 P99 TTFT、吞吐。目标是不超过 1%，超过就降采样率。
- 显存调度策略的计算在调度步内同步执行，开销单独测，口径见 13.4。

精度：

- 时间戳用单调时钟，GPU 侧用 CUDA event 记录首 token 与块边界，避免主机时钟与异步执行错位。
- 首 token 在异步执行下可能比主机看到的时间早，差值单独测量并写进报告。
- 打点不能进 CUDA Graph 的捕获区，Graph 重放期间没有主机分支。做法是在 Graph 外记录 step 级的时刻，请求级时刻按 step 归属推算。推算误差与 TPOT 条款阈值同量级时，decode 段归因改用模型估计，两套口径的差值写进报告。

### 7.5 与调度特性的交互

五类特性会改变时序的含义，逐条处理：

1. chunked prefill。一个请求的 prefill 分多段，归因时把各段加总，段间让给 decode 的时间不计入该请求的 prefill。
2. 前缀命中。命中部分不参与计算，prefill 耗时按「实际计算 token 数」归因。命中数单独记，合同若约定命中不计费，结算也用它。
3. 抢占与重算。被抢占的请求重新 prefill，记一次重算事件，重复计算的 token 数单列。这一项是违约归因里最容易被忽略的一段。
4. 换出与换入。请求的 KV 搬到主机内存期间不在批里，这段等待计入排队段；换回后的重新 prefill 计入 prefill 段的重算子项。两段分开记，合并会掩盖换出策略的真实代价。
5. 取消。客户端断连后引擎是否停止计算，取决于引擎的取消实现。trace 记取消时刻与已生成 token 数，用于计量与误拒统计。

### 7.6 标定

五组参数离线标定，在线查表：

1. TPOT 与 batch token 数的关系。扫 batch 大小 1、4、8、16、32，记录每步耗时，拟合一张表。混批另扫一档：固定 decode 请求数 8，prefill chunk 取 512、1024、2048、4096 token，记录同一步里 decode 请求的实测间隔。预测与批组装按批内是否含 prefill chunk 选表。
2. prefill 每 token 时间。命中与未命中两档，各扫输入长度 1k、4k、16k、32k。
3. 排队时间不用模型。入队到出队是直接测出来的，排队模型只在预测器里用于前瞻。
4. 换出与换入带宽。扫传输块大小 1 MB、16 MB、128 MB、1 GB，记录设备到主机与主机到设备的实测带宽与每次传输的固定开销，拟合一张表。13.1 的让位选择用这张表与第 2 组比较。
5. 冷启动四段耗时。进程拉起、权重加载、KV 池初始化与 CUDA Graph 捕获、前缀缓存重建各记一段。权重加载扫对象存储与本地盘两个来源；前缀缓存重建按共享前缀比例三档各记回到稳态命中率所需的请求数与时间。10.4 的替换决策与 18 节的恢复报告用这张表。

### 7.7 降级与采样

打点有开关，三种状态：

- 全量。合同窗口内、违约相关请求。
- 采样。正常流量按比例。
- 关闭。引擎压力过高或打点自身开销超标时降级，归因退化为模型估计，误差单列一节。

缓冲区溢出时丢最旧的记录，丢掉的条数计数并进面板。批次快照与显存事件不参与请求级采样，缓冲区溢出时按同样规则丢弃并计数。

调度策略有独立的退回开关，三种触发条件：参数缺失或过期、特征漂移超阈值、策略计算开销超标。退回后引擎沿用上游默认，归因与结算照常，调度收益按退回期间的实测值计。

### 7.8 引擎侧验收

三项指标验收这一节：

1. 开销。开关前后的 TTFT 与吞吐差，目标 1% 以内。
2. 完整性。网关请求计数与 trace 条数对账，缺失率低于 0.1%；批次快照条数与调度步数对账，显存事件与引擎侧抢占计数对账；副本健康事件与摘除、回插动作逐条对账，摘掉一个副本必须有一条对应的改路记录。
3. 归因精度。同一批违约请求上，打点归因与模型估计比较，报误差。

三项都过，预测、结算与显存调度才有依据。

## 8. 核心一：计量与契约登记

计量口径先定死，后面所有数字都以它为准：

1. token 数取引擎返回的 usage，网关不自行估算。
2. 缓存命中的 token 是否计费，写进合同，两种约定分别给出实验结果。
3. 被拒绝的请求计 0 token，计入误拒率。
4. 断连的请求按已生成 token 计费，未生成部分不计。

契约登记管四件事：条款版本、生效与失效时间、变更审计、样本量门槛。条款变更留旧版本，结算时按请求发生时刻对应的版本计算，避免同一窗口内两套规则。

合同期限同时供三处使用：结算判违约、预测器算完成概率、显存调度器算剩余期限。三处读同一个条款版本，版本号写进流水表、预测记录与显存事件。可用性条款与故障责任分档的两档系数一并登记，版本号写进副本健康事件与归因记录，摘除决策与硬件子项判定都按请求发生时刻的版本取系数。

## 9. 核心二：违约预测

预测对象是一个概率：在当前队列、显存与副本状态下，这个请求在合同期限内完成的概率。输出概率与置信区间，不输出布尔判定。概率与剩余期限同时供处置器与显存调度器使用。

特征分三组：

- 系统状态：队列长度、KV 占用、inflight、近期 TTFT 分位、副本余量、副本健康状态（在役、疑似慢、已摘除、回插预热中）。
- 请求形状：输入 token 数、是否命中前缀、合同分位。
- 输出长度估计：首 token 前用同类请求的历史分布，首 token 后按已生成数与历史衰减更新。

计算分四步，每步能单独核对：

1. 排队时间。当前队列与副本吞吐估计，给区间。
2. prefill 时间。实际计算 token 数乘以每 token 时间，命中与未命中分档，参数来自 7.6 的标定。
3. decode 时间。输出长度乘以 TPOT，TPOT 按 batch 组成查表，批内含 prefill chunk 时查混批表。
4. 汇总。把输出长度的分布积分到「总时间不超过期限」的概率。

校准单独做。按预测概率分桶，比较桶内实际达标率与预测值，画可靠性曲线，报 Brier 分数。未通过校准的概率不进入处置，也不进入让位选择的排序。校准按统计窗口重做，窗口与合同窗口一致。

漂移检测：特征分布与历史基线比较，超阈值告警并暂停自动处置，转人工确认。显存调度同步退回上游默认，记退回事件。漂移暂停的是准入、降级、扩容三类按概率触发的动作；副本摘除按健康信号触发，不随漂移暂停，否则漂移期间的硬件故障无人处理。

副本被摘除时，它上面在飞请求的完成概率归零，处置器改路到其余副本，预测按新副本的队列与前缀命中状态重算一次。改路后的请求带原 request id 与一条重算标记，结算按已生成 token 计费，重算部分按合同约定决定是否计入违约。

失效条件：突发到达时特征失真；缓存全冷时 prefill 分布偏移；模型或引擎版本切换后历史样本失效；副本摘除与回插期间队列状态突变，历史分位失真。

## 10. 核心三：处置与副本容错

### 10.1 五类动作

1. 准入。预测概率低于阈值时拒绝，返回理由与建议重试时间。误拒率单独统计，它是本方案的主要成本。
2. 降级。限制输出长度、降低优先级、切到合同允许的小模型。降级改变质量，合同预先写明哪一档允许。
3. 扩容。预测下一窗口会集体违约时提前触发。触发时点按「预热耗时」与「预测窗口」的交叉点定，预热四段见 7.6 第 5 组。
4. 路由。按副本预测余量选副本，避免把请求送进即将违约的副本；命中同一前缀的请求优先送往已缓存该前缀的副本。
5. 摘除与替换。副本失联或判定为慢副本时摘掉 endpoint，在飞请求改路重算，备副本预热后接流量，故障副本修复后回插。触发信号见 10.3，子决策见 10.4。

### 10.2 代价表

代价列四项折算成同一单位：

| 动作 | 代价 | 收益 |
|---|---|---|
| 拒绝 | 业务损失，按合同请求单价折算 | 保住其他请求的达标率 |
| 降级 | 质量折损，按合同折算系数 | 降低单请求耗时 |
| 扩容 | 单位时间成本乘以预热时长 | 提升整体容量 |
| 摘除与替换 | 在飞请求重算的 prefill 算力成本，加备副本冷启动机时，误杀时再加一次白付的冷启动 | 故障窗口内的违约次数减少 |

迟滞与冷却按动作分别设，避免振荡。每次动作记录触发时的预测概率或健康信号、动作类型与事后结果，形成重标定样本。

### 10.3 检测：三条信号

| 信号 | 来源 | 判据 | 延迟量级 | 判得出什么 |
|---|---|---|---|---|
| 网关探针 | 编排侧健康检查 | 连续失败次数达阈值 | 探针周期乘失败阈值，K8s 默认 periodSeconds 10、failureThreshold 3，合计 30 s；要秒级就把周期降到 1–5 s | 进程死、网络断 |
| step 时间分布 | 7.3 的批次快照按副本聚合 | 同 batch token 数桶内，某副本 step 时间中位数连续 N 个窗口超过集群中位数一个百分比 | 一个聚合窗口 | 慢副本 |
| 硬件信号 | XID、降频原因、ECC 计数 | XID 79 掉卡、63/64 ECC、74 NVLink；`nvidia-smi -q -d PERFORMANCE` 的 Clocks Throttle Reasons 非零 | 内核即时上报，告警延迟取决于采集周期 | 坏卡、慢的成因 |

三条各判一层：探针判进程活着，step 分布判算得快，硬件信号判为什么慢。缺硬件信号时慢副本判定只靠 step 分布，归因的硬件子项标证据不足。

采集路径：XID 从内核日志取，降频与 ECC 走 DCGM 或 `nvidia-smi -q -d ECC,PAGE_RETIREMENT`，采集周期决定告警延迟的下限。降频字段名随驱动版本变，旧驱动叫 Clocks Throttle Reasons，新驱动叫 Clocks Event Reasons，现勘时按实际输出记。容器里能不能读到取决于设备挂载与权限，现勘第 7 条核实。短诊断用 `dcgmi diag -r 1`，秒级返回，只对已摘除的副本跑，在接流量的副本上跑会污染测量。

### 10.4 摘除与替换的三个子决策

在飞请求默认重算。代价式子与 13.1 共用一张表：已生成 token 数 × prefill 每 token 时间。跨副本 KV 迁移属于 16 节调研层，不自建；本机型上迁移带宽账与重算账的实测差值写进报告。

误杀门槛与回插。慢不等于坏：机房温度导致降频时，摘掉旧副本拉起新副本一样降频，白付一次冷启动。判定要连续 N 个窗口成立才摘除，摘除后带冷却期，冷却期内对同一副本不再重复动作。故障副本修复后重新预热再回插，回插时先给一部分流量，达标率回到集群中位数才恢复全量。误杀次数单列成验收门槛，判定用配对轨迹：对照组同一时刻该副本仍在役且请求按时完成，实验组把它摘了，这次计入误杀分子。

冷启动四段账查 7.6 第 5 组表。权重 16 GB，对象存储 10 GB/s 是 1.6 s，本地 NVMe 3 GB/s 是 5.3 s；CUDA Graph 按捕获的 shape 数各付一次；前缀缓存重建靠流量重新命中，共享前缀比例高时要几十个请求才回到稳态。进程就绪与热态回到稳态是两个时刻，面板与报告分开报，秒级恢复只适用于前者。

### 10.5 分工与对照

处置与显存调度的分工：处置改变请求的命运（拒绝、降级、换副本、加副本、摘副本），显存调度改变请求在副本内的等待与计算顺序。扩容触发前先看显存调度的收益空间，池占用长期低于阈值的副本不触发扩容。摘除与扩容共用同一份预热耗时表，摘除造成的容量缺口由扩容补，两个动作之间带互锁，避免同一窗口里既摘又扩造成振荡。

容错三档对照吃同一份轨迹与同一组故障注入：无容错（探针失败也继续路由）、只探针摘除、探针加 step 分布加回插。验收三项：

1. 故障窗口内的违约次数低于无容错档，报中位数与区间。
2. 第三档的误杀次数不高于第二档，慢副本判定新增的摘除动作里误杀占比单列。
3. 恢复四段耗时分段报，进程就绪与热态稳态分开。

## 11. 核心四：归因与举证

四段拆分：排队、prefill（含重算）、decode、客户端与网络。换出到换入之间的等待计入排队段，换回后的重新 prefill 计入 prefill 段的重算子项，切分规则见 7.5。

归因以 7.2 的打点为主，模型估计为辅。两套结果在同一批请求上对照，报告误差。四段之间存在交叉，排队与 prefill 争抢同一份算力，交叉部分的归属规则写进报告。

decode 段拆一个硬件子项。判据两条同时成立：该副本的 step 时间偏离同桶集群中位数超阈值，且降频原因或 ECC 计数非零。只满足前一条时子项标证据不足，偏离留在批次组成里解释。硬件子项的占比供 12 节的故障责任分档用，它把「平台慢」与「硬件故障」分开，两者的赔付口径不同。

证据包七件：违约事件编号、请求 trace、当时副本指标快照、批次组成、显存事件序列、副本健康与硬件信号快照、合同条款版本。证据包可回放：同一份轨迹重跑，比较处置决策、让位选择与摘除决策是否一致。

多租户归因回答第二个问题：这次违约由哪个租户的流量造成。判定依据是同时段批次快照与各租户的请求占比，批次快照全量记录保证分母完整。

## 12. 核心五：结算与对账

结算按合同窗口出账，四项数字：达标率、违约次数、赔付金额、归因占比。

规则：

1. 样本量不足门槛时按合同约定处理，默认沿用上一窗口的达标率并标注。
2. 赔付公式可配置，设单窗口上限。
3. 账单与流水表对账，差异超过阈值时冻结出账并告警。
4. 争议期内证据包可导出，租户可自行复核。
5. 故障责任分档。归因的硬件子项成立时，违约归平台侧硬件故障，按合同约定的一档系数折算；子项证据不足时归运行态违约，按另一档折算。两档系数与判定依据写进条款版本，申诉时以证据包里的硬件信号快照为准。

对账差异的常见来源：断连请求、重试请求、摘除后改路重算的请求、缓存命中计费口径、窗口边界。

结算与显存调度共用同一份达标判定，两处读同一个条款版本。调度收益报告里的达标 token 产出率不进结算单，它衡量平台侧的算力效率，不构成对租户的赔付依据。

## 13. 核心六：显存调度

一个指标：达标 token 产出率 = 合同窗口内达标请求的输出 token 总数 / (KV 池容量 GB × 窗口秒数)。

口径四条：

1. 分子只计达标请求的输出 token，违约请求计 0。
2. 分母取引擎启动时配置的 KV 池容量，一组对照内固定不变，跨组比较时标注容量与机型。
3. 前缀命中的 token 不进分子，命中省下的是 prefill 计算量。
4. 被拒绝与被降级的请求不进分子，误拒率与降级次数作为验收门槛单列。

多副本时分母取参与对照的各副本配置容量之和，副本数在对照内固定。摘除期间该副本的容量留在分母里，分子按实际产出计，摘除造成的损失不被分母缩小掩盖。

三个决策点，都在引擎调度器内，参数由契约服务按窗口下发。本节作用在单个副本内；副本被摘除后它的调度器不再运行，在飞请求改路由 10.4 处理，两层动作互不覆盖。

### 13.1 让位选择

KV 池占用超过配置阈值时，调度器从当前持有 KV 的请求里选一个让出显存。上游按到达顺序抢占并重算，这里对每个候选算两个耗时：

- 重算耗时 = 该请求已生成的 token 数 × prefill 每 token 时间，查 7.6 第 2 组表。
- 换出耗时 = 该请求 KV 字节数 / 实测带宽 + 换回时的同量传输 + 两次固定开销，查 7.6 第 4 组表。

取耗时小的动作。候选之间按「合同剩余期限 − 让位造成的延迟」排序，值最小的先让位。剩余期限由合同条款、已生成 token 数与输出长度估计给出，估计走 9 节的同一套分布。

排序只在池占用超阈值时触发，阈值写进配置；未超阈值时沿用上游顺序，不产生排序开销。输出长度估计在首 token 之前误差最大，这一段让位选择退回上游顺序并记退回事件。

### 13.2 前缀保留

前缀缓存满时上游按 LRU 驱逐。这里对每个前缀算保留收益：

保留收益 = 未来一个窗口内预计命中次数 × 每次命中省下的 prefill token 数 × prefill 每 token 时间

预计命中次数由该前缀的历史到达率与租户合同请求量给出，每次命中的 token 数取该前缀的实际长度，每 token 时间查 7.6 第 2 组表。按收益升序驱逐末位。历史到达率超漂移阈值时退回 LRU，记退回事件。

### 13.3 批组装

chunked prefill 的 chunk 上限决定同一步里 decode 请求被拖慢多少。调度器取批内 decode 请求的合同剩余期限最小值，按该值选 chunk 上限档位：期限紧的批取小 chunk，宽松的批取大 chunk。档位与期限的映射来自 7.6 第 1 组的混批表，离线标定，在线查表。

chunk 调小会拉长长请求的 prefill，输入 ≥16K 请求的 TTFT 与达标率单列监控。

### 13.4 对照与验收

四组吃同一份轨迹：上游默认、只开让位选择、只开前缀保留、三项全开。每组七次取中位数，冷热态分开，口径按 18 节。

验收三项：

1. 达标 token 产出率的提升幅度，报中位数与区间。
2. 误拒率与降级次数不高于对照组。误拒的判定用配对轨迹：对照组按时完成的请求在实验组被拒绝，这些请求计入误拒分子，完成时间取对照组实测值。
3. 输入 ≥16K 请求的达标率不低于对照组。

开销单列一项：策略计算在调度步内执行，记录每步的排序与查表耗时，目标不超过步长时间的 1%，超过就提高触发阈值或退回默认。

### 13.5 已知限制

换出收益取决于 PCIe 与主机内存带宽，单机实测值不外推到其他机型。共享前缀比例低的负载下前缀保留收益接近零，报告给出该负载的实测差值。池占用长期低于阈值时让位选择不触发，这一档的收益为零。策略插入位置依赖引擎调度器的代码结构，版本升级后重新核实位置与开销。

## 14. 可观测性

指标分六层，每层有明确的负责人：

| 层 | 指标 | 用来回答 |
|---|---|---|
| 契约层 | 达标率、违约率、赔付额、误拒率 | 合同是否被履行 |
| 预测层 | 校准误差、Brier 分数、漂移告警数 | 预测值能不能信 |
| 处置层 | 动作次数、动作收益、振荡次数、摘除与回插次数、误杀次数、故障窗口违约次数、冷启动四段耗时 | 处置是否值得 |
| 显存层 | 达标 token 产出率、换出与重算比例、前缀命中率、长请求达标率、策略退回次数 | 固定算力下的产出是否提高 |
| 归因层 | 四段占比、残差、重算 token 占比、硬件子项占比与证据不足条数 | 违约由哪一段造成 |
| 引擎层 | 打点开销、策略计算开销、trace 缺失率、采样率 | 测量与策略本身是否可信 |

面板四块：契约总览（当前窗口进度与预测达标率）、租户视图（单个租户的请求与归因）、副本视图（余量、扩容记录、KV 池占用、换出吞吐、产出率与长请求达标率、健康状态、同桶 step 时间分布、摘除与回插记录、进程就绪与热态稳态两个时刻）、预测视图（可靠性曲线与漂移）。显存层的产出率与长请求达标率在副本视图里与对照组同图。

告警七类：违约率超阈值、校准误差超阈值、误拒率超阈值、对账差异超阈值、长请求达标率低于对照组、副本失联、副本 step 时间偏离同桶集群中位数。告警带 request id 样本，点开即到 trace 与当步批次快照；后两类带副本编号与健康信号快照，点开即到摘除决策与当时的三条信号取值。

可回放是这一层的核心：任一违约事件都能从面板跳进证据包，重跑一次并对比处置决策与让位选择。

## 15. 增量池

两项，与主线共用 trace 与面板：

- 多租户公平。按合同权重分配 KV 与算力，度量干预前后的达标率差距。
- 结构化输出。合同加入格式约束，token 预算与违约概率随之变化。

## 16. 调研层

P/D 分离与跨副本迁移两项只读文档与源码，各做一次集成实验，写调研笔记，不自建。KV 到主机内存的换出属于 13 节的实现范围，跨节点与落 NVMe 的换出不在本期。跨副本 KV 迁移在 10.4 里默认走重算，迁移与重算的收益账由这一项的集成实验给出，实测差值写进报告。覆盖边界在报告里单列一节。

## 17. 覆盖边界

覆盖副本级分布式：单机多卡多副本、副本间路由、故障摘除与回插。判据是权重单卡放得下就加副本，放不下才做模型并行，本期模型 8B 走加副本一侧，跨机张量并行与流水并行不做。不覆盖模型质量与效果评估，不覆盖训练侧，不覆盖跨云调度，不覆盖节点级维修与备件管理。合同条款限定在延迟与可用性两类，吞吐类条款不纳入。赔付口径与故障责任分档是自定义模板，法律效力未经核实。显存调度的收益指标衡量平台侧效率，不改写合同条款，也不进结算单。硬件信号在容器里读不到时，慢副本判定只靠 step 时间分布，归因的硬件子项标证据不足。

## 18. Benchmark 方法学

1. 每组至少七次，取中位数，报告区间。
2. 冷热态分开。冷态每轮重启副本，热态写明预热流程。
3. 模型、引擎、镜像、机器、负载配置、KV 池容量、副本数、故障注入类型与时刻随报告入库，一条命令复现。
4. 三组条件吃同一份轨迹：现状（反应式扩容加无准入）、仅预测不处置、完整方案。显存调度另按 13.4 跑四组，副本容错另按 10.5 跑三档。
5. 客户端饱和的轮次作废，负载台自身的 CPU 与连接数曲线作为附件。
6. 预测校准单独一节，与性能指标分开报告。
7. 处置动作的收益按「同窗口内违约次数差」计算，不用单次请求的耗时差。
8. 打点与策略计算的开销各单列一组，见 7.8 与 13.4。
9. 负载形状按共享前缀比例与输入长度分布分档，每档单独出结论，不合并成一个总均值。
10. 故障注入按 6.2 四类各跑一遍，爆炸半径限定一个副本，注入期间的负载轨迹与无注入轮次共用同一份。
11. 恢复耗时按四段分别报，进程就绪与热态回到稳态是两个时刻，两者都进报告，秒级恢复的结论只挂在前者上。

## 19. 项目优点

1. 交付物是一个可部署的服务，六个核心各有输入输出，可以单独演示。
2. 引擎侧有自研的打点、批次快照与调度策略，归因与收益都不依赖猜测，误差可量化。
3. 四个结算数字都能被第三方用同一份流水复算。
4. 预测的校准误差与处置收益画在同一张图上，回答「预测准到什么程度才值得处置」。
5. 违约可回放，争议有证据，这在私有化部署的采购场景里是硬需求。
6. 同一份合同条款既用于赔付判定，也用于显存取舍，固定算力下的产出提升有配对轨迹与门槛指标作证。
7. 副本故障可注入、可检测、可回放，可用性条款的赔付金额有故障窗口违约次数作证，硬件故障与运行态违约在归因里分开。

## 20. 诚实清单

- 合同模板是自定义的，赔付口径不来自行业标准。
- 单卡与双卡规模只做机制验证，不做规模外推。
- 输出长度未知，首 token 之前预测误差最大，这一段单独报告，让位选择在这一段退回上游顺序。
- 四段归因有交叉，占比之和与总延迟存在残差，残差写进报告。
- 突发流量下预测滞后，处置来不及，这个区间属于方案的失效范围。
- 结算依赖业务口径，报告给模板与假设，不给普适结论。
- 降级档位改变输出质量，本产品不评估质量损失，只按合同系数折算。
- 打点与策略插入位置依赖引擎版本，升级后需要重新核实。
- 换出收益依赖 PCIe 与主机内存带宽，换机型需重测 7.6 第 4 组。
- 共享前缀比例低、输入短、池占用长期低于阈值时，显存调度收益接近零，该档实测差值写进报告。
- 副本容错只在单机多卡上验证，跨机故障与真实网络分区的形态未覆盖。
- 锁频模拟的是降频的结果，温度与电源故障的成因未复现。
- 硬件信号在容器里可能读不到，读不到时慢副本判定只剩 step 时间分布一条，归因的硬件子项标证据不足。
- 进程就绪是秒级，热态回到稳态靠流量重新命中，两者分开报，秒级恢复的结论只挂在前者上。
- 误杀门槛与回插流量比例没有普适值，按负载与副本数标定，换场景重标。
- 故障责任分档是自定义模板，法律效力未经核实。
- 跨机张量并行的通信占比是量级推算，本期不做模型并行，推算值不进收益结论。

## 21. 交付物

网关；契约服务（登记、预测、处置与副本容错、显存调度、归因、结算六段）；引擎打点、批次快照与调度策略补丁；观测面板与告警规则；负载台（合同场景生成器与四类故障注入器，可独立复现）；七份报告（打点开销与精度、预测校准、处置收益、显存调度收益、副本容错收益、归因精度、结算对账）；一份核实报告（现状矩阵与缺口排序）。

## 22. 术语

| 术语 | 含义 |
|---|---|
| TTFT | 从请求发出到收到第一个内容型 token 的时间 |
| TPOT | 解码阶段每个输出 token 的平均间隔 |
| 统计窗口 | 合同约定的达标率统计周期 |
| 赔付口径 | 违约判定与金额折算规则 |
| 归因残差 | 四段耗时之和与总延迟的差 |
| 证据包 | 一次违约的可复核材料集合 |
| 误拒率 | 被拒绝但本可按时完成的请求占比 |
| 批次快照 | 每个调度步的请求组成与资源占用记录 |
| 显存事件 | 抢占、换出、换入、前缀驱逐四类动作的记录 |
| KV 池容量 | 引擎启动时配置的 KV 可用显存，产出率的分母 |
| 达标 token 产出率 | 达标请求的输出 token 数除以 KV 池容量与窗口秒数的乘积 |
| 让位选择 | KV 池超阈值时选哪个请求换出或重算 |
| 前缀保留 | 前缀缓存满时按保留收益排序驱逐 |
| 策略退回 | 参数缺失、过期或漂移超阈值时改用上游默认策略 |
| 副本摘除 | 网关停止向某副本路由，在飞请求改路重算 |
| 回插 | 故障副本修复并预热后重新接流量 |
| 误杀 | 副本本可按时完成请求却被摘除 |
| 慢副本 | 同 batch token 数桶内 step 时间持续偏离集群中位数的副本 |
| 冷启动四段 | 进程拉起、权重加载、KV 池初始化与 CUDA Graph 捕获、前缀缓存重建 |
| 热态稳态 | 前缀命中率与 step 时间回到集群中位数的状态 |
| XID | NVIDIA 驱动上报的硬件错误编号 |
| 硬件子项 | decode 段里由降频或 ECC 解释的那部分耗时 |
