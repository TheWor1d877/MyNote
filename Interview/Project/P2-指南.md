# P2 指南：KV 取回与重算的在线决策与重叠执行层

## 1. 项目介绍

电梯陈述：请求到达时，决策层按本机标定的代价表与当前计算进度，决定这个请求的前缀 KV 从分层存储取回还是重算；自研传输引擎按块优先级与期限执行取回，与 GPU 计算重叠；没有 RDMA 的机器降级到 TCP，语义不变。主干交付请求级决策的可部署产品，侧枝放块粒度混合执行与层间流水，逐项独立降级。

五重定位：

1. 决策方。取回还是重算按请求在线判定，输入是代价表与当前状态，替掉静态配置与人工经验。
2. 测量方。取回带宽、重算成本、重叠干扰系数按机器标定，决策查表，代价表带版本与口径。
3. 传输方。自研 RDMA 传输引擎，块优先级与期限进入传输调度，TCP 降级同语义。
4. 执行方。取回与计算在独立 CUDA stream 上重叠，pinned 内存、GPUDirect、GDS 决定传输路径。
5. 运维方。k8s 部署、一条命令拉起、滚动升级不冷缓存、存储节点故障不中断服务。

三类用户与各自关心的事：

| 用户 | 关心的事 | 在本产品里看到的东西 |
|---|---|---|
| 平台运维 | 命中率、取回与重算比例、TTFT 分布、降级与退回事件 | 决策记录、代价表版本、运维演练记录 |
| 引擎接入方 | connector 挂法、对 vLLM 的补丁面、回退方式 | 挂载配置、三层改动边界、一键回退 |
| 性能复核方 | 收益来自哪档负载、数字能否复现 | 六组对照报告、一条命令复现、RDMA 与 TCP 双口径 |

本项目不改 attention kernel 与量化实现，不做模型并行与跨机张量并行，不做训练侧，不做合同结算与 SLO 赔付，不做多网卡池化与多协议通用化。NCCL 不引入，集合通信语义与点对点 KV 传输不匹配。

主干与侧枝：主干是请求级决策产品，含决策层、传输引擎、重叠执行、最小块存储、平台四件，半年内保证交付。侧枝两项：块粒度混合执行（一个请求内一部分块取回、一部分块重算，第 12 节），层间流水（算第 i 层时取第 i+1 层的 KV，第 13 节）。侧枝每项带独立降级开关，降级后回到主干语义，主干验收不受影响。

## 2. 问题与动机

### 2.1 外部事实

- 分层 KV 存储与 RDMA 传输已有产品。Mooncake Transfer Engine 做零拷贝 RDMA、GPUDirect、拓扑感知选网卡、TCP 兜底，在阿里与蚂蚁部署；LMCache 做 HBM/DRAM/NVMe 三层与跨实例共享；NVIDIA Dynamo KVBM 分 G1–G4 四档，传输走 NIXL。出处：[Mooncake 进展](https://www.infoq.cn/article/EhS1Zy1CiUHtJ7mheqmv)、[Dynamo KV offloading](https://docs.nvidia.com/dynamo/v1.5.0/kubernetes/kv-cache-offloading/overview)。
- LMCache 论文自述加载 KV 不一定比重算快，收益取决于带宽与负载。出处：[LMCache 论文解析](https://gentlecold.top/20260613/lmcache-paper-analysis/)。
- LMCache 团队 2026 年 5 月 MI300X 实测：低负载 8 用户、32K 上下文，原生前缀缓存完成 52 个请求，LMCache 完成 25 个；高负载 32 用户、100K 上下文，TTFT 102.17 s，原生 34.59 s。offload 静态开启后收益随负载档翻面。出处：[MI300X 实测](https://www.51cto.com/article/853886.html)。
- 生产默认路由仍是前缀亲和（sticky）：取不取、从哪层取由静态配置给出，没有在线组件读当前带宽与计算占用。出处：[vLLM/SGLang KV 调研](http://juejin.cn/entry/7685238126571208731)。
- FAST'26 归纳三个矛盾：数据放不对、复用算不对、调度看不见。本项目接「复用算不对」。出处：[FAST'26 归纳](https://github.com/ForceInjection/forceinjection.github.io/blob/main/09_inference_system/kv_cache/README.md)。
- vLLM 已带 kv_connector v1 与官方 OffloadingConnector。connector 提供命中查询、加载、保存三类回调，支持异步加载与按层等待；OffloadingConnector 做 chunk 粒度加载，命中判定按连续前缀，同步或异步由静态字节预算（sync_load_budget_bytes）决定。取回与重算之间没有在线成本决策。源码核实结论见第 3 节。

### 2.2 仍然成立的问题

1. 取回与重算的决策是静态的。同一份配置换机型、换负载档收益翻面，MI300X 那组数据是证据；OffloadingConnector 的字节预算也是静态配置，没有组件在线算这笔账。
2. 传输与计算不重叠。取回占网卡与 PCIe，计算占 SM，两者串行时取回耗时全额暴露在 TTFT 上。
3. 代价表缺位。带宽与重算成本不按机器标定，决策用经验值；换机型后没有重标定入口。
4. 降级即断档。非 RDMA 机器上 KV 复用路径整体不可用，或回退到另一套语义，两类机器的数字不可比。

### 2.3 需求强度

8B GQA 模型每 token 的 KV 是 128 KiB，30K 上下文的前缀占 3.8 GiB。这 3.8 GiB 取回还是重算，取决于传输带宽与重算成本。量级推算（A100 bf16、8B、prefill 按 50% MFU，取回不含固定开销）：

| 路径 | 有效带宽 | 取回 3.8 GiB | 重算 30K token |
|---|---|---|---|
| IB 200 Gbps | 25 GB/s | 0.15 s | 3 s |
| PCIe Gen4 x16 | 20 GB/s | 0.2 s | 3 s |
| 25 GbE TCP | 2.8 GB/s | 1.4 s | 3 s |
| 10 GbE TCP | 1.1 GB/s | 3.5 s | 3 s |

IB 上取回比重算快一个数量级；10 GbE 上两者同量级，收益随队列与负载翻面。高负载下重算挤占 decode 批的算力，重算成本上升；传输路径饱和也抬高取回耗时，两边都在动，静态配置跟不住。这组推算由第 6 节标定的实测值替换。

KV 池容量决定复用需求的规模：80 GB 卡的 KV 池约 60 GB，放得下十五个 30K 请求，并发越过这条线，前缀只能放 DRAM、NVMe 或远端，取回决策成为每个命中请求的必经路径。

## 3. 现勘与核实

接口与调度语义已在本地 vLLM checkout（v0.34.0rc0，HEAD 595b1514e8）读源码核实，结论如下。路径相对 vLLM 仓库根目录。

| 事实 | 结论 | 位置 |
|---|---|---|
| 命中查询语义 | get_num_new_matched_tokens 返回（token 数，是否异步），只表达连续前缀，无按块选择能力 | kv_connector/v1/base.py:544 |
| 块粒度信息 | update_state_after_alloc 收到 KVCacheBlocks，每块的 block_id 与 block_hash 都拿得到 | base.py:597，kv_cache_utils.py:166 |
| 异步加载 | 请求状态 WAITING_FOR_REMOTE_KVS 存在，get_finished 报告加载完成，调度器才放请求进 prefill | request.py:427，scheduler.py:1548 |
| 按层等待 | wait_for_layer_load / save_kv_layer 在每层 attention 前后调用，调用点带 eager_break_during_capture，在 CUDA Graph 断点处 eager 执行 | attention/kv_transfer_utils.py:51，attention.py:800 |
| 图捕获模式 | 默认优化级别 O2 对应 FULL_AND_PIECEWISE，prefill 与混批也被分段捕获；图在 attention op 处切开；connector 可声明强制 PIECEWISE | config/vllm.py:338，compilation.py:926，base.py:750 |

| 上游 offload | OffloadingConnector 按 chunk 加载、连续前缀命中、静态字节预算分同步异步，无取回/重算成本决策 | kv_offload/，offloading/scheduler.py:828 |

两条结论直接决定侧枝形态：块粒度信息拿得到，但命中判定与调度按连续前缀记账，非连续命中要动调度器核心（第 12 节补丁面）；按层等待在图断点处执行，prefill 被捕获也不冲突，层间流水不需要改捕获模式（第 13 节）。

剩余动作清单，全部是实测与部署核实：

1. 部署版本对齐。锁定产品挂载的 vLLM 版本，与上表核实版本不一致时重读差异项，重点是命中查询签名、异步加载状态、图捕获默认值三处。
2. soft-RoCE 上跑通 verbs 最小通路（复用 S3 装置）：QP 建立、MR 注册、一次 RDMA READ、CQ 取完成，记容器权限要求。
3. 租用的 A100 确认拓扑：网卡与 GPU 是否在同一 PCIe switch 下（GPUDirect 可行性），IB 实测带宽，NVMe 型号与 GDS 可用性。
4. 四张代价表（第 6 节）在本地 4060 与租用 A100 各出一版实测表，记固定开销与干扰系数。
5. 4060 上验证 pinned 内存与 cudaMemcpyAsync 的 stream 重叠可行性，记 pinned 与 pageable 的带宽差。
6. 侧枝补丁回归面核实：在第 12 节列出的补丁点上跑 vLLM 原有调度测试集，记失败项与修复方式。

现状矩阵：

| 环节 | 上游现状 | 本产品接的位置 |
|---|---|---|
| 分层存储 | LMCache、KVBM、Mooncake Store 成熟，vLLM 自带 OffloadingConnector | 自研最小块存储，只做块读底座，增量不在这 |
| RDMA 传输 | TE 做零拷贝、多网卡、failover | 自研引擎，增量在块优先级与期限调度、与决策层协同 |
| 取回/重算决策 | 论文承认问题，生产静态配置，OffloadingConnector 用静态字节预算 | 自研核心，按请求在线判定 |
| 重叠执行 | connector 有按层等待接口，在图断点执行 | 主干做整请求预取重叠，层间流水放侧枝 |
| 路由 | 前缀亲和默认 | 主干保持前缀亲和，决策层只输出取回或重算 |

头号风险：侧枝补丁的回归面。非连续命中要动调度器记账、块分配、输入构造多处（第 12 节），补丁后原有调度行为的回归测试是主要工作量。第二风险是 GPUDirect 拓扑：网卡与 GPU 不在同一 PCIe switch 下时传输走 pinned 中转，带宽折扣进代价表。第三风险是 soft-RoCE 的容器权限，读不到时 RDMA 路径只在租机上实测。

红灯处理：部署版本与核实版本差异大到接口语义变化，主干退化为网关侧决策，重算成本用估计口径，侧枝标未做。GPUDirect 不可用，中转路径照跑，报告直连与中转的实测差。RDMA 环境完全拿不到，产品按 TCP 单路径交付，RDMA 数字标未测。

## 4. 产品形态与使用流程

部署形态：一个薄网关（接入、request id 注入、路由执行），N 个 vLLM 副本（挂 connector），一个决策服务（索引同进程），M 个存储节点。传输引擎嵌在副本与存储节点两侧，副本发起取回，存储节点服务块读。单机跑通全流程（4060，TCP 路径），双机验证远端取回与 RDMA（租用 A100 带 IB）。副本之间不共享模型状态，一个副本故障不动其余副本的 KV 池。

使用流程六步：

1. 标定。标定工具在目标机器跑四张代价表，写版本与机器口径（GPU 型号、网卡、PCIe 拓扑、驱动、引擎版本）。表入库后决策服务按版本加载，同一集群里不同机型各用各的表。
2. 挂载。connector 配置指向决策服务与存储节点，网关挂副本。挂载只改配置，不动 vLLM 核心代码；摘掉配置即回到原生 vLLM。
3. 运行。命中查询返回命中深度与层位，决策层输出取回或重算。输出取回时请求进异步加载状态，传输引擎发起块读，与其余请求的计算重叠；加载完成后调度器放请求进 prefill，跳过命中段。save 路径在 HBM 驱逐时把 KV 写回分层。
4. 降级。RDMA 不可用的机器配置切 TCP，指令与完成事件语义不变，代价表切对应口径。代价表缺失、漂移或开销超标时决策退回重算，产品语义等于原生 vLLM 加本地前缀缓存。
5. 运维。滚动升级、存储节点故障演练、配置热更新，见第 11 节。
6. 复现。benchmark 一条命令跑六组对照，报告随轨迹与代价表版本入库，见第 16 节。

## 5. 架构总览

```
租户
  │
  ▼
薄网关（接入、request id、路由执行）
  │
  ▼
vLLM 副本 ×N
  ├── kv_connector v1（命中查询 / 加载 / 保存）
  │       │ 命中深度、层位、计算进度
  │       ▼
  │   决策服务（索引同进程）◄── 代价表（标定工具按机器写，带版本）
  │       │ 取回/重算、块优先级、期限
  │       ▼
  ├── 重叠执行（计算 stream / 传输 stream，event 同步）
  └── 传输引擎（RDMA verbs / TCP 降级）
          │
          │ 块读（优先级 + 期限）
          ▼
      存储节点 ×M（DRAM / NVMe / 远端块服务）
```

数据面与控制面分开：网关只做接入与路由执行；决策服务在请求路径上查表与算术，不做模型推理；传输引擎与重叠执行是数据面；标定工具离线跑，代价表带版本下发。代价表缺失或过期时决策退回重算，记退回事件，退回期间产品语义等于原生 vLLM 加本地前缀缓存。

四层边界：决策层定取回还是重算、块的顺序；传输引擎定每个块走哪条 QP 与路径；存储节点定块放置与驱逐；vLLM 定批组成。四层各管一件事，决策记录里能分清是哪一层做的决定。

异步加载的状态机走 vLLM 现成机制：决策输出取回后，connector 在命中查询里返回异步标记，调度器把请求置为 WAITING_FOR_REMOTE_KVS；传输引擎读块，完成后经 get_finished 报告；调度器收到完成才把请求排进 prefill。请求等待期间其余请求照常计算，这就是主干重叠的时间窗口。取回失败或期限错过时请求退出等待状态，整请求改重算。

对 vLLM 的改动分三层：

| 层 | 改动位置 | 服务什么 | 回退方式 |
|---|---|---|---|
| 零改动 | kv_connector v1 回调与异步加载状态 | 主干整请求决策与预取 | 摘 connector 配置 |
| 非核心小钩子 | prefill chunk 边界与 step 进度传给决策层 | 主干重叠执行与干扰标定 | 钩子开关关闭 |
| 核心最小补丁 | 非连续命中的记账、分配与输入构造 | 侧枝块粒度混合执行 | 补丁一键回退 |

主干依赖前两层，第三层只服务侧枝，补丁点清单在第 12 节。层间流水用现成的按层等待接口，不动核心，归零改动层。

## 6. 代价表与标定

四张表按机器标定，带版本与机器口径（GPU 型号、网卡、PCIe 拓扑、驱动版本、引擎版本）。决策层在线查表，表由标定工具离线产出。块大小跟随引擎配置，默认 64 token，8B GQA 模型下单块 8 MiB；下文块大小均按此口径。

### 6.1 取回带宽表

行是来源层与路径：本地 DRAM 经 cudaMemcpyAsync 进 HBM，本地 NVMe 经 GDS 或 pinned 中转进 HBM，远端经 RDMA 或 TCP 进 HBM。列是传输块大小：8 MiB（单块）、64 MiB（八块条带）、256 MiB、1 GiB。单块档的固定开销占比最高，单独记。每格记两个数：有效带宽、每次传输的固定开销（指令下发、完成轮询、地址交换）。MR 注册一次性完成，注册时间单列，不进每格开销。远端列的耗时含 staging（第 10 节），NVMe 到 DRAM 的 staging 带宽另扫 8、64、256 MiB 三档记入。

### 6.2 重算每 token 时间表

prefill 每 token 时间按输入长度分档（1k、4k、16k、32k），另按批组成分两列：纯 prefill 批，与 decode 混批（chunk 取 512、1024、2048、4096）。重算发生在混批里，查混批列；决策层按当前批组成选列。同一输入长度档内按实际 token 数线性插值，不外推档位之外的长度。

### 6.3 干扰系数表

取回与计算并发时两边都变慢。扫并发传输量（在飞块数 1、2、4、8、16）与 decode 批大小（1、8、32）的组合，每格记两个数：计算负载下的取回带宽折扣，传输负载下的 decode step 时间增幅。决策层用折扣后的带宽算取回耗时，用 step 增幅约束传输并发。这张表是决策与传输协同的测量基础，通用传输引擎不提供。

### 6.4 决策与排队开销表

决策计算（查表加算术）耗时、connector 回调与决策服务 RPC 耗时、入队到出队的排队等待。排队等待直接测，不建模。前两项供开销闸门用，合计不超过 step 时间的 1%。

### 6.5 标定规程与漂移

标定工具一条命令跑完四张表，冷热态分开，写版本入库。在线漂移检查：探针每 30 秒传一个 64 MiB 固定块，实测耗时与表值对照，偏差超过 20% 连续三次触发重标定，重标定窗口内决策退回重算。换机型、换驱动、换引擎版本后重跑标定，旧表保留供对照。

三个在线参数的默认值与标定方法：

| 参数 | 默认值 | 标定方法 |
|---|---|---|
| 迟滞系数 | 0.8 | 同一轨迹扫 0.6、0.7、0.8、0.9、1.0，记决策翻转次数与 TTFT，取翻转少且 TTFT 不劣的档 |
| 干扰闸门 | decode step 增幅 5% | 扫并发档，取 step 增幅不超闸门的最高并发，写进传输引擎配置 |
| 传输并发上限 | 每副本在飞 8 块 | 同上，带宽接近饱和且 step 增幅在闸门内的拐点 |

验收：同一机器重跑标定，表值偏差有数；决策用表值与逐请求实测最优选择的误差分布有数；探针漂移能触发重标定与退回事件。

## 7. 核心一：在线取回/重算决策

### 7.1 决策点与输入输出

决策发生在命中查询回调（get_num_new_matched_tokens）返回时。输入五项：命中深度（token 数）、命中块的层位（DRAM、NVMe、远端）、当前队列长度与请求的预计调度步、当前批组成（batch token 数、是否含 prefill chunk）、代价表版本。HBM 命中由 vLLM 原生前缀缓存处理，不进决策。输出三项：取回或重算、取回来源层、块顺序与期限。主干对一个请求的整段前缀输出单一动作与单一来源层。

决策结果翻译成 connector 返回值：取回输出命中 token 数加异步标记，请求进 WAITING_FOR_REMOTE_KVS；重算输出 0，请求走正常 prefill。决策服务与副本之间的 RPC 耗时进 6.4 开销表。

### 7.2 决策算术

取回耗时 = 各块（字节数 / 折扣后带宽 + 固定开销）之和，带宽查 6.1 与 6.3，来源层按 7.3 选。重算耗时 = 命中 token 数 × 每 token 时间，查 6.2 的当前批组成列。取回耗时不超过重算耗时乘迟滞系数（默认 0.8）时输出取回，否则输出重算。迟滞留出估计误差的余量，避免负载抖动下来回切换。

算例（30K 前缀，3.8 GiB，约 470 块，单块固定开销按 0.5 ms，重算按混批 3 s，数值为推算口径）：

| 场景 | 取回耗时 | 重算耗时 × 0.8 | 决策 |
|---|---|---|---|
| 远端 IB，带宽折扣 0.8 | 3.8/20 + 470×0.0005 ≈ 0.43 s | 2.4 s | 取回 |
| 本地 NVMe，GDS 10 GB/s | 3.8/10 + 0.24 ≈ 0.62 s | 2.4 s | 取回 |
| 10 GbE TCP，高负载折扣 0.7 | 3.8/0.77 + 0.24 ≈ 5.2 s | 2.4 s | 重算 |

同一份前缀，三种场景两个决策，静态配置给不出这个区分。

期限由预计调度步给出：假设该请求立即重算，估计它开始 prefill 的时刻，取回必须在这个时刻前完成。预计取回完成时间超过期限时输出重算，记一条期限不足事件。期限估计用队列长度与近期 step 时间，误差进 7.5 的决策记录。请求进异步加载状态后期限仍在计时，传输引擎按期限撤读（第 8 节），错过期限整请求改重算。

### 7.3 来源层选择

同一前缀存在于多层时，按 6.1 表取耗时最小的层，顺序通常是本地 DRAM、本地 NVMe、远端 RDMA、远端 TCP。跨层混合取回（一个请求内一部分块走一层、另一部分走另一层）属于侧枝（第 12 节），主干整段前缀走单一层。

### 7.4 退回与漂移

三类触发退回重算：代价表缺失或过期、探针漂移超阈值、决策计算开销超闸门。退回期间产品语义等于原生 vLLM 加本地前缀缓存，每次退回记事件带原因。退回不影响 save 路径，KV 照常写回分层，重标定完成后决策恢复。

### 7.5 决策记录与验收

每请求一条决策记录：request id、命中深度、层位、动作、取回与重算的估计耗时、表版本、实际取回完成时刻、TTFT。记录供决策误差复核与 benchmark 归因用。

验收三项：同一轨迹上决策选择与逐请求实测最优选择的偏差分布，选错边的请求占比与损失分布有数；决策与回调开销不超过 step 时间的 1%；三类退回各能演示一次，退回期间语义与原生 vLLM 对照一致。

## 8. 核心二：自研传输引擎

### 8.1 与 TE 的分界

Mooncake TE 覆盖通用点对点传输：零拷贝、多网卡池化、拓扑选网卡、failover。本引擎只做一件事：按决策层给出的块顺序与期限执行块读，把完成事件喂回重叠执行。传输指令带优先级与期限、由决策层对着计算进度下发，这条协同是 TE 不提供也不需要的。多网卡池化与多协议通用化不做，也不放侧枝。

### 8.2 verbs 通路

连接用 RC QP。KV 池在引擎启动时预分配，地址稳定，MR 注册一次缓存复用；存储节点的服务缓冲同样启动时注册。控制通道交换块地址与 rkey，数据通道走 RDMA READ，请求方直接读远端内存。流程四阶段：

| 阶段 | 执行者 | 触发条件 | 消息与字段 | 判断条件 | 返回与后续 |
|---|---|---|---|---|---|
| 地址交换 | 副本传输引擎 | 决策输出取回 | 控制消息：块哈希列表、来源节点 | 存储节点索引命中且缓冲已注册 | 返回地址与 rkey，未命中回失败，决策改重算 |
| 发起读 | 副本传输引擎 | 拿到地址 | RDMA READ：远端地址、rkey、本地 MR、块大小 | 期限未过 | post 到 QP，按优先级排队 |
| 完成 | CQ 轮询线程 | CQ 有完成 | 完成事件：块 id、时刻 | 无 | 通知重叠执行 record event |
| 超时 | 传输引擎 | 期限已过未完成 | 取消指令 | 无 | 撤未完成块，通知决策层，整请求改重算 |

地址交换按批打包，一次控制消息带一个请求的全部块哈希，摊薄每块的控制开销；固定开销的实测值进 6.1 表。

### 8.3 GPUDirect 与中转

网卡与 GPU 在同一 PCIe switch 下时，GPU 内存经 dmabuf 或 nv_peer_mem 注册 MR，RDMA READ 直接落 HBM。不在同一 switch 下时走 pinned 主机中转：RDMA READ 落 pinned 缓冲，cudaMemcpyAsync 经传输 stream 进 HBM。路径在现勘与标定时确定，写进代价表口径。本地 NVMe 层支持 GDS 时 cuFile 直读进 HBM，不支持时 pinned 中转加拷贝。两条路径的带宽差进 6.1 表。

### 8.4 传输调度

大块跨多 QP 条带化，64 MiB 以上的传输拆到多条 QP 并行。块队列按决策层给的期限排序，期限近的优先。期限已过的块撤读，整请求改重算（主干规则；侧枝可保留已取回部分，第 12 节）。在飞块数上限默认 8，由 6.3 干扰表约束：decode step 增幅超闸门时降并发，通知决策层重算期限。

### 8.5 TCP 降级

TCP 路径接收同样的指令语义：块列表、优先级、期限，返回同样的完成事件。实现走 socket 加零拷贝发送，NVMe 块直接读文件，不经 DRAM staging。配置开关切换路径，代价表切对应列。混合集群允许 RDMA 副本与 TCP 副本并存，各按本机表决策。

### 8.6 验收

带宽表复跑偏差有数；MR 注册确认一次性（传输路径上无注册调用）；负载下期限错过率有数；同一轨迹 RDMA 与 TCP 两口径的决策分布与 TTFT 分开报。

## 9. 核心三：重叠执行

### 9.1 主干的重叠形态

取回在决策输出时发起，此时请求进 WAITING_FOR_REMOTE_KVS 还在排队，取回与其余请求的 prefill、decode 重叠。请求被调度时 KV 已大部分或全部 resident，prefill 跳过命中段。主干要求 KV 在 prefill 开始前 resident，等待发生在 connector 的 load 回调里；该回调在 CUDA Graph 断点处 eager 执行（第 3 节核实），prefill 被分段捕获也不冲突。层间流水（算第 i 层时取第 i+1 层）放侧枝，见第 13 节。

### 9.2 stream 与 event

计算 stream 沿用 vLLM 的，传输 stream 独立。pinned 中转缓冲启动时分配，cudaMemcpyAsync 走传输 stream。每块完成 record 一个 event，load 回调按块 wait event。传输路径上不调用 .cpu()、.item() 这类隐式同步。pinned 与 pageable 的带宽差在现勘第 5 条实测，进 6.1 表。

### 9.3 干扰管理

传输并发上限查 6.3 表，默认在飞 8 块。在线监测 decode step 时间，增幅超过闸门（默认 5%）时传输并发减半，回落到 2% 以下后逐级恢复；降并发时决策层对未发起的取回重算期限，期限不足的改重算。这条回路是决策、传输、执行三层协同的在线部分。

### 9.4 验收

同一轨迹预取重叠与串行取回对照，TTFT 差有数；传输活跃期间 decode step 增幅不超过闸门；pinned 与 pageable 两档带宽与 TTFT 分开报。

## 10. 核心四：分层块存储

### 10.1 范围

最小块存储，只做块读底座：索引、放置、驱逐、远端服务四件。LMCache 的压缩（CacheGen）、跨实例去重等特性不做。增量在决策与传输协同，存储只保证块读得到、地址拿得到、节点坏了服务不断。

### 10.2 块与索引

块对齐 vLLM 的 KV block：默认 64 token，8B GQA 模型下 8 MiB，块大小跟随引擎配置。键用前缀哈希链，与 vLLM 同口径：hash(父块哈希, 块内 token ids, extra_keys)，extra_keys 含 LoRA、cache_salt、多模态哈希，存储侧照单全收，不自行裁剪。索引服务与决策服务同进程部署，映射块哈希到（层、节点、地址或偏移、长度）。

索引是软状态：存储节点写入块后上报登记，驱逐后上报注销，另按周期上报块清单心跳。决策服务重启后索引从各节点清单重建，重建窗口内命中查询按未命中返回，请求走重算，save 路径不受影响。索引与决策不拆分进程：命中查询在每个请求的路径上，拆分多一跳 RPC；索引可重建，进程故障的代价被限定在重建窗口内的重算，不需要为它引入独立故障域。

### 10.3 层与放置

HBM 层是 vLLM 原生前缀缓存，存储不拥有。存储拥有 DRAM、NVMe、远端三层。save 回调在 HBM 驱逐时把块写 DRAM；DRAM 容量超阈值按 LRU 下沉 NVMe；NVMe 超阈值下沉远端或丢弃。读不提升层级，放置策略只做写入下沉与 LRU 驱逐。每层容量写配置，驱逐事件记录带块哈希与原因。

### 10.4 远端服务

存储节点把 DRAM 服务缓冲注册 MR，响应地址交换。远端 NVMe 块先 staging 到本节点 DRAM 再服务 RDMA 读：地址交换等 staging 完成才回地址，staging 耗时计入取回估计，进 6.1 表远端列；staging 带宽按 8、64、256 MiB 三档实测。TCP 路径直接读文件，不 staging。节点故障时索引把该节点块标不可用，命中查询排除，决策按剩余层位重算；节点恢复后重新上报块清单，索引恢复登记。

### 10.5 验收

索引与数据抽查对账：随机抽块读回校验哈希；杀一个存储节点，服务继续，命中率下降幅度有数；节点恢复后块登记重建，命中率回到故障前水平的时间有数；决策服务重启后索引重建窗口内的请求全部走重算，无错误命中。

## 11. 平台与运维

平台侧占交付工作量两到三成，四件加 benchmark 装置，不做合同与结算层。

### 11.1 部署

k8s manifests 加一条命令拉起：薄网关、vLLM 副本、决策与索引服务、存储节点。单机 kind 集群跑 TCP 全流程，租机双节点跑 RDMA。GPU 走 device plugin，存储节点挂本地 NVMe。manifests 里副本数、KV 池容量、块大小、路径开关都是显式配置项，benchmark 复现时随报告入库。

### 11.2 健康与热更新

副本与存储节点带就绪探针；代价表版本、迟滞系数、干扰闸门、传输并发上限、路径开关配置热更新，不重启进程。探针失败的副本由网关摘除，在飞请求改路重算。热更新生效时刻记事件，决策记录带更新前后的表版本，供对照。

### 11.3 滚动升级不冷缓存

存储节点逐台升级，块留在盘上，进程拉起后上报块清单，索引重建后继续服务。副本逐台升级，HBM 缓存冷，命中由存储层接住，命中率回到稳态所需的请求数记录进报告。升级期间决策与传输照常，升级动作本身不进决策路径。

### 11.4 故障演练

杀存储节点、杀副本、断网关到存储节点网络三类，爆炸半径限定一个节点，演练记录带时刻与节点编号。每类演练核对三件事：服务是否继续、命中率下降与恢复曲线、决策记录里退回与改重算事件是否对得上。

验收三条：同一轨迹重跑两次，请求数、token 数、P50 TTFT 对得上；杀一个存储节点服务继续，命中率下降与恢复时间有数；滚动升级后命中率回到升级前水平，恢复请求数有数。

## 12. 侧枝一：块粒度混合执行

### 12.1 动机

主干整段前缀走单一来源层，两类场景吃亏。一是前缀跨层分布：前半段在本地 DRAM、后半段在远端 NVMe，整段决策只能选一层，要么放弃本地快层，要么放弃远端命中。二是期限边缘：取回进行到一半期限已过，主干整请求改重算，已取回的块白付传输成本。块粒度混合执行把决策单位从整段前缀细化到块范围：每个块各选远端取回、本地取回或重算，三股流并行推进，期限错过时保留已取回部分，只重算未取回范围。

### 12.2 机制与补丁面

决策层对每个块范围输出动作，connector 把命中信息按块掩码传给调度器。上游的记账按连续前缀：num_computed_tokens 是单个整数，命中查询只返回最大连续前缀（第 3 节核实）。混合执行要求非连续命中，最小补丁点如下，路径相对 vLLM 仓库根目录：

| 补丁点 | 位置 | 改什么 |
|---|---|---|
| 命中掩码接口 | kv_connector/v1/base.py 的 get_num_new_matched_tokens 与 update_state_after_alloc | 返回值与入参从连续 token 数扩为按块命中掩码 |
| 调度记账 | v1/core/sched/scheduler.py 的 schedule（命中查询调用、num_computed_tokens 合成、allocate_slots、异步状态预设四处） | 按分段命中记账，外部命中段与本地命中段分开 |
| 块分配 | v1/core/kv_cache_manager.py 的 allocate_slots | 外部命中段的块分配与缓存逻辑适配非连续 |
| 命中查找 | v1/core/kv_cache_coordinator.py 的 find_longest_cache_hit 与 get_num_blocks_to_allocate | 连续前缀查找改为按块掩码 |
| 请求状态 | v1/request.py 与 sched/output.py | num_computed_tokens 的单整数前缀语义改为分段表达 |
| 输入构造 | v1/worker/gpu/model_runner.py 的 prepare_inputs | slot mapping 按分段命中跳过已取回段 |
| 失败回退 | scheduler.py 的 _update_requests_with_invalid_blocks | 复用现成的失败块回退路径，按块改重算 |

执行形态：远端取回与本地取回走传输引擎的两组队列，重算段进 prefill 批，三股流按块掩码对齐；prefill 只算未取回范围，attention 的 slot mapping 跳过已 resident 的块。补丁带一键回退，回退后调度器回到连续前缀语义。补丁回归面是现勘第 6 条：vLLM 原有调度测试集在补丁前后各跑一遍，失败项逐个修复或记录。

### 12.3 代价与验收

决策算术与主干共用四张表，单位换成块范围：每段各算取回与重算耗时，各选小的动作；期限按段独立计时。收益口径：同一轨迹对主干整请求决策，报 TTFT P50 与 P99、取回字节数、重算 token 数。跨层分布与期限边缘两类负载单独出结论，这两类是混合执行的收益来源，其余负载档收益接近零时照实报。降级开关关闭后回到主干整请求语义，主干验收不受影响。

## 13. 侧枝二：层间流水

### 13.1 动机

主干的重叠窗口是请求的排队时间：队列短或请求到达即被调度时，取回没有足够的重叠窗口，等待全额暴露在 prefill 起点。层间流水把等待摊进 prefill 内部：算第 i 层时取第 i+1 层的 KV，每层只等自己的 KV 到位，取回耗时被计算逐层掩盖。32 层模型每层计算时间是毫秒级，单层 KV 的取回时间小于单层计算时间时，等待接近零。

### 13.2 机制

传输引擎按层计算顺序交付 KV：第 i+1 层的块排在第 i 层之后，层内按块期限排序。等待用 connector 现成的 wait_for_layer_load，调用点在每层 attention 前，带 eager_break_during_capture，在 CUDA Graph 断点处 eager 执行（第 3 节核实）。默认捕获模式 FULL_AND_PIECEWISE 下 prefill 被分段捕获，等待点在图外，不需要改捕获模式；connector 声明 requires_piecewise_for_cudagraph 可强制 PIECEWISE，两种模式都兼容。decode 段不插等待，KV 在 prefill 结束时已全部 resident。

与上游的分界：connector 提供按层等待接口，LMCache 等实现已用它做加载同步；本侧枝的增量在交付顺序与期限进入传输调度，传输引擎对着计算进度逐层喂块，干扰闸门（第 9 节）照常约束层间传输的并发。

### 13.3 代价与验收

层粒度交付把一次整段传输拆成 32 次层传输，固定开销按层数放大，6.1 表的单块档开销决定这笔账是否划算：层 KV 字节数小、固定开销占比高时，流水收益被控制开销吃掉。验收口径：同一轨迹对主干整请求预取，报 prefill 等待时间、TTFT、每层等待的分布；短队列与长队列两档分开报，短队列是层间流水的收益来源。收益接近零的档照实报，标不采纳。降级后回到主干整请求预取，等待退回 prefill 起点一次性发生。

## 14. 侧枝顺序与砍项顺序

侧枝顺序：层间流水先做，不动调度器核心，接口现成；块粒度混合执行后做，补丁面大，回归测试是主要工作量。两项都在主干验收通过后开工，各带独立降级开关。收益接近零的项标不采纳，不留半成品。

砍项顺序从后往前：先砍侧枝两项，再砍故障演练自动化与远端层（保留本地 DRAM 与 NVMe），再砍 RDMA 实测（TCP 单路径交付，RDMA 数字标未测）。决策、传输、重叠、存储、部署五件不动，它们是产品与玩具的分界线。

## 15. 覆盖边界

覆盖单机多副本与双机远端取回，副本级分布式，权重单卡放得下走加副本一侧。跨机张量并行与流水并行不做，模型质量评估不做，训练侧不做，合同结算不做，多网卡池化与多协议通用化不做，KV 压缩与跨实例去重不做。副本故障时在飞请求改路重算，跨副本 KV 迁移不自建。soft-RoCE 只做功能验证，带宽数字不进收益结论。GPUDirect 与 GDS 按机器拓扑决定路径，实测值不外推到其他机型。源码结论基于本地 v0.34.0rc0 checkout，部署版本不一致时按现勘第 1 条重核。

## 16. Benchmark 方法

六组吃同一份轨迹：原生 vLLM（本地前缀缓存）、静态全取回（offload 常开）、静态全重算（offload 常关）、sticky 路由加静态 offload（生产默认）、vLLM OffloadingConnector（上游现状，静态字节预算）、本产品。侧枝另加两组：请求级对块粒度，整请求预取对层间流水。

负载分档：共享前缀比例三档乘输入长度三档，低负载与高压力两档压力，轨迹用 Mooncake 公开 agent trace 加合成补齐。每档单独出结论，不合并总均值。侧枝收益来源的负载档（跨层分布、期限边缘、短队列）单独构造轨迹。

规程：每组至少七次取中位数报区间；冷热态分开；客户端饱和的轮次作废，负载台自身 CPU 与连接数曲线作附件；模型、引擎、镜像、机器、KV 池容量、副本数、代价表版本随报告入库，一条命令复现；RDMA 与 TCP 双口径分开报；决策误差与开销各单列一节。

收益口径：同轨迹下 TTFT P50 与 P99、窗口内完成请求数、取回字节数与重算 token 数，对照该档最优静态组。完成请求数口径与 MI300X 那组实测一致，供外部对照。

## 17. 项目优点

1. 决策在线化有工业证据：MI300X 实测证明静态 offload 收益翻面，上游 OffloadingConnector 也只有静态字节预算，本产品按请求算这笔账。
2. RDMA 深入到 verbs 层：QP、MR、CQ 自管，块优先级与期限进传输调度，与决策层协同。
3. 重叠与干扰有测量：干扰系数表把取回与计算的互相拖慢量化，决策用折扣后带宽。
4. 降级同语义：RDMA 与 TCP 两套路径指令与完成事件一致，两类机器数字可比。
5. 产品四肢健全：部署、热更新、滚动升级、故障演练四件齐，存储节点坏了服务不断。
6. 数字可复现：六组对照一条命令复现，代价表带版本，第三方能复核收益来自哪档。

## 18. 诚实清单

- 2.3 的带宽与重算时间是量级推算，由标定实测替换，推算值不进收益结论。
- soft-RoCE 只做功能验证，rxe 带宽数字不进收益结论与简历。
- 单机与双机规模只做机制验证，不做规模外推。
- 期限估计用队列与近期 step 时间，突发到达时估计失真，该区间决策退回重算。
- 干扰系数表按机器标定，换机型重测，不外推。
- GPUDirect 与 GDS 依赖拓扑与驱动，不可用时走中转，报告直连与中转实测差。
- 侧枝两项收益可能接近零，照实报，标不采纳。
- 块粒度混合执行的补丁面跨调度器多处，回归风险是侧枝的主要成本，补丁后原有调度测试集全跑。
- 存储是最小实现，无压缩、无去重、读不提升层级，特性覆盖小于 LMCache。
- 副本故障在飞请求重算，迁移收益账未测。
- 代价表漂移窗口内决策退回重算，退回期间无取回收益。
- 决策与回调开销闸门 1% 是目标值，超标时退回，实测值进报告。
- CUDA 与 PyTorch 停留在使用层：stream、event、异步拷贝、pinned、内存地址管理，不改 kernel 与运行时。
- 块大小与哈希口径跟随引擎配置，64 token 与 extra_keys 按核实版本的默认值写，部署配置不同时表与键口径同步改。

## 19. 交付物

薄网关；决策与索引服务；传输引擎（RDMA 与 TCP 双路径）；重叠执行与 connector 挂载配置、非核心钩子；最小块存储；侧枝核心补丁（一键回退，未做标未做）；标定工具与按机器版本的四张代价表；k8s manifests 与一条命令拉起；benchmark 装置与六组对照报告；现勘报告（现状矩阵、拓扑结论、源码核实表、补丁回归记录）。诚实清单随报告入库。

## 20. 术语

| 术语 | 含义 |
|---|---|
| 取回 | 把分层存储里的前缀 KV 搬进 HBM，跳过该段 prefill |
| 重算 | 不取回，对该段前缀重新 prefill |
| 代价表 | 按机器标定的四张表：取回带宽、重算每 token 时间、干扰系数、决策与排队开销 |
| 干扰系数 | 取回与计算并发时的带宽折扣与 step 时间增幅 |
| 期限 | 取回必须完成的最晚时刻，取请求 prefill 开始计算前 |
| 块 | vLLM KV block，默认 64 token，8B GQA 模型下 8 MiB |
| 层位 | 块所在的存储层：DRAM、NVMe、远端 |
| 前缀哈希链 | 与 vLLM 同口径的块键，hash(父块哈希, token ids, extra_keys) |
| QP / MR / CQ | RDMA 的队列对、内存注册区、完成队列 |
| GPUDirect | 网卡直读直写 GPU 内存，要求网卡与 GPU 同 PCIe switch |
| GDS | GPUDirect Storage，NVMe 直读进 HBM |
| pinned 中转 | 锁页主机缓冲作 RDMA 与 HBM 之间的跳板 |
| staging | 远端 NVMe 块先搬进本节点 DRAM 再服务 RDMA 读 |
| stream / event | CUDA 的任务队列与队列间同步点 |
| 图断点 | piecewise CUDA Graph 在 attention op 处切开的位置，connector 等待在此 eager 执行 |
| 异步加载 | 请求置 WAITING_FOR_REMOTE_KVS，KV 加载完成后才进 prefill |
| OffloadingConnector | vLLM 自带的 CPU/DRAM offload connector，静态字节预算，无在线成本决策 |
| 退回 | 代价表缺失、漂移或开销超标时决策改用重算 |
| sticky | 前缀亲和路由，同前缀请求送同一副本 |
| 主干 | 保证交付的请求级决策产品 |
| 侧枝 | 块粒度混合执行与层间流水，逐项独立降级 |
