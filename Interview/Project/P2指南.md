## 6. 代价表与标定
![[Attachments/mermaid-diagram.png]]


四张表按机器标定，每张都带版本和口径。口径包括 GPU 型号、网卡、PCIe 拓扑、驱动版本、引擎版本、模型和 KV 精度。决策层在线查表，表由标定工具离线产出。硬件特性只进表，不进代码。决策层查表时不判断机器型号。代码里和硬件有关的只有直连和中转两条路径。带宽、折扣、固定开销的差异全部记在表里。块大小跟随引擎配置，默认 64 token。8B GQA 模型在 FP16 下，单块为 8 MiB。换 FP8 或换结构时，按每 token 字节数换算。下文未特别说明时，块大小按 64 token、8 MiB 计算。

### 6.1 取回带宽表

这张表的行是来源层与路径。本地 DRAM 经异步拷贝进 HBM。本地 NVMe 经 GDS 或 pinned 中转进 HBM。远端经 RDMA 或 TCP 进 HBM。列是传输块大小，分 8 MiB（单块）、64 MiB（八块条带）、256 MiB 和 1 GiB 四档。单块档的固定开销占比最高，单独记录。每格记两个数：有效带宽，以及每次传输的固定开销。固定开销包括指令下发、完成轮询和地址交换。MR 注册只做一次，注册时间单列，不计入每格开销。远端列的耗时含 staging（第 10 节）。NVMe 到 DRAM 的 staging 带宽另扫 8、64、256 MiB 三档，记入表内。

表的列按字节档标，不假设块恒为 8 MiB。每 token 字节数由 KV 精度与注意力结构决定。FP16 换 FP8 后折半，MLA latent 按压缩后的每 token 字节计。块字节等于块 token 数乘每 token 字节数，由形态索引给出。决策按实际块字节查档。小于最小档时按最小档取值，介于两档之间时取较低档，固定开销按高档计。带宽格按字节档复用，换精度只换换算口径，不重标带宽。

### 6.2 重算每 token 时间表

这张表按输入长度分档，1k、4k、16k、32k 各一档，记 prefill 每 token 时间。表再按批组成分两列，一列是纯 prefill 批，另一列是 decode 混批，chunk 取 512、1024、2048、4096。重算发生在混批里，所以查混批列。决策层按当前批组成选列。同一输入长度档内，按实际 token 数线性插值，不外推档位之外的长度。表头带模型口径：参数量、层数、注意力结构、KV 精度。换模型或换 KV 精度时重标这张表。形态索引里的每 token 字节数与这张表同版本。

### 6.3 干扰系数表

取回与计算并发时，两边都会变慢。标定时扫并发传输量与 decode 批大小的组合。在飞块数取 1、2、4、8、16，decode 批大小取 1、8、32。每格记两个数：计算负载下的取回带宽折扣，传输负载下的 decode step 时间增幅。决策层用折扣后的带宽算取回耗时，用 step 增幅约束传输并发。这张表是决策与传输协同的测量基础，通用传输引擎不提供。表存区间，不存定值。每格记轻载与重载两端的系数，决策时用 6.5 的在线参数定位当前值落在区间内的位置。表给出路径的带宽上限与干扰区间。在线参数给出当前负载能拿到的份额，也就是上限的几成。决策用上限乘份额算有效带宽。换机型只换表。份额随负载变化，不写进代码。

### 6.4 决策与排队开销表

这张表记三项。第一项是决策计算耗时，即查表加算术。第二项是取回组件回调和决策服务 RPC 的耗时。第三项是请求入队到出队的排队等待。排队等待直接测，不建模。前两项用于开销闸门，合计不超过 step 时间的 1%。

### 6.5 标定规程与漂移

标定工具用一条命令跑完四张表。冷态与热态分开跑，写下版本后入库。探针负责在线漂移检查。探针每 30 秒传一个 64 MiB 固定块，把实测耗时与表值对照。偏差超过 20% 且连续三次，就触发重标定。重标定窗口内，决策退回重算。换机型、换驱动、换引擎版本、换模型或换 KV 精度后，都要重跑标定，旧表保留供对照。换机型与驱动，改的是带宽和固定开销。换引擎版本，改的是回调和排队开销。换模型或换 KV 精度，改的是每 token 字节数和重算每 token 时间。后三类不重标，表就过期，决策还在用旧口径算账。

三个在线参数的默认值与标定方法：

| 参数 | 默认值 | 标定方法 |
|---|---|---|
| 迟滞系数 | 0.8 | 同一轨迹扫 0.6、0.7、0.8、0.9、1.0，记决策翻转次数与 TTFT，取翻转少且 TTFT 不劣的档 |
| 干扰闸门 | decode step 增幅 5% | 扫并发档，取 step 增幅不超闸门的最高并发，写进传输引擎配置 |
| 传输并发上限 | 每副本在飞 8 块 | 同上，带宽接近饱和且 step 增幅在闸门内的拐点 |

验收四条。同一机器重跑标定，表值偏差有数。换 KV 精度后按新口径重标，块字节和重算时间随口径更新，旧表留档对照。决策用表值与逐请求实测最优选择的误差分布有数。探针漂移能触发重标定和退回事件。

### 6.6 形态与生命周期参数

形态参数不进四张表，单独进形态索引。形态索引记五项：KV 形态（页式块、会话状态）、块大小、每 token 字节数、哈希口径、能否分块取回。每 token 字节数按精度与结构算。FP16、FP8、MLA latent 各一个值，换精度即换值，块字节随之变。决策第一步查形态。不可分块取回的形态输出不可取回，不查带宽表，例如会话状态按整体搬迁计量。形态索引随引擎配置走，换模型、换精度或换块大小时同步更新。形态索引的版本与代价表版本一起进决策记录。

生命周期参数三件，先给默认值，实测后按轨迹调：

| 参数 | 默认值 | 调法 |
|---|---|---|
| 保留层级与期限 | 活跃会话留 DRAM 1 小时，冷会话沉 NVMe 或直接丢 | 按轨迹扫活跃度分档，记每档的后续命中率与近层占用 |
| 升温触发条件 | 同会话再活跃且预测的再活跃收益超门槛时触发 | 扫门槛，记升温节省的 TTFT、多付的字节与误判浪费 |
| 活跃度口径 | 最近请求距今 10 分钟窗口 | 与保留参数联动扫，取近层命中率与占用平衡的档 |

这三件参数是时间参数的落点，性质与四张表不同。四张表记可测的当前状态，这三件是对未来的先验。再活跃间隔分布按轨迹统计，按周重估。置信不足时取保守动作：保留时沉远层不丢，升温时不动。误判与浪费字节单独记。

## 7. 核心一：在线取回/重算决策

### 7.1 决策点与输入输出

决策发生在三个时点，机制分两套：请求时点做确定性仲裁，逐出和再活跃做预测加策略表。三处共用同一份决策记录格式。

| 时点 | 触发 | 输出 |
|---|---|---|
| 请求到达 | 命中查询回调返回 | 取回 / 重算 / 不可取回；取回时附来源层、块顺序与期限 |
| 逐出 | HBM 逐出块，save 路径触发 | 保留动作：留近层 / 沉远层 / 丢弃，附置信档 |
| 会话再活跃 | 同会话编号的请求到达网关 | 升温动作：搬回近层或 HBM / 不动，受带宽预算约束 |

请求时点的输入有五项。第一项是命中深度，按 token 数计。第二项是命中块所在层位，取 DRAM、NVMe 或远端。第三项是当前队列长度和请求的预计调度步。第四项是当前批组成，含 batch token 数与是否含 prefill chunk。第五项是代价表版本。形态参数先查。命中 KV 登记为不可分块取回时，决策层直接输出不可取回，不进带宽算术。HBM 命中由引擎原生前缀缓存处理，不进决策。输出分三档：取回、重算、不可取回。主干对一个请求的整段前缀只输出一个动作，取回时只附一个来源层。

不可取回与退回是两回事。退回是系统异常，表缺失、漂移或开销超标都会触发。不可取回是正常裁决。形态登记为按整体搬迁计量的 KV（如会话状态）时，决策层输出不可取回，请求直接重算，不发起取回。这一档记一条不可取回事件，单独统计，不混进退回。取回与重算的账算下来不划算，属于重算这一档，不算不可取回。

决策结果由取回组件翻译成返回值。输出取回时，返回命中 token 数加异步标记，请求进远程 KV 等待状态。输出重算或不可取回时，返回 0，请求走正常 prefill。决策服务与副本之间的 RPC 耗时进 6.4 开销表。

### 7.2 决策算术

决策算术只有两笔账，先算取回耗时，再算重算耗时。取回耗时等于各块耗时之和，单块耗时按「字节数 / 折扣后带宽 + 固定开销」算。折扣后带宽等于表里的路径上限乘在线份额。上限查 6.1，干扰区间查 6.3，份额由当前队列长度与在飞块数定，来源层按 7.3 选。重算耗时等于命中 token 数乘每 token 时间，查 6.2 的当前批组成列。取回耗时不超过重算耗时乘迟滞系数时，决策层输出取回，否则输出重算。迟滞系数默认 0.8，留出估计误差的余量，避免负载抖动下来回切换。

算例（30K 前缀，3.8 GiB，约 470 块，单块固定开销按 0.5 ms，重算按混批 3 s，数值为推算口径）：

| 场景 | 取回耗时 | 重算耗时 × 0.8 | 决策 |
|---|---|---|---|
| 远端 IB，带宽折扣 0.8 | 3.8/20 + 470×0.0005 ≈ 0.43 s | 2.4 s | 取回 |
| 本地 NVMe，GDS 10 GB/s | 3.8/10 + 0.24 ≈ 0.62 s | 2.4 s | 取回 |
| 10 GbE TCP，高负载折扣 0.7 | 3.8/0.77 + 0.24 ≈ 5.2 s | 2.4 s | 重算 |

同一份前缀在三种场景下得出两个决策，静态配置给不出这个区分。

期限由预计调度步给出。决策层假设该请求立即重算，估计它开始 prefill 的时刻，取回必须在这个时刻前完成。预计取回完成时间超过期限时，决策层输出重算，记一条期限不足事件。期限估计用队列长度与近期 step 时间，误差进 7.5 的决策记录。请求进异步加载状态后，期限仍在计时。传输引擎按期限撤读（第 8 节），错过期限时整请求改重算。

### 7.3 来源层选择

来源层选择只比较耗时。同一前缀存在于多层时，决策层按 6.1 表选耗时最小的层，顺序通常是本地 DRAM、本地 NVMe、远端 RDMA、远端 TCP。跨层混合取回属于侧枝（第 12 节），指一个请求内一部分块走一层，另一部分走另一层。主干让整段前缀走单一层。

### 7.4 退回与漂移

退回重算的触发有三类。第一类是代价表缺失或过期，第二类是探针漂移超阈值，第三类是决策计算开销超闸门。退回期间，产品语义等于原生引擎加本地前缀缓存。每次退回记一条事件，带原因。退回不影响 save 路径，KV 照常写回分层。重标定完成后，决策恢复。

### 7.5 决策记录与验收

每请求记一条决策记录。字段有会话编号、request id、命中深度、层位、动作（取回、重算、不可取回）、取回与重算的估计耗时、表版本、实际取回完成时刻和 TTFT。保留与升温另记。逐出时点记保留动作、层级与置信档。升温记搬回字节、中止原因与误判浪费。这些记录供决策误差复核与 benchmark 归因用。

验收六项。第一项，同一轨迹上决策选择与逐请求实测最优选择的偏差分布有数，选错边的请求占比与损失分布也有数。第二项，决策与回调开销不超过 step 时间的 1%。第三项，三类退回各能演示一次，退回期间的语义与原生引擎对照一致。第四项，不可取回事件与退回事件分开统计，两类各能演示一次。第五项，保留决策的置信档分布有数。第六项，升温强制开关对照的净 TTFT 与浪费字节有数。

### 7.6 保留与升温

保留与升温要回答的是未来的事，查表给不出答案，机制因此与请求时点分开。请求时点的输入是当前带宽、当前重算成本和当前负载，三项都可测。保留与升温的输入是这个会话多久回来、回来时负载什么样。表只能给历史统计的先验，给不了这一次的判断。

保留发生在逐出时点，触发者是 HBM 的逐出动作。save 路径不再固定写 DRAM。决策层按会话编号统计再活跃间隔分布，用分布给先验。再结合近层占用与空间参数，输出保留动作：留近层、沉远层或丢弃。动作按间隔落在分布的分位定。间隔落在长尾且近层紧张时，沉远层。分布不足以判断时，沉远层不丢。置信不足时一律取保守动作。保留参数的默认值与调法见 6.6，参数包括层级、期限和活跃度口径。

升温发生在再活跃时点，前提是会话还在保留期内。同会话编号的请求到达网关时，决策层先查该会话 KV 是否在冷层。KV 在冷层且预测的再活跃收益过门槛时，决策层提前把它搬回近层或 HBM。请求真正到达时，命中深度因此变长。升温有三件约束。第一件，搬运字节计入每副本的升温带宽预算，预算用尽即停。第二件，预测落空时立即中止搬运，落空指请求迟迟不到或命中深度低于阈值。第三件，误判记一条事件，浪费字节单列。升温未完成时，请求按当前命中深度正常走请求时点决策，不阻塞。

收益归因必须用反事实对照。同一轨迹强制开、强制关升温各跑一遍，报净 TTFT 收益与浪费字节，不能只报命中率变化。这一时点的实验难度比请求时点高一档，单机规模下的结论只作方向验证。升温与取回共用传输通路与代价表，差别在触发时点与输入性质。升温在请求前预测，取回在请求时算当前账。

三个时点的决策各记各的记录，验收按时点分开数。请求时点记三档动作。逐出时点记保留动作、层级与置信档。升温时点记搬回字节、中止原因、误判浪费与反事实对照结果。

## 8. 核心二：自研传输引擎

### 8.1 与 TE 的分界

Mooncake TE 覆盖通用点对点传输，包括零拷贝、多网卡池化、拓扑选网卡和 failover。KVFerry 的传输引擎只做一件事：按决策层给出的块顺序与期限执行块读，把完成事件交给重叠执行。传输指令带优先级与期限，由决策层对着计算进度下发。这条协同 TE 不提供，也不需要。多网卡池化与多协议通用化不做，也不放侧枝。

复用边界要能一句话答辩。外部传输引擎若已提供块级期限语义，并能通过协同回调向决策层回传进度，执行器就可以整体复用，KVFerry 只保留决策与协同协议。自研的支点是块级期限与决策协同，verbs 封装本身不构成支点。当前 TE 两者都不提供，所以自研。上游补上后，执行器可替换，决策层不受影响。

### 8.2 verbs 通路

连接用 RC QP。KV 池在引擎启动时预分配，地址稳定，MR 注册一次后缓存复用。存储节点的服务缓冲同样在启动时注册。控制通道交换块地址与 rkey，数据通道走 RDMA READ，请求方直接读远端内存。流程分四个阶段：

| 阶段 | 执行者 | 触发条件 | 消息与字段 | 判断条件 | 返回与后续 |
|---|---|---|---|---|---|
| 地址交换 | 副本传输引擎 | 决策输出取回 | 控制消息：块哈希列表、来源节点 | 存储节点索引命中且缓冲已注册 | 返回地址与 rkey，未命中回失败，决策改重算 |
| 发起读 | 副本传输引擎 | 拿到地址 | RDMA READ：远端地址、rkey、本地 MR、块大小 | 期限未过 | post 到 QP，按优先级排队 |
| 完成 | CQ 轮询线程 | CQ 有完成 | 完成事件：块 id、时刻 | 无 | 通知重叠执行 record event |
| 超时 | 传输引擎 | 期限已过未完成 | 取消指令 | 无 | 撤未完成块，通知决策层，整请求改重算 |

地址交换按批打包。一次控制消息带一个请求的全部块哈希，摊薄每块的控制开销。固定开销的实测值进 6.1 表。

### 8.3 GPUDirect 与中转

代码里硬件相关的只有直连与中转两条路径。网卡与 GPU 在同一 PCIe switch 下时走直连。GPU 内存直接注册 MR，RDMA READ 直接落 HBM。注册方式优先用驱动原生直连通道，驱动不支持时回落到通用直连通道。两条直连通道的实测差进 6.1 表。网卡与 GPU 不在同一 switch 下时走 pinned 主机中转。RDMA READ 落 pinned 缓冲，异步拷贝经传输 stream 进 HBM。路径在现勘与标定时确定，写进代价表口径。本地 NVMe 层支持 GDS 时直读进 HBM，不支持时走 pinned 中转加拷贝。两条路径的带宽差进 6.1 表。除此之外不识别任何硬件型号，换机型只换表不换码。

### 8.4 传输调度

传输调度按期限排优先级。大块跨多 QP 条带化，64 MiB 以上的传输拆到多条 QP 并行。块队列按决策层给的期限排序，期限近的优先。期限已过的块撤读，整请求改重算。这是主干规则，侧枝可保留已取回部分（第 12 节）。在飞块数上限默认 8，由 6.3 干扰表约束。decode step 增幅超过闸门时，传输引擎降并发，并通知决策层重算期限。

系统厚度在调度器与重叠器。调度器管四件事：块队列按优先级与期限排序，在飞窗口按干扰闸门调节，撤读与失败重排，断点插入与事件合并。仲裁器本身只是算术。这两块是系统级工作量，也是与策略包装的区别。

### 8.5 TCP 降级

TCP 路径接收同样的指令语义，即块列表、优先级和期限，返回同样的完成事件。实现走 socket 加零拷贝发送，NVMe 块直接读文件，不经 DRAM staging。配置开关切换路径，代价表切到对应列。混合集群允许 RDMA 副本与 TCP 副本并存，各按本机表决策。

### 8.6 验收

验收四项。带宽表复跑偏差有数。MR 注册确认是一次性的，传输路径上没有注册调用。负载下的期限错过率有数。同一轨迹上 RDMA 与 TCP 两口径的决策分布与 TTFT 分开报。决策分布另做自检。10 GbE 档的取回占比低于 5%，重算占多数。IB 档取回占多数。低带宽档仍频繁取回，就判定续表错，冻结决策回退重算。这两条断言验证仲裁逻辑本身，与端到端收益分开报。

## 9. 核心三：重叠执行

### 9.1 主干的重叠形态

主干的重叠窗口来自请求排队。取回在决策输出时发起，此时请求进远程 KV 等待状态，还在排队。取回与其余请求的 prefill、decode 重叠。请求被调度时，KV 已大部分或全部 resident，prefill 跳过命中段。主干要求 KV 在 prefill 开始前 resident，等待发生在取回组件的加载回调里。该回调在 CUDA Graph 断点处 eager 执行（第 3 节核实），prefill 被分段捕获也不冲突。层间流水放在侧枝，见第 13 节，它在算第 i 层时取第 i+1 层。

### 9.2 stream 与 event

计算 stream 沿用引擎的，传输 stream 独立。pinned 中转缓冲在启动时分配，异步拷贝走传输 stream。每块完成时 record 一个 event，load 回调按块 wait event。传输路径上不做同步等待，也不把 GPU 数据拉回主机再推回去。做了这两件事，重叠就归零。pinned 与 pageable 的带宽差在现勘第 5 条实测，进 6.1 表。

### 9.3 干扰管理

传输并发上限查 6.3 表，默认在飞 8 块。传输引擎在线监测 decode step 时间。增幅超过闸门（默认 5%）时，传输并发减半。增幅回落到 2% 以下后，并发逐级恢复。降并发时，决策层对未发起的取回重算期限，期限不足的改重算。这条回路是决策、传输、执行三层协同的在线部分。

### 9.4 验收

同一轨迹上，预取重叠与串行取回对照，TTFT 差有数。传输活跃期间，decode step 增幅不超过闸门。pinned 与 pageable 两档的带宽与 TTFT 分开报。

## 10. 核心四：分层块存储

### 10.1 范围

最小块存储只做块读底座，包含索引、放置、驱逐、远端服务四件。LMCache 的压缩（CacheGen）与跨实例去重等特性不做。增量在决策与传输协同。存储只保证三件事：块读得到，地址拿得到，节点坏了服务不断。

### 10.2 块与索引

块对齐引擎的 KV block，默认 64 token，8B GQA 模型下为 8 MiB，块大小跟随引擎配置。键用前缀哈希链，与引擎同口径。哈希式为 hash(父块哈希, 块内 token ids, 附加键)，附加键含 LoRA、缓存盐、多模态哈希。存储侧照单全收，不自行裁剪。索引服务与决策服务同进程部署，存两样东西。一样是页式块的哈希映射，把块哈希映射到层、节点、地址或偏移、长度。另一样是形态登记，记 KV 形态、能否分块取回和搬迁单位。决策第一步查形态登记，再查块映射。

索引是软状态。存储节点写入块后上报登记，驱逐后上报注销，另按周期上报块清单心跳。决策服务重启后，索引从各节点清单重建。重建窗口内，命中查询按未命中返回，请求走重算，save 路径不受影响。形态登记随引擎配置下发，重启后从配置重建，不进软状态。索引与决策不拆分进程。命中查询在每个请求的路径上，拆分会多一跳 RPC。索引可重建，进程故障的代价限定在重建窗口内的重算，不需要为它引入独立故障域。

### 10.3 层与放置

HBM 层是引擎原生前缀缓存，存储不拥有。存储拥有 DRAM、NVMe、远端三层。HBM 逐出块时，save 回调把块交给保留决策（7.6），由它输出落哪层或丢弃。DRAM 容量超阈值时按 LRU 下沉 NVMe。NVMe 超阈值时下沉远端或丢弃。读不提升层级。放置只做写入下沉与 LRU 驱逐，升温（7.6）是唯一把 KV 往近层搬的路径。每层容量写配置，驱逐事件记录带块哈希与原因。

### 10.4 远端服务

存储节点把 DRAM 服务缓冲注册 MR，用它响应地址交换。远端 NVMe 块先 staging 到本节点 DRAM，再服务 RDMA 读。地址交换要等 staging 完成才回地址。staging 耗时计入取回估计，进 6.1 表的远端列。staging 带宽按 8、64、256 MiB 三档实测。TCP 路径直接读文件，不 staging。节点故障时，索引把该节点的块标为不可用，命中查询排除这些块。命中深度按剩余层位缩减，剩下的走重算。节点恢复后重新上报块清单，索引恢复登记。

### 10.5 验收

验收分四项。索引与数据抽查对账，随机抽块读回并校验哈希。杀一个存储节点，服务继续，命中率下降幅度有数。节点恢复后块登记重建，命中率回到故障前水平所需的时间有数。决策服务重启后，索引重建窗口内的请求全部走重算，没有错误命中。

## 11. 平台与运维

平台侧只做壳，共三件：网关发会话编号，存储节点服务块读，k8s 清单负责拉起。这三件占交付工作量两到三成，不做合同与结算层。决策与传输逻辑全部在引擎侧，平台不掺和。

### 11.1 部署

部署靠 k8s manifests 加一条命令拉起，组件有薄网关、引擎副本、决策与索引服务、存储节点。单机 kind 集群跑 TCP 全流程，租机双节点跑 RDMA。GPU 走 device plugin，存储节点挂本地 NVMe。manifests 里副本数、KV 池容量、块大小、路径开关都是显式配置项，benchmark 复现时随报告入库。

### 11.2 健康与热更新

副本与存储节点带就绪探针。代价表版本、迟滞系数、干扰闸门、传输并发上限和路径开关支持配置热更新，不重启进程。探针失败的副本由网关摘除，在飞请求改路重算。热更新生效时刻记一条事件，决策记录带更新前后的表版本，供对照。

### 11.3 滚动升级不冷缓存

存储节点逐台升级，块留在盘上。进程拉起后上报块清单，索引重建后继续服务。副本逐台升级，HBM 缓存变冷，命中由存储层接住。命中率回到稳态所需的请求数记录进报告。升级期间决策与传输照常，升级动作本身不进决策路径。

### 11.4 故障演练

故障演练分三类：杀存储节点、杀副本、断网关到存储节点的网络。爆炸半径限定在一个节点，演练记录带时刻与节点编号。每类演练核对三件事：服务是否继续，命中率下降与恢复曲线，决策记录里退回与改重算事件是否对得上。

验收三条。同一轨迹重跑两次，请求数、token 数、P50 TTFT 对得上。杀一个存储节点，服务继续，命中率下降与恢复时间有数。滚动升级后命中率回到升级前水平，恢复请求数有数。

## 12. 侧枝一：块粒度混合执行

### 12.1 动机

主干让整段前缀走单一来源层，有两类场景吃亏。第一类是前缀跨层分布。前半段在本地 DRAM，后半段在远端 NVMe，整段决策只能选一层，只能放弃本地快层或放弃远端命中。第二类是期限边缘。取回进行到一半期限已过，主干让整请求改重算，已取回的块白付传输成本。块粒度混合执行把决策单位从整段前缀细化到块范围。每个块各选远端取回、本地取回或重算，三股流并行推进。期限错过时，保留已取回部分，只重算未取回范围。

### 12.2 机制与补丁面

决策层对每个块范围输出动作，取回组件把命中信息按块掩码传给调度器。上游的记账按连续前缀走。已计算 token 数是单个整数，命中查询只返回最大连续前缀（第 3 节核实）。混合执行要求非连续命中，最小补丁点如下：

| 补丁点 | 改什么 |
|---|---|
| 命中掩码 | 命中查询的返回值与分配回调的入参从连续 token 数扩为按块命中掩码 |
| 调度记账 | 调度主流程按分段命中记账，外部命中段与本地命中段分开 |
| 块分配 | 外部命中段的块分配与缓存逻辑要适配非连续 |
| 命中查找 | 连续前缀查找改为按块掩码 |
| 请求状态 | 已计算 token 数的单整数前缀语义改为分段表达 |
| 输入构造 | 计算图输入的槽位映射按分段命中跳过已取回段 |
| 失败回退 | 复用现成的失败块回退路径，按块改重算 |

执行形态是三股流并行。远端取回与本地取回走传输引擎的两组队列，重算段进 prefill 批，三股流按块掩码对齐。prefill 只算未取回范围，attention 的 slot mapping 跳过已 resident 的块。补丁带一键回退，回退后调度器回到连续前缀语义。补丁的回归面见现勘第 6 条。引擎原有调度测试集在补丁前后各跑一遍，失败项逐个修复或记录。

### 12.3 代价与验收

决策算术与主干共用四张表，单位换成块范围。每段各算取回与重算耗时，各选小的动作。期限按段独立计时。收益口径是同一轨迹对主干整请求决策，报 TTFT P50 与 P99、取回字节数、重算 token 数。跨层分布与期限边缘两类负载单独出结论，这两类是混合执行的收益来源。其余负载档收益接近零时照实报。降级开关关闭后回到主干整请求语义，主干验收不受影响。

## 13. 侧枝二：层间流水

### 13.1 动机

主干的重叠窗口来自请求的排队时间。队列短或请求到达即被调度时，取回没有足够的重叠窗口，等待全额暴露在 prefill 起点。层间流水把等待摊进 prefill 内部。算第 i 层时取第 i+1 层的 KV，每层只等自己的 KV 到位，取回耗时被计算逐层掩盖。32 层模型每层计算时间是毫秒级。单层 KV 的取回时间小于单层计算时间时，等待接近零。

### 13.2 机制

传输引擎按层的计算顺序交付 KV。第 i+1 层的块排在第 i 层之后，层内按块期限排序。等待用取回组件现成的按层等待回调，调用点在每层 attention 前，位于图捕获断点处（第 3 节核实）。默认捕获模式下，prefill 被分段捕获，等待点在图外，不需要改捕获模式。必要时，挂载组件声明强制分段捕获，两种模式都兼容。decode 段不插等待，KV 在 prefill 结束时已全部 resident。

与上游的分界在交付顺序。挂载接口提供按层等待回调，LMCache 等实现已用它做加载同步。本侧枝的增量是把交付顺序与期限交给传输调度。传输引擎对着计算进度逐层喂块，干扰闸门（第 9 节）照常约束层间传输的并发。

### 13.3 代价与验收

层粒度交付把一次整段传输拆成 32 次层传输，固定开销按层数放大。6.1 表的单块档开销决定这笔账是否划算。层 KV 字节数小、固定开销占比高时，流水收益被控制开销吃掉。验收口径是同一轨迹对主干整请求预取，报 prefill 等待时间、TTFT 和每层等待的分布。短队列与长队列两档分开报，短队列是层间流水的收益来源。收益接近零的档照实报，标不采纳。降级后回到主干整请求预取，等待回到 prefill 起点一次性发生。

## 14. 侧枝顺序与砍项顺序

侧枝顺序由补丁面决定。层间流水先做，它不动调度器核心，接口现成。块粒度混合执行后做，补丁面大，回归测试是主要工作量。两项都在主干验收通过后开工，各带独立降级开关。收益接近零的项标不采纳，不留半成品。

砍项顺序从后往前。先砍侧枝两项。再砍故障演练自动化与远端层，保留本地 DRAM 与 NVMe。最后砍 RDMA 实测，产品按 TCP 单路径交付，RDMA 数字标未测。决策、传输、重叠、存储、部署五件不动，它们划出产品与玩具的分界。

## 15. 覆盖边界

覆盖范围是单机多副本与双机远端取回，副本级分布式。权重单卡放得下时，走加副本一侧。跨机张量并行与流水并行不做。模型质量评估不做，训练侧不做，合同结算不做。多网卡池化与多协议通用化不做，KV 压缩与跨实例去重不做。副本故障时在飞请求改路重算，跨副本 KV 迁移不自建。soft-RoCE 只做功能验证，带宽数字不进收益结论。GPUDirect 与 GDS 按机器拓扑决定路径，实测值不外推到其他机型。源码结论基于本地锁定的引擎版本，部署版本不一致时按现勘第 1 条重核。形态登记只覆盖页式块与会话状态两类，其余形态按不可取回处理，不在 KVFerry 范围。

## 16. Benchmark 方法

基准测试有六组，吃同一份轨迹：原生 vLLM（本地前缀缓存）、静态全取回（offload 常开）、静态全重算（offload 常关）、sticky 路由加静态 offload（生产默认）、vLLM OffloadingConnector（上游现状，静态字节预算）、KVFerry。侧枝另加两组对照：请求级对块粒度，整请求预取对层间流水。

负载分档由共享前缀比例、输入长度和压力三项决定。共享前缀比例三档，输入长度三档，压力分低负载与高压力两档。轨迹用 Mooncake 公开 agent trace，缺的用合成数据补齐。每档单独出结论，不合并总均值。侧枝收益来源的负载档单独构造轨迹，包括跨层分布、期限边缘和短队列。

规程有六条。每组至少跑七次，取中位数并报区间。冷态与热态分开。客户端饱和的轮次作废，负载台自身的 CPU 与连接数曲线作附件。模型、引擎、镜像、机器、KV 池容量、副本数、代价表版本随报告入库，一条命令复现。RDMA 与 TCP 双口径分开报。决策误差与开销各单列一节。

收益口径看五个数：TTFT P50 与 P99、窗口内完成请求数、取回字节数、重算 token 数，对照该档最优静态组。完成请求数的口径与 MI300X 那组实测一致，供外部对照。

## 17. 项目优点

1. 决策在线化有工业证据。MI300X 实测证明静态 offload 的收益会翻面，上游 offload 也只有静态字节预算。KVFerry 按请求算这笔账。
2. RDMA 实现深入到 verbs 层。QP、MR、CQ 由自研引擎管理，块优先级与期限参与传输调度，并与决策层协同。
3. 重叠与干扰有测量。干扰系数表把取回与计算的互相拖慢量化，决策改用折扣后的带宽。
4. 降级后语义不变。RDMA 与 TCP 两套路径的指令与完成事件一致，两类机器的数字可比。
5. 硬件差异不进代码。带宽、折扣、固定开销全在标定表里，代码只有直连与中转两条路径，换机型只换表，不换代码。
6. 生命周期分两套机制：请求时点做确定性仲裁，逐出和再活跃做预测加策略表。保留按再活跃间隔分布决定，升温带带宽预算、落空中止与误判统计，冷 KV 不占近层。
7. 产品配套齐全。平台只做壳，部署、热更新、滚动升级、故障演练四件齐备，存储节点坏了服务不断。
8. 数字可复现。六组对照用一条命令复现，代价表带版本，第三方能复核收益来自哪档。

## 18. 诚实清单

- 2.3 的带宽与重算时间是量级推算，由标定实测替换，推算值不进收益结论。
- soft-RoCE 只做功能验证，rxe 带宽数字不进收益结论，也不进简历。
- 单机与双机规模只做机制验证，不做规模外推。
- 期限估计用队列与近期 step 时间。突发到达时估计失真，这一段决策退回重算。
- 干扰系数表按机器标定，换机型重测，不外推。
- GPUDirect 与 GDS 依赖拓扑与驱动。两者不可用时走中转，报告里给出直连与中转的实测差。
- 侧枝两项收益可能接近零，照实报，标不采纳。
- 块粒度混合执行的补丁面跨调度器多处，回归风险是侧枝的主要成本。补丁后要跑完原有调度测试集。
- 存储是最小实现，没有压缩，没有去重，读不提升层级，特性覆盖小于 LMCache。
- 副本故障时在飞请求重算，迁移收益的账未测。
- 代价表漂移窗口内决策退回重算，退回期间无取回收益。
- 决策与回调开销闸门 1% 是目标值，超标时退回，实测值进报告。
- CUDA 与 PyTorch 停在调用层，用到 stream、event、异步拷贝、pinned 和内存地址管理，不改 kernel 与运行时。
- 块大小与哈希口径跟随引擎配置。64 token 与附加键按核实版本的默认值写，部署配置不同时，表与键口径同步改。
- 形态登记只覆盖页式块与会话状态两类。未登记形态一律按不可取回处理，形态枚举不全时收益范围收窄。
- 保留与升温的收益账在单机规模没有测全。活跃度口径与保留期限是默认值，按轨迹调参，调参记录随报告入库。
- 会话编号由网关注入。网关失效时，保留与升温退化为固定规则，请求时点的决策不受影响。
- 仲裁器本身是代价比较，不含新传输协议与新 kernel。系统厚度在传输调度与重叠执行。这两块做浅，项目就会被看成策略包装。
- 保留与升温是预测问题，先验来自再活跃间隔分布，单机规模下置信有限。升温收益必须带反事实对照与浪费字节，不能只报命中率。
- 决策层与引擎版本靠接口语义解耦，与版本号无关。部署版本升级后，接口语义若变，按现勘第 1 条重核，主干合同不变，重核清单会变长。
- 传输执行器可替换。外部引擎若提供块级期限与协同回调，KVFerry 只留决策与协同协议。自研支点不在 verbs 封装，在块级期限与决策协同。

## 19. 交付物

交付物共十一项。薄网关，负责会话编号注入。决策与索引服务，含形态登记与保留升温决策。传输引擎，RDMA 与 TCP 双路径，直连或中转。重叠执行与取回组件的挂载配置、非核心钩子。最小块存储。侧枝核心补丁，支持一键回退，未做的标未做。标定工具与按机器版本的四张代价表。形态与生命周期参数配置。k8s manifests 与一条命令拉起。benchmark 装置与六组对照报告。现勘报告，含现状矩阵、拓扑结论、接口能力核实表和补丁回归记录。诚实清单随报告入库。
