# P2 选题候选 v1

## 规则

R1 与 P1 的技术点不重复作为重点。分层缓存、预取、冷热比、调度门控、混沌测试、JuiceFS/Fluid 数据路径不进 P2 主线。
R2 深度落在推理引擎内部。改动触及 scheduler、batching、KV 管理、attention、采样、量化之一。
R3 落脚点是性能。至少一项可量化：TTFT、ITL、tokens/s、每百万 token 成本、单位卡时吞吐。
R4 空白必须有强需求。有明确的生产负载、付费方，以及不做的损失数字。
R5 上游仓库或论文已有实现的不做。
R6 执行层全部复用。vLLM、SGLang、xgrammar、LMCache、K8s、Prometheus。
R7 产品级。入口、状态、决策、执行、观测五层齐备，可部署可交付。
R8 有故事。一段生产场景加一组数字。
R9 1–2 卡可测。核心结论在单卡或双卡租用窗口内复现。
R10 允许融合两个点，融合后共用一套度量与一个落脚点。

## 候选 A：约束解码批处理

定位：面向工具调用与结构化输出的推理加速层。一个服务、一个引擎补丁、一个能生成工具调用负载的负载台。

机制：

1. 按 grammar 分组批处理。vLLM 按到达顺序组批，不看请求的 grammar。同一工具 schema 的请求聚成批，FSM 状态推进改成批内向量化；不同 grammar 的请求分批。分组同时决定 token 预算在 prefill 与 decode 之间怎么切。
2. mask 计算从 CPU 挪走。每个 decode step 要为批内每个请求推进 FSM 并生成 logits mask，高并发下 CPU 先饱和。改成预计算 grammar 的 token 允许位图常驻显存，或把 mask 下沉到 GPU 的 logits processor kernel。
3. 同 schema 请求共享前缀的 KV 命中作为附带收益，不列为主线。

度量：相同 QPS 下的 TTFT P50/P99、tokens/s、CPU 与 GPU 利用率、每百万 token 的卡时成本。对照组为 vLLM 原生 structured output、关闭约束的自由解码、按到达顺序组批的基线。

边界：grammar 编译复用 xgrammar 或 outlines，模型服务复用 vLLM，调度补丁与观测层是自研范围。

闸门：vLLM 的 structured output manager 是否已做批内 grammar 分组；xgrammar 的 jump-forward 覆盖到什么程度；bitset 常驻显存或 GPU 侧 mask 是否已有开源实现。

名字候选：GuidedServe、StructBatch。

## 候选 B：KV 精度分层

定位：按层、按请求分配 KV 存储精度的管理器。

现状：vLLM 提供全局 FP8 KV 开关。按层与按请求的自适应没有实现。

机制：以层为单位测误差敏感度，长上下文、低重要度的层用更低精度，把省下的显存换成并发；给出一条「上下文长度 × 任务类型 × 精度」的质量与吞吐边界曲线。

落脚点：显存减半，并发翻倍，单位卡时吞吐上升，每百万 token 成本下降。

深度：attention backend 的 KV 存储格式、量化误差累积、质量评测。

风险：需要 GPU 与质量评测，噪声控制在实验纪律内。

名字候选：KVMix。

## 候选 C：混合负载 token 预算编排

定位：同一副本内按请求的算力形状分配 prefill 与 decode 的 token 预算。

现状：vLLM 的 max_num_batched_tokens 是固定值，chunked prefill 按固定块切分。

机制：按请求类型（长输入短输出、短输入长输出、工具调用）动态分配预算，同时服务长 prefill 与短 decode。

落脚点：SLO 内的吞吐与 P99。

深度：scheduler 与 batching。风险：chunked prefill 已产品化，差异化要靠预算模型。

## 已淘汰

- 会话级运行时：核心手段是 KV 降层与回迁预取，与 P1 的分层缓存重叠，违反 R1。
- 推理飞行记录仪：落脚点是可观测性，违反 R3。
- 多版本 KV 共存：首日延迟属于平台运维指标，违反 R3。
- 抢占代价模型单独成篇：粒度只覆盖一个决策，产品形态不足。

## 待核实

四家上游的现状：vLLM 的 KV 池与 scheduler、SGLang 的 radix 前缀树、AIBrix 的路由与弹性、llm-d 的 P/D 与调度。核实内容为它们各自做到哪一级粒度，用于判断候选的差异化空间。
