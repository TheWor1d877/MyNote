# P2 实施步骤详解（白话版）

这份文档把《P2 指南：KV 取回与重算的在线决策与重叠执行层》的 20 节展开成可以照着做的步骤。指南负责讲设计，本文负责讲顺序：每一步做什么、为什么先做它、做到什么程度算过关、过不了往哪退。指南的节号标在每一步开头，细节随时翻回去看。

## 先弄清楚：两种章节，一条主线

指南第 2 到 13 节按零件组织：动机、现勘、形态、架构、代价表、决策、传输、重叠、存储、平台、两个侧枝。第 14 到 20 节按交付组织：顺序与砍项、覆盖边界、benchmark、优点、诚实清单、交付物、术语。

动手时以本文的步骤为主线，一步一个闸门，过不了就停下来修，不带着问题往下走。后面几步吃前面几步的产物：标定表喂决策算术与传输调度，存储节点的块与地址喂传输引擎，传输的完成事件喂重叠执行，决策记录与演练记录喂 benchmark 归因。

本文顺序与指南节号有三处不一致。标定（指南第 6 节）排在存储与传输实现之前：决策查表、传输并发查表，表先有，实现才有输入；标定工具自带最小传输探针，不依赖产品代码。A100 拓扑核实与 RDMA 路径（指南第 3、8 节）排在 TCP 主干跑通之后：4060 没有 RDMA 网卡，主干语义先在 TCP 上冻结，租机窗口集中做 RDMA，进窗口第一件事是拓扑核实。侧枝补丁回归核实（现勘第 6 条）排在侧枝开工前，不占主干工期。

## 名词小词典

| 名词 | 大白话解释 |
| --- | --- |
| TTFT | 请求发出到收到第一个内容 token 的时间。 |
| 前缀命中 | 请求的开头与缓存里的内容相同，这部分不用重新计算。 |
| 取回 | 把分层存储里的前缀 KV 搬进显存，跳过该段 prefill。 |
| 重算 | 不搬 KV，对该段前缀重新 prefill。 |
| KV block | 引擎管理 KV 的最小单位，默认 64 token，8B GQA 模型下 8 MiB。 |
| 代价表 | 按机器实测的四张表：取回带宽、重算每 token 时间、干扰系数、决策与排队开销。 |
| 干扰系数 | 取回与计算同时跑时两边变慢的程度：带宽折扣与 decode step 时间增幅。 |
| 期限 | 取回必须完成的最晚时刻，取请求开始 prefill 之前。 |
| 迟滞系数 | 取回耗时不超过重算耗时乘这个系数才取回，默认 0.8，留出估计误差的余量。 |
| 在飞块数 | 已发起、还没完成的取回块数量，传输并发上限按它计。 |
| 退回 | 代价表缺失、漂移或开销超标时决策改用重算，记一条事件。 |
| 层位 | 块所在的存储层：DRAM、NVMe、远端。 |
| 前缀哈希链 | 块的键，hash(父块哈希, 块内 token ids, extra_keys)，与引擎前缀缓存同口径。 |
| extra_keys | 哈希里除 token 外的附加项：LoRA、cache_salt、多模态哈希，存储侧照单全收。 |
| 索引软状态 | 索引不持久化，靠存储节点的登记与清单心跳重建，重启窗口内按未命中处理。 |
| staging | 远端 NVMe 块先搬进本节点 DRAM，再服务 RDMA 读。 |
| QP | RDMA 的队列对，发送与接收各一条队列，连接用 RC 类型。 |
| MR | RDMA 的内存注册区，注册后网卡才能直接读写这块内存，注册一次复用。 |
| CQ | RDMA 的完成队列，传输完成后网卡往里写一条完成记录。 |
| RDMA READ | 请求方网卡直接读远端内存，远端 CPU 不参与。 |
| rkey | 远端内存区的访问凭证，地址交换时连同地址一起拿到。 |
| GPUDirect | 网卡直读直写显存，要求网卡与 GPU 在同一 PCIe switch 下。 |
| GDS | GPUDirect Storage，NVMe 直读进显存，不经主机内存。 |
| pinned 中转 | 锁页主机缓冲作跳板：RDMA 或文件读先落这里，再拷进显存。 |
| stream | CUDA 的任务队列，不同 stream 上的操作可以并行。 |
| event | CUDA 的同步点，一条 stream 记录、另一条 stream 等待。 |
| 图断点 | piecewise CUDA Graph 在 attention op 处切开的位置，connector 的等待在这里 eager 执行。 |
| 异步加载 | 请求置 WAITING_FOR_REMOTE_KVS 状态，KV 加载完成后调度器才放它进 prefill。 |
| connector | vLLM 的 KV 传输挂载接口，提供命中查询、加载、保存三类回调。 |
| 命中查询 | get_num_new_matched_tokens 回调，返回命中 token 数与是否异步加载。 |
| OffloadingConnector | vLLM 自带的 CPU/DRAM offload connector，静态字节预算，没有在线成本决策。 |
| sticky | 前缀亲和路由，同前缀请求送同一副本。 |
| soft-RoCE | 用软件模拟 RDMA 网卡（rxe），只做功能验证，带宽数字不作数。 |
| chunked prefill | 把长 prefill 切成多段推进，和 decode 混在一批里跑。 |
| 探针漂移 | 周期传一个固定块，实测耗时与表值偏差超阈值，说明表过期了。 |
| 旁路开关 | 决策服务的配置开关，强制取回或强制重算、跳过查表，供误差复核与静态对照组用。 |
| 清单心跳 | 存储节点周期上报的块清单，索引靠它重建软状态。 |
| 条带化 | 一个大块拆到多条 QP 并行传输，完成事件按段聚合回块。 |
| 零拷贝 | 数据不经用户态缓冲中转，文件直发 socket 或网卡直读内存。 |
| 主干 | 保证交付的请求级决策产品：决策、传输、重叠、存储、平台。 |
| 侧枝 | 块粒度混合执行与层间流水，逐项独立降级，收益为零就标不采纳。 |

## 步骤 0：现勘与核实——先确认接口与通路（指南第 3 节）

这一步的目标：动工前确认四件事。部署版本与源码核实版本一致；soft-RoCE 上 verbs 最小通路跑通；4060 上 pinned 内存与 stream 重叠可行；S3 装置与租机渠道可用。接口语义已在指南第 3 节的表里核实（本地 checkout v0.34.0rc0，HEAD 595b1514e8），这一步不重读源码，只对齐版本与实测通路。

具体做什么：

1. 版本对齐。锁定产品挂载的 vLLM 版本，与核实版本不一致时重读差异项，重点三处：命中查询签名看 kv_connector/v1/base.py，异步加载状态看 v1/request.py 与 scheduler.py，图捕获默认值看 config/vllm.py。三处与指南第 3 节表逐字对照，重读结论更新进表，后续步骤按部署版本走。
2. soft-RoCE verbs 最小通路，复用 S3 装置。建连顺序走一遍：打开设备与分配 PD，注册 MR，创建 CQ 与 QP，QP 状态走 INIT→RTR→RTS，两端经控制通道交换 QPN、地址与 rkey，post 一次 RDMA READ，轮询 CQ 取完成。四个阶段各留一条成功记录，状态迁移参数（PSN、MTU、超时重试次数）记档。容器权限要求记档：设备节点、IPC_LOCK、相关 capabilities。rxe 的带宽数字只作功能记录，不进收益结论。
3. pinned 与 stream 重叠验证。4060 上分配 pinned 与 pageable 两块主机缓冲，cudaMemcpyAsync 走独立 stream，与一个持续运行的 kernel 并发，扫 8 MiB、64 MiB、256 MiB、1 GiB 四档，记两种缓冲的带宽差与 kernel 时间增幅。这组探针是步骤 2 干扰表的原型。
4. 装置盘点。S3 的 soft-RoCE 容器装置能否直接复用；4060 的驱动、CUDA、PyTorch 版本记档；A100 带 IB 的租机渠道与价格确认，窗口预约在步骤 7 主干验收通过后。
5. 产出现勘报告，内容五项：

| 项 | 内容 |
|---|---|
| 版本对齐 | 部署版本与核实版本的差异项、重读记录 |
| verbs 通路 | 四阶段成功记录、容器权限要求 |
| pinned 重叠 | 四档带宽差、kernel 时间增幅 |
| 装置清单 | S3 复用结论、4060 环境版本 |
| 租机渠道 | A100 带 IB 的渠道与价格、窗口预约条件 |

A100 拓扑核实与补丁回归核实两项写明排在步骤 8 与步骤 12，不算缺失。

过关标准：部署版本与核实版本一致，或差异项已重读并更新表；verbs 四阶段各有一条成功记录；pinned 与 pageable 四档带宽差有数；现勘报告入库。

红灯处理：版本差异大到接口语义变化，主干退化为网关侧决策，重算成本用估计口径，侧枝标未做。soft-RoCE 权限拿不到，verbs 功能验证推到租机窗口开头补做，步骤 8 的工期相应加长。

## 步骤 1：搭实验装置——负载台、网关与记录（指南第 4、11、16 节）

为什么第二步是它：后面每做完一段都要立刻看到效果，看到效果全靠轨迹与记录。装置不稳，所有数字都不可信。

具体做什么：

1. 模型选型先定口径。4060 显存 8 GB，8B bf16 权重约 16 GB 放不下，单机机制验证用 1.5B 或 3B 模型，KV 每 token 字节数与块大小按实际模型记进表口径；8B 的收益数字出自步骤 8 的 A100 窗口。两组口径分开报，不混用。
2. 负载台。轨迹参数：共享前缀比例三档、输入长度分布三档、压力两档（低负载与高压力）、冷热态、KV 池容量、副本数。轨迹用 Mooncake 公开 agent trace 加合成补齐：真实 trace 的前缀比例不够时，按档位合成共享前缀段拼到请求头部，合成段与真实段的比例写进轨迹元数据。分档参数写进轨迹文件名，换档不改代码。同一份轨迹喂本产品与对照组，两侧 KV 池容量与副本数取同一个值。
3. 薄网关。接入、request id 注入、sticky 路由执行、摘除执行四件。网关不判副本好坏，只按探针结果摘 endpoint 并改路：在飞请求带原 request id 改路到其余副本重新 prefill，改路事件记一条。这一步先用原生 vLLM 副本做路由目标，connector 在步骤 5 挂。
4. 记录落盘。四张表，按 request id 或块哈希关联，这一步定表结构与写入通路，决策服务后面填内容：

| 表 | 粒度 | 关键字段 |
|---|---|---|
| 决策记录 | 每请求一条 | 指南 7.5 字段：命中深度、层位、动作、估计耗时、表版本、完成时刻、TTFT |
| 退回与降级事件 | 每次一条 | 时刻、类型、原因、表版本 |
| 驱逐事件 | 每块一条 | 块哈希、层位、原因 |
| 演练记录 | 每次一条 | 时刻、节点编号、手段、命中率曲线 |
5. 冷热态规程。冷态每轮重启副本并清空 KV 与存储层。热态预热：按轨迹的共享前缀比例先打一轮预热请求，命中率与 step 时间回到稳态后开始计数，预热轮不计入结果。两组数字分开报。两档压力的定义写进轨迹元数据：低负载取到达率低于单副本容量，高压力取到达率超过容量、队列持续积压，容量用原生基线的完成速率估。
6. 一条命令拉起。单机进程级脚本起网关、原生副本、负载台，k8s 版在步骤 9。这一步先保证轨迹可复跑。
7. 原生基线。原生 vLLM 加本地前缀缓存跑一遍分档轨迹，这是 benchmark 六组里的第一组，后面所有对照以它为底。

过关标准：一条命令起全套；同一轨迹重跑两次，请求数、token 数、P50 TTFT 对得上；九档负载形状（前缀三档乘长度三档）各能生成轨迹，两档压力各跑一遍；原生基线入库。

常见坑：负载台自身 CPU 或连接数先饱和，测出来的是负载台上限不是引擎上限，饱和轮次作废；冷热态混在一张表里，命中率数字没法解释；单机用小模型、对照用 8B，口径不一致数字没法比。

## 步骤 2：标定工具与四张代价表——决策的输入（指南第 6 节）

为什么排在实现前面：决策算术、传输并发、干扰回路全查表，表先有，步骤 3 起的实现才有输入。标定工具自带最小探针（cudaMemcpyAsync、cuFile 或 pread、socket），不依赖产品引擎。

具体做什么：

1. 取回带宽表。行是来源层与路径：本地 DRAM 经 cudaMemcpyAsync、本地 NVMe 的 GDS 与 pinned 两条、TCP。列是 8 MiB、64 MiB、256 MiB、1 GiB，每格记有效带宽与固定开销。两个数的取法：同一路径扫多个块大小，传输耗时对字节数线性拟合，斜率的倒数是有效带宽，截距是固定开销；单块档另直接测一次验证截距。RDMA 行与 MR 注册时间留到步骤 8 的 A100 版补齐。NVMe 到 DRAM 的 staging 带宽按 8、64、256 MiB 三档另记。单机 TCP 走 loopback，口径标注「单机机制验证」，收益结论用双机表。
2. 重算每 token 时间表。vLLM prefill 微基准，输入长度 1k、4k、16k、32k 四档，纯 prefill 批与 decode 混批两列，混批 chunk 取 512、1024、2048、4096。微基准构造：固定输入长度的请求批量打进引擎，纯 prefill 列不混 decode，混批列按 chunk 档位配置 chunked prefill 并持续喂 decode 请求；每 token 时间 = prefill 段耗时 / 实际计算 token 数，命中段不计入分母。档内按实际 token 数线性插值，不外推档位之外的长度。
3. 干扰系数表。在飞块数 1、2、4、8、16 乘 decode 批大小 1、8、32，每格记两个数：计算负载下的取回带宽折扣、传输负载下的 decode step 时间增幅。计算负载用 vLLM 持续 decode，传输负载用步骤 0 的探针。
4. 决策与排队开销表。查表加算术耗时、connector 回调与决策 RPC 耗时、入队到出队的排队等待，排队直接测不建模。前两项合计对照 step 时间的 1% 闸门。
5. 三个在线参数定值。迟滞系数默认 0.8，同一轨迹扫 0.6、0.7、0.8、0.9、1.0 五档，记决策翻转次数与 TTFT，取翻转少且 TTFT 不劣的档；干扰闸门默认 decode step 增幅 5%；传输并发上限默认每副本在飞 8 块，取带宽接近饱和且 step 增幅在闸门内的拐点。
6. 漂移探针。每 30 秒传一个 64 MiB 固定块，实测耗时与表值偏差超 20% 连续三次触发重标定，重标定窗口内决策退回重算。探针这一步跑通，接入决策在步骤 5。
7. 表带版本与机器口径（GPU 型号、网卡、PCIe 拓扑、驱动、引擎版本、模型与块大小），一条命令跑完四张表，冷热态分开，入库。

测量规程：

1. 每格预热后至少测五次取中位数。
2. 带宽按完成时刻差算，不用发起时刻，发起时刻含排队。
3. 探针独立进程跑，与产品进程分开，避免互相干扰。
4. 干扰表的计算负载与传输负载同时起，两侧各记各的数。

过关标准：四张表 4060 版齐全，每格有实测值与口径；同机重跑一次，表值偏差有数；三个参数各有扫描记录与选定值；人为制造探针偏差能触发重标定。

常见坑：固定开销混进带宽，小块档的取回耗时被低估；重算表只测纯 prefill 批，决策在混批里查错列；干扰表只记传输对计算的影响，漏了计算对带宽的折扣，两个方向都要记。

## 步骤 3：最小块存储——块读底座（指南第 10 节）

这一步的目标：块写得出、读得回、地址拿得到、节点坏了服务不断。压缩与去重不做，增量不在存储，存储只保证块读可靠。

具体做什么：

1. 块格式与键。块对齐引擎 KV block，默认 64 token、8 MiB，跟随引擎配置，单机小模型按实际块大小记口径。键用前缀哈希链 hash(父块哈希, 块内 token ids, extra_keys)，extra_keys 含 LoRA、cache_salt、多模态哈希，存储侧照单全收，不自行裁剪。
2. 存储节点服务。DRAM 服务缓冲与 NVMe 文件布局，块写入、读回、清单上报三个接口。NVMe 用大文件加偏移，每块一段，偏移记进索引，不用每块一个文件，小文件的 inode 与目录开销放大。这一步用离线灌块验证，connector 的 save 对接在步骤 5。
3. 索引。块哈希到（层、节点、地址或偏移、长度）的映射，与决策服务同进程部署，这一步先独立跑。索引是软状态：写入登记、驱逐注销、周期清单心跳，心跳默认 10 秒一次，周期写配置，心跳字段带节点编号、块哈希列表、各块层位与偏移、容量水位；进程重启后从各节点最近一次清单逐条重建，重建完成前命中查询一律按未命中返回，请求走重算，save 路径不受影响。
4. 放置与驱逐。save 写 DRAM，DRAM 容量超阈值按 LRU 下沉 NVMe，NVMe 超阈值丢弃，远端层在步骤 8 接。读不提升层级，放置只做写入下沉与 LRU 驱逐。每层容量写配置，驱逐事件带块哈希与原因。
5. 节点故障语义。节点失联，索引把它的块标不可用，命中查询排除，决策按剩余层位重算；节点恢复后重新上报清单，索引恢复登记。
6. 对账抽查规程。每轮随机抽 1% 的块，不足一百块抽一百块，读回重算哈希与索引登记对照；已驱逐的块抽查索引已注销，盘上残留段抽查已释放。

过关标准：随机抽块读回校验哈希，索引与数据对账一致；杀一个存储节点（这一步用双进程模拟），服务继续，命中率下降幅度有数；索引进程重启，重建窗口内请求全走重算，无错误命中；节点恢复后命中率回到故障前水平的时间有数。

常见坑：哈希口径与引擎不一致，漏了 extra_keys，命中查询报命中但读回的块对不上；索引做成硬状态，重启后登记与盘上实际块不一致，错误命中比重算更贵。

## 步骤 4：传输引擎 TCP 路径——指令语义先冻结（指南第 8 节）

为什么 TCP 先做：4060 没有 RDMA 网卡。指令语义（块列表、优先级、期限）与完成事件先在 TCP 上冻结，步骤 8 的 RDMA 只换数据通道，决策层与重叠执行不用改。

具体做什么：

1. 指令与完成事件。决策层下发块列表、来源节点、优先级、期限；引擎返回每块完成事件，带块 id 与时刻。这套语义 RDMA 与 TCP 共用，写成引擎内部接口，两条路径各实现一遍。
2. 地址交换（TCP 版）。控制消息按批打包，一次带一个请求的全部块哈希；存储节点回地址或偏移，未命中回失败，决策改重算。每块单发控制消息会把固定开销放大，打包摊薄。
3. 数据通道。NVMe 块用 sendfile 从文件直发 socket，DRAM 块用 MSG_ZEROCOPY 发送，不经用户态缓冲中转。控制通道与数据通道分开连接，控制消息小、数据消息大，混在一条连接上互相阻塞。
4. 传输调度。块队列按期限排序，期限近的优先；期限已过的块撤读，整请求改重算；在飞块数上限默认 8，查干扰表。
5. 路径开关。配置切 TCP 或 RDMA，代价表切对应列。这一步 RDMA 侧是空实现，开关与表切换逻辑先跑通。

指令生命周期分五段，每段留记录：

| 阶段 | 执行者 | 触发条件 | 动作 | 判断条件 | 返回与后续 |
|---|---|---|---|---|---|
| 下发 | 决策层 | 决策输出取回 | 块列表、来源节点、优先级、期限 | 无 | 进引擎队列 |
| 排队 | 传输引擎 | 并发额度有空位 | 按期限排序等待 | 期限未过 | 出队进发起 |
| 发起 | 传输引擎 | 地址交换成功 | 读块，NVMe 直读文件 | 期限未过 | 完成后出事件 |
| 完成 | 传输引擎 | 块读完成 | 每块一条完成事件，带块 id 与时刻 | 无 | 喂重叠执行 |
| 撤读 | 传输引擎 | 期限已过 | 未完成块取消，通知决策层 | 无 | 整请求改重算 |

撤读与完成可能竞态：撤读指令发出后完成事件仍会到达，引擎按请求当前状态丢弃迟到的完成事件，不能写进已改重算请求的 KV。

过关标准：同一轨迹 TCP 路径的取回成功率与期限错过率有数；期限撤读能演示，人为把期限压到取回耗时以下，请求改重算且记录对得上；指令与完成事件语义冻结成文档，步骤 8 照此实现；带宽复跑与步骤 2 表值偏差有数。

常见坑：期限排序只按下发时刻不看剩余时间，晚下发的紧期限块排在后面，错过期限；并发额度按请求数计而不是在飞块数，一个大请求把额度占满，小请求饿死。

## 步骤 5：决策服务与 connector 挂载——把账算起来（指南第 7、5 节）

这一步的目标：命中查询返回时，决策层按表算出取回或重算，请求按结果走异步加载或正常 prefill。这一步把存储（步骤 3）、传输（步骤 4）、代价表（步骤 2）串成请求路径。

具体做什么：

1. 决策算术。取回耗时 = 各块（字节数 / 折扣后带宽 + 固定开销）之和，带宽查 6.1 与 6.3；重算耗时 = 命中 token 数 × 每 token 时间，查 6.2 的当前批组成列。取回耗时不超过重算耗时乘迟滞系数（默认 0.8）才输出取回。来源层按带宽表取耗时最小的层，整段前缀走单一层。
2. 期限。假设该请求立即重算，估计它开始 prefill 的时刻，取回必须在这个时刻前完成；预计超期输出重算，记一条期限不足事件。期限估计用队列长度与近期 step 时间，请求进异步加载状态后期限仍在计时。决策 RPC 设超时，超时按重算处理并记一条退回事件，请求路径不因决策服务抖动卡住；批组成从钩子与调度器状态读，决策服务不自己估。
3. connector 实现。命中查询里调决策 RPC：取回返回命中 token 数加异步标记，请求进 WAITING_FOR_REMOTE_KVS；重算返回 0，请求走正常 prefill。传输完成经 get_finished 报告，调度器才放请求进 prefill。save 回调在 HBM 驱逐时把块写存储节点。
4. 非核心钩子。prefill chunk 边界与 step 进度传给决策层，供期限估计与干扰标定用。钩子带开关，关闭后期限估计退回队列长度口径。
5. 三类退回，各记事件带原因：

| 触发 | 判据 | 退回期间动作 |
|---|---|---|
| 代价表缺失或过期 | 表版本不在或超有效期 | 决策输出重算，save 照常 |
| 探针漂移超阈值 | 偏差超 20% 连续三次 | 触发重标定，窗口内决策输出重算 |
| 决策开销超闸门 | 决策与回调合计超 step 时间 1% | 决策输出重算，开销降下来后恢复 |

退回期间产品语义等于原生 vLLM 加本地前缀缓存，save 路径不受影响，KV 照常写回。漂移探针（步骤 2）在这一步接入决策。
6. 决策记录。每请求一条，字段按指南 7.5：request id、命中深度、层位、动作、取回与重算的估计耗时、表版本、实际取回完成时刻、TTFT，写进步骤 1 定的表。

请求从命中查询到 prefill 的完整路径如下，排查问题时按这张表定位卡在哪一段：

| 阶段 | 执行者 | 触发条件 | 动作与消息字段 | 判断条件 | 返回与后续 |
|---|---|---|---|---|---|
| 命中查询 | connector | 调度器扫描到该请求 | 调决策 RPC，带前缀哈希链、队列长度、批组成 | 索引返回命中深度与层位 | HBM 命中不进决策；未命中返回 0 |
| 决策 | 决策服务 | 收到查询 | 查四张表算取回与重算耗时，比迟滞，校期限 | 取回 ≤ 重算×0.8 且期限够 | 输出动作、来源层、块顺序与期限，记决策记录 |
| 异步等待 | 调度器 | 决策输出取回 | 请求置 WAITING_FOR_REMOTE_KVS | 无 | 其余请求照常计算，重叠窗口开始 |
| 块读 | 传输引擎 | 拿到地址与偏移 | 按期限排序发起块读，完成事件喂重叠执行 | 期限未过 | 超期撤读，整请求改重算 |
| 完成报告 | connector | 全部块完成 | get_finished 报告请求 id | 无 | 调度器放请求进 prefill |
| 跳段计算 | 引擎 | 请求进 prefill | load 回调按块 wait event，prefill 只算未命中段 | KV 已 resident | 首 token 产出，TTFT 落记录 |

过关标准：指南 7.2 算例的三场景在实测表下决策方向一致；决策与回调开销合计不超过 step 时间的 1%；三类退回各演示一次，退回期间与原生 vLLM 对照语义一致；决策记录条数与网关请求计数对账。

常见坑：HBM 命中也进决策，原生前缀缓存的命中被重复记账，HBM 命中不进决策；重算耗时查纯 prefill 列，混批里低估重算成本，取回被过度触发；退回时把 save 也停了，存储层不再进新块，决策恢复后命中率回不来。

## 步骤 6：重叠执行——取回与排队时间重叠（指南第 9 节）

这一步的目标：取回与其余请求的计算重叠，请求被调度时 KV 已大部分或全部 resident，prefill 跳过命中段，取回耗时不全额暴露在 TTFT 上。

具体做什么：

1. stream 与 event。计算 stream 沿用 vLLM 的，传输 stream 独立；pinned 中转缓冲启动时分配，cudaMemcpyAsync 走传输 stream；每块完成 record 一个 event，load 回调按块 wait event。
2. 隐式同步排查。传输路径上不调用 .cpu()、.item() 这类隐式同步；用 profiler 确认传输与计算在时间轴上重叠，不是串行。判据：时间轴上取回拷贝与 decode kernel 有重叠区间，重叠区间占取回耗时的比例记进报告；比例接近零说明 stream 或 event 接错，回查同步点。
3. 干扰回路。在线监测 decode step 时间，按阈值动作：

| 监测量 | 阈值 | 动作 |
|---|---|---|
| decode step 增幅 | 超过 5% | 传输并发减半 |
| decode step 增幅 | 回落到 2% 以下 | 并发逐级恢复 |
| 降并发时未发起的取回 | 重算期限后不足 | 改重算，记期限不足事件 |
4. 等待位置确认。load 回调在 CUDA Graph 断点处 eager 执行（指南第 3 节核实），prefill 被分段捕获也不冲突；这一步用 profiler 再验一次，等待点落在图外。

过关标准：同一轨迹预取重叠与串行取回对照，TTFT 差有数；传输活跃期间 decode step 增幅不超过闸门；pinned 与 pageable 两档带宽与 TTFT 分开报；人为把并发压到闸门以上，减半与恢复动作各记一条事件。

常见坑：wait event 写成同步等待，传输 stream 与计算 stream 串成一条，重叠收益归零；pinned 缓冲按请求临时分配，分配耗时进请求路径，要启动时预分配；干扰回路只看带宽不看 step，计算被拖慢没人管。

## 步骤 7：单机主干验收——TCP 全流程闸门（指南第 4、7.5、8.6、9.4、10.5 节）

这一步的目标：4060 单机上产品全流程跑通，主干语义冻结。这一步不过，不进租机窗口。

具体做什么：

1. 全流程串联。标定、挂载、运行、降级、运维、复现六步（指南第 4 节）走一遍，每步留记录。运维这一步只做进程级重启与配置切换，k8s 版在步骤 9。
2. 决策误差复核。同一轨迹上决策选择与逐请求实测最优选择对照，选错边的请求占比与损失分布有数。实测最优的取法：同一请求分别强制取回与强制重算各跑一遍，取 TTFT 小的那个。强制动作用决策旁路开关实现，配置指定动作、跳过查表，开关状态记进决策记录；这个开关同时供步骤 10 的静态全取回与静态全重算两组用。
3. 降级演示。路径开关切换与代价表切列演示一次；三类退回各一次；摘 connector 配置回到原生 vLLM，一键回退验证。
4. 存储对账与故障复跑。抽块校验、杀存储节点、索引重启重建，按步骤 3 的过关标准复跑一遍，记录入库。
5. 主干验收报告，内容五项，随轨迹与表版本入库：

| 项 | 内容 |
|---|---|
| 决策分布 | 取回与重算占比，按层位与负载档分 |
| 流量账 | 取回字节数、重算 token 数 |
| TTFT | P50 与 P99，对照原生基线 |
| 开销 | 决策与回调占 step 时间比例实测 |
| 事件 | 退回、降级、期限不足、改重算清单 |

过关标准：指南 7.5、8.6、9.4、10.5 四处验收项全过；同一轨迹重跑两次，请求数、token 数、P50 TTFT 对得上；回退到原生 vLLM 后行为与步骤 1 基线一致。

红灯处理：决策误差大到收益为负，先回步骤 2 查表值口径，再查期限估计；修不动就按指南第 14 节砍项顺序缩范围，决策、传输、重叠、存储、部署五件不动。

## 步骤 8：RDMA 路径与双机验证——租机窗口（指南第 3、6、8 节）

为什么排在这：主干语义已在 TCP 上冻结，RDMA 只换数据通道。租机窗口集中用：拓扑核实、verbs 引擎、A100 四张表、双机端到端，一次做完。

具体做什么：

1. 拓扑核实，进窗口第一件事（现勘第 3 条）。网卡与 GPU 是否在同一 PCIe switch 下，看 lspci 拓扑树，两者挂在同一个 switch 下游才满足 GPUDirect 条件；IB 带宽用 ib_write_bw 实测；NVMe 型号记档，GDS 可用性查 nvidia-fs 驱动与 cuFile 接口。结论写进代价表口径，决定走 GPUDirect 还是 pinned 中转。
2. verbs 引擎。RC QP；KV 池与存储节点服务缓冲启动时预分配，MR 注册一次缓存复用；控制通道交换块地址与 rkey，按批打包；数据通道走 RDMA READ，请求方直接读远端内存；CQ 轮询线程出完成事件。指令与完成事件照步骤 4 冻结的语义实现。
3. GPUDirect 与中转。同 switch 时 GPU 内存注册 MR，RDMA READ 直落 HBM；注册方式优先 dmabuf，驱动不支持时退回 nv_peer_mem，两者都不可用走 pinned 中转。不同 switch 也走 pinned 主机中转，RDMA READ 落 pinned 缓冲，cudaMemcpyAsync 经传输 stream 进 HBM。本地 NVMe 层 GDS 可用时 cuFile 直读进 HBM，不可用走 pinned 中转加拷贝。两条路径的带宽差进表。
4. 条带化与调度。64 MiB 以上的传输按 QP 数均分拆段，每段独立 post，完成事件按段聚合回块；期限排序、撤读、并发上限照 TCP 版语义。
5. 远端存储节点。DRAM 服务缓冲注册 MR，响应地址交换；远端 NVMe 块先 staging 到本节点 DRAM，地址交换等 staging 完成才回地址，staging 耗时计入取回估计，进表远端列。TCP 路径直读文件，不 staging。
6. A100 四张表。标定工具在租机重跑，RDMA 行补齐，干扰表与重算表出 A100 版，模型换回 8B，三个在线参数按 A100 表重定。旧表保留供对照。
7. 双机端到端。副本机跑 vLLM 与传输引擎请求侧，存储机跑存储节点与传输引擎服务侧，两机 IB 直连或经交换机；网关与决策服务放副本机，负载台放存储机或第三台，避免负载台抢副本机 CPU。远端取回全流程跑通；同一轨迹 RDMA 与 TCP 双口径各跑一遍，决策分布与 TTFT 分开报。混合集群语义顺带验证：RDMA 副本与 TCP 副本并存，各按本机表决策。
8. 窗口收尾。租机数据全部落盘带回：四张表、profiler 记录、演练记录、双口径报告入库；退租前按清单核对，缺项在窗口内补测，退租后补不了。

过关标准：MR 注册确认一次性，传输路径上无注册调用；带宽表复跑偏差有数；负载下期限错过率有数；拓扑允许时 GPUDirect 与中转两档带宽差有数；双机全流程与单机主干语义一致。

红灯处理：GPUDirect 不可用，中转路径照跑，报告直连与中转的实测差。租机窗口拿不到或 IB 不可用，产品按 TCP 单路径交付，RDMA 数字标未测，soft-RoCE 的功能记录不进收益结论。

常见坑：MR 注册进了请求路径，每次取回付一次注册耗时；rkey 与地址按块单发，控制开销放大；staging 没等完就回地址，RDMA READ 读到半块。

## 步骤 9：平台四件——能部署能运维（指南第 11 节）

具体做什么：

1. 部署。k8s manifests 加一条命令拉起：薄网关、vLLM 副本、决策与索引服务、存储节点。单机 kind 集群跑 TCP 全流程，租机双节点跑 RDMA。kind 的 GPU 透传：节点容器挂 /dev/nvidia* 与驱动库，装 nvidia device plugin，副本 Pod 声明 nvidia.com/gpu 资源，节点挂载传播用 rslave，否则设备节点进不去容器。存储节点挂本地 NVMe。副本数、KV 池容量、块大小、路径开关都是显式配置项，benchmark 复现时随报告入库。
2. 健康与热更新。副本与存储节点带就绪探针，探针周期与失败阈值写显式配置，检测延迟 = 周期 × 阈值，演练记录里报这个值；代价表版本、迟滞系数、干扰闸门、传输并发上限、路径开关配置热更新，不重启进程。探针失败的副本由网关摘除，在飞请求改路重算。热更新生效时刻记事件，决策记录带更新前后的表版本，供对照。
3. 滚动升级不冷缓存。存储节点逐台升级，块留在盘上，升级窗口内该节点的块按不可用处理，命中查询排除，命中率短暂下降；进程拉起后上报块清单，索引重建后继续服务。存储不做复制，这段下降是设计内的代价，演练记录里单列。副本逐台升级，HBM 缓存冷，命中由存储层接住，命中率回到稳态所需的请求数记录进报告。升级期间决策与传输照常，升级动作本身不进决策路径。
4. 故障演练。三类，爆炸半径限定一个节点，演练记录带时刻与节点编号：

| 演练 | 手段 | 核对 |
|---|---|---|
| 杀存储节点 | 停一个存储节点进程 | 服务继续，命中率下降与恢复曲线，索引标不可用事件 |
| 杀副本 | 停一个 vLLM 副本 | 网关摘除与改路重算事件，其余副本照常 |
| 断网络 | 断网关到存储节点的网络 | 决策退回与改重算事件对得上，恢复后登记重建 |

过关标准：同一轨迹重跑两次，请求数、token 数、P50 TTFT 对得上；杀一个存储节点服务继续，命中率下降与恢复时间有数；滚动升级后命中率回到升级前水平，恢复请求数有数；热更新不重启进程，决策记录能看出表版本切换时刻。

常见坑：kind 集群没配 device plugin，GPU 副本起不来；存储节点升级把盘清了，不冷缓存变成冷缓存；热更新只改配置不记事件，决策误差复核分不清是哪版表做的决定。

## 步骤 10：Benchmark 六组对照——收益数字（指南第 16 节）

具体做什么：

1. 六组定义。原生 vLLM（本地前缀缓存）、静态全取回（offload 常开）、静态全重算（offload 常关）、sticky 路由加静态 offload（生产默认）、vLLM OffloadingConnector（上游现状，静态字节预算）、本产品。六组吃同一份轨迹，KV 池容量与副本数取同值。各组配置差异如下：

| 组 | 存储挂载 | 路由 | 取回/重算决策 |
|---|---|---|---|
| 原生 vLLM | 无，只有本地前缀缓存 | sticky | 无 offload |
| 静态全取回 | 本产品存储 | sticky | 旁路开关强制取回 |
| 静态全重算 | 本产品存储，save 照常 | sticky | 旁路开关强制重算 |
| sticky 加静态 offload | 分层存储常开 | sticky | 静态配置 |
| OffloadingConnector | vLLM 自带 CPU offload | sticky | 静态字节预算 |
| 本产品 | 本产品存储 | sticky | 在线查表决策 |
2. 分档跑。九档负载形状各配两档压力，每档单独出结论，不合并总均值。轨迹用步骤 1 的装置，Mooncake 公开 agent trace 加合成补齐。
3. 规程。每组至少七次取中位数报区间；冷热态分开；客户端饱和的轮次作废，负载台自身 CPU 与连接数曲线作附件；模型、引擎、镜像、机器、KV 池容量、副本数、代价表版本随报告入库，一条命令复现。复现命令的要素逐项列：轨迹文件名与版本、镜像 tag、模型与量化、KV 池容量、块大小、副本数、表版本、路径开关、随机种子，缺一项复现不成立。
4. 双口径。RDMA 与 TCP 分开报，TCP 用双机表，不用单机 loopback 表。
5. 收益口径。同轨迹下 TTFT P50 与 P99、窗口内完成请求数、取回字节数与重算 token 数，对照该档最优静态组。完成请求数指固定时长窗口里收到完整响应的请求数，超时与断连不计，窗口时长写进报告，口径与 MI300X 那组实测对齐，供外部对照。
6. 决策误差与开销各单列一节：

| 节 | 内容 |
|---|---|
| 决策误差 | 选错边占比、损失分布、按负载档分的决策翻转次数 |
| 开销 | 决策计算、connector 回调、RPC 三项实测值与 step 时间占比 |

过关标准：六组数字能画在同一张图上，任一组一键复现；收益来自哪档负载能指出来；收益接近零的档照实报；OffloadingConnector 组与本产品组的决策分布差异能解释，静态字节预算对在线查表。

常见坑：对照组 KV 池容量与本产品不一致，命中率差异被容量差异掩盖；只报总均值，收益翻面的档被平均掉；拿单机 loopback TCP 数字当远端收益。

## 步骤 11：侧枝二层间流水——先做不动核心的（指南第 13 节）

为什么先做它：接口现成，wait_for_layer_load 在每层 attention 前调用，不动调度器核心，补丁面小。主干验收通过后开工。

具体做什么：

1. 层序交付。传输引擎按层计算顺序排块：第 i+1 层的块排在第 i 层之后，层内按块期限排序。指令语义加一个层序号字段，完成事件按层聚合。计算进度用步骤 5 的非核心钩子报当前层号，传输引擎对着层号提前一层交付，交付进度落后于计算进度时该层等待暴露在 prefill 里，等待时长记进每层分布。
2. 等待接入。wait_for_layer_load 的调用点带 eager_break_during_capture，在 CUDA Graph 断点处 eager 执行；默认捕获模式 FULL_AND_PIECEWISE 下 prefill 被分段捕获，等待点在图外，不需要改捕获模式；必要时 connector 声明 requires_piecewise_for_cudagraph 强制 PIECEWISE，两种模式都兼容。decode 段不插等待，KV 在 prefill 结束时已全部 resident。
3. 干扰闸门照常。层间传输的并发受 5% 闸门约束，超限减半，回路照步骤 6。
4. 固定开销账。层粒度交付把一次整段传输拆成 32 次层传输，固定开销按层数放大。先用步骤 2 表值算账，再实测验证。推算算例（8B、30K 前缀、32 层，数值为推算口径）：每 token 每层 KV 是 4 KiB，30K token 的单层 KV 约 120 MiB；单层计算时间约 3 s / 32 ≈ 94 ms。IB 折扣后 20 GB/s 取一层约 6 ms，小于 94 ms，等待接近零；10 GbE TCP 折扣后 0.77 GB/s 取一层约 164 ms，大于 94 ms，每层暴露约 70 ms 等待，流水收益被带宽吃掉。层 KV 字节数小、单块档固定开销占比高时同样不划算，这笔账决定该机型是否采纳层间流水。
5. 对照验收。同一轨迹对主干整请求预取，短队列与长队列两档分开报 prefill 等待时间、TTFT、每层等待的分布。短队列是层间流水的收益来源：队列短时主干没有足够的重叠窗口。每层等待分布的读法：等待集中在前几层说明交付起步慢，控制通道或首块延迟大；等待均匀分布在所有层说明带宽不够，层 KV 字节数除以单层计算时间超过可用带宽。两种情况修法不同，报告里分开写。

过关标准：短队列档 prefill 等待时间下降有数；长队列档收益接近零时照实报，标不采纳；降级开关关闭后回到主干整请求预取，主干验收复跑不受影响。

红灯处理：固定开销吃掉收益，整项标不采纳，不留半成品。

## 步骤 12：侧枝一块粒度混合执行——后做补丁面大的（指南第 12 节）

为什么后做：非连续命中要动调度器核心，回归测试是主要工作量。开工前先做现勘第 6 条：在指南 12.2 的七点补丁上跑 vLLM 原有调度测试集，记失败项与修复方式，估回归工期。

具体做什么：

1. 补丁回归先行。七点补丁：命中掩码接口、调度记账、块分配、命中查找、请求状态、输入构造、失败回退，位置见指南 12.2 表。按依赖顺序落：先命中掩码接口与请求状态，这两处定义分段语义；再调度记账、块分配、命中查找，适配记账；最后输入构造与失败回退，适配执行。每落一处跑一遍原有调度测试集，失败项当处修复或记录，不攒到最后。
2. 决策细化。决策单位从整段前缀换成块范围，每段各算取回与重算耗时，各选小的动作，期限按段独立计时。四张表与主干共用。块掩码用按块 id 的位图表达命中与动作；调度记账把 num_computed_tokens 的单整数换成段列表，每段记起始块、块数、来源（本地命中、外部取回、重算），调度器其余读点按段列表求和适配。
3. 三股流。远端取回与本地取回走传输引擎的两组队列，重算段进 prefill 批，三股流按块掩码对齐；prefill 只算未取回范围，attention 的 slot mapping 跳过已 resident 的块。块掩码在调度器、传输引擎、model_runner 三处用同一份，掩码版本随请求走；传输完成更新掩码，prefill 按掩码跳段，两处读到的掩码不一致时以调度器版本为准并记事件。
4. 失败回退。复用 _update_requests_with_invalid_blocks 现成的失败块回退路径，按块改重算；期限错过时保留已取回部分，只重算未取回范围，已取回的块不白付。
5. 一键回退。补丁带开关，关闭后调度器回到连续前缀语义，主干验收复跑。
6. 对照验收。同一轨迹对主干整请求决策，跨层分布与期限边缘两类负载单独构造轨迹、单独出结论，报 TTFT P50 与 P99、取回字节数、重算 token 数。这两类是混合执行的收益来源，其余负载档收益接近零时照实报。

过关标准：原有调度测试集补丁后全绿，或失败项有记录与修复；两类收益负载档的收益有数；回退后主干语义与验收不受影响。

红灯处理：回归面修不动，整项标未做，主干不受影响；收益接近零，标不采纳。

常见坑：num_computed_tokens 的单整数语义改分段后，调度器其它读点漏改，记账错乱；块掩码与 slot mapping 对不齐，attention 读到未 resident 的块。

## 步骤 13：交付与诚实清单（指南第 18、19 节）

交付物：薄网关；决策与索引服务；传输引擎（RDMA 与 TCP 双路径）；重叠执行与 connector 挂载配置、非核心钩子；最小块存储；侧枝核心补丁（一键回退，未做标未做）；标定工具与按机器版本的四张代价表；k8s manifests 与一条命令拉起；benchmark 装置与六组对照报告；现勘报告（现状矩阵、拓扑结论、源码核实表、补丁回归记录）。

诚实清单逐条写进报告，按指南第 18 节十四条：推算值不进收益结论；rxe 带宽数字不进结论与简历；单机与双机只做机制验证；突发到达时期限估计失真，该区间退回重算；干扰表换机型重测；GPUDirect 与 GDS 依赖拓扑与驱动；侧枝收益可能接近零；补丁回归风险是侧枝主要成本；存储是最小实现；副本故障在飞请求重算，迁移收益账未测；漂移窗口内无取回收益；1% 开销闸门是目标值；CUDA 与 PyTorch 停留在使用层；块大小与哈希口径跟随引擎配置。

报告按组分节，每节四件：配置与表版本、收益数字与区间、决策分布与误差、该档结论。侧枝两组单独成节，未做项标未做。诚实清单与现勘报告随附，第三方复核从现勘报告的源码核实表进，对照部署版本重核。

过关标准：交付物清单逐项有着落，未做项标未做；诚实清单随报告入库；第三方拿报告与一条命令能复现任一组数字。

交付核对按清单逐项演示，每项留命令与输出，演示记录随交付物入库：

1. 网关接入与摘除改路。
2. 决策三类退回。
3. 传输双路径与期限撤读。
4. 重叠的 profiler 记录。
5. 存储对账与节点故障。
6. 平台一条命令与三类演练。
7. benchmark 一键复现。

## 顺序锚点与砍项顺序

顺序锚点：

1. 步骤 0 与 1 是闸门，任何一步红灯都先修，不带病写实现。
2. 步骤 2 的表是决策与传输的输入，表不齐不写决策算术。
3. 步骤 3 到 6 完成后能演示「请求进、决策出、取回与计算重叠」。
4. 步骤 7 是主干闸门，不过不进租机窗口。
5. 步骤 8 补齐 RDMA 与双机，产品有 RDMA 与 TCP 两套口径。
6. 步骤 9 与 10 补齐后才是可部署、数字可复现的产品。
7. 步骤 11 与 12 是侧枝，主干验收通过后开工，先层间流水后块粒度混合。
8. 步骤 13 收口，交付物与诚实清单入库。

砍项顺序从后往前，与指南第 14 节一致：

1. 先砍侧枝两项。
2. 再砍故障演练自动化与远端层，保留本地 DRAM 与 NVMe。
3. 再砍 RDMA 实测，TCP 单路径交付，RDMA 数字标未测。

决策、传输、重叠、存储、部署五件不动，它们是产品与玩具的分界线。
