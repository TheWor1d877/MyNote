# 工程化与协作面试题库（修订版）

覆盖版本管理、评审测试、CI/CD、文档文化与开源贡献的面试题，共 30 题，标注 ★ 的为面试必会 P0 题。

## 版本管理与协作流程

1. 解释 Git 的分支模型，以及 trunk-based development 与 Git Flow 的取舍。
2. 什么是 rebase 与 merge？在多人协作的 Infra 项目中如何选择。

## 代码评审与测试

★3. 解释代码评审的核心关注点，哪些问题应该在评审中拦住，哪些应该留给测试。
★4. 什么是测试金字塔？单元测试、集成测试、端到端测试在 AI Infra 中如何分配。
5. 解释 mock 与 fake 的区别，在测试 K8s 控制器时如何选择。
★6. 什么是表驱动测试？Go 中如何用它覆盖调度器或网关的边界条件。
7. 解释竞态检测与压力测试在 CI 中的位置。
8. 什么是 flaky test？在分布式系统测试中如何治理。

## CI/CD 与制品管理

9. 解释 CI/CD 流水线的关键阶段，以及如何为 GPU 相关代码设计 CI。
10. 什么是制品仓库？容器镜像与模型文件分别如何做版本管理。
11. 解释语义化版本与 API 兼容性，在 Operator 与 CRD 演进中如何落地。
12. 什么是 feature flag？如何在推理网关中安全地灰度新路由策略。

## 文档与运行文化

13. 解释设计文档的结构：背景、目标、非目标、方案、取舍、风险、迁移。
14. 什么是 RFC 流程？开源 Infra 项目中 RFC 如何推动架构演进。
15. 解释故障复盘的文化与结构，如何区分根因与触发条件。
16. 什么是 on-call？AI Infra 值班时最常遇到的告警类型有哪些。
17. 解释 runbook 的价值，如何为推理服务与训练任务编写可执行手册。

## 开源贡献

★18. 什么是开源贡献路径？如何从 good first issue 走到核心模块 patch。
★19. 解释如何定位一个开源项目的 issue，并提交可被接受的 PR。
20. 解释 DCO sign-off 的含义与 Signed-off-by 的作用，以及一个规范的开源 PR 从分支提交、DCO 签名、CI 通过到 review 礼仪的完整工程流程。
★21. 一份高质量的 issue 应该包含哪些要素？为什么精确复现步骤、已排查项与环境信息是其中的关键。

## 思考与取舍题

23. flaky test "重跑通过"为什么是技术债而非解决了问题？辩论一下：容忍 1% 的 flaky 率换取发布速度，这笔账在 AI Infra 项目里应该怎么算。
24. 测试金字塔在没有常驻 GPU 的 CI 里会怎么变形？哪几层会被迫上移或下移，代价转移到了哪里？
25. 被遗忘的 feature flag 会让路由矩阵爆炸：估算 10 个残存 flag、每个 3 个状态的组合空间有多大，并辩论 flag 该不该有强制到期日。
26. RFC 流程过慢会把创新闷死，过快又会让架构失控：设计一条"什么样的改动必须走 RFC"的分界线，并说明它如何保护小改动快速前进。
27. 现象诊断：CI 的偶发失败集中在每天固定时段。候选原因：(a) 共享 GPU runner 被其他团队的定时任务抢占；(b) 依赖镜像的 latest tag 被覆盖；(c) 时段性网络抖动拖慢制品拉取。请排序并给出最小验证步骤。
28. 反直觉追问：评审意见越多代码质量越高吗？当评审延迟迫使开发者绕过流程时，这条正相关的链条会在哪里断掉？
29. 取舍辩论：实验性 notebook 与一次性脚本要不要进主干？为"实验代码进主干的资格"设定一条你自己的红线。
30. 量级估算：一个 5 人团队每周 20 个 PR、每个 PR 需要 2 个 approval、平均评审等待 24 小时：估算这套流程的吞吐上限，并用这个数字辩论"加人、加自动化还是减流程"。
