# 项目考察 · P2 Pact（19）

## C. P2 Pact：推理服务契约层、显存调度与副本容错（1–70）

### C0 七问（1–7）

1. ★【数字】⏳ 一句话讲清 Pact 卖什么：条款、四段归因、结算单、固定算力下的达标产出、副本故障下的可用性保障。四个数字要背下来：8B GQA 每 token 的 KV 是 128 KiB，30K 上下文占 3.8 GiB，80 GB 卡放得下约十五个请求，产出率的分母取配置的 KV 池容量。面试官只记住「十五个并发」时，你怎么用违约率、误拒率、赔付额、达标 token 产出率、故障窗口违约次数五个数把它接到合同、算力、可靠性三边？
2. ★【对标】Scorpio 做了预测器加 TTFT 与 TPOT 守卫，Cascade 做了请求级延迟预算，LLMVisor 做了请求级归因。你只做哪一段？被追问「预测和归因都是论文」时，五条自研证据是什么（契约与结算、引擎打点与批次快照、显存调度三处排序、副本容错的慢副本判定与硬件归因、证据包与回放）？
3. ★【复现】⏳ 面试官拿到仓库，半小时内能跑到哪一步？没有合同流量的环境里，最小复现集是什么：合成合同、固定请求轨迹、一条违约事件的证据包回放、一组显存调度前后对照、一次杀副本的摘除与改路记录，五件够不够？
4. ★【失败】⏳ 打点的全量、采样、关闭三种状态各在什么条件下触发？关闭后归因精度掉多少，你怎么证明降级后的结算数字仍然可用？调度策略退回上游默认的三种触发条件与打点降级是不是同一套开关？三条副本健康信号缺一路时容错怎么降级运行？
5. ★【上难度】⏳ 你主动制造过哪些违约：冷缓存、突发到达、长上下文、抢占重算、换出等待、副本缩容、杀副本进程、网络分区、锁频慢副本、冷启动失败。哪一件让归因残差最大，残差落在哪一段？哪一件让误杀次数最多？
6. ★【天花板】⏳ 预测的理论上限是什么（已知输出长度，且知道 batch 组成时）？输出长度未知时，误差下界由什么决定？处置在完美预测下的收益上限怎么算？显存调度在完美预测下的产出率上限又由什么决定，是 KV 池容量还是带宽？容错在完美检测下的收益上限由什么决定，是检测延迟还是冷启动时长？
7. ★【复盘】如果只写一篇复盘，题目是什么？冲突点、证据链、你承认的判断错误分别是什么？为什么这篇比「我实现了一个 SLO 预测器」更值得写？

### C1 定位、现状与核实（8–12）

8. ★【现状】现状矩阵七行：违约预测、请求级预算、延迟归因、合同与结算、请求级 trace、显存调度、副本容错。逐行说清上游做到哪一步、你接哪一步。凭什么认定「合同与结算」没有公开产品，你用什么方法核实的？显存调度与副本容错两行的上游现状各核实到哪个版本与哪几处代码位置？编排侧已有的健康检查加重启策略，与你的慢副本判定差在哪？
9. ★【止损】你既做契约层又做显存调度还做副本容错，三者的边界在哪？调度论文已经有预测器、预算、公平性三类，你的增量是合同剩余期限进入让位、前缀、chunk 三处排序，凭什么认定上游没做这件事？容错这一段的增量是慢副本判定、误杀门槛与硬件归因，编排侧的健康检查为什么不够？如果核实发现某云厂商已经在卖带赔付的推理服务，你退到哪一步，退到之后还剩下什么可讲？
10. ★ 合同模板八项：适用模型、SLO 分位、统计窗口、最小样本量、赔付公式、允许的降级档位、可用性条款、故障责任分档系数。哪一项最容易在真实采购里引起争议？故障责任分档凭什么把硬件故障与运行态违约分开折算，租户不认这个分档时你拿什么举证？赔付公式的单窗口上限怎么定，定高了平台赔不起，定低了租户不签？
11. ★ 四类用户的使用路径：平台运维、租户、采购与财务、模型与算法。运维面板和财务面板看到的东西差在哪？同一份数据给两类人看，口径需要变吗？产出率为什么只给运维看、不进结算单？误杀次数给谁看，租户能不能查到自己的请求是被哪一次摘除影响的？
12. ★【对标】私有化部署的采购合同里，延迟条款与可用性条款通常怎么写？你的模板和真实合同差多少？如果面试官说「这就是把监控包装成合同」，你用什么证据反驳？

### C2 基座：网关、负载台、计量（13–18）

13. ★ 网关做六件事：鉴权、配额、request id 注入、拒绝响应、路由、摘除执行。SSE 断连为什么要通知引擎取消？不取消时，一次断连浪费多少 token 与 KV 位，这个浪费怎么观测？摘除的判定为什么放在处置器而不放在网关，判定与执行合在一处会出什么问题？
14. ★ request id 怎么贯通网关与引擎？引擎不认外部 id 时，你用哪一层做映射？映射表丢了以后，证据包还能不能复原一次违约？改路重算的请求带原 request id 与重算标记，流水表里算一行还是两行，两种记法各会让对账差在哪？
15. ★ 负载台的参数维度：前缀共享比例、输入输出长度分布、突发形状、租户数量、缓存冷热、KV 池容量、副本数、故障注入类型与时刻。两组实验怎么保证吃同一份轨迹且池容量与副本数相同？客户端自身饱和时，什么信号判废？九档负载形状为什么要各出各的结论，合并成总均值会掩盖什么？四类故障注入各考哪一段恢复耗时？
16. ★ 计量四条口径：token 取引擎 usage、命中是否计费、拒绝计零、断连按已生成计。缓存命中计费两种约定各会改变租户什么行为？你实测的差异有多大？摘除后改路重算的那部分 token 计不计费、计不计违约，合同里怎么写？
17. ★ 流水表与指标库共用 request id，两边数字不一致时以谁为准？回查路径怎么走？你遇到过对不上的情况吗，原因是什么？达标判定为什么要只写一处，结算、校准、产出率三处各算各的会出什么事？
18. ★【复用】为什么不自建计费系统、不自建网关、不自建指标存储、不自建节点级故障维修？四者的复用边界在哪？哪一段一旦复用就会丢掉你的核心能力？引擎调度器你改了而不是复用，改的那三处为什么不能靠配置项解决？编排侧的探针与重启策略你复用了，自己加的是哪一层？

### C3 引擎侧打点（19–28）

19. ★【为什么不够】引擎给出的三类指标：TTFT 直方图、队列长度、KV 占用。逐条给一个它答不了的问题：一次违约追到租户、TPOT 波动的解释、chunked prefill 下 prefill 的终点。三条缺口为什么都指向请求级时序记录？显存调度还要第四类记录，聚合的抢占计数答不了什么问题？慢副本判定要用批次快照做第几种用途？
20. ★ 五个打点位置：入队、出队、每个 prefill 块结束、首 token、结束或取消。漏掉「出队」会怎样？漏掉块边界、漏掉首 token 各会怎样？哪一个是三个都漏时最先暴露的？
21. ★ 九项记录里哪四项最难拿：重算 token 数、命中 token 数、换出与换入耗时、KV 块占用峰值。各需要读引擎的哪个结构？读不到时你用什么替代，误差朝哪个方向？
22. ★ 批次快照每步一条且全量记录，请求级 trace 按 1/32 采样。两者采样率为什么不同？把快照也降到 1/32 会让哪三个结论失真（多租户归因、让位复核、慢副本判定）？违约请求全量、正常请求采样，这个策略会不会漏掉一次违约，漏了怎么办？
23. ★ 开销怎么测到 1% 以内：200 字节一条、每请求五到八条、环形缓冲、独立线程落盘。开关前后对照要锁哪些变量？超过 1% 时你的降级顺序是什么，先降采样率还是先关字段？批次快照全量记录后缓冲区容量怎么重算？副本健康信号的采集周期与打点开销是不是同一笔账？
24. ★ CUDA Graph 的捕获区为什么不能打点？Graph 外记 step 时刻，请求级时刻按 step 归属推算，这一步误差有多大？误差与 TPOT 50ms 条款同量级时你改用什么口径？异步执行下首 token 的主机时刻与 GPU 时刻差多少，你怎么测出来的？step 时间分布用于慢副本判定时，这个推算误差会不会把正常副本判成慢的？
25. ★ chunked prefill 下一个请求有多段 prefill，归因时怎么加总？段间让给 decode 的时间算谁的？如果不让，长请求的 prefill 占比会被高估多少？
26. ★ 抢占重算与换出换入怎么记：每次重算的 token 数、重算次数、换出与换入的 token 数与耗时。重复 prefill token 占比怎么算？换出到换入之间的等待归哪一段，换回后的重新 prefill 归哪一段？两项合并会掩盖什么？摘除后改路的重算与抢占重算在流水表里怎么区分？
27. ★ 打点完整性怎么对账：网关请求计数与 trace 条数，缺失率目标 0.1% 以内；批次快照条数与调度步数；显存事件与引擎侧抢占计数；副本健康事件与摘除、回插动作。丢了怎么补，补不了怎么在结算里标注？如果缺失集中在某一类请求上，结论会怎么偏？摘掉一个副本却没有改路记录，说明哪一段出了问题？
28. ★ 五组标定表各扫哪些档：TPOT 与 batch token 数（含混批四档 chunk）、prefill 每 token 时间、排队时间直接测、换出与换入带宽四个块大小、冷启动四段。哪一组换机型就要重测？冷启动那组为什么权重加载要扫对象存储与本地盘两个来源，前缀重建要按共享前缀比例分三档？

### C4 预测与校准（29–34）

29. ★ 预测输出是概率加区间，不是布尔。为什么布尔判定在处置阶段会放大错误？概率低于阈值就拒绝，阈值定错时误拒率会怎么变？
30. ★ 预测四步：排队、prefill、decode、汇总。哪一步误差最大？排队时间直接测，为什么预测器里还要建模前瞻？两者的口径怎么一致？decode 查表时纯 decode 批与混批为什么要分两张表，查错表误差朝哪个方向？
31. ★ 输出长度未知怎么处理：首 token 前用同类请求的历史分布，首 token 后按已生成数与衰减更新。切换点定在首 token 是否合理？切换前后的预测值不连续时怎么办？显存调度为什么在这一段不用预测值排序？
32. ★ 校准怎么做：按预测概率分桶，比较桶内实际达标率，画可靠性曲线，报 Brier 分数。未通过校准的概率为什么不进处置、也不进让位排序？校准窗口与合同窗口一致的理由是什么，不一致会怎样？
33. ★ 漂移检测用什么统计量？特征分布与基线比较，超阈值告警并暂停自动处置。暂停的是哪三类动作，副本摘除为什么不随漂移暂停？暂停期间违约继续发生，这个代价怎么算？恢复自动处置的条件是什么？显存调度同步退回默认，退回期间的收益怎么计？
34. ★ 四条失效条件：突发到达、缓存全冷、版本切换、副本摘除与回插期间队列突变。各给一个可复现实验，并说明预测误差在这四种情况下各偏大多少。副本被摘除时在飞请求的概率归零、改路后重算一次，重算后的预测用新副本的哪些特征？

### C5 处置（35–39）

35. ★ 五类动作：准入拒绝、降级、扩容、路由、摘除与替换。各自的触发条件是什么，哪几类按概率触发、哪一类按健康信号触发？哪一类动作会改变输出质量，合同里怎么预先约定？降级档位与质量损失的折算系数从哪来？
36. ★ 代价表四项折算成同一单位：拒绝的业务损失、降级的质量折损、扩容的单位成本乘以预热时长、摘除与替换的重算算力成本加冷启动机时。折算系数怎么定？系数错了会偏向哪一类动作？误杀时白付的那一次冷启动为什么必须单列进代价？
37. ★ 误拒率为什么是本方案的主要成本？被拒绝但本可按时完成的请求怎么判定？用配对轨迹取对照组实测完成时间，对照组也拒绝了同一请求时怎么办？两侧轨迹的到达时刻锁得住吗，锁不住时这个判定还成立吗？误杀次数的判定与它同构在哪一步、不同在哪一步？
38. ★ 扩容触发时点按预热耗时与预测窗口的交叉点定。预热四段各占多久，哪一段能到秒级、哪一段不能？预热耗时估错时，扩容会提前还是滞后，各造成什么后果？池占用长期低于阈值的副本为什么不触发扩容？摘除与扩容共用预热耗时表，两个动作之间的互锁防的是什么振荡？
39. ★ 迟滞与冷却按动作分别设。振荡怎么观测——动作在窗口内来回触发的次数？振荡时违约率与成本各怎么变？处置与显存调度同时动作时，怎么分清是哪一层带来的收益？摘除、扩容、显存调度三者同时动作时呢？

### C6 归因与举证（40–45）

40. ★ 四段拆分：排队、prefill 含重算、decode、客户端与网络。交叉部分怎么归属？换出等待算排队、换回后重算算 prefill，这个切分理由是什么？残差多大算可接受，残差为负时说明什么？
41. ★ decode 段的硬件子项两条判据是什么，为什么必须两条同时成立？只满足 step 时间偏离那一条时怎么标，偏离留在哪里解释？降频造成的变慢与批次组成造成的变慢怎么分开？硬件信号在容器里读不到时，这一子项还剩多少解释力？
42. ★ 打点归因与模型估计在同一批请求上对照，误差怎么报？模型估计在哪些情况下反而更准？两套结果不一致时，结算用哪一套？
43. ★ 证据包七件：事件编号、请求 trace、副本指标快照、批次组成、显存事件序列、副本健康与硬件信号快照、条款版本。缺哪一件会让举证失效？显存事件序列缺了以后让位选择的争议还能不能复核，硬件信号快照缺了以后故障责任分档还能不能判？证据包怎么防篡改，租户怎么自行复核？
44. ★ 多租户归因回答「由谁造成」：依据是同时段批次快照与各租户请求占比。两个租户同时超标时怎么分摊？分摊规则写在哪里，租户不认时怎么办？如果这次违约是平台摘除了一个副本造成的，多租户归因还成立吗？
45. ★ 回放要一致：同一份轨迹重跑，比较处置决策、让位选择与摘除决策。哪些因素锁不住（到达时刻、batch 组成、GPU 频率、PCIe 带宽、故障注入时刻）？锁不住时你怎么判断「差异属于噪声」而不是「逻辑错」？锁频注入本身改变了 GPU 频率，这一条怎么与回放的不确定性区分？

### C7 结算与对账（46–49）

46. ★ 四项数字：达标率、违约次数、赔付金额、归因占比。各怎么算？样本量不足门槛时默认沿用上一窗口，这个默认条款合理吗，租户会不会因此吃亏？被拒绝的请求进不进达标率分母，两种取法各会让平台有什么动机？
47. ★ 赔付公式可配置加单窗口上限，怎么防刷——租户故意制造违约来索赔怎么办？平台侧怎么区分「自身违约」「租户请求形状导致的违约」「平台侧硬件故障」三类？故障责任分档的两档系数为什么属于合同模板而不属于技术判定，「法律效力未经核实」这句话在面试里怎么说才不减分？
48. ★ 对账差异五个来源：断连、重试、摘除后改路重算、命中计费口径、窗口边界。逐个说定位方法。差异超过阈值冻结出账，冻结期间租户投诉怎么处理？改路重算的请求在流水表里记一行还是两行，两种记法各会让对账差在哪？
49. ★ 条款版本变更后，跨版本窗口怎么结算？按请求发生时刻对应的版本计算，这个规则的边界情况有哪些（窗口中途变更、追溯生效、版本回滚）？显存事件里存的版本号与结算用的版本不一致时以谁为准？摘除记录里的分档系数版本与归因记录里的不一致时呢？

### C8 显存调度（50–57）

50. ★【口径】⏳ 达标 token 产出率的分子分母各是什么？分母为什么取配置的 KV 池容量而不是实测占用峰值？平台把池子配小，指标会怎么变？分子为什么排除违约请求与被拒绝请求，排除之后靠什么防止平台多拒绝？多副本时分母怎么取，摘除期间为什么该副本的容量要留在分母里？

### C9 副本容错与分布式（58–65）

61. ★【恢复】⏳ 冷启动四段各是什么，哪几段能到秒级、哪一段不能？权重 16 GB 从对象存储 10 GB/s 与本地 NVMe 3 GB/s 各多久？前缀缓存重建靠什么回到稳态，共享前缀比例高时要多少个请求？为什么「进程就绪」与「热态稳态」必须分开报，合并报会被追问什么？回插时直接给全量流量会引发什么连锁？
62. ★【改路】⏳ 在飞请求为什么默认重算而不迁移 KV？重算代价式子与让位选择共用哪张表？R 个副本时一个副本挂掉损失多少流量，改路后其余副本的池占用与 TPOT 怎么变，会不会引发连锁违约？迁移与重算的差值由哪一层给出实测数？

64. ★【漂移与故障】漂移暂停自动处置期间来了一个硬件故障，摘除动作为什么不暂停？如果一起暂停会出什么事？反过来，硬件信号误报导致连续摘除，会不会被漂移检测当成特征漂移而暂停处置，两个机制怎么互锁？
65. ★【边界】⏳ 这套容错在什么情况下没用：副本数为 1、硬件信号读不到、负载低到 step 时间分布没有统计意义、故障成因是全局的（机房温度、上游存储、交换机）。四条各给一个可复现实验。跨机故障与真实网络分区未覆盖，被问「你这套能撑千卡吗」时怎么答？

### C10 上难度与复盘（66–70）

66. ★【上难度】⏳ 预测器在突发下全错，处置会不会放大问题——错误拒绝把流量推给别的副本，引发连锁？显存调度同时按错误的剩余期限排序，会不会把快完成的请求换出去？慢副本判定同时把接流量最多的副本误杀，三件事叠在一起怎么防护：阈值随置信度变化、连续错误自动退出、三层动作互锁？
