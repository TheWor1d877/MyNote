# 项目考察 · P2 Pact（19）

## C. P2 Pact：推理服务契约层（1–52）

### C0 七问（1–7）

1. ★【数字】⏳ 一句话讲清 Pact 卖什么：条款、四段归因、结算单。三个数字要背下来：8B GQA 每 token 的 KV 是 128 KiB，30K 上下文占 3.8 GiB，80 GB 卡放得下约十五个请求。面试官只记住「十五个并发」时，你怎么用违约率、误拒率、赔付额三个数把它接到合同上？
2. ★【对标】Scorpio 做了预测器加 TTFT 与 TPOT 守卫，Cascade 做了请求级延迟预算，LLMVisor 做了请求级归因。你只做哪一段？被追问「预测和归因都是论文」时，三条自研证据是什么（契约与结算、引擎打点与批次快照、证据包与回放）？
3. ★【复现】⏳ 面试官拿到仓库，半小时内能跑到哪一步？没有合同流量的环境里，最小复现集是什么：合成合同、固定请求轨迹、一条违约事件的证据包回放，三件够不够？
4. ★【失败】⏳ 打点的全量、采样、关闭三种状态各在什么条件下触发？关闭后归因精度掉多少，你怎么证明降级后的结算数字仍然可用？
5. ★【上难度】⏳ 你主动制造过哪些违约：冷缓存、突发到达、长上下文、抢占重算、副本缩容。哪一件让归因残差最大，残差落在哪一段？
6. ★【天花板】⏳ 预测的理论上限是什么（已知输出长度，且知道 batch 组成时）？输出长度未知时，误差下界由什么决定？处置在完美预测下的收益上限又是什么，这个上限怎么算出来？
7. ★【复盘】如果只写一篇复盘，题目是什么？冲突点、证据链、你承认的判断错误分别是什么？为什么这篇比「我实现了一个 SLO 预测器」更值得写？

### C1 定位、现状与核实（8–12）

8. ★【现状】现状矩阵五行：违约预测、请求级预算、延迟归因、合同与结算、请求级 trace。逐行说清上游做到哪一步、你接哪一步。凭什么认定「合同与结算」没有公开产品，你用什么方法核实的？
9. ★【止损】你选择做契约层，没有选择做更强的调度器。调度论文已经有预测器、预算、公平性三类，你的位置在哪？如果核实发现某云厂商已经在卖带赔付的推理服务，你退到哪一步，退到之后还剩下什么可讲？
10. ★ 合同模板六项：适用模型、SLO 分位、统计窗口、最小样本量、赔付口径、归因口径。哪一项最容易在真实采购里引起争议？赔付公式的单窗口上限怎么定，定高了平台赔不起，定低了租户不签？
11. ★ 四类用户的使用路径：平台运维、租户、采购与财务、模型与算法。运维面板和财务面板看到的东西差在哪？同一份数据给两类人看，口径需要变吗？
12. ★【对标】私有化部署的采购合同里，延迟条款通常怎么写？你的模板和真实合同差多少？如果面试官说「这就是把监控包装成合同」，你用什么证据反驳？

### C2 基座：网关、负载台、计量（13–18）

13. ★ 网关做五件事：鉴权、配额、request id 注入、拒绝响应、路由。SSE 断连为什么要通知引擎取消？不取消时，一次断连浪费多少 token 与 KV 位，这个浪费怎么观测？
14. ★ request id 怎么贯通网关与引擎？引擎不认外部 id 时，你用哪一层做映射？映射表丢了以后，证据包还能不能复原一次违约？
15. ★ 负载台的参数维度：前缀共享比例、输入输出长度分布、突发形状、租户数量、缓存冷热。两组实验怎么保证吃同一份轨迹？客户端自身饱和时，什么信号判废？
16. ★ 计量四条口径：token 取引擎 usage、命中是否计费、拒绝计零、断连按已生成计。缓存命中计费两种约定各会改变租户什么行为？你实测的差异有多大？
17. ★ 流水表与指标库共用 request id，两边数字不一致时以谁为准？回查路径怎么走？你遇到过对不上的情况吗，原因是什么？
18. ★【复用】为什么不自建计费系统、不自建网关、不自建指标存储？三者的复用边界在哪？哪一段一旦复用就会丢掉你的核心能力？

### C3 引擎侧打点（19–27）

19. ★【为什么不够】引擎给出的三类指标：TTFT 直方图、队列长度、KV 占用。逐条给一个它答不了的问题：一次违约追到租户、TPOT 波动的解释、chunked prefill 下 prefill 的终点。三条缺口为什么都指向请求级时序记录？
20. ★ 五个打点位置：入队、出队、每个 prefill 块结束、首 token、结束或取消。漏掉「出队」会怎样？漏掉块边界、漏掉首 token 各会怎样？哪一个是三个都漏时最先暴露的？
21. ★ 八项记录里哪三项最难拿：重算 token 数、命中 token 数、KV 块占用峰值。各需要读引擎的哪个结构？读不到时你用什么替代，误差朝哪个方向？
22. ★ 批次快照每步一条，记请求组成、阶段、token 数、KV 占用、是否抢占。它怎么把 TPOT 波动归因到同批其他请求？正常请求按 1/32 采样，违约请求全量，这个策略会不会漏掉一次违约？漏了怎么办？
23. ★ 开销怎么测到 1% 以内：200 字节一条、每请求五到八条、环形缓冲、独立线程落盘。开关前后对照要锁哪些变量？超过 1% 时你的降级顺序是什么，先降采样率还是先关字段？
24. ★ CUDA Graph 的捕获区为什么不能打点？Graph 外记 step 时刻，请求级时刻按 step 归属推算，这一步误差有多大？异步执行下首 token 的主机时刻与 GPU 时刻差多少，你怎么测出来的？
25. ★ chunked prefill 下一个请求有多段 prefill，归因时怎么加总？段间让给 decode 的时间算谁的？如果不让，长请求的 prefill 占比会被高估多少？
26. ★ 抢占重算怎么记：每次重算的 token 数、重算次数、重算后的 prefill 段。重复 prefill token 占比怎么算？这一项为什么在违约归因里最容易被忽略，忽略后归因结果会偏向哪一段？
27. ★ 打点完整性怎么对账：网关请求计数与 trace 条数，缺失率目标 0.1% 以内。丢了怎么补，补不了怎么在结算里标注？如果缺失集中在某一类请求上，结论会怎么偏？

### C4 预测与校准（28–33）

28. ★ 预测输出是概率加区间，不是布尔。为什么布尔判定在处置阶段会放大错误？概率低于阈值就拒绝，阈值定错时误拒率会怎么变？
29. ★ 预测四步：排队、prefill、decode、汇总。哪一步误差最大？排队时间直接测，为什么预测器里还要建模前瞻？两者的口径怎么对齐？
30. ★ 输出长度未知怎么处理：首 token 前用同类请求的历史分布，首 token 后按已生成数与衰减更新。切换点定在首 token 是否合理？切换前后的预测值不连续时怎么办？
31. ★ 校准怎么做：按预测概率分桶，比较桶内实际达标率，画可靠性曲线，报 Brier 分数。未通过校准的概率为什么不进处置？校准窗口与合同窗口对齐的理由是什么，不对齐会怎样？
32. ★ 漂移检测用什么统计量？特征分布与基线比较，超阈值告警并暂停自动处置。暂停期间违约继续发生，这个代价怎么算？恢复自动处置的条件是什么？
33. ★ 三条失效条件：突发到达、缓存全冷、版本切换。各给一个可复现实验，并说明预测误差在这三种情况下各偏大多少。

### C5 处置（34–38）

34. ★ 四类动作：准入拒绝、降级、扩容、路由。各自的触发条件是什么？哪一类动作会改变输出质量，合同里怎么预先约定？降级档位与质量损失的折算系数从哪来？
35. ★ 代价表三项折算成同一单位：拒绝的业务损失、降级的质量折损、扩容的单位成本乘以预热时长。折算系数怎么定？系数错了会偏向哪一类动作？
36. ★ 误拒率为什么是本方案的主要成本？怎么统计——被拒绝但本可按时完成的请求怎么判定？判定本身要用预测，这不构成循环论证吗？
37. ★ 扩容触发时点按预热耗时与预测窗口的交叉点定。预热包含权重加载与 KV 池初始化，两者各占多久？预热耗时估错时，扩容会提前还是滞后，各造成什么后果？
38. ★ 迟滞与冷却按动作分别设。振荡怎么观测——动作在窗口内来回触发的次数？振荡时违约率与成本各怎么变？

### C6 归因与举证（39–43）

39. ★ 四段拆分：排队、prefill 含重算、decode、客户端与网络。交叉部分怎么归属？残差多大算可接受？残差为负时说明什么？
40. ★ 打点归因与模型估计在同一批请求上对照，误差怎么报？模型估计在哪些情况下反而更准？两套结果不一致时，结算用哪一套？
41. ★ 证据包五件：事件编号、请求 trace、副本指标快照、批次组成、条款版本。缺哪一件会让举证失效？证据包怎么防篡改，租户怎么自行复核？
42. ★ 多租户归因回答「由谁造成」：依据是同时段批次快照与各租户请求占比。两个租户同时超标时怎么分摊？分摊规则写在哪里，租户不认时怎么办？
43. ★ 回放要一致：同一份轨迹重跑，比较处置决策。哪些因素锁不住（到达时刻、batch 组成、GPU 频率）？锁不住时你怎么判断「差异属于噪声」而不是「逻辑错」？

### C7 结算与对账（44–47）

44. ★ 四项数字：达标率、违约次数、赔付金额、归因占比。各怎么算？样本量不足门槛时默认沿用上一窗口，这个默认条款合理吗，租户会不会因此吃亏？
45. ★ 赔付公式可配置加单窗口上限，怎么防刷——租户故意制造违约来索赔怎么办？平台侧怎么区分「自身违约」与「租户请求形状导致的违约」？
46. ★ 对账差异四个来源：断连、重试、命中计费口径、窗口边界。逐个说定位方法。差异超过阈值冻结出账，冻结期间租户投诉怎么处理？
47. ★ 条款版本变更后，跨版本窗口怎么结算？按请求发生时刻对应的版本计算，这个规则的边界情况有哪些（窗口中途变更、追溯生效、版本回滚）？

### C8 上难度与复盘（48–52）

48. ★【上难度】⏳ 预测器在突发下全错，处置会不会放大问题——错误拒绝把流量推给别的副本，引发连锁？你怎么设计防护：阈值随置信度变化、连续错误自动退出？
49. ★【上难度】⏳ 引擎版本升级后打点位置变了，归因怎么迁移？你怎么发现「位置还在但语义变了」？迁移一次的成本记在哪？
50. ★【上难度】⏳ 租户申诉「是你们平台慢」，你拿什么自证？证据包里哪一件最有说服力？如果证据显示违约由另一个租户的流量造成，你怎么向申诉方解释而不泄露对方信息？
51. ★【边界】这套东西在什么负载下没用：低压力时预测无意义，突发时预测滞后，超长上下文时单请求就超预算。三条阴性边界怎么画成图，横纵轴各是什么？
52. ★【复盘】⏳ 你从「做一个更强的调度器」转到「做契约层」，转折的证据是什么？如果面试官说这只是把监控换了个名字，你用什么一张图回答？
