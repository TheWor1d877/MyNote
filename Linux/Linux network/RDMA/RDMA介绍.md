## 分布式训练的通信场景
- 数据并行（Data Parallel）：每个GPU持有模型副本，处理不同数据，每轮需要all_reduce梯度
- 模型并行（Model/Tensor/Pipeline Parallel）：模型被切分到多个GPU，前向/后向传播中需要频繁传递激活值和梯度
- 混合并行：上述两种的组合，通信模式更加复杂

## RDMA
RDMA（Remote Direct Memory Access）的本质，就是让一台机器的网卡直接读写另一台机器的 GPU/内存，全程不经过对方的 CPU 和操作系统。

#### 传统场景
传统网络收发包的时候，应用要发数据，得走系统调用进内核，内核协议栈层层封装，最后交给网卡。
对面收到包之后，网卡中断 CPU，内核一层层解包、拷贝到用户态 buffer——上下文切换、中断，都是开销。

#### RDMA 场景
RDMA绕过了远端CPU与内核的网络协议栈，RDMA 在连接建立、内存注册完成后，网卡直接读/写应用程序内存，远端 CPU 不被中断，内核不被穿越。

网卡是知道对方"内存地址"的。应用先把内存注册给网卡，这样我方网卡就拿到了对方内存的访问权限，以及虚拟地址到物理地址的映射关系。

然后应用直接在用户态把发送指令交给网卡，网卡从内存里取出数据，通过网络发到对面网卡，对方网卡直接写进目标内存——这就是说的内核旁路与零拷贝。

整个过程是单边操作：只有我们这边的 CPU 发一次指令，对面应用甚至不知道数据到了，这就是说的 CPU 卸载。

代价是需要专用硬件与网络，比如 InfiniBand，或者 RoCE。

#### 三大核心特性
- 内核旁路（Kernel Bypass）
传统网络通信需要经过操作系统的内核协议栈，而RDMA通过用户态直接访问网卡硬件，绕过内核。应用层直接调用RDMA verbs（如ibv_post_send）发起传输请求，网卡硬件自行完成数据搬运。
- 零拷贝（Zero-Copy）
数据从源端GPU显存/内存直接传输到目标端GPU显存/内存，中间不经过任何缓冲区和协议栈。CPU完全不参与数据传输，只负责下发指令。
- CPU卸载（CPU Offload）
RDMA网卡（RNIC）内置专用的传输引擎，自行处理可靠性保证、流量控制、拥塞控制等协议逻辑。CPU只需要注册内存区域、发布工作请求，之后就可以去做其他事情。


#### RDMA 在分布式训练与分布式推理中的价值
AllReduce 的本质是每个 rank 都要拿到全局梯度，通信量很大。传统传输中，GPU 需要等待 CPU 发起并搬运梯度的通信请求，这一环节容易成为瓶颈，通信与计算会争抢 CPU 资源。

引入 RDMA 后，梯度可直接从 GPU 显存对应的主机内存发出，或经 GPUDirect 路径直接打出去，延迟低，CPU 占用几乎为零。类似地，大模型 checkpoint 动辄几百 GB，通过 RDMA 写入远端存储，比走内核协议栈快得多，也不会拖累训练进程。

分布式推理同样受益于 RDMA。PD 分离、KV Cache 跨节点传输这类场景数据量大、延迟敏感，走内核协议栈一来一回开销过重。用 RDMA 直接在节点间读写显存/内存，延迟低、CPU 不参与数据面，推理吞吐和尾延迟都能保持稳定。
