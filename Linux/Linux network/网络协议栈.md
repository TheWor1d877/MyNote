## 网络协议栈全景

| 层次 | 职责 | 关键机制 |
|---|---|---|
| 应用层（用户态） | 业务数据 | `read/write`、`send/recv` |
| 套接字与接口层 | socket API | `socket/bind/connect`、epoll/select |
| 传输层 | TCP/UDP | 内核收发缓冲区、乱序重组、流控 |
| 网络层 | IP | 路由、分片/重组、iptables/NAT/包过滤 |
| 数据链路层 | 以太网帧 | MAC 地址、帧处理 |
| 硬件驱动 | 网卡驱动 | DMA、RX/TX Ring、NAPI |
| 硬件 | 网卡 | PHY/MAC |

## 数据表示
```
应用层： data / message
传输层： segment
网络层： packet
链路层： frame
```

## 收发路径
分层是逻辑视图，不是逐层开函数调用。收包在软中断里由 NAPI 一路把 `sk_buff` 往上推；发包则由应用发起、逐层压头部、最后交给驱动 DMA 发出。

### 发送方向

```
应用 send/write/sendto
    ↓
套接字层：拷贝用户数据，定位 socket
    ↓
传输层：
    ├── TCP：申请 sk_buff，填充数据；保留副本用于重传
    └── UDP：申请 sk_buff 直接发出，不保留重传副本
    ↓
网络层：压 IP 头（可能按 MSS 分段）、查路由
    ↓
链路层：压 MAC 头
    ↓
驱动：拿 sk_buff 数据地址做 DMA 映射，交给网卡读取并放到TX Ring缓冲区中发送
    ↓
发送完成 → 驱动释放 sk_buff
```

sk_buff 生命周期（发送）**：传输层申请 → 逐层填充头部 → 驱动 DMA 发送 → 驱动释放。

### 接收方向

```
网卡收到帧
    ↓
网卡 DMA 把数据写入 RX Ring（驱动预分配的内存环）
    ↓
硬中断（极短）：网卡通知 CPU；驱动只调度 NAPI，不做包处理，尽快返回
    ↓
NET_RX_SOFTIRQ 软中断：NAPI 的 poll() 在软中断上下文里批量轮询 RX Ring
    ├── 每次 poll 受 budget 限制，防止霸占 CPU
    ├── 取到的每个包关联/构造成 sk_buff（memcpy 或零拷贝引用 RX Ring 缓冲区）
    └── 可选 GRO：把同流小包合并成大 sk_buff，减少向上递送次数
    ↓
链路层：剥离以太网帧头
    ↓
网络层：剥离 IP 头、路由/过滤
    ↓
传输层 tcp_v4_rcv：
    ├── 按四元组查找 socket
    └── sk_buff 放入 socket 接收队列
    ↓
入队触发 socket 唤醒 → ep_poll_callback → epoll 就绪队列 + 唤醒进程
    ↓
应用被唤醒 / epoll_wait 返回 EPOLLIN
    ↓
read/recv：从 socket 接收队列拷贝到用户缓冲区 → 返回
```

数据先入 socket 接收队列 → 入队触发 epoll 回调标脏就绪列表 → 进程被唤醒 → 进程再调 `read` 拷贝。不是 `read` 去轮询网卡，也不是 epoll 自己收包。

## TCP vs UDP 接收差异

| | TCP | UDP |
|---|---|---|
| 接收缓冲区 | 有，每 socket 独立 | 有接收队列，但无重排、无流控、无拥塞控制 |
| 发送缓冲区 | 有，保留副本用于重传 | 无重传副本，发完即释放 |
| 乱序处理 | 重组、去重、更新接收窗口 | 不重排，按到达顺序交付 |
| 唤醒机制 | 入队触发 epoll 回调 | 同样入队触发 |

## sk_buff
一个描述网络数据包如何在内核中存放与传递的结构体。
sk_buff 本身只是一个“元数据”结构体，它不包含数据包的真实数据。但它通过内部的指针，管理着一块或多块存放真实数据的内存。
真实数据存放在 sk_buff.head 所指向的关联缓冲区里

### 发送方向

1. 用户态经 socket 库调系统接口，数据到达 socket 内核层。
2. socket 层读取用户数据，按协议类型送交传输层。
3. 传输层**申请 sk_buff 并填充数据**，向下传给网络层、链路层，逐层压入 IP 头和 MAC 头。
4. 驱动从 sk_buff 取出 packet data 的虚拟地址，映射成 DMA 总线地址交给网卡，网卡 DMA 读取后发送。
5. 发送完成后，**驱动释放 sk_buff**。

### 接收方向

1. 网卡经 PCIe + DMA 把数据写入驱动预分配的 RX Ring 缓冲区。
2. 驱动在 NAPI 轮询阶段**申请/关联 sk_buff**，把数据挂上去。
3. 放入方式两种：**memcpy** 到 sk_buff 线性区，或**零拷贝**让 sk_buff 直接引用 DMA 缓冲区。
4. sk_buff 向上经链路层、网络层、传输层处理，最终入 socket 接收队列，应用 `read` 时拷贝到用户态。
