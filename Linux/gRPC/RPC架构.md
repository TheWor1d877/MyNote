## RPC使用
1.  Protocol Buffers（protobuf）定义服务和消息格式
2. 使用 protoc 编译 .proto 文件，生成客户端和服务器端的代码
3. 服务端实现自己的逻辑并启动
4. 客户端实现自己的逻辑并且启动

## gRPC 与 OSI 七层模型的对应关系
物理层：gRPC不直接处理
数据链路层： gRPC不直接处理
网络层： 网络层负责数据包的路由选择和转发。gRPC 依赖 TCP/IP 协议栈中的 IP 协议来实现这一层的功能
传输层：  gRPC 中，这一层主要由 TCP 协议实现
会话层：HTTP/2 在这个层次上提供了多路复用、流量控制、首部压缩等功能。gRPC 使用 HTTP/2 来管理多个并发 RPC 调用的会话。
表示层： 在 gRPC 中，表示层的功能由 Protocol Buffers 实现，负责序列化和反序列化消息数据
应用层： 应用层是用户和网络之间的接口。gRPC 的应用层包括客户端和服务器端的应用程序代码，以及 gRPC 框架提供的库和接口，用于定义和调用远程服务。

通过这种方式，gRPC 实现了高效、可靠的远程过程调用，广泛应用于分布式系统和微服务架构中。

## 开发者视角的三层架构
1. Stub层： 直接生成的客户端与服务端代码，提供类型类型安全的接口，这一层实现“跟本地使用也一样的体验”
2. Channel层：对下面Transport层的抽象，核心价值是可以拦截，拦截之后挂载自己的逻辑，在这一层统一处理日志监控认证等问题
3. Transport层： 真正地把字节放到网络线上或从线上拿下来，他的接口实现了即插即用不同的实现(比如 HTTP/2、进程内传输等)
