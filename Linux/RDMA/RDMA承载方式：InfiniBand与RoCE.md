DMA 是一种通信能力：让一台机器的网卡直接读写另一台机器的内存，绕过操作系统协议栈和 CPU 数据拷贝。它本身不绑定某一种网络，具体由谁承载，分为 InfiniBand、RoCE 和 iWARP

|名称|本质|承载介质|
|---|---|---|
|RDMA|远程直接内存访问能力|不绑定单一介质|
|InfiniBand|RDMA 原生实现|专用 HCA、IB 交换机、专用线缆|
|RoCE|在以太网上实现 RDMA|支持 RDMA 的以太网卡、以太网交换机|
|iWARP|在 TCP/IP 上实现 RDMA|标准以太网|
## IB
端到端专用协议栈，链路层到传输层都独立实现，不运行在IP之上
需要专用的HCA(RDMA网卡)与专用交换机

协议路径短，交换机使用16 位 LID(由子网管理器SM分配，子网内16位本地地址) 转发，配合 Cut-Through(直通转发：交换机一种低延迟的转发方式) 转发，延迟较低；

链路层采用 Credit 流控，发送端确认对端有缓存空间后才继续发送，网络本身更容易保持无损
固定头部开销约 40 字节，端到端延迟可做到 0.5～1 μs 量级。
```text
应用 / verbs 接口 
InfiniBand 传输层 
InfiniBand 链路层 
InfiniBand 物理层 / 专用线缆
```
因为 同一子网内通信不需要网络层参与。
数据包只带 LRH + LID，交换机查 LFT 转发表就能转发；只有在跨子网时，才会加上 GRH + GID，由 IB 路由器做三层转发。
LRH：Local Route Header，本地路由头，它固定出现在 IB 报文最前面，长度 8 字节
GRH：Global Route Header，全局路由头，它长度 40 字节，结构类似 IPv6 头部

#### LID/GID/GUID

| 概念       | 作用          | 类比        |
| -------- | ----------- | --------- |
| **LID**  | 子网内转发用的短地址  | 小区里的楼栋门牌号 |
| **GID**  | 跨子网用的全局地址   | 完整邮政地址    |
| **GUID** | 设备端口的硬件唯一标识 | 身份证号      |

## RoCE
RoCE 的核心是把 InfiniBand 的传输层能力放到以太网链路层之上，将 RDMA 数据包封装成以太网可传输的格式
```text
┌─────────────────────────────────────┐ 
│ RDMA 应用 / verbs 接口               │ 
├─────────────────────────────────────┤ 
│ InfiniBand 传输层                    │ 
├─────────────────────────────────────┤ 
│ UDP / IP 头 (RoCEv2)                │ 
│─────────────────────────────────────┤ 
│ 以太网帧头 / 交换机转发                │ 
├─────────────────────────────────────┤ 
│ 普通以太网物理层                       │ 
└─────────────────────────────────────┘
```

#### RoCE中的协议栈

| 概念           | IB 里怎么用               | RoCE 里怎么处理               |
| ------------ | --------------------- | ------------------------ |
| **LID**      | 子网内转发用的短地址，交换机靠它做二层转发 | **不再使用**，由 MAC 地址替代      |
| **GID**      | 跨子网全局标识，格式兼容 IPv6     | **仍然保留**，但通常由对端 IP 推导出来  |
| **GUID**     | 端口硬件唯一标识              | 底层硬件标识，不参与 RoCE 转发       |
| **IP / MAC** | IB 原生不依赖它们            | RoCEv2 完全依赖 IP 路由、MAC 转发 |
#### RoCE v1/v2
版本	        封装方式	                                是否可路由	     现状
RoCEv1	RDMA 直接封装进以太网帧	否，仅二层	     已很少使用
RoCEv2	RDMA 封装进 UDP/IP         	是，可跨三层	 当前主流

###### RoCE v1
RoCEv1 跑在二层以太网上，帧类型是 0x8915
它没有 IB 的 LID，也没有 IP 头。原来 IB 里用 LID 做子网内转发，RoCEv1 直接改成用 以太网 MAC 地址 转发。
帧结构：以太网头（MAC） + IB GRH + IB 传输头 + 数据

###### RoCE v2
RoCEv2 把 IB 的 GRH 替换成 IP + UDP
帧结构：以太网头（MAC） + IP头 + UDP头 + IB 传输头 + 数据
交换机/路由器看 IP 和 MAC：决定数据包走哪条路径、下一跳发给谁。
RDMA 网卡看 GID 和 QP：决定这个包属于哪个 RDMA 连接、交给哪个队列处理。

- 转发过程：
用户给出对端IP -> 网卡推导出对端的GID -> 通过ARP协议获得对端的MAC地址 -> 封装成：以太网头 + IP头 + UDP头 + IB 传输头 -> 交换机按照MAC/IP转发 -> 对端网卡按照GID/QP找到对应的RDMA连接

#### ECN/PFC/MTU
以太网本身不是无损网络，拥塞时可能丢包。而 RDMA 通常假设数据包能够可靠到达，丢包会明显影响性能。
所以 RoCE 需要通过 PFC 和 ECN 构建无损以太网。

ENC用于提前感知拥塞，当交换机队列尚未占满但已经出现拥堵趋势时，会在数据包头部打上拥塞标记。接收方收到后通过 CNP 包通知发送方降速

PFC用于兜底防止丢包，当端口缓冲区即将占满时，向上游发送 Pause 帧，暂停对应优先级流量
```text
发送端 → 交换机 → 接收端 
正常传输：发送端发出数据包 
轻度拥塞：交换机标记 ECN → 接收端回 CNP → 发送端降速 
重度拥塞：交换机发送 PFC Pause → 上游暂停对应优先级流量
```

MTU 表示单个网络包能承载的最大数据量。RoCE 场景常将 MTU 设置为 4096，即启用巨型帧。更大的 MTU 可以减少数据包数量和头部开销，降低分片重组带来的处理负担。

## 特殊情况：丢包处理
RDMA在可靠连接下，通过PSN包序列号来判断是否发生丢包

IB 网络本身通过 Credit 流控尽量不丢包。若真的发生丢包或损坏，接收端检测到 PSN 缺口后，会发送 NAK，发送端从丢失位置重传

RoCE 走以太网，依赖 PFC + ECN 防丢包。一旦丢包，同样通过 NAK 快速触发重传，超时则兜底。但 RoCE 的重传代价很高

## IB与RoCE的硬件差异 
|组件|InfiniBand|RoCE|
|---|---|---|
|网卡|HCA（Host Channel Adapter）|RNIC（RDMA NIC）|
|交换机|IB 交换机（如 NVIDIA Quantum 系列）|支持 PFC/ECN 的以太网交换机（如 Broadcom Tomahawk 芯片）|
|协议|专用 IB 协议栈，不跑 IP|以太网 + UDP/IP|
|无损机制|Credit 流控，硬件原生保证|需配置 PFC + ECN + DCQCN|
|生态|封闭，NVIDIA 主导|开放，多厂商可选|

网卡层面：很多高端网卡是双模的，同一张 Mellanox ConnectX 系列既可以插 IB 端口跑 InfiniBand，也可以插以太网端口跑 RoCE交
换机层面：IB 交换机和以太网交换机是两种完全不同的设备。IB 交换机不认识以太网帧和 IP 包，以太网交换机也不认识 IB 的 LID 和 Credit 流控
