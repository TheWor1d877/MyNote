## podman与docker的网络架构对比
#### Docker:内置网络架构
```TXT
Docker 网络架构：
用户 → docker CLI → dockerd → 内置网络驱动 → 容器
                      ↓
                libnetwork (内置)
```
所有的网络均有dockerd守护进程协调

#### Podman:CNI标准架构
```txt
Podman 网络架构：
用户 → podman CLI → CNI 插件 → 容器
                    ↓
           /etc/cni/net.d/ 配置文件
```
完全遵循CNI标准，支持任何符合CNI规范的插件
每个网络功能由独立的插件实现

## bridge与host模式
#### bridge
```bash
# Docker 默认创建 docker0 网桥
ip link show docker0
# 创建自定义网络
docker network create --driver bridge mynet

# Podman 默认使用 CNI bridge 插件
podman network create mynet
# 配置文件位置：/etc/cni/net.d/mynet.conflist
```
podman使用标准CNI插件支持容器名解析（通过 dnsmasq）
docker使用 libnetwork 库管理网络，内置DNS解析

#### host
```bash
docker run --network host nginx

podman run --network host nginx
```
Docker：需要 dockerd 处理网络命名空间共享
Podman：直接使用主机网络命名空间，路径更短
性能：Podman 在 host 模式下启动更快（减少 IPC 开销）

## IPvlan 与 Macvlan: 容器直连物理网络的两种方法
#### 区别：
Macvlan:基于mac地址的网络虚拟化
每个虚拟接口拥有独立的 MAC 地址
在物理网络中表现为独立的网络设备
容器可以直接获得局域网 IP 地址
```txt
Macvlan 架构：
┌─────────────────┐
│   容器1         │ ← MAC: AA:BB:CC:00:01
│ IP: 192.168.1.101│
└────────┬────────┘
         │
┌────────▼────────┐
│   容器2         │ ← MAC: AA:BB:CC:00:02  
│ IP: 192.168.1.102│
└────────┬────────┘
         │
┌────────▼────────┐
│ 物理网卡 eth0   │ ← MAC: AA:BB:CC:00:00
│ IP: 192.168.1.100│
└────────┬────────┘
         │
┌────────▼────────┐
│   物理交换机    │
└─────────────────┘
```


IPvlan：基于 IP 地址的虚拟化
所有虚拟接口共享同一个 MAC 地址
只分配不同的 IP 地址
更节省网络资源（特别是 MAC 地址表）
```txt
IPvlan 架构：
┌─────────────────┐
│   容器1         │ ← IP: 192.168.1.101
│ 共享 MAC: AA:BB:CC│
└────────┬────────┘
         │
┌────────▼────────┐
│   容器2         │ ← IP: 192.168.1.102
│ 共享 MAC: AA:BB:CC│
└────────┬────────┘
         │
┌────────▼────────┐
│ 物理网卡 eth0   │ ← MAC: AA:BB:CC:00:00
│ IP: 192.168.1.100│
└────────┬────────┘
         │
┌────────▼────────┐
│   物理交换机    │
└─────────────────┘
```

#### Macvlan模式
默认是Bridge模式
最常用的模式，在物理接口上面连接一个交换机，虚拟接口之间可以直接通信
```bash
# Docker 创建 Macvlan 网络
docker network create -d macvlan \
  --subnet=192.168.1.0/24 \
  --gateway=192.168.1.1 \
  -o parent=eth0 \
  macvlan_net

# 运行容器并指定 IP
docker run -d --network macvlan_net --ip=192.168.1.101 nginx

# Podman 创建 Macvlan 网络（需要 CNI 配置）
# 创建 /etc/cni/net.d/macvlan.conf
{
  "cniVersion": "0.3.1",
  "name": "macvlan-conf",
  "type": "macvlan",
  "master": "eth0",
  "mode": "bridge",
  "ipam": {
    "type": "host-local",
    "subnet": "192.168.1.0/24",
    "routes": [{"dst": "0.0.0.0/0"}],
    "gateway": "192.168.1.1"
  }
}
```
局限性：
- MAC 地址限制：交换机的 MAC 地址表有容量限制
- 无线网络不支持：大多数无线 AP 不允许同一物理接口有多个 MAC

#### IPvlan模式
两种工作模式

1. L2 模式（Layer 2）
在同一子网内通信
支持 ARP 协议
容器间可以直接通信（如果配置允许）
2. L3 模式（Layer 3）
支持跨子网路由
不处理 ARP，只处理 IP 层
性能更好，但配置更复杂
需要在外部路由器配置路由规则

```bash
# Docker 创建 IPvlan 网络 (L2 模式)
docker network create -d ipvlan \
  --subnet=192.168.1.0/24 \
  --gateway=192.168.1.1 \
  -o ipvlan_mode=l2 \
  -o parent=eth0 \
  ipvlan_net

# Docker IPvlan L3 模式
docker network create -d ipvlan \
  --subnet=192.168.1.0/24 \
  --subnet=192.168.2.0/24 \
  -o ipvlan_mode=l3 \
  -o parent=eth0 \
  ipvlan_l3_net

# Podman IPvlan CNI 配置
{
  "cniVersion": "0.3.1",
  "name": "ipvlan-conf",
  "type": "ipvlan",
  "master": "eth0",
  "mode": "l2",
  "ipam": {
    "type": "host-local",
    "subnet": "192.168.1.0/24",
    "gateway": "192.168.1.1"
  }
}
```

#### 总结二者对比

| 特性 | Macvlan | IPvlan |
|------|---------|--------|
| MAC 地址 | 每个容器独立 MAC | 所有容器共享 MAC |
| 资源消耗 | 较高（MAC 表压力） | 较低（节省 MAC 资源） |
| 网络兼容性 | 需要支持多 MAC | 兼容性更好 |
| 无线网络 | ❌ 不支持 | ✅ 支持 |
| 配置复杂度 | 中等 | L2: 简单, L3: 复杂 |
| 性能 | 良好 | L3 模式性能更优 |
| 安全隔离 | Private 模式提供隔离 | 依赖 IP 层策略 |
