## Go编译器自动决定变量位置
在 C/C++ 中，你要自己写 malloc() 把变量放堆上，写 free() 释放它。
但在 Go 中，你只管写 x := 10 或 s := &Student{}，Go 编译器会自动判断：这个变量该放栈还是堆？这个判断过程，就叫 逃逸分析（Escape Analysis）。

“逃逸” = 本该在栈上的变量，“逃”到了堆上。

## 什么情况下会发生内存逃逸
| 场景 | 为什么逃逸？ |
|------|-------------|
| 1. 返回局部变量的指针 | 函数结束后，栈帧销毁，但外面还要用这个变量 → 必须放堆 |
| 2. 把变量传给接口（interface{}） | 接口要能装任何类型，必须在堆上统一管理 |
| 3. 在闭包里用到局部变量 | 闭包可能在函数结束后才执行，变量必须活着 → 放堆 |
| 4. 变量太大（比如大数组） | 栈空间小，放不下 → 自动挪到堆 |

## 示例
```go
package main

import (
	"fmt"
)

func getValue() *int {
	x := 114
	return &x
}
func main() {
	p := getValue()
	fmt.Println(*p)
}
```
- 运行
`go build gcflag="m" main.go`
可以看到:
./main.go:8:2: moved to heap: x

- 原因：
Go 不允许你返回指向栈变量的指针并让它失效,它要保证：
   “只要你能访问一个变量，它就一定是有效的。”

## 使用pprof观察堆分配
```go
package main

import (
	"fmt"
	"log"
	"net/http"
	_ "net/http/pprof" // 导入即注册 /debug/pprof 路由
)

func main() {
	// 分配大数组（会逃逸到堆）
	p := [100000000]int{}
	fmt.Println("Allocated 800MB array. Visit http://localhost:6060/debug/pprof/heap")

	// 启动 pprof HTTP 服务器（独立 goroutine）
	go func() {
		log.Println(http.ListenAndServe("localhost:6060", nil))
	}()

	// 阻塞主 goroutine，防止程序退出
	select {}
}
```

```bash
go tool pprof -http=:8081 http://localhost:6060/debug/pprof/heap
```
