反射是程序在运行时动态探查类型和值的功能

编译期间只知道类型是interface{},运行时通过reflect.Typeof() 与 reflect.Valueof() 获取动态信息

## 开销大的原因：
在Go语言中反射的开销很大，原因：
1. 内存分配：每次reflect.Valueof()都会分配堆对象（reflect.Value）
2. 运行期间做类型检查，每次必查表
3. 热路径函数无法被编译器内联，如果在存储节点路径中 每条日志都使用反射，那么QPS就会下降


## 避免反射
编译期间信息优先

原则：能用具体类型，就不用 interface{}；能用泛型，就不用反射

```go
// ❌ 反射方式（慢）
func LogWithReflect(key string, value interface{}) {
    t := reflect.TypeOf(value)
    // ... 根据类型做 switch，拼接字符串
}

// ✅ zap 方式（零反射，零分配）
logger.Info("event",
    zap.Int("user_id", 123),      // 编译期已知类型
    zap.String("action", "login"),
)
```

## 反射的替代方案：泛型
```go
// 泛型版本（无反射）
func Max[T constraints.Ordered](a, b T) T {
    if a > b {
        return a
    }
    return b
}

// 反射版本（慢且不安全）
func MaxReflect(a, b interface{}) interface{} {
    // 需要判断类型、转换、比较...
}
```
