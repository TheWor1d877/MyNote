大多数实际的 Gin 应用都需要数据库。本指南介绍了如何整洁地组织数据库访问、配置连接池，以及应用能保持处理函数可测试性和连接健康的模式。

database/sql 包在内部维护一个连接池。对于生产工作负载，请配置连接池以匹配你的数据库和流量配置。



## 使用示例
```go
package main

import (
  "database/sql"
  "log"
  "net/http"

  "github.com/gin-gonic/gin"
  _ "github.com/lib/pq"
)

func main() {
  db, err := sql.Open("postgres", "host=localhost port=5432 user=app dbname=mydb sslmode=disable")
  if err != nil {
    log.Fatal(err)
  }
  defer db.Close()

  // Verify the connection is alive
  if err := db.Ping(); err != nil {
    log.Fatal(err)
  }

  r := gin.Default()

  r.GET("/users/:id", func(c *gin.Context) {
    var name string
    err := db.QueryRowContext(c.Request.Context(), "SELECT name FROM users WHERE id = $1", c.Param("id")).Scan(&name)
    if err == sql.ErrNoRows {
      c.JSON(http.StatusNotFound, gin.H{"error": "user not found"})
      return
    }
    if err != nil {
      c.JSON(http.StatusInternalServerError, gin.H{"error": "database error"})
      return
    }
    c.JSON(http.StatusOK, gin.H{"name": name})
  })

  r.Run(":8080")
}
```
始终将 c.Request.Context() 传递给数据库调用，以便在客户端断开连接时自动取消查询。


- 安全查询策略：
? 占位符 + 参数列表 → 驱动自动转义，绝不拼接字符串

占位符不能用于表名！

## 数据库连接池
```go
var DB *sqlx.DB


func initDB() {
	dsn := "postgres://postgres@localhost/test??host=/var/run/postgresql"
	db, err := sqlx.Open("postgres", dsn)
	if err != nil {
		panic(err)
	}

	db.SetMaxOpenConns(25)           // Go连接池中总连接数量
	db.SetMaxIdleConns(5)            // 最大空闲连接数量
	db.SetConnMaxLifetime(time.Hour) // 连接最大存活时间（不会重置）
	DB = db
}
```

## 事物处理
| 特性 | 说明 | Go 中的实现要点 |
| :--- | :--- | :--- |
| Atomicity (原子性) | 操作要么全成功，要么全失败 | `tx.Commit()` / `tx.Rollback()` |
| Consistency (一致性) | 数据库从一个有效状态到另一个 | 业务逻辑 + 数据库约束共同保证 |
| Isolation (隔离性) | 并发事务互不干扰 | 通过 `BEGIN ...` 设置隔离级别 |
| Durability (持久性) | 提交后数据永久保存 | 依赖数据库 WAL 机制 |


```go
// services/transfer.go
import (
    "database/sql"
    "errors"
    "github.com/jmoiron/sqlx"
)

func TransferMoney(db *sqlx.DB, fromID, toID int64, amount float64) error {
    // 1. 开启事务（关键！）
    tx, err := db.Beginx()
    if err != nil {
        return err
    }
    defer func() {
        // 2. 自动回滚（如果未提交）
        if err != nil {
            tx.Rollback()
        }
    }()

    // 3. 查询转出账户余额
    var fromBalance float64
    err = tx.Get(&fromBalance, 
        "SELECT balance FROM accounts WHERE user_id = ? FOR UPDATE", 
        fromID)
    if err != nil {
        return err
    }
    if fromBalance < amount {
        return errors.New("insufficient balance")
    }

    // 4. 查询转入账户（可选 FOR UPDATE）
    var toExists bool
    err = tx.Get(&toExists, 
        "SELECT EXISTS(SELECT 1 FROM accounts WHERE user_id = ?)", 
        toID)
    if err != nil || !toExists {
        return errors.New("recipient account not found")
    }

    // 5. 执行转账
    _, err = tx.Exec(
        "UPDATE accounts SET balance = balance - ? WHERE user_id = ?", 
        amount, fromID)
    if err != nil {
        return err
    }

    _, err = tx.Exec(
        "UPDATE accounts SET balance = balance + ? WHERE user_id = ?", 
        amount, toID)
    if err != nil {
        return err
    }

    // 6. 提交事务（关键！）
    err = tx.Commit()
    return err
}
```
尽量减少事物数量


## 最佳实践
1. 在 main 中初始化数据库连接，并通过闭包、结构体或中间件共享。永远不要每个请求打开一个新连接。
2. 始终使用参数化查询。 将用户输入作为参数传递（$1、?），而不是拼接字符串。这可以防止 SQL 注入。
3. 为生产环境配置连接池。 将 MaxOpenConns、MaxIdleConns 和 ConnMaxLifetime 设置为与数据库服务器限制和预期流量匹配的值。
4. 优雅地处理连接错误。 在启动时调用 db.Ping() 以快速失败。在处理函数中，返回有意义的 HTTP 状态码，避免向客户端泄露内部错误详情。
5. 将请求上下文传递给查询。 使用 c.Request.Context()，以便在客户端断开连接或超时触发时取消长时间运行的查询。
6. 使用 defer 关闭`*sql.Rows`。 未关闭 rows 会导致连接泄漏回连接池。

#### 通过结构体传递数据库实例
```go
// handlers/user.go
type UserHandler struct {
    DB *sql.DB
}

func (h *UserHandler) GetUser(c *gin.Context) {
    var name string
    err := h.DB.QueryRow("SELECT name FROM users WHERE id = ?", 1).Scan(&name)
    if err != nil {
        c.AbortWithError(500, err)
        return
    }
    c.JSON(200, gin.H{"name": name})
}

// main.go
func main() {
    db, err := sql.Open("mysql", "user:pass@tcp(localhost:3306)/test")
    if err != nil {
        log.Fatal(err)
    }
    db.SetMaxOpenConns(25)
    db.SetMaxIdleConns(5)

    userHandler := &UserHandler{DB: db}
    
    r := gin.Default()
    r.GET("/user", userHandler.GetUser)
    r.Run(":8080")
}
```

#### 在查询中传递上下文
将http请求的周期跟数据库查询绑定在一起，客户端断开或者超时 => 自动取消数据库查询
```go
func getUser(c *gin.Context) {
    var user User
    
    // ✅ 关键：使用请求的 Context
    ctx := c.Request.Context()
    
    // 使用 QueryRowContext 而不是 QueryRow
    err := db.QueryRowContext(ctx, "SELECT * FROM huge_table WHERE id = ?", 1).Scan(&user)
    if err != nil {
        if errors.Is(err, context.Canceled) {
            // 客户端主动断开
            c.AbortWithStatusJSON(499, gin.H{"error": "client disconnected"})
            return
        }
        if errors.Is(err, context.DeadlineExceeded) {
            // 超时
            c.AbortWithStatusJSON(504, gin.H{"error": "database timeout"})
            return
        }
        c.AbortWithError(500, err)
        return
    }
    
    c.JSON(200, user)
}
```

MySQL/PostgreSQL 驱动会监听 Context 的 Done() 通道
一旦收到信号，就会发送取消查询命令，释放连接回到go连接池中成为空闲连接

#### 数据库连接防永生设置
`db.SetConnMaxLifetime(time.Hour)`
我们希望连接能定期轮换，以应对数据库故障转移和网络变更。
假设云数据库发生主从切换
某时刻 MySQL 主库故障，VIP 切到从库
- 如果连接是“永生”的：
Go 服务继续用旧连接 → 所有请求失败
- 如果连接有固定寿命：
10 分钟内所有旧连接被淘汰 → 自动连上新主
