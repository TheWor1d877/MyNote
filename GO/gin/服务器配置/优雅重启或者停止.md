#面试-Go语言-复习  什么是优雅关闭？如何让 HTTP server 在滚动更新时不丢请求

## 优雅终止：Shutdown
当服务器进程收到终止信号时（例如在部署或扩缩容事件中），立即关闭会丢弃所有正在进行中的请求，导致客户端连接断开和操作可能损坏。
优雅关闭核心： 不再接受新请求，等待在途请求处理完再推出

先使用`Shutdown(ctx)`方法，让server先关闭监听socket，不再accept新请求
然后它去等在途的请求，包括已经建立连接、正在处理的那些，全都跑完。
直到所有的连接全部等处理完成或者ctx超时，Shutdown才返回
Close() 是立即关掉所有连接，在途请求直接被掐断，这就是丢请求的来源。

## k8s滚动更新不丢请求
滚动更新不丢请求是k8s与进程配合完成的
k8s删除Pod的的时候，两条异步线：
1. 将Pod从Service中的EndPoint摘掉
2. 给容器发送SIGTERM
但是如果SIGTERM先到容器，但是kube-proxy那里的转发规则还没更新完，新请求就依然会打到这个Pod上面，这样就会丢请求

解决办法：这里的标准解法是加一个 preStop hook，sleep 个 5 到 10 秒，让进程先别收到 SIGTERM，给 Endpoints 摘除和各方规则收敛留出时间。
sleep的时间没有标准值，具体取决于集群中摘除流量这个动作的实际速度

## http长连接，WebSocket、流式相应的优雅关闭
如果这个 HTTP server 后面还挂着长连接、WebSocket 或者流式响应，Shutdown 不会主动去关用hijack劫持的连接，他只管还在走的HTTP连接
这些连接都需要自己管理

Shutdown只看header是否返回，如果返回就认为请求完成
但是handler可能有后台异步任务，这些Shutdown管不到
需要单独维护： 你自己得有一个 WaitGroup 或者类似的机制，把这些后台任务登记进去，关闭时先 Wait 它们跑完，再真正退出。

## 需要优雅关闭的程序模板
主Goroutine中跑ListenAndServe
另外起一个Goroutine监控信号，收到SIGINT/SIGterm之后就调用Shutdown，带一个10~30s的context
```go
package main

import (
	"context"
	"errors"
	"log"
	"net/http"
	"os"
	"os/signal"
	"syscall"
	"time"

	"github.com/gin-gonic/gin"
)

func main() {
	r := gin.Default()

	r.GET("/work", func(c *gin.Context) {
		log.Println("开始处理请求...")
		time.Sleep(3 * time.Second) // 模拟耗时操作
		c.JSON(200, gin.H{"message": "工作完成!"})
		log.Println("请求处理完毕")
	})

	srv := &http.Server{
		Addr:    ":8080",
		Handler: r,
	}

	go func() {
		if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
			log.Fatalf("server启动失败: %s\n", err)
		}
	}()

	quit := make(chan os.Signal, 1)
	signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
	log.Println("<-quit")
	<-quit // 阻塞，等待信号 (如 Ctrl+C)
	log.Println("收到关闭信号，正在执行优雅关闭...")

	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()
	if err := srv.Shutdown(ctx); err != nil {
		log.Fatal("服务器强制关闭:", err)
	}
	log.Println("服务器安全退出")
}

```
