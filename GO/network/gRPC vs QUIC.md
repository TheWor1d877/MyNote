“在设计云原生分布式存储系统（如对象存储、块存储）时，节点间通信该用 gRPC（基于 TCP）还是 QUIC（基于 UDP）？”

## 存储系统的特殊性质
高吞吐 ，低延迟，可靠性，多流并发，跨数据中心

## gRPC: 主流选择
使用HTTP2作为传输层
序列化使用Protobuf
四种调用模式
多路复用 允许单个TCP连接上面并发多个stream(避免了队头阻塞)
强类型接口 .proto文件自动生成客户端服务端代码，减少错误
流式支持	完美匹配“上传/下载大文件”的 streaming 场景
TLS 内置	grpc.WithTransportCredentials() 一键启用 mTLS

#### 缺点： 队头阻塞
TCP 是字节流协议，保证顺序交付
如果 packet # 2 丢失 → 即使 packet # 3 # 4 已到达，接收方也不能交给应用层
必须等 # 2 重传成功 → 所有后续数据被阻塞
TCP多路复用也不能解决这个问题，因为本质还是一个TCP连接
 TCP 的可靠性是以牺牲高丢包环境下的性能为代价的。

## QUIC
由 Google 发明，现为 IETF 标准（RFC 9000）
基于 UDP，但内置了 TCP 的所有可靠特性（重传、拥塞控制、加密）
最关键创新：每个 stream 独立可靠 → 一个 stream 丢包，不影响其他 stream

## 选择
跨公网/混合云 QUIC协议
控制面： gRPC
数据面： 使用自定义协议
