 #面试-Go语言-复习 解释 singleflight 的原理，以及它在模型权重加载、缓存回源中的应用

singleflight 是"同一时刻对同一个 key 的重复请求，只让一个真的去执行，其余的原地等结果，然后共享同一份返回值"——说白了就是请求合并 / 去重。

## 核心
它核心就一个 map,key 是你要查的东西（比如某个文件路径、某个 cache key）,value 是一个"正在执行中"的标记，里面挂着一批等待的调用者。

调用进来，先加锁查 map。

如果这个 key 没有正在执行的:把自己标记成"执行者",去真正调用那个函数（比如读文件、查数据库），完事后把结果写回去，唤醒所有等待者，从 map 里删掉这个 key。

如果这个 key 已经有执行者在跑:自己不当执行者，把自己挂到这个 key 的等待列表上，然后阻塞等——执行者拿到结果后，所有等待者共享同一份返回值。

注意： ：返回的如果是 map、slice 这类引用类型，多个调用者拿到同一份，谁改了都影响别人。正确做法是返回不可变数据，或者每个调用者拷贝一份。

## 边界
它只合并同一时刻正在飞行中的请求。第一个请求执行完了，第二个请求再来，会重新执行一遍——它不做缓存,只做合并。

它没有超时机制,如果一个执行者卡死了，所有等待者一起陪葬。所以实际用的时候经常要配合 context 或外层超时。

合并的粒度是 key,key 设计得不好反而会拖慢——比如把太多东西塞进一个 key,合并过头，本该并行的也串了。

## 应用
模型权重加载。 一个大模型可能有几十 GB 的权重文件，多个推理实例、或者同一个实例里多个 worker 几乎同时启动，都要加载同一份权重。如果每个都去磁盘/对象存储读一遍，I/O 直接打满，而且重复占内存。用 singleflight 按"权重文件路径"做 key,第一个 worker 去读，其余的等它读回来，共享同一份内存。省的是磁盘 I/O 和内存。

缓存回源。 这是 singleflight 最经典的用法。缓存击穿场景：某个热点 key 刚过期，一瞬间几百个请求同时发现缓存没了，全部涌向后端数据库。用 singleflight 合并后，只有一个请求真的去查后端,其余等它回来共享结果，数据库压力从几百降到 1。这个在 groupcache 里就是标准套路。
