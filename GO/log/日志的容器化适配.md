在Docker K8S中，情况不一样： 
日志采集链路断裂：
容器运行时（如 Docker）只捕获进程的 stdout 和 stderr，并转发给日志驱动（如 json-file, fluentd, loki）。
→ 如果你直接写文件，这些日志不会被平台收集！

生命周期不一致：
容器可能随时被销毁重建，挂载的卷若未持久化，日志会丢失。

运维复杂度高：
需要额外配置 sidecar 容器或 DaemonSet 来收集文件日志，违背“单一职责”原则。

容器化最佳实践：
所有日志统一输出到 stdout / stderr，由平台负责采集、聚合、存储和查询。

## 如何兼顾轮转的日志与容器环境

通过环境变脸动态切换

func NewLogger() *zap.Logger {
    var output io.Writer

    // 判断是否在容器环境（约定：存在 CONTAINERIZED=1）
    if os.Getenv("CONTAINERIZED") == "1" {
        // 容器模式：输出到 stdout
        output = os.Stdout
    } else {
        // 传统模式：使用 lumberjack 轮转文件
        output = &lumberjack.Logger{
            Filename:   "logs/app.log",
            MaxSize:    100,    // MB
            MaxBackups: 5,
            MaxAge:     28,     // days
            Compress:   true,
