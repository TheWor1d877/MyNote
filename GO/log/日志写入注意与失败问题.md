## 日志写入注意
在流式 RPC（或任何服务端代码）中：
1. 不要用 fmt.Errorf 直接返回错误（除非是 CLI 工具）
2. 必须记录结构化日志（如 zap）
3. 返回给客户端的错误要经过“净化”（隐藏内部细节）
4. 日志级别要分场景（error/warn/debug）


## 日志写入失败
在分布式存储系统中，日志写入失败虽然不常见，但一旦发生，可能意味着更严重的底层故障（如磁盘满、权限错误、文件描述符耗尽等）。zap 本身设计稳健，但其底层依赖操作系统和文件系统，因此仍需我们主动防御。

场景1： 磁盘空间不足
```bash
# 模拟：创建一个 10MB 的小分区（Linux）
2dd if=/dev/zero of=/tmp/small_disk bs=1M count=10
3mkfs.ext4 /tmp/small_disk
4mkdir -p /mnt/small
5sudo mount -o loop /tmp/small_disk /mnt/small
```
