## 为什么需要日志轮转
想象一下：你的分布式存储服务每天产生 10GB 的日志。如果不加管理：
日志文件会无限增长，最终撑爆磁盘；
单个超大文件难以查看、传输或分析；
无法按时间或大小归档历史日志；
系统性能可能因频繁写入大文件而下降。
✅ 日志轮转（Log Rotation） 就是解决这些问题的标准做法：
当当前日志文件达到指定条件（如大小、天数）时，自动将其“归档”（重命名或压缩），并创建一个新的空文件继续写入

## lumberjack
一个日志写入器（io.Writer），不是完整的日志库。
可以和任何日志框架（如 log、zap、logrus）无缝集成。
支持按 大小、备份数量、天数 自动轮转，并可选压缩

```go
&lumberjack.Logger{
    Filename:   "logs/app.log", // 日志文件路径
    MaxSize:    100,            // 单个文件最大 100 MB
    MaxBackups: 5,              // 最多保留 5 个旧文件
    MaxAge:     28,             // 文件最多保留 28 天
    Compress:   true,           // 是否启用 gzip 压缩
}
```
