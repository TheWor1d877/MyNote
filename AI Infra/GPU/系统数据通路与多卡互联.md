## 主机视角下的数据通路
训练数据从存储到GPU显存，走的是一条逐级下降的链路：
```text
分布式存储（Ceph / 本地 NVMe）
        ↓ NFS / RDMA / 本地文件系统
宿主机内存（Page Cache）
        ↓ PCIe（DMA / cudaMemcpy）
GPU 显存（HBM）
        ↓ GPU 内部路径
SM
```

宿主机内存到GPU显存的拷贝走PCIe总线，带宽由PCIe代际和lane数决定,PCIe 4.0 x16的单向有效带宽约31.5 GB/s，5.0 x16约63 GB/s。这是理论峰值，实际DMA传输还要扣除协议开销和竞争

存储到宿主机内存这一段也有开销。小文件随机读会把I/O打碎，顺序读吞吐上不去。RecordIO、TFRecord、Parquet这类打包或列式格式的作用就是把小I/O合并成大块顺序读，让数据在进入PCIe之前就已经是连续的大块。

GDS（GPUDirect Storage）绕过了宿主机内存这一跳。传统路径是NVMe → 宿主机内存 → GPU显存，GDS让NVMe控制器直接通过PCIe将数据DMA到GPU显存，拷贝次数从两次降到一次。代价是需要特定的内核模块和文件系统支持，且并非所有存储后端都兼容。在LLM推理场景中，模型加载插件和KV Cache卸载已经开始使用GDS加速。-3

## NUMA与GPU拓扑
NUMA 的全称是 Non-Uniform Memory Access，中文通常翻译为非统一内存访问

分成多个 NUMA 的核心目的，是在增加核心数量的同时，避免所有核心争抢同一个内存控制器，从而维持较高的内存带宽并控制访问延迟
代价是，如果一个程序的内存访问跨越了 NUMA 节点，就会产生额外的通信开销，速度会比本地访问慢
```text
NUMA Node 0（物理 CPU 0）
├── CPU 核心 0-31
├── 内存控制器
├── 本地内存 512GB  ← 直连 CPU 0 的内存控制器
├── GPU-0, GPU-1
└── PCIe 交换机 A

NUMA Node 1（物理 CPU 1）
├── CPU 核心 32-63
├── 内存控制器
├── 本地内存 512GB  ← 直连 CPU 1 的内存控制器
├── GPU-2, GPU-3
└── PCIe 交换机 B
```
GPU-0 访问 Node 1 内存：跨越 NUMA 互联，延迟增加、带宽下降

## GPU之间的通信
分成PCLe与NVLink两种,带宽差距在一到两个数量级。

走PCIe时，两张GPU之间的数据传输要经过PCIe交换机，可能还要经过CPU和系统内存中转。如果两张卡不在同一个PCIe交换机下，路径更长、带宽更低

走NVLink时，GPU之间有专用直连链路，不经过CPU和PCIe。

NVLink早期只是点对点直连。8张卡两两直连的线数会组合爆炸，所以有了NVSwitch：所有GPU都连到交换芯片上，任意两张卡之间一跳可达，全互联无阻塞

#### 使用NVLink的情况
第一，GPU必须是数据中心级或专业级型号
第二，GPU必须处在同一个NVLink Domain之内，在单机8卡服务器上，这个Domain就是机箱内的8张GPU，通过NVSwitch全互联
第三，调度必须把GPU放在同一个Domain内。 在Kubernetes环境中，即使物理上GPU在同一个NVLink Domain，如果Pod或作业被调度到了Domain外的节点，跨节点NVLink内存访问就不会按预期工作

NVLink能跨NUMA，但是一般不能跨节点

NVLink Switch改变了这个局面：在NVL72这样的机架级系统里，跨节点的GPU可以通过NVSwitch在NVLink上互通，整个机架表现为一个统一的NVLink Domain。但注意机架之间的连接仍然走InfiniBand，机架内部才走NVLink

#### NVLink的速度优势
- 协议栈的轻量化
NVLink只服务于NVIDIA设备之间的通信，两端都是同一家公司的芯片，链路训练可以简化,PCIe是一个通用总线标准，要兼容CPU、网卡、NVMe、GPU等各种设备。

- 拓扑的点对点性质
NVLink是点对点链路，交换芯片内部是一个无阻塞crossbar(只要输出端口空闲，输入端口的数据就能通过，不需要和其他输入端口竞争内部带宽)，任意两端之间的带宽是独占的、可同时并行的。

PCIe是树状总线，GPU之间的P2P通信往往要经过PCIe Switch甚至CPU Root Complex，路径上存在共享和排队。
CPU Root Complex：CPU芯片内部管理PCIe总线的根节点。所有PCIe设备最终都连到某个Root Complex上，由它把PCIe事务转换成CPU能理解的内存访问。
```text
			┌──────────────┐
			│ CPU Root     │
			│ Complex      │
			└──────┬───────┘
				   │ 上行链路（共享）
			┌──────┴───────┐
			│ PCIe Switch  │
			└──┬───┬───┬───┘
			   │   │   │
	  ┌────────┘   │   └────────┐
	  │            │            │
 ┌────┴────┐  ┌────┴────┐  ┌────┴────┐
 │ GPU 0   │  │ GPU 1   │  │ 网卡     │
 └─────────┘  └─────────┘  └─────────┘
```

- 原生内存语义与统一地址空间
PCIe GPU间通信本质上走的是DMA路径
NVLink支持原生的load/store语义，GPU可以直接用指令访问对端GPU的显存，多个GPU共享统一的内存地址空间。
```text
PCIe 路径的抽象层级：
应用 → CUDA API → 驱动 → DMA引擎拷贝到内存 → PCIe事务层 → 交换机 → 对端DMA接收 → 对端DMA拷贝到对端显存

NVLink 路径的抽象层级：
GPU 指令（load/store）→ NVLink 链路 → NVSwitch → 对端显存
```
