一个Warp执行一条Load指令的时候，32个线程各自带着自己的地址。硬件并不把32个地址当成32个独立请求直接发往内存。
它首先把32个地址送进L1的地址合并逻辑，判断这些地址是否落在连续、对齐的区域内
如果32个线程访问的地址可以被合并到少数几个固定大小的内存段里，硬件就只用发出少数几次事务

```text
Warp 内 32 个线程各自的地址
        ↓
LD/ST 单元
        ↓
L1 地址合并逻辑（判断能否合并成少数事务）
        ↓
L1 缓存查找（命中则返回，未命中则向 L2 发起请求）
        ↓
L2 → 显存控制器 → HBM
```
硬件发出的事务数由地址的连续性决定，不由线程数决定

## Coalesced Access(合并访问)
一个Warp有32个线程，每个线程读一个float，总共128字节。如果这32个线程访问的地址是连续、对齐的，硬件会把它们合并成一次内存事务。32个float正好128字节，对齐到128字节边界时，一次事务就能满足。
坏模式的问题不在于线程数多，而在于每个线程的地址落在不同的内存段里。硬件无法把不同段的请求合并成一次事务，只能逐个发起。每次事务传输128字节，但只有4字节是线程真正需要的，其余124字节被浪费。
在AI场景中，batch维度通常放在最外层、连续维度放在内层，就是这个原因：让同一个Warp处理连续样本或连续特征，使32个线程的地址落在连续的内存段内，形成合并访问

## Shared Memory Banking
Shared Memory被划分成多个bank，常见是32个bank
一个Warp的32个线程如果各自访问不同bank，可以一次完成；如果多个线程访问同一个bank的不同地址，就会发生bank conflict，访问被串行化。

- 理想情况（无冲突）：
thread 0 → bank 0
thread 1 → bank 1
...
thread 31 → bank 31
32 个线程各访问不同 bank，一次完成。

- 冲突情况（bank conflict）：
thread 0 → bank 0 地址 A
thread 1 → bank 0 地址 B
thread 2 → bank 0 地址 C
...
最坏情况是32个线程全落在同一个bank的不同地址上，Shared Memory访问退化为32次串行
如果同一个Warp的多个线程访问同一个bank的同一个地址，硬件会做广播，不产生冲突。

## Divergence对访存的影响
如果一个Warp在分支前执行了一条load，32个线程的地址本来是连续合并的，一次事务完成。但如果分支导致Warp发散，每条路径上的活跃线程数不再是32，后续的访存指令只能由该路径上的活跃线程发出，导致带宽利用率下降

如果发散后的地址不再连续，问题更严重。比如路径A的16个线程访问的是跨步地址，硬件需要为这16个线程发起多次事务，每次事务只用到其中一小部分字节

Divergence本身已经让指令发射次数增加，访存模式的破坏又让每次发射的带宽利用率下降，两个效应叠加，有效吞吐可能远低于分支前的水平。

#### 事物粒度不会随着活跃线程数缩小
硬件发起内存事务的时候，事物的大小是固定的，一个完整事务通常是128字节。这个粒度由硬件和协议决定，不会因为当前路径上只有16个活跃线程就自动减半。
```text
分支前：32 线程连续访问
[========== 128 字节事务 ==========]
 32 个线程，32 个有效 float，字节利用率 100%

分支后路径 A：16 线程活跃，地址连续
[========== 128 字节事务 ==========]
 只有 16 个线程，64 字节有效，字节利用率 50%
 另外 64 字节对应被屏蔽的线程，但仍被事务覆盖
```

#### 发散窗口长度决定损失规模
发散不是永久状态，路径执行完后线程会在汇合点重新合并。
损失的大小取决于发散窗口内有多少条访存指令，以及每条指令的有效带宽被压缩到什么程度。
```text
Warp 时间轴：
[ 分支前：32 线程，合并访存，1 次事务 ]
[ 发散窗口开始 ]
  [ 路径 A：16 线程，访存 1 ]
  [ 路径 A：16 线程，访存 2 ]
  [ 路径 B：16 线程，访存 3 ]
  [ 路径 B：16 线程，访存 4 ]
[ 发散窗口结束，重新汇合 ]
[ 汇合后：32 线程，合并访存恢复 ]
```

如果分支体只有一两条算术指令，编译器可能直接用Predication扁平化，Warp根本不发散，没有这个窗口
如果分支体里没有访存指令，发散只影响指令发射次数，不直接破坏访存合并
真正代价大的是发散窗口内包含多次访存的情况：每次访存都在低有效带宽下执行，损失随访存次数累积
