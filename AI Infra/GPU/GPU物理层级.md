GPU芯片内部是一个固定的物理分区树。
从大到小是：GPU芯片 → GPC → TPC → SM → SM内部执行单元与存储资源。
GPC和TPC只是物理组织单元，真正的计算发生在SM内部。
## GPU芯片
```text
┌─────────────────────────────────────────────┐
│                  GPU 芯片                    │
│                                             │
│  ┌─────────┐ ┌─────────┐       ┌─────────┐  │
│  │  GPC 0  │ │  GPC 1  │  ...  │  GPC 6  │  │
│  └─────────┘ └─────────┘       └─────────┘  │
│                                             │
│  ┌───────────────────────────────────────┐  │
│  │  L2 缓存（全GPU共享，80 slice）          │  │
│  └───────────────────────────────────────┘  │
│  ┌──────────┐ ┌──────────┐     ┌────────┐   │
│  │ 显存控制器 │ │ 显存控制器│ ... │ GMMU   │   │
│  └──────────┘ └──────────┘     └────────┘   │
│  ┌───────────────────────────────────────┐  │
│  │  HBM 显存（5 堆栈）                     │  │
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```
芯片级有三类部件：计算分区（GPC）、共享缓存（L2）、访存后端（显存控制器、GMMU、HBM）

## GPC、TPC
```text
GPC（图形处理集群）
 └── TPC 0 ── SM 0
 │         └─ SM 1
 ├── TPC 1 ── SM 2
 │         └─ SM 3
 ├── ...
 └── TPC n ── SM 2n
           └─ SM 2n+1
```
GPC（Graphics Processing Cluster）是GPU芯片内最大的物理分区。
一个GPC下面挂若干TPC（Texture Processing Cluster），每个TPC固定包含两个SM（Streaming Multiprocessor）。

GPC和TPC本身不执行指令，它们的作用是物理分组和片上互连的组织。写kernel的人不需要直接操作GPC或TPC

芯片的伸缩规模本质上就是屏蔽几个TPC

## SM
```text
┌─────────────────────────── SM ───────────────────────────┐
│                                                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │Partition0│  │Partition1│  │Partition2│  │Partition3│  │
│  │          │  │          │  │          │  │          │  │
│  │ Scheduler│  │ Scheduler│  │ Scheduler│  │ Scheduler│  │
│  │ Dispatch │  │ Dispatch │  │ Dispatch │  │ Dispatch │  │
│  │ 执行单元  │  │ 执行单元  │  │ 执行单元  │  │ 执行单元  │  │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘  │
│                                                          │
│  ┌────────────────────────────────────────────────────┐  │
│  │ 寄存器文件 256 KB（4个16K分区，每分区64 KB）            │  │
│  └────────────────────────────────────────────────────┘  │
│  ┌────────────────────────────────────────────────────┐  │
│  │ Shared Memory / L1 共享物理池 192 KB                 │  │
│  └────────────────────────────────────────────────────┘  │
│                                                          │
│  驻留上限：64 warp / SM，32 block / SM                     │
└──────────────────────────────────────────────────────────┘
```
#### SM分区
一个SM内部被划分成四个个物理分区，每个分区有自己的：
- Warp Scheduler
- Dispatch Unit
- L0指令缓存
- 16K寄存器文件分区(四个分区合起来就是64K个32位寄存器，共256KB)

四个分区共享SM级别的L1缓存与Shared Memory，但是调度是按照分区独立进行的
某一个warp只能属于某一个分区，warp并行度也不是整体数字，每个分区都是并行的

#### SM级别资源
寄存器文件：上文说的256KB寄存器文件。每个线程最多使用255个寄存器，但实际分配的时候每个warp都按照256的倍数分配

Shared Memory与L1：A100的SM内部，Shared Memory和L1缓存共享一块192 KB的物理存储，可以通过配置划分给两者的容量。Shared Memory是程序员可控制的片上存储，L1是自动缓存，两者在物理上是同一块存储的不同用途。

驻留容量：A100和H100的每个SM最多同时驻留64个warp和32个block。64个warp就是SM调度器能同时管理的warp上限。

## SM分区内执行单元
```text
一个 Partition（A100 / CC 8.0）
 ├── 16 × FP32 Core
 ├── 16 × INT32 Core
 ├── 8  × FP64 Core
 ├── 8  × LD/ST 单元
 └── 1  × Tensor Core（第三代）
```
FP32/INT32/FP64 Core执行算术指令，LD/ST单元是访存指令的执行端口，Tensor Core执行矩阵指令
LD/ST单元定位在SM内部，不在L2或显存控制器里。
warp的load/store指令由LD/ST单元发出，经片上互连到L1、L2、显存。\

```text
SM 发出访存请求
      ↓
L1（SM内，与Shared共享物理池）
      ↓
L2（全GPU共享，A100 40 MB，80 slice）
      ↓
显存控制器（A100 10个）
      ↓
HBM（A100 5堆栈，带宽约1555 GB/s）
```
