runner = 那台真正执行 steps 的机器。 GitHub Actions 只是调度器，命令都在 runner 上跑。runner 两种

|  | GitHub 托管 | 自托管（你自己机器） |
| --- | --- | --- |
| 机器谁出 | GitHub 的数据中心 | 你 |
| 费用 | 公开仓库的 Linux runner 不计分钟（只有并发上限）；私有仓库按计划每月给固定分钟数，超了付费 | GitHub 不收钱，你出电费和运维 |
| 环境 | 每次全新、干净、规格固定（常见 2 vCPU / 7 GB） | 长期存在，可以预热缓存，也可以脏 |
| 规格 | 高档要付费 | 你机器多强就多强 |
| 风险 | 无 | 它会执行别人 PR 里的代码。公开仓库 + fork PR + 自托管 = 真实攻击面 |
| macOS/Windows | 按倍率扣费额度 | 只能自己有硬件 |

完全可以用自己的机器。 注册流程很轻——仓库设置里新增 runner，下载配置脚本，跟着提示跑一次 config.sh（拿一次性令牌换长期注册），再 run.sh 或用 systemd 常驻。之后工作流里 `runs-on: [self-hosted, 你的标签]` 就会把任务派给这台机器。

但自托管有两个代价，对个人项目常常不划算：

机器要 24 小时可达、掉线时 CI 卡住排队；
状态会跨任务污染：上一次留下的 kind 集群、镜像缓存、临时数据会被下一次读到，跑出"只有那台机器能复现"的结果。
