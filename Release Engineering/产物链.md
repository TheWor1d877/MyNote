## 产物链
交付一个软件是在交付不同层次的东西，具体可以分为下面内容：
源码(必须)： go文件 + go.mod
库： 只能被import的包，
二进制： go build 出来的单个可执行文件
镜像： 二进制 + 一层最小文件系统 + 启动元数据
manifest: 声明跑的镜像，配置的yaml文件
Release: git tag + 说明 + 上述东西的下载链接，这是版本对外的门面

## 镜像
镜像 = 一个只读的文件系统分层快照 + 一段元数据（默认执行哪个命令、以什么用户运行、暴露哪些端口）。它不是一个"打包的二进制"，它是"一个迷你 rootfs + 启动说明书"，运行时的容器只是"在这层文件系统之上挂一层可写层再启动那个进程"。

## manifest中的镜像tag
注册表域名 / 仓库路径 / 名字 : tag。

第三段那个 tag 只是注册表里的一个可变名字，和 git tag 是两个完全独立的命名空间——这是"隐式版本"的意思：
镜像 tag 写成一个数字，它看着像版本号，但没有任何机制保证它和 git 历史里的某个 commit 对应。
写 0.8.0 而仓库里从来没有 v0.8.0 这个 tag，就是这个数字只是手打的字符串，无法回答"这份镜像是哪份源码构建的"。
