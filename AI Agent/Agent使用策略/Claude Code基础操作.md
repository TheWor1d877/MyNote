## 启动与会话管理

| 命令                           | 作用           |
| ---------------------------- | ------------ |
| `claude`                     | 启动交互式会话      |
| `claude "任务描述"`              | 带初始提示启动      |
| `claude -c`                  | 继续当前目录最近的对话  |
| `claude -r "<session>"`      | 按 ID 恢复指定会话  |
| `claude -p "查询"`             | 单次查询后退出，适合脚本 |
| `cat file \| claude -p "分析"` | 管道处理文件内容     |
| `claude --bg "分析"`           | 创建一个后台任务     |
`claude -p` 可以和 shell 管道组合，这是 Unix 哲学的核心体现。

## 会话管理
在终端中直接运行`claude --resume`命令，会打开一个交互式的会话选择器
使用快捷键:
↑ / ↓	在会话间导航
Ctrl+A	显示这台机器上所有项目的会话（再次按下返回当前仓库）
Ctrl+W	显示当前仓库所有 worktrees 的会话
Ctrl+B	筛选当前 git 分支的会话
Space	预览会话内容
Ctrl+R	重命名会话
/ 或其他可打印字符	进入搜索模式筛选会话

使用`claude rm <session-id>`删除一个后台agent会话

## 会话内核心命令

输入 `/` 会弹出命令菜单，输入字母可筛选。最常用的：

| 命令         | 作用                            |
| ---------- | ----------------------------- |
| `/init`    | 扫描代码库，自动生成 `CLAUDE.md` 项目记忆文件 |
| `/clear`   | 清空对话，但保留项目记忆，开始全新任务           |
| `/compact` | 压缩对话历史，释放上下文空间                |
| `/context` | 查看当前上下文窗口被什么占用了               |
| `/diff`    | 查看本次会话的所有文件改动                 |
| `/model`   | 切换模型                          |
| `/cost`    | 查看 Token 用量                   |
| `/doctor`  | 诊断安装和配置问题                     |
| `/rewind`  | 将代码和对话回滚到检查点                  |

**`/clear` 和 `/compact` 的区别**：`/clear` 是硬重置，完全清空对话历史，适合切换到完全不同的任务；`/compact` 是软压缩，保留核心摘要，适合对话过长但任务还在继续。

## 权限模式
底部状态栏显示的模式用 `Shift+Tab` 循环切换：


| 模式 | 无需询问即可执行的操作 | 核心逻辑与场景 |
| :--- | :--- | :--- |
| **Manual (手动)** | 仅**读取**文件 | **全程人工把关**。这是默认模式，Claude 可以看，但任何改动（编辑、命令）都需要你点头。适合敏感代码库或刚开始磨合。 |
| **Plan (规划)** | 仅**读取** | **先看图纸再动工**。只读模式，Claude 会分析代码并给你一份执行计划，你批准后它才会真正开始执行。适合大型重构前理清思路。 |
| **Accept Edits (接受编辑)** | 读取、**编辑文件**、常见文件系统命令（如 mkdir, mv, cp, rm 等） | **信任编辑，但不信任命令**。Claude 改代码不用问，但执行 `npm run build` 这类 Shell 命令时仍会停下来确认。适合日常迭代开发。 |
| **Auto (自动)** | **几乎一切**，但有**后台安全分类器**兜底 | **带安全网的自动化**。Claude 自主执行，但高风险操作（如 `curl | bash`、强推主分支）会被独立的分类器模型拦截。适合长任务、减少提示疲劳。 |

- **Manual 和 Plan**：都属于**强人工干预**。Plan 是 Manual 的“前置规划版”，把审查工作从每一步前移到整个计划批准前。
- **Accept Edits**：在 Manual 的基础上，**只放开了“文件编辑”** 这一项的自动批准，命令操作仍需确认。
- **Auto**：则是**最大程度的放手**，把判断权交给了后台的安全分类器。但“放手”不等于“无限制”，分类器会拦截破坏性、越权或数据外泄等高风险操作。



## 上下文管理
**上下文窗口是 Claude Code 最重要的资源。** 单个调试会话可能消耗数万个 token，当上下文接近满时，Claude 会开始“遗忘”早期指令。

- 用 `/context` 定期查看占用情况；
- 用 `/compact` 在对话过长时主动压缩；
- 用子代理隔离探索性任务；
- 用 `/btw` 提旁支问题，不加入对话历史。

## 后台任务与并行会话
Ctrl + B 将一个会话中的当前运行的命令挂在后台,主要用在子代理上面

/background 将整个会话都放到后台

/batch实现大规模的并行改写
流程：
研究规划：自动进入 Plan 模式，分析你的代码库，理解这个改动涉及哪些文件、哪些模块。
拆解单元：把工作拆成 5 到 30 个独立的工作单元。每个单元必须能独立完成、独立合并，不依赖其他单元的结果。
你审批：给你展示完整的执行计划，等你确认。
并行执行：为每个工作单元启动一个子代理，每个子代理在独立的 git worktree 中工作，互不干扰。
各自收尾：每个子代理独立完成实现、测试，并创建自己的 PR

## @符号使用
#### 引用文件或者目录
这是最基础、最常用的用法。输入 @ 后，会自动弹出当前工作目录下的文件列表，你可以继续输入路径来筛选-7。
引用单个文件：`@src/auth.ts`，Claude 会读取这个文件的内容作为上下文
引用整个目录：`@src/components/`，Claude 会获取该目录下的文件信息

#### 引用MCP资源
如果你连接了 MCP 服务器，@ 也能用来引用服务器暴露的资源，格式是 @服务器名:协议://路径。
引用 GitHub Issue：`@github:issue://123`。
引用数据库 Schema：`@postgres:schema://users`。
引用文档文件：`@docs:file://api/authentication`。
这些资源会在你引用时被自动拉取，并作为附件包含在上下文中。

#### 引用子代理
 还可以用来显式指定要运行哪个子代理，而不是把选择权交给 Claude 自动判断-3。
明确调用子代理：输入 `@agent-<name>` 来调用本地子代理，或者从自动补全菜单中选择子代理-3。
示例：`@agent-code-reviewer look at the auth changes`，这会确保 code-reviewer 子代理运行，而不是让 Claude 自己决定
