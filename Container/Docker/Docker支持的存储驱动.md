存储驱动	底层技术	特点
overlay2	OverlayFS	当前推荐首选，需要 Linux 内核 4.0+
overlay	OverlayFS	原始版本，有 inode 限制
aufs	AUFS	Docker 最早使用的驱动，仅支持 Ubuntu/Debian
devicemapper	Device Mapper	块级存储，适合写负载高的场景，RedHat/CentOS 默认
btrfs	Btrfs	下一代写时复制文件系统，适合 Docker build
zfs	ZFS	适合高密度容器场景，但较耗内存
vfs	VFS	不使用写时复制，简单但效率低，仅用于测试
每个驱动都有自己的实现方式、性能特征和适用场景，没有哪个驱动能适应所有场景-2。

┌─────────────────────────────────────────────────────┐
│                   Docker 架构                        │
│  ┌─────────────────────────────────────────────┐   │
│  │         Storage Driver 层（可插拔！）         │   │
│  │  overlay2 | aufs | devicemapper | btrfs | .. │   │
│  └─────────────────────────────────────────────┘   │
│                         ↓ 调用                       │
│  ┌─────────────────────────────────────────────┐   │
│  │            Linux 内核文件系统层               │   │

│  └─────────────────────────────────────────────┘   │
│                         ↓ 寄居于                     │
│  ┌─────────────────────────────────────────────┐   │
│  │        底层物理文件系统（ext4/xfs）           │   │
│  └─────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────┘
