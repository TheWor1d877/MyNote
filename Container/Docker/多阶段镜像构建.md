Docker 镜像由多个只读层（layers）叠加而成，基于 UnionFS（联合文件系统）。
每条 Dockerfile 指令（如 RUN, COPY, ADD）都会生成一个新层。
问题：传统单阶段构建会把编译器（如 gcc）、Go SDK、源码、测试文件等全部打包进最终镜像 → 体积大（常 >500MB），攻击面广。

```dockerfile
FROM golang:1.25-alpine AS builder

RUN apk add --no-cache ca-certificates git

WORKDIR /app

COPY go.mod ./

RUN go mod download

COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -a -installsuffix cgo -o main .


FROM scratch

COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/
COPY --from=builder /app/main /main

EXPOSE 8080

ENTRYPOINT ["/main"]
```

Docker 在构建时：
   为每个 FROM 创建一个临时容器（基于该基础镜像）
   在该容器内执行后续指令（COPY, RUN 等）
   当遇到下一个 FROM 时，丢弃前一个容器的运行时环境（但保留文件系统快照）
   通过`--from=<stage> `可以访问之前阶段的文件系统快照

## 最佳实践
当镜像崩溃的时候，临时替换成alpine，使用exec调试

- 使用 .dockerignore 排除 `*.log, node_modules, .git, Dockerfile`
- 先 `COPY go.mod go.sum `再 RUN go mod download（利用缓存）
- 静态编译（CGO_ENABLED=0）是使用 scratch 的前提
- 如果程序需要时区信息，可额外拷贝 /usr/share/zoneinfo
