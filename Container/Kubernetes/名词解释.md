### Pod CIDR
Pod Classless Inter-Domain Routing

Kubernetes 分配给每个 Node 的私有 IP 段，用于该 Node 上所有 Pod 的 IP

### VXLAN
Virtual eXtensible Local Area Network
一种网路虚拟化隧道技术，要解决跨物理机器的容器需要好像在同一个交换机下面运行
加入PodA在NodeA上面向NodeB上面的PodB发送一个以太网帧

Pod A 确实发出了一个标准的以太网帧。在它自己的视角里，这个帧就是在一个二层广播域里传输——就像插在同一个交换机上一样。
 这个纯正的二层帧，在离开 Node1 网卡之前，被 VXLAN 抓起来装进了一个快递袋：
```text
原始内容（Pod A 眼中的真实世界）：
[ 目标MAC=PodB | 源MAC=PodA | 目标IP=192.168.1.2 | 源IP=192.168.1.1 | 数据 ]

套上快递袋后（物理世界看到的）：
[ 外层目标IP=10.0.0.2 | 外层源IP=10.0.0.1 | UDP | VXLAN头 | 上面的原始内容 ]

[ 外层 UDP 头 (8字节) ] + [ VXLAN 头 (8字节) ] + [ 外层 IP 头 (20字节) ]
```
这就是物理网络的欺骗手段
VXLAN使用8432端口

在 Calico 中的用途：让每个 Kubernetes Node 变成一个路由器，互相通告“我这里有 10.244.1.0/24 这个网段”。
其他node将这个网段加入自己的路由表
```text
ip route add 10.244.1.0/24 via 10.0.0.1
```
物理网络设备（或 Node 自身）生成路由表，无需封装，直接转发 Pod 流量。
如果节点宕机，也能及时删除相关路由

### IPIP
把一个 IP 包整个塞进另一个 IP 包的数据负载里，外层 IP 用于路由，内层 IP 才是真正的通信目标。
类似与VXLAN，就是没有MAC地址
与VXLAN相比，他仅仅建立三层隧道，只管理IP包
```text
[ 外层 IP 头 (20字节) ]  +  [ 原始 IP 包 (不动) ]
```

### iptables
Linux 内核的包过滤/ NAT / 策略框架

### eBPF
Linux 内核的可编程沙箱，允许用户态程序安全地注入代码到内核

eBPF 允许你在不重启内核、不改一行源码的情况下，往内核里动态注入一小段程序，去监听或修改内核的行为。

具体流程：
1.你写一段 C 代码（比如“统计所有 80 端口的包”）
2.编译器将这段代码编译成 eBPF 字节码（一种极简的、安全的中间指令）
3.内核里的 eBPF 虚拟机执行这段字节码
4.eBPF 程序被挂载到内核的特定“钩子”（Hook）上，比如：
- 网卡收到包时
- 系统调用发生时
- 进程调度时

eBPF 程序运行在受限的虚拟机里
即使程序崩溃，也不会导致内核崩溃，eBPF 程序执行出错时（比如访问越界），只会导致该程序被停止，并返回一个错误码，内核本身稳定运行。

| 传统方式（iptables/IPVS） | eBPF 方式（Cilium） |
|---------------------------|---------------------|
| 每个包要经过多链条规则匹配，延迟高 | 包到达网卡时，eBPF 程序直接处理，**零拷贝** |
| 规则变更需要重写整个 iptables 链 | eBPF 程序可动态更新，不影响现有连接 |
| 负载均衡需要经过内核协议栈 | eBPF 在网卡驱动层直接做负载均衡（XDP） |
| 网络策略（NetworkPolicy）通过 iptables 过滤 | eBPF 程序直接在内核判定“这个包能不能通” |
| 监控数据需要额外工具（tcpdump、perf） | eBPF 程序直接在内核采集延迟、流量、错误码，**无需修改应用** |
