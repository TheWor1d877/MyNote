阶段 1：验证身份与协商（对应图中标号 ①）
Client Hello（客户端打招呼）： 客户端（你的电脑）向服务器发送一个“你好”消息，包含它支持的 TLS 版本、加密算法列表以及一个随机数。

Server Hello + SSL Cert（服务器回应 + 发送证书）： 服务器收到后，回复“你好”，选定一个加密算法，并附上自己的数字证书 (SSL Cert)。

验证证书（图上方虚线）： 客户端收到证书后，会使用内置的 CA 的公钥（图上方的绿色钥匙）去解密证书上的签名。如果解密成功且信息匹配，说明这个证书确实是权威机构颁发的，且没有被篡改，从而确认了服务器的真实身份。

提取公钥： 验证通过后，客户端从证书中提取出服务器的公钥（图中客户端左侧的绿色钥匙）。

阶段 2：生成并交换密钥（对应图中标号 ②）
生成 Pre-master Key： 客户端生成一个随机的预主密钥 (Pre-master Key)（图中左侧的深蓝色钥匙）。

Encrypted Pre-master Key（加密发送预主密钥）： 客户端用刚才提取的 服务器公钥 对这个 Pre-master Key 进行加密，然后发送给服务器。

Decrypt Using Private Key（服务器解密）： 服务器收到加密数据后，使用自己独有的、绝不外泄的 服务器私钥（图中服务器右侧的红色钥匙）进行解密，成功拿到 Pre-master Key。

注意：此时只有客户端和服务器知道这个 Pre-master Key，中间人即使截获了加密数据，没有私钥也解不开。

生成 Session Key（生成会话密钥）： 客户端和服务器各自利用“客户端随机数 + 服务器随机数 + Pre-master Key”，通过相同的算法，独立计算出最终的会话密钥 (Session Key)（图中黄色的钥匙）。

阶段 3：加密通信（对应图中标号 ③）
Encrypted Data（加密数据传输）： 握手完成！现在双方都拥有了同一把 Session Key。之后的 HTTP 请求和响应数据，都会使用这把对称密钥进行加密和解密。
