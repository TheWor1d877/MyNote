## 存储介质
常见的存储介质包括 HDD、SSD 
#### HDD
HDD（Hard Disk Drive）通过磁头在高速旋转的磁性盘片上读取和写入数据。
它具有机械运动部件，因此访问延迟主要受到寻道时间和旋转等待时间影响。

- 顺序读写性能较好，适合连续访问大量数据。
- 随机读写性能较差，因为磁头需要频繁移动和等待盘片旋转。
- 单位存储成本低，适合大容量数据存储。
- 机械结构使其抗震性和访问延迟不如 SSD。

适合保存冷数据或者对成本敏感对随机IO延迟要求不高的业务

#### SSD
SSD（Solid State Drive）使用 NAND Flash 闪存芯片存储数据，没有机械运动部件。
它通过电子信号访问数据，因此随机访问性能和并发 I/O 能力通常远高于 HDD。

- 随机读写延迟低。
- 不需要机械寻道。
- 并发 I/O 能力强。
- NAND Flash 存在擦写次数限制。
- 写入数据时存在擦除粒度限制，因此会涉及写放大和垃圾回收。

适合高并发业务、操作系统运行盘、AI模型权重的存储与加载、训练数据缓存与Checkpoint业务

## 存储接口与协议
操作系统不能直接理解 NAND Flash 的物理结构，需要通过接口和协议与存储设备通信

接口：设备通过什么硬件连接方式与主机通信
协议：主机与设备之间如何组织、发送与处理命令
总线：设备之间数据传输的通道

#### SATA + AHCI
SATA（Serial ATA）是一种存储设备接口，AHCI（Advanced Host Controller Interface）是常见的 SATA 主机控制器接口规范及对应的软件编程模型

它们最初主要面向机械硬盘设计，后来也被 SATA SSD 使用。
SATA SSD 虽然使用闪存介质，但它的性能仍受到 SATA 接口和 AHCI 协议的限制

#### PCIe + NVMe
PCIe（Peripheral Component Interconnect Express）是一种高速总线，NVMe（Non-Volatile Memory Express）是一种专门为非易失性存储设计的通信协议

- 最多支持 65,535 个 I/O Submission Queues。
- 每个队列最多支持 65,536 个命令。
- 支持多核 CPU 并发提交 I/O 请求。
- 使用队列和 Doorbell 机制实现高效命令交互

多个 CPU 核心可以使用不同的 I/O 队列提交请求，降低并发场景下的队列竞争和软件开销。

关系：操作系统 / CPU -> PCIe 总线 + NVMe 协议 -> SSD 控制器 + NAND Flash

## SSD内部机制
机制：FTL、GC、TRIM 与写放大

NAND Flash的限制：数据不能像普通内存一样直接原地覆盖，写入和擦除有不同的粒度要求
- Page：页，是 NAND Flash 的基本读取和编程单位。
- Block：块，由多个 Page 组成，是擦除的基本单位。
- Erase：擦除操作，必须以 Block 为单位进行。

#### FTL：闪存转换层
FTL（Flash Translation Layer）是 SSD 控制器中的核心管理机制。
它负责将主机使用的逻辑地址（LBA）映射到 NAND Flash 的物理地址。

因为 NAND Flash 的物理地址不能像普通磁盘扇区一样随意覆盖。FTL 通过地址映射，让操作系统看到一个逻辑上连续、可覆盖写入的块设备

#### GC：垃圾回收
GC（Garbage Collection）是 SSD 内部回收无效存储空间的机制。
步骤：
1. 选择包含无效 Page 的 Block。
2. 将其中仍然有效的数据搬迁到其他位置。
3. 擦除整个 Block。
4. 将擦除后的 Block 放回空闲空间池。

#### TRIM：通知 SSD 数据已经无效
当删除了一个文件。

从文件系统角度看，这些数据已经不再需要了，但 SSD 并不一定立即知道这些逻辑地址已经可以回收。

操作系统可以通过 TRIM（在 SATA 中）或 Dataset Management / Deallocate（在 NVMe 中）通知设备：这些 LBA 对应的数据已经不再需要。

SSD 收到通知后，可以将对应物理数据标记为无效，在后续 GC 中回收空间。

#### OP(Over Provisioning）如何降低写放大
预留空间 / 超额配置
SSD 内部有一部分 NAND Flash 容量，不对用户开放，而是留给 SSD 控制器自己管理。
假设：
一个 Block 有 10 个 Page。
其中 8 个有效，2 个无效。
GC 必须搬迁 8 个 Page，才能擦除整个 Block。
这意味着，为了回收 2 个 Page 的空间，却额外写入了 8 个 Page。

如果 SSD 有更多 OP 空间，就有更多可用的空闲 Block：
不必频繁回收那些仍包含大量有效数据的 Block。
可以等待更多 Page 变成无效数据。
优先回收无效 Page 占比更高的 Block。
减少有效数据搬迁量。
