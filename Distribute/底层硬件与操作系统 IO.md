## 存储介质特性
- HDD 机械硬盘
HDD 里面是真正在“转”的盘片，靠一根机械磁头去“吸”数据。
顺序读写快，随机读写慢
HDD 只能用来做冷数据备份，或者作为极大规模分布式存储的最底层（比如 Ceph 的廉价存储层），而且必须通过算法把零碎数据合并成大块（顺序写）再存进去

-  SSD/NVMe
SSD 没有机械部件，全靠电子芯片（NAND Flash）存数据，速度瞬间起飞

NVMe 协议：专门为 SSD 修了一条“双向多车道高速公路”（通过 PCIe 通道直连 CPU）。它支持几万个队列同时干活，彻底释放了 SSD 的性能。

NVMe 是现代 AI 集群的标配。所有的训练数据缓存、模型权重加载，都必须放在 NVMe SSD 上。

写放大（Write Amplification）问题：SSD 底层有个规矩，修改数据不能“原地改”，必须“搬到新地方写，再把旧地方擦掉”。如果你频繁修改小块数据，SSD 内部就会疯狂倒腾数据（垃圾回收），导致寿命缩短、速度突然变慢。所以，AI 训练框架在写 Checkpoint 时，一定要尽量“大块、顺序地写”，顺应 SSD 的脾气。

- PMem（持久内存）：跨越鸿沟的“超级缝合怪”
物理真相：这是近年来非常前沿的技术。你可以把它理解为“断电也不会丢数据的内存”。
它的速度比普通内存（DRAM）稍微慢一点点，但比最快的 NVMe SSD 还要快得多！
它直接插在主板内存插槽上，CPU 可以像访问普通内存一样直接访问它（绕过了一大堆存储协议）。

#### 数据分层
最烫的数据（正在算的）：放在 GPU 显存里。
次烫的数据（马上要算的）：放在 PMem 或 DRAM 里。
温数据（这一轮训练要用的）：放在 NVMe SSD 里。
冷数据（历史归档）：扔进 HDD 阵列里

## 操作系统IO栈
- VFS 虚拟文件系统
你的服务器里可能同时插着 NVMe 固态、机械硬盘，还连着网络存储（NFS）。它们底层的“方言”完全不同。VFS 的作用，就是给上层提供一个统一的普通话接口。
VFS 让我们实现了“计算与存储的解耦”，GPU 节点根本不需要关心数据到底在哪。

- IO调度器
成百上千个程序同时要求读写硬盘，OS 不能傻乎乎地按先来后到排队。它必须像个聪明的交警，重新规划路线：
合并（Merge）：A 要读第 1 扇区，B 要读第 2 扇区，交警把他们合并成一个请求，一次性读完。
排序（Sort）：把相邻的请求排在一起，让磁头顺着走，减少来回寻道的时间（电梯算法）。

对于机械硬盘（HDD），I/O 调度器是神，能大幅提升性能。
新规矩：对于现代的 NVMe SSD，I/O 调度器反而成了累赘！ 因为 NVMe 内部有几十个微控制器（多队列）并行处理，它自己就是个“超级交警”。如果 OS 还要在前面强行排队、合并，反而增加了 CPU 开销和延迟。

实战调优：在配置 AI 训练节点时，对于 NVMe 设备，我们通常会把 I/O 调度器关掉（设置为 none），让请求直接提交给硬件。这就是 AI Infra 中典型的“绕过 OS 限制，直达硬件”的思想。

## 高性能IO技术
- Direct IO
直接IO，不经过操作系统的缓存
数据库系统（如MySQL、PostgreSQL），它们自己管理缓存，不需要操作系统“帮忙”

 数据直接从硬盘（或网络）搬到 GPU 显存，完全绕过 Page Cache。这就是为什么我们在 AI 训练里，几乎全用 Direct I/O

- 异步IO
在 AI Infra 里，我们追求的是“流水线并行”。GPU 在算当前这一批数据（Batch）时，CPU 必须提前把下一批数据从硬盘里“异步”读出来准备好。如果 I/O 是同步阻塞的，GPU 就会因为等数据而空转。所以，异步 I/O 是保证 GPU 不饿肚子的前提。

#### 用户态IO
- DPDK（网络越狱）
网络收发包，网卡收到数据要触发硬件中断(硬件设备)
OS需要处理全套协议栈，然后在拷贝给应用

DPDK 直接让网卡把数据写到用户态内存里，全程绕过 OS 内核。在 AI 集群的分布式训练中，节点间通信全靠它

- SPDK（存储越狱）：
传统： 应用想读取硬盘上的内容 需要：
应用 -> VFS -> 具体文件系统(ext4) -> 块设备驱动 -> 硬盘上面的数据
SPDK模式： 应用 -> SPDK用户态驱动 -> 硬盘上面的数据
这样VFS与文件系统就被绕过了

使用：
1. SPDK在系统启动的时候就在用户态大页内存中化出一块空间
2. SPDK直接将这块内存地址告诉NVMe硬盘，硬盘内置一个DMA，将数据搬运只应用的空间中

- io_uring（现代异步IO）：
SPDK 虽然猛，但开发太痛苦，而且跟 OS 生态不兼容。io_uring 是 Linux 内核给出的“妥协版完美方案”。
它的本质是：在用户态和内核态之间建了一条“共享内存传送带”（Ring Buffer）。
有两个队列： 提交队列SQ与完成队列CQ

你攒够一批请求（比如攒了100个），把进菜口的100个格子全塞满，然后只喊一次服务员（调用一次 io_uring_enter()），说：“这100个单子都给你了！” 这样，内核一次性拿走100个请求去处理，系统调用次数从100次降为1次。

优点：
应用放请求、内核取请求，都在同一块物理内存上操作，没有数据拷贝
完全异步操作，应用扔完请求就可以立刻干别的事，内核在后台慢慢处理。
支持复杂操作，不仅能读/写文件，还能把多个操作链起来
跟SPDK相比多一次系统调用，数据也要经过VFS与ext4，但开发成本低很多

行为：
应用直接提交10w个io请求在“共享内存”传送带（SQ）上面，一次提交io_uring_enter()，CPU转去处理其他请求，DMA在后台完成这些请求即可
