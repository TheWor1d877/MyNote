一条日志复制到多数派，仍可能被后续 term 的新 Leader 覆盖。只有当前 term 的日志拿到多数派，才算提交成功。

## 场景（5 节点）


S1 是 term2 的 Leader，S2~S5 是 follower，日志都只到 term1。

#### ① S1 写 X，只复制到 S2 后崩溃

```
S1: [1, 2(X)]   S2: [1, 2(X)]   S3: [1]   S4: [1]   S5: [1]
```

X 在 2 个节点，未达多数派（3 个）。S1 崩溃。

#### ② S5 当选 term3，写 Y，只写到自己后崩溃

S1 崩溃后 S5 发起 term3 选举：

- S2 日志比 S5 新，不投 S5
- S3、S4 日志比 S5 旧，投 S5
- S5 投自己

S5 拿三票当选 term3，在 index2 写入 Y（term3），只写到自己后崩溃：

```
S1: [1, 2(X)]   S2: [1, 2(X)]   S3: [1]   S4: [1]   S5: [1, 3(Y)]
```

Y 只在 S5 一个节点，但 term=3，高于 X 的 term=2。

#### ③ S1 重启，当选 term4，把 X 复制到多数派

S1 发起 term4 选举：

- S2 日志与 S1 相同，投 S1
- S3、S4 日志比 S1 旧，投 S1
- S5 日志 [1,3] 比 S1 的 [1,2] 新，不投 S1

S1 拿四票当选 term4，把 X 复制给 S3：

```
S1: [1, 2(X)]   S2: [1, 2(X)]   S3: [1, 2(X)]   S4: [1]   S5: [1, 3(Y)]
```

X 此时在 S1、S2、S3 三个节点，已达多数派。

#### ④ S1 崩溃，S5 当选 term5，覆盖 X

S5 发起 term5 选举：

- S1、S2、S3 日志最后 term=2，S5 日志最后 term=3，这三个节点投 S5
- S4 日志更旧，投 S5

S5 全票当选 term5，把 index2 覆盖成 Y：

```
S1: [1, 3(Y)]   S2: [1, 3(Y)]   S3: [1, 3(Y)]   S4: [1, 3(Y)]   S5: [1, 3(Y)]
```

## X 到了多数派，为什么还能被覆盖

选举规则比较的是日志最后一条的 term 与长度，不比较谁持有已提交的日志。S5 的日志最后 term=3，高于 S1/S2/S3 的 term=2，所以 S1/S2/S3 把票投给 S5，让 S5 用 Y 覆盖它们手里的 X。

持有 X 的多数派节点，会在下一轮选举中投给日志更新的候选人。X 的多数派副本无法阻止覆盖。

## 两种策略的后果

#### 策略 A（错误）：X 到多数派就提交

- S1/S2/S3 apply X
- 步骤 ④ 发生，S5 用 Y 覆盖 X
- S1/S2 执行过 X，S3/S4/S5 执行 Y
- 同一个 index2 执行了两条不同的命令，状态机分裂

#### 策略 B（Raft）：只提交当前 term 的日志

- X 是 term2 的日志，S1 在 term4 不能提交它
- X 从未 apply，没有任何节点执行过
- 步骤 ④ 中 X 被 Y 覆盖，合法
- 所有节点最终只执行 Y，状态机一致
