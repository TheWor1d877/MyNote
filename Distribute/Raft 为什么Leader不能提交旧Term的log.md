# Raft 为什么不能提交旧任期日志 —— 笔记

## 一句话结论

**一条日志即使到了多数派，也不代表安全。因为它可能是"旧任期"的日志，后面还可能被更高 term 的日志覆盖。只有"当前任期"的日志拿到多数派，才能真正锁死。**


## 完整场景（5 节点，严格按时间）

#### 起点
S1 是 term2 的 Leader。S2~S5 是 follower，日志都只有 term1。

#### ① S1 写 X，只复制给 S2 就崩了
```
S1: [1, 2(X)]   S2: [1, 2(X)]   S3: [1]   S4: [1]   S5: [1]
```
X 只到了 2 个节点，**没到多数派（3 个）**。S1 崩溃。

#### ② S5 趁机当选 term3，写了一条 Y，也只写给自己就崩了
S1 崩了，S5 发起 term3 选举：
- S2 日志比 S5 新 → 不投 S5
- S3、S4 日志比 S5 旧 → 投 S5
- S5 投自己

S5 拿到 S3、S4、S5 三票，**当选 term3**，在 index2 写入 **Y（term3）**，只写给自己就崩了：
```
S1: [1, 2(X)]   S2: [1, 2(X)]   S3: [1]   S4: [1]   S5: [1, 3(Y)]
```

**这就是"少数派有更高 term 日志"的来源。** Y 只存在于 S5 一个节点，但 term=3，比 X 的 term=2 高。

#### ③ S1 重启，当选 term4，把 X 复制到多数派
S1 发起 term4 选举：
- S2 日志和 S1 一样 → 投
- S3、S4 日志比 S1 旧 → 投
- S5 日志 [1,3] 比 S1 的 [1,2] 新 → 不投

S1 拿 S1、S2、S3、S4 四票，**当选 term4**。然后把 X 复制给 S3：
```
S1: [1, 2(X)]   S2: [1, 2(X)]   S3: [1, 2(X)]   S4: [1]   S5: [1, 3(Y)]
```

**X 现在到了多数派（S1、S2、S3 三个节点）。**

#### ④ S1 崩溃，S5 靠"日志更新"重新当选，把 X 覆盖掉
S5 发起 term5 选举：
- S1、S2、S3 日志最后 term=2，比 S5 的 term=3 旧 → **全都投 S5**
- S4 日志更旧 → 投 S5

S5 **全票当选 term5**，把 index2 覆盖成 Y：
```
S1: [1, 3(Y)]   S2: [1, 3(Y)]   S3: [1, 3(Y)]   S4: [1, 3(Y)]   S5: [1, 3(Y)]
```

---

## 关键点：X 到多数派了，为什么还能被覆盖？

因为持有 X 的 S1、S2、S3，**会投票给日志更新的 S5**。

选举规则不是看"谁持有已提交的日志"，而是看"谁的日志最后 term 更大/更长"。S5 的日志最后 term=3 > S1/S2/S3 的 term=2，所以 S1/S2/S3 **心甘情愿把票投给 S5**，让 S5 覆盖自己手里的 X。

**X 的"多数派"是假的安全。** 多数派里的节点会"叛变"投给日志更新的人。

---

## 两种策略的后果

#### 策略 A（错误）：X 一到多数派就提交
- S1/S2/S3 apply X
- ④ 发生时，X 被 S5 覆盖
- 结果：S1/S2 执行过 X，S3/S4/S5 执行 Y，**同一个 index2 执行了不同命令 → 状态机分裂**


#### 策略 B（Raft 正确）：只提交当前任期的日志
- X 是 term2 的旧日志，S1（term4）**不能**提交它
- X 从未 apply，从未被任何节点执行过
- ④ 时 X 被覆盖，完全合法，因为它从未提交过
- 所有节点最终只执行 Y，状态机一致
