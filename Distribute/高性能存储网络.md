## NVMe协议
NVMe 的本质，是为了匹配现代多核 CPU 和闪存介质的并行物理特性，彻底抛弃了传统机械硬盘时代的串行架构包袱。

NVMe直接挂载到PCle总线上面，通过内存映射的方式来与CPU直接通信，支持多个IO队列，队列中名命令深度高

在训练数据预处理阶段，当你用 PyTorch 开启几十个 Worker 并发读取海量小文件时，NVMe 可以为每个 CPU 核心分配专属队列，实现真正的无锁并行处理

MVMe采用及简的指令集，驱动层面延迟低


## RDMA
而 RDMA 就是为了让网络 I/O 像访问本地内存一样而诞生的
三大核心机制： 
- 内核旁路： 应用程序直接通过Verb API直接与RDMA网卡进行交互，数据通路直接绕过操作系统内核
- 零拷贝: 数据直接在本地应用内存与远程应用内存之间传输，无需经过内核缓冲区，彻底消灭了内存拷贝。
- 协议卸载： 数据包的封装/解析、拥塞控制、校验和计算全部由 RNIC 硬件完成。GPU 和 CPU 彻底从网络搬运中解放出来。

## RoCEv2
RoCEv2 是一种允许在标准以太网上实现 RDMA（远程直接内存访问）的网络协议。它的核心作用是让数据能在服务器内存之间直接传输，绕过 CPU 和操作系统内核，从而实现极低延迟和高吞吐量

传统的 RDMA 通常依赖专用的 InfiniBand 网络，成本高且难以与现有以太网融合。RoCEv2 解决了这个问题，关键在于“封装”与“可路由”

由于 RDMA 机制假定网络不丢包，一旦发生丢包，性能会急剧下降。因此，RoCEv2 必须配合特定的以太网技术，构建“无损网络”环境：
- PFC（优先级流量控制）：在链路拥塞时，逐跳发送暂停帧，防止交换机缓冲区溢出丢包。
- ECN（显式拥塞通知）：在拥塞发生前，在 IP 报文头上打标记，通知发送端主动降速，避免丢包。
- DCQCN：配合 ECN 使用的拥塞控制算法，动态调节发送速率。

如果发生丢包在进行重传操作

## 相关应用
- 基于 RoCEv2 的分布式 Checkpoint 加速方案
痛点：千卡集群每 10 分钟保存一次权重，几十 TB 的数据通过传统 TCP 写入 Ceph/MinIO，耗时 5 分钟，GPU 闲置率高达 8%。

实战：设计并落地了基于 RoCEv2 + NVMe-oF 的异步 Checkpoint 机制。
利用 RDMA 的零拷贝特性，将 GPU 显存中的模型状态直接通过 PCIe 映射到本地 NVMe SSD。
后台 Sidecar 进程利用 RoCEv2 网络，将本地 NVMe 数据直接 DMA 到远端存储节点的内存中，全程 CPU 占用率低于 5%。
