虚函数表是 C++ 编译器和 ABI 常见的实现机制，不是操作系统提供的功能

## 操作系统的虚拟内存
操作系统为每个进程提供独立的虚拟地址空间（Virtual Address Space）。
- 每个进程看到的都是自己的虚拟地址空间，不直接使用物理内存地址。
- CPU 通过 MMU（内存管理单元）将虚拟地址转换为物理地址。
- 操作系统通过页表管理虚拟地址与物理地址之间的映射。
- 不同进程可以拥有相同的虚拟地址，但映射到不同的物理内存。

|内存区域|主要内容|
|---|---|
|`.text`|程序机器指令，通常可读可执行|
|`.rodata`|字符串常量、只读数据等|
|`.data`|已初始化的全局变量和静态变量|
|`.bss`|未初始化或零初始化的全局变量和静态变量|
|Heap|动态分配的内存|
|mmap 区域|动态库、内存映射文件等|
|Stack|函数调用栈、局部变量等|

## 虚函数表（VTable）
- 虚函数表保存虚函数对应的函数地址。
- 对象内部通常包含一个隐藏指针 `vptr`，指向所属类的虚函数表。
- 调用虚函数时，通过 `vptr` 找到对应函数地址，实现动态绑定。

虚函数表通常位于程序的只读数据区域（例如 `.rodata` 或相关只读段
```c++
class Base {
public:
    virtual int func() = 0;
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    int x = 41;

    int func() override {
        return x + 1;
    }
};

int main() {
    Base* p = new Derived();

    int result = p->func(); // 返回 42

    delete p;
}
```

优点：
- 支持运行时多态，提高代码扩展性。
- 可以通过基类接口操作不同派生类对象，降低模块之间的耦合。
- 适合插件系统、框架接口、驱动抽象等场景。
    
缺点：
- 对象通常需要额外存储 `vptr`，增加内存开销。
- 虚函数调用需要间接寻址，可能影响性能和内联优化。
- 虚函数增加了类的实现复杂度，需要注意对象生命周期和析构问题。
