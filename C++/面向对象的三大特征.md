## 封装

隐藏实现细节，实现模块化。

- **访问权限**：`public`（对外接口）、`protected`（子类可见）、`private`（仅内部可见）。
- **核心目的**：数据与操作绑定，外部只能通过受控接口访问，防止状态被非法修改。

## 继承

无需修改原有类即可扩展功能，建立 is-a 关系。

- **权限继承**：子类成员的最终权限 = `min(父类原始权限, 继承方式)`。子类永远无法获得比父类更高的访问权限。
- **注意**：基类有虚函数时，必须声明虚析构函数，否则通过基类指针删除派生类对象会内存泄漏。

## 多态

### 静态多态

编译期锁死调用目标，零运行开销。包括函数重载、运算符重载、模板。

### 动态多态

运行期根据实际类型分发调用，依赖虚表（vtable），有间接寻址开销。

### 运算符重载不能直接用动态多态

```cpp
struct Base {
    // 返回值必须是Base（值类型），发生切片，丢失派生类信息
    virtual Base operator+(const Base& rhs) const;
};

struct Der : Base {
    // override只能保证签名一致，返回仍被限定为Base
    Base operator+(const Base& rhs) const override;
};

// b1+b2 调用Der::operator+，但返回Base（被切片），无法得到Der结果
Base& b1 = der1;
Base& b2 = der2;
auto result = b1 + b2; 
```

**核心矛盾**：虚函数协变返回仅限指针/引用，值返回必然切片；运算符又通常需要返回具体类型。

### CRTP 解决方案

编译期绑定，避免切片，零开销：

```cpp
template <typename Derived>
struct Base {
    // 返回Derived，编译期确定，无切片
    Derived operator+(const Derived& rhs) const {
        return static_cast<const Derived*>(this)->addImpl(rhs);
    }
};

struct Der : Base<Der> {
    Der addImpl(const Der& rhs) const { /* 实际逻辑 */ }
};
```

- **适用场景**：类型编译期已知、追求性能、需要精确返回派生类类型。
- **局限**：不同 Derived 是不同类型，无法存入同一异构容器；若需运行时多态+运算符，可考虑返回智能指针或 clone 机制。
