## 第一优先：推理 KV Cache 显存实测

**背景**

推理岗面试的高频考点集中在一条链上：KV Cache 是什么 → 它吃掉多少显存 → PagedAttention / Continuous Batching 怎么解决。面试官不会满足于你背公式，他会追问“你实测过吗”“GQA 到底省多少”“batch 增大时显存怎么变”。这一部分的目标，是让你手里有一组**自己跑出来的 KV Cache 显存数字**，公式和实测能对上，GQA 的收益能用数据说清楚。

**前置**

一张单卡即可，16GB 显存绰绰有余。GPT-2 small 的权重在 FP16 下只有约 0.25 GB，KV Cache 在 1K 上下文、单序列下约 0.04 GB。不需要 vLLM 集群，不需要多卡，一台按量计费的 T4 或 3090 就够，测完立即释放。

**具体执行步骤**

**1. 先写公式，算出“理论上 KV Cache 该占多少”。**

单 sample 的 KV Cache 显存：

\[
\text{KV bytes} = 2 \times L_{\text{ctx}} \times N_{\text{layers}} \times N_{\text{kv\_heads}} \times d_{\text{head}} \times \text{bytes}
\]

“2”来自 K 和 V 两份。GQA 下 \(N_{\text{kv\_heads}}\) 小于 Q 的头数，MHA 下两者相等。GPT-2 small 是 MHA（\(N_{\text{layers}}=12, N_{\text{heads}}=12, d_{\text{head}}=64\)），单 token 单序列在 FP16 下的 KV Cache 约 **36,864 字节**，1K 上下文约 **0.04 GB**。把这个公式和 GPT-2 的实测值先算出来，作为对照基线。

**2. 用 HuggingFace 原生实现跑“有 cache vs 无 cache”的对比。**

这是最干净的第一组实测：同一个模型、同一个输入，一次不传 `use_cache`，一次传 `use_cache=True`，分别记录峰值显存和生成相同 token 数的耗时。你会看到有 cache 时显存更高，但耗时显著更低——因为 decode 阶段不用每步重算全部 K/V。这组数据直接回答“KV Cache 为什么存在”。

**3. 固定模型，只变上下文长度，画显存增长曲线。**

取 \(L_{\text{ctx}}\) = 128 / 256 / 512 / 1024，每次跑一次完整生成，用 `torch.cuda.max_memory_allocated` 读峰值。每轮测量前调用 `reset_peak_memory_stats()`，确保峰值只反映本轮。你会得到一条随上下文线性增长的曲线，斜率就是每个 token 的 KV Cache 成本。把实测斜率和第 1 步的公式值并排放，差值来源是 CUDA context 和框架常数开销。

**4. 用 vLLM 观察“KV Cache 池”和 `gpu_memory_utilization` 的关系。**

vLLM 的显存账是：`可用显存 = gpu_memory_utilization × 总显存`，权重加载后剩下的全部划给 KV Cache 池，池子大小除以 `bytes_per_token × max_model_len` 得到最大并发数。用 GPT-2 small 起一个 vLLM 实例，分别设 `gpu_memory_utilization` = 0.5 / 0.7 / 0.9，从启动日志里读 vLLM 报告的 KV Cache 块数和可用 token 数。这组数据让你在面试里能说：“vLLM 不是动态伸缩 KV Cache，它是启动时就根据 `gpu_memory_utilization` 把池子划死，`max_model_len` 越大，同样的池子能容纳的并发就越少。”

**5. GQA 的收益：用同一个公式，换一组头数算一遍。**

GPT-2 small 是 MHA，没有原生 GQA 版本。你不需要跑一个 GQA 模型，只需要在公式层面做替换：把 \(N_{\text{kv\_heads}}\) 从 12 降到 4（GQA 4 组）或 1（MQA），其他不变，算出 KV Cache 降到原来的 1/3 或 1/12。然后在笔记里写一句：“Llama-3-8B 用 GQA（\(N_{\text{kv}}=8\)），同样 8K 上下文、batch 16 下，KV Cache 比 MHA 的 Llama-2-7B 少约 4 倍”。这一步不需要额外硬件，但它是面试里区分“知道 GQA”和“能算 GQA”的关键。

**验收**

KV Cache 公式与 GPT-2 实测值对照表齐全；“有 cache vs 无 cache”的显存/耗时对比；上下文长度 128/256/512/1024 的峰值显存曲线；vLLM 在不同 `gpu_memory_utilization` 下的 KV Cache 池大小记录；GQA/MQA 的公式替换计算。全部数据一页纸。

**弹药**

推理显存的大头不是权重，是 KV Cache；KV Cache 随 `batch × seq_len` 线性增长，且每个并发序列独立占用。PagedAttention 解决的是 KV Cache 的**碎片化**（利用率从 ~70% 提到 ~96%），不是“让 KV Cache 变小”。Continuous Batching 让 batch 不等待短请求，配合 PagedAttention 才能把 decode 阶段的访存成本摊薄。GQA 从公式上直接缩小 \(N_{\text{kv\_heads}}\)，是 KV Cache 显存的结构性下降，和量化、分页是不同层面的优化。

**讲法**

先写公式，再给 GPT-2 的实测锚点（1K 上下文单序列约 0.04 GB KV Cache，权重才 0.25 GB），然后说 vLLM 怎么把剩下的显存划成池子、`max_model_len` 和并发数怎么互相挤压。被问到 GQA 时，不背“Llama-3 用了 GQA”，而是说“GQA 把 \(N_{\text{kv\_heads}}\) 从等于 Q 头数降到 Q 头数的 1/G，KV Cache 直接降到 1/G，在同样的显存池里能容纳 G 倍的并发 token”。


## 第二优先：训练显存轻量验证（半小时完成）

**背景**

你主搞推理，训练实验不需要铺开。但面试里常有一个对比性问题：“推理显存和训练显存有什么区别”。如果你能说出“训练时每个参数静态 16 字节，其中 12 字节是梯度和 Adam 状态，推理只存权重和 KV Cache”，这个对比会立刻显示你对显存“两本账”的理解是完整的。这一部分的目的，就是**用单卡、一个模型、几行代码，拿到一个属于你自己的训练峰值显存数字**，让这句话有底气。

**前置**

和第一优先同一张单卡即可。GPT-2 small（约 1.24 亿参数）在 FP16 + AdamW 下静态状态约 **1.98 GB**，16GB 显存完全够用。不需要多卡，不需要 ZeRO，不需要追求收敛。

**具体执行步骤**

**1. 写静态公式。**

混合精度 + AdamW 下，每参数静态 16 字节：FP16 参数 2 + FP16 梯度 2 + FP32 主权重 4 + Adam 一阶动量 4 + Adam 二阶动量 4。GPT-2 small 约 \(1.24 \times 10^8\) 参数，静态理论值 \(16 \times 1.24 \times 10^8 \approx 1.98\) GB。把这 1.98 GB 作为公式预测值。

**2. 单卡跑几步训练，读峰值。**

用 `torch.cuda.amp` + `GradScaler`，`AdamW`，batch size 取小（比如 2 或 4），序列长度取 **512**，跑 5 步。每轮测量前 `gc.collect()` + `torch.cuda.empty_cache()` + `torch.cuda.reset_peak_memory_stats()`，跑完读 `max_memory_allocated()`。你会看到峰值**明显高于 1.98 GB**，高出来的部分就是**激活**（加上 CUDA context 等常数开销），而激活不参与任何分片。

**3. 只变序列长度，看峰值怎么涨。**

固定模型和 batch，把序列长度从 **256 改到 512**，再读一次峰值。静态 1.98 GB 不变，但峰值会随序列长度上升。这条曲线不需要多卡，单卡就能做，它直接支撑一句话：“训练显存里有一大块是激活，跟序列长度成正比，ZeRO 分不走它。”

**4. 把推理和训练的数字放在一张表里。**

|  | 推理（GPT-2 small, FP16, 1K ctx, 单序列） | 训练（GPT-2 small, FP16+AdamW, seq=512） |
|---|---|---|
| 权重 | ~0.25 GB | ~0.25 GB（FP16 参数） |
| 额外静态 | KV Cache ~0.04 GB | 梯度 + Adam + FP32 主权重 ~1.73 GB |
| 动态部分 | KV Cache 随并发和上下文增长 | 激活随 batch 和 seq_len 增长 |
| 公式锚点 | \(2 \cdot L \cdot N_{\text{layers}} \cdot N_{\text{kv}} \cdot d \cdot \text{bytes}\) | \(16\Psi\)（静态） + 激活 |

这张表就是你面试里“推理 vs 训练显存”对比的完整答案。

**验收**

16Ψ 的公式和 GPT-2 small 的 1.98 GB 静态预测；单卡实测峰值（seq=512）；seq=256 和 seq=512 的峰值对比，显示激活随序列长度的增长；一张推理 vs 训练的显存对照表。

**弹药**

训练静态 16Ψ 中，梯度和 Adam 状态占 12Ψ，推理只存权重；激活是训练显存中不参与分片、随 batch 和序列长度增长的部分。推理的弹性部分是 KV Cache，训练的弹性部分是激活——两者都是“动态的”，但推理的 KV Cache 可以用 PagedAttention 管理，训练的激活基本是刚性的。


## 一页纸交付模板

**左栏：推理 KV Cache。** 公式 \(2 \cdot L \cdot N_{\text{layers}} \cdot N_{\text{kv}} \cdot d \cdot \text{bytes}\)；GPT-2 small 1K 上下文单序列 ~0.04 GB；上下文 128/256/512/1024 的峰值显存曲线；“有 cache vs 无 cache”的耗时对比；GQA 公式替换（\(N_{\text{kv}}\) 除以 G，KV Cache 降到 1/G）。

**右栏：训练显存锚点。** 16Ψ = 1.98 GB（GPT-2 small）；单卡实测峰值（seq=512）和 seq=256 的对比；推理 vs 训练的显存对照表。

**底部：一句话结论。** 推理的显存大头是 KV Cache，随并发和上下文增长，PagedAttention 管的是它的碎片；训练的显存大头在静态 16Ψ 之上还要加激活，激活不参与 ZeRO 分片。两张“显存账”的弹性项不同，优化手段也不同。

**硬件口径。** 单卡（T4 / 3090 / A100 32G 均可），机内运行，无多卡通信；`max_memory_allocated` 每轮用 `reset_peak_memory_stats` 隔离。
