将串行的数据准备与GPU计算并行化，构建一条永远不中断的数据供给链条
当GPU处理当前这一批的时候，CPU已经在准备下一批，IO子系统在读取下一批
GPU算完第N批，直接DMA取走第N+1批，中间不停。

GPU计算速度远远超过CPU的数据准备速度，如果串行执行，GPU每算完一批都要等待下一批数据，利用率会大幅下降

## 双缓冲与多缓冲策略
系统维护两个缓冲区：
缓冲区A：当前正在被GPU使用的数据
缓冲区B：后台正在加载的下一批数据
当GPU完成A的计算时，B已经就绪，立即切换。同时后台开始加载下一批到A（此时A已释放）。

双缓冲的扩展。维护多个缓冲区形成队列，进一步隐藏I/O延迟。PyTorch DataLoader的prefetch_factor本质上就是多缓冲——每个worker维护一个本地队列，队列长度由prefetch_factor决定。

## 异步加载的实现机制
```python
# DataLoader配置
loader = DataLoader(dataset, pin_memory=True, num_workers=4)

# 训练循环
for x, y in loader:
    x = x.cuda(non_blocking=True)  # 异步拷贝，CPU不等待
    y = y.cuda(non_blocking=True)
    output = model(x)  # GPU计算与数据传输重叠
```

pinned memory配合non_blocking=True，CPU可以在数据传输的同时继续执行其他任务。

或者采用CUDA Stream来进行数据预加载

#### pin_memory
页锁定内存（pinned memory）不会被操作系统换出到swap，GPU可以直接通过DMA读取，无需额外的锁定操作。
传统内存页在DMA传输过程中可能会被换走，所以并不安全
###### 性能陷阱
- 增加cpu内存压力: pinned内存不能被swap,是"真实"的物理内存,如果 num_workers 大、prefetch_factor 大、样本又大，pinned 内存会快速累积。
   
- 对于临时的小张量,只在CPU中间使用的中间结果等,推理阶段的零散数据,不适合使用pin,只适合频繁传输到GPU上面的大张量

#### non_blocking异步操作的 前提
- 源张量必须在 pinned memory 中；
- 目标设备是 CUDA；
- 当前 CUDA Stream 允许异步执行；
- 没有立即触发 CPU 侧同步。

#### CUDA Stream
CUDA Stream 是 GPU 上的异步命令队列。一个 stream 内部操作严格顺序执行，不同 stream 之间如果没有依赖，可以并行。
默认情况下，PyTorch 的 GPU 操作都落在 default stream 上。tensor.to(device) 如果不指定 stream，也会进入默认流。

多Stream并行关键:

用 with torch.cuda.stream(stream) 把操作绑定到指定 stream；
传输和计算放到不同 stream；
存在依赖时，用 stream.wait_stream(other_stream) 或 Event 同步；
避免在 stream 上下文里调用 .item()、.cpu()、print(tensor)。


## 缓存策略
如果某些数据在多个epoch中被反复使用，每次都从磁盘读取+预处理是巨大的浪费。缓存策略的本质是用内存换I/O。

#### Smart Cache机制
确定性变换识别：如果一个变换序列对相同输入总是产生相同输出（如Resize、Normalize），则其输出可以缓存
缓存最长确定性序列的输出：从第一个变换开始，找到最长的确定性变换链，缓存其输出结果
渐进式替换：每轮epoch只替换部分缓存内容（如10%），保持GPU始终有数据可用

实测显示，使用Smart Cache后，每step耗时从1.5秒降至0.5秒，GPU利用率持续保持在90%以上。

工程实践：
小数据集：可将全部预处理数据预加载至GPU显存
中等数据集：使用内存映射文件（mmap）或LMDB/HDF5格式，减少文件系统开销
大数据集：分层缓存——热数据（高频访问样本）存NVMe SSD，温数据存SATA SSD，冷数据存对象存储
