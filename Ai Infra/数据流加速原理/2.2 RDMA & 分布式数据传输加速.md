## 分布式训练的通信场景
数据并行（Data Parallel）：每个GPU持有模型副本，处理不同数据，每轮需要all_reduce梯度
模型并行（Model/Tensor/Pipeline Parallel）：模型被切分到多个GPU，前向/后向传播中需要频繁传递激活值和梯度
混合并行：上述两种的组合，通信模式更加复杂

## RDMA的核心机制：内核旁路与零拷贝
#面试-计算机基础-复习  解释 RDMA 的基本原理，以及它在分布式训练 AllReduce、参数同步和存储访问中的价值。

RDMA（Remote Direct Memory Access）的本质是让一台机器的网卡直接读写另一台机器的GPU/内存，全程不经过对方的CPU和操作系统。

传统网络收发包的时候，应用要发送数据需要走系统调用进入内核，内核协议栈层层封装，最后交给网卡
对面收到网络包之后，网卡中断CPU，内核一层层解包拷贝到用户态buffer
上下文切换，中断等都是开销

RDMA： 网卡认识对方的“内存地址”的，应用先将内存注册给网卡，这样我方网卡就拿到了对方内存的访问权限与虚拟地址与物理地址的映射关系

应用直接在用户态将发送数据的指令交给网卡，网卡从内存中取出数据，然后通过网络发到对面网卡，对方网卡直接写进目标内存，这就是所说的内核旁路与零拷贝

整个过程是单边操作，只有我们这边的CPU发送一次指令，对面应用甚至不知道数据到了，这就是所说的CPU卸载

代价是需要专用的硬件与网络，比如 InfiniBand，或者 RoCE
#### 三大核心特性
- 内核旁路（Kernel Bypass）
传统网络通信需要经过操作系统的内核协议栈，而RDMA通过用户态直接访问网卡硬件，绕过内核。应用层直接调用RDMA verbs（如ibv_post_send）发起传输请求，网卡硬件自行完成数据搬运。
- 零拷贝（Zero-Copy）
数据从源端GPU显存/内存直接传输到目标端GPU显存/内存，中间不经过任何缓冲区和协议栈。CPU完全不参与数据传输，只负责下发指令。
- CPU卸载（CPU Offload）
RDMA网卡（RNIC）内置专用的传输引擎，自行处理可靠性保证、流量控制、拥塞控制等协议逻辑。CPU只需要注册内存区域、发布工作请求，之后就可以去做其他事情。

#### 分布式训练 AllReduce、参数同步和存储访问中的价值
AllReduce 本质是每个 rank 都要拿到全局梯度，通信量很大，传统传输中GPU等待CPU搬运梯度可能成为问题所在，通信与计算会争抢CPU
使用RDMA梯度直接从一块 GPU 显存对应的主机内存或者 GPUDirect 路径上打出去，延迟低、CPU 占用几乎为零，大模型 checkpoint 动辄几百 GB，走 RDMA 写远端存储，比走内核协议栈快得多，也不拖累训练进程


#### 通信原语
RDMA具有单边与双边操作，send/recv是 双边操作，对方需要提前提供一个recive buffer
read/write 是单边，只要知道对面地址和 rkey 就能直接操作，对面无感知。

| 模式 | 描述 | 适用场景 |
|------|------|----------|
| Send/Recv | 类似传统socket，需要双方配合完成传输 | 通用通信 |
| RDMA Write | 单方发起，直接写入对端内存，对端无感知 | GPU显存直传、Checkpoint同步 |
| RDMA Read | 单方发起，直接从对端内存读取 | 参数服务器拉取权重 |

其中RDMA Write是最强大的模式——你可以让GPU A直接把梯度写入GPU B的显存，GPU B甚至不需要知道这件事正在发生，直到它去读取那块内存。



#### 实现方式 InfiniBand vs RoCE
###### InfiniBand
InfiniBand是端到端的专用协议栈
从链路层到传输层都是自己实现的一套，不跑在IP上面
需要专用的InfiniBand 网卡（HCA）和专用交换机

###### RoCE（RDMA over Converged Ethernet）
核心是将InfiniBande的传输层搬运到以太网链路层上面
把 RDMA 的数据包，封装成以太网能传输的格式，通过普通以太网卡和交换机发出去

- PFC（Priority Flow Control）
RDMA假设发送的所有包都会到达，所以丢包不会重发，但是以太网的特性就是天生就会丢包
开启PFC，在缓冲区快要满之前主动暂停
这样，RDMA 流量在拥塞时不会被丢弃，而是被“暂停”等待。这就是所谓“无损以太网”的含义

- ECN：显式拥塞通知（Explicit Congestion Notification）
当队列还没满但是有点堵的时候，在包头放置一个标记
接收方收到这个被标记的包，知道传输路程有点堵塞
接收方通过一个专门的 CNP 包（拥塞通知包） 告诉发送方减慢发送速度
发送方收到 CNP，主动降低发送速率

- MTU：最大传输单元
MTU 全称最大传输单元，意思是一个网络包最大能装多少数据
MTU设置为 4096（Jumbo Frame）：减少分片开销

网卡要求：需要支持RDMA的网卡（如Mellanox ConnectX系列、NVIDIA BlueField DPU）


#### 落地方式： NCCL
NCCL（NVIDIA Collective Communications Library）是NVIDIA提供的集合通信库，PyTorch分布式训练默认使用它。

NCCL 是 NVIDIA 的集合通信库，负责 GPU 与 GPU 之间的数据传输-1-12。它提供 all-reduce、all-gather、broadcast 等通信原语，优化的是：
- 单机内：通过 PCIe、NVLink、NVSwitch 连接多张 GPU
- 跨节点：通过 InfiniBand、RoCE 连接多台机器

NCCL会自动检测底层网络能力，不需要手动调用RDMA verbs，NCCL会帮你处理好一切。但你需要确保环境配置正确（驱动、网卡、PFC、MTU等），否则NCCL会回退到TCP，性能大打折扣。

#### GPU Drirect RDMA

考察点：能不能把 RDMA 和 GPU 训练场景真正接起来。传统路径 GPU 显存要先拷到主机内存再发，GPUDirect 让网卡直接读写 GPU 显存，省掉一次拷贝，跨节点通信延迟明显下降。这个点跟你做训练数据流、推理加速是直接相关的。
## 传输方式维度
数据传输语义	流式（Stream）/ 消息（Message）/ 数据报（Datagram）	数据是字节流还是带边界的信息
通信原语	Send/Recv、RDMA Write、RDMA Read	谁发起、谁感知、怎么访问内存
同步方式	同步 / 异步、阻塞 / 非阻塞	调用后是否等待完成
连接方式	面向连接 / 无连接	是否需要先建连接
