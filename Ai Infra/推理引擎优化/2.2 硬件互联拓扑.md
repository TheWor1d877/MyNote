分布式推理的性能上限，不仅取决于算法和并行策略的设计，更受制于底层硬件的互联能力。不同互联技术的带宽、延迟和拓扑结构，直接决定了通信开销能否被有效隐藏

## NVLink与NVSwitch
NVLink 是 NVIDIA 专为 GPU 间通信设计的高速点对点互联协议，旨在替代传统 PCIe 总线，解决多 GPU 协同计算中的带宽瓶颈。其本质是一组物理链路，每根链路包含双向差分信号对，支持 GPU 与 GPU 之间的直接内存访问（P2P），无需经过 CPU 或系统内存中转。
在 NVLink 互联下，GPU 间传递激活值或 KV Cache 的耗时可以忽略不计，而在 PCIe 上则可能成为致命瓶颈。

NVSwitch 是基于 NVLink 协议的专用交换芯片，用于构建多 GPU 全互联（All-to-All）拓扑。如果说 NVLink 是"两根 GPU 之间的专线"，那么 NVSwitch 就是"GPU 集群的交换中心"，让任意两张 GPU 都能以满带宽直接通信。

## 拓扑感知
即使硬件支持 NVLink/NVSwitch，软件层面也必须"知道"拓扑结构才能做出最优调度决策

拓扑感知是指推理框架或通信库（如 NCCL）在初始化时探测 GPU 之间的物理连接关系（哪些 GPU 通过 NVLink 直连、哪些通过 PCIe 连接、哪些跨 NUMA 节点），并据此选择最优的通信路径和算法。

典型场景：
- NCCL 自动探测：NCCL 在初始化时会调用 nvidia-smi topo -m 获取拓扑矩阵，自动选择 Ring、Tree 或 CollNet 等通信算法。
- vLLM 的 TP 组绑定：vLLM 在分布式部署时，会将 TP 组内的 GPU 绑定到同一 NVSwitch 域内，避免跨域通信
- 手动干预：在某些非标准拓扑（如消费级主板多 GPU）下，NCCL 可能错误判断拓扑，需通过 NCCL_IB_DISABLE=1 或 CUDA_VISIBLE_DEVICES 手动指定。
