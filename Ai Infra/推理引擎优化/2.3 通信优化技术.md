## 异步通信
核心思想： 在计算当前层的同时提前发起下一层数据的通信需求，二者在时间上面重叠

以流水线并行（Pipeline Parallelism）为例，假设模型被切分为 Stage0 和 Stage1 两个阶段，分别部署在 GPU0 和 GPU1 上：

| 时间步 | 传统同步模式 | 异步重叠模式 |
|-------|------------|------------|
| T0 | GPU0: FWD(micro-batch 0) | GPU0: FWD(micro-batch 0) |
| T1 | GPU0: 等待 Send 完成 | GPU0: 异步 Send → 立即开始 FWD(micro-batch 1) |
| T2 | GPU1: 等待 Recv 完成 | GPU1: 异步 Recv → 立即开始 FWD(micro-batch 0) |
| T3 | GPU1: FWD(micro-batch 0) | GPU1: FWD(micro-batch 0) + GPU0: FWD(micro-batch 1) 并行 |

在异步模式下面，Send/Recvd的通信时间被后续的计算时间覆盖

#### 实现细节：
- CUDA  Stream隔离
使用独立的 CUDA Stream 分别执行通信和计算，避免资源争用。NCCL 通信操作在专用 Stream 上发起，计算操作在默认 Stream 上执行，两者通过 CUDA Event 实现同步
```python
import torch
comm_stream = torch.cuda.Stream()

# 在通信流上异步发送
with torch.cuda.stream(comm_stream):
    dist.isend(tensor, dst=1)  # 立即返回，不阻塞

# 在默认流上继续计算
output = model(input)

# 在需要数据时再等待通信完成
comm_stream.synchronize()
```

- 梯度/激活分桶
反向传播中的梯度分桶处理，每个桶固定大小（默认 25MB），每个桶中的梯度计算完毕就异步触发它的All-Reduce（将所有桶中的梯度求平均，然后所有GPU根据平均梯度做梯度下降更新参数）
分桶的操作将网络通信次数减少，增加吞吐

- 延迟等待（Postponed Wait）
不在每次 Send/Recv 后立即调用 wait()，而是将通信句柄缓存起来，在真正需要数据时才允许等待

#### 推理场景的特殊考量
Prefill 阶段：激活张量大但通信频率低，适合用大桶一次性传输；
Decode 阶段：每生成一个 Token 都需要通信，张量小但延迟敏感，适合用小桶 + 低延迟算法（Tree/NVLSTree）；
KV Cache 共享：在 PD 分离架构中，Prefill 节点通过异步 RDMA Write 将 KV Cache 直接写入 Decode 节点显存，无需 CPU 介入。

## 通信压缩
| 技术 | 原理 | 压缩率 | 精度影响 |
|-----|------|-------|---------|
| FP16/BF16 量化 | 将 FP32 梯度转为半精度 | 2× | 几乎无影响 |
| INT8 量化 | 8-bit 整数表示，带缩放因子 | 4× | <0.5% 精度下降 |
| 1-bit Quantization | 仅传输符号位 + 全精度缩放因子 | 32× | 需误差补偿 |
| Top-k 稀疏化 | 仅传输绝对值最大的 k% 梯度 | 10~100× | 需动量补偿 |
| PowerSGD | 对梯度矩阵做低秩近似 | 5~20× | 收敛速度略慢 |
| DUO 框架 | 在计算阶段插入高精度同步，完全隐藏通信 | 4-bit 无精度损失 | 理论证明收敛 |

推理场景与训练的关键差异在于：训练压缩的是梯度（误差信号，对噪声有一定容忍度），而推理压缩的是激活值（前向传播的中间结果，直接影响输出精度）。因此，直接套用梯度压缩技术会导致推理精度显著下降。

迁移策略：
激活值分组向量量化（Grouped Vector Quantization）
UMass Amherst 的研究表明，在 Transformer 推理中，对非局部 Key-Value 表示进行分组向量量化，可在不切断信息流的前提下将通信量减少 80% 以上。
核心思想：将激活张量按通道维度分组，每组学习一个小型码本（Codebook），传输时仅发送码本索引而非原始浮点数。
效果：在 Vision Transformer 和 LLM 推理中，4-bit 量化可将通信带宽需求降至原始的 1/8，任务准确率保持 92% 以上。
