LLM 推理天然分成两个阶段：

| 阶段 | 在干什么 | 主要瓶颈 | 关键指标 |
|---|---|---|---|
| Prefill | 把整段 Prompt 一次性算完，生成初始 KV Cache 和首 Token | 算力密集，矩阵运算多 | TTFT |
| Decode | 基于 KV Cache 逐 Token 生成 | 显存带宽密集，算力利用率低 | TPOT / TBT |

- 二者都需要适用KV Cache，但是用法完全不同
Prefill：写入 KV Cache（把 prompt 所有 token 的 K、V 算出来存进去）
Decode：读取 + 追加 KV Cache（每个新 token 都要读历史 KV，再把自己的 KV 追加进去）


Prefill 阶段并行度高，GPU 算力基本能吃满；Decode 阶段每次只算一个新 Token，却要反复读取历史 KV Cache，GPU 经常处于“等数据”的状态。如果两个阶段放在同一批 GPU 上，Prefill 的大计算量会挤占 Decode 的带宽和调度资源，导致首 Token 延迟和 Token 间延迟同时变差。PD 分离就是把这两个阶段拆开，让 Prefill 池专门吃算力，Decode 池专门吃带宽，互不干扰。

## 架构设计：Prefill 池 + Decode 池 + KV Cache 传输
Prefill 节点池
- 负责处理 Prompt，构建 KV Cache；
- 适合用高算力 GPU，张量并行可以开得更大；
- 调度时会优先复用前缀缓存，避免重复计算长上下文。

Decode 节点池
- 负责逐 Token 生成；
- 适合用大显存、高带宽 GPU；
- 更关注 TPOT、TBT 和连续批处理效率。

KV Cache 跨节点传输
Prefill 完成后，需要把 KV Cache 送到 Decode 节点。常见传输方式有：
- RDMA / GPUDirect RDMA：跨节点显存直传，延迟通常在毫秒级；
- NVLink：同机多卡之间迁移，延迟极低，几乎可以忽略；
KV Cache传输开销必须小于他带来的收益

## 开源项目：

| 项目        | 核心思路                                                                 | 适用场景              |
| --------- | -------------------------------------------------------------------- | ----------------- |
| Mooncake  | 以 KV Cache 为中心的分布式架构，Prefill/Decode 池 + 分布式 KV Cache 池，支持 RDMA 和分层缓存 | 大规模集群、长上下文、多轮对话复用 |
| Splitwise | 同机内解耦，Prefill 和 Decode 放在同一节点不同 GPU 上，通过 NVLink 迁移 KV Cache          | 中小规模部署，改造成本低      |
| DistServe | 跨节点解耦，Prefill 和 Decode 可独立设置并行策略，重点优化 Goodput                        | 中长上下文、高并发 Serving |
| FlowKV    | 优化 KV Cache 块级传输和负载感知调度，降低跨节点迁移延迟                                    | 异构 GPU、负载波动明显场景   |
   
Mooncake 的特别之处在于，它把 Prefill/Decode 解耦和 KV Cache 存储层绑在一起。KV Cache 不再只挂在某个 GPU 上，而是可以被集群共享、复用和淘汰。
Splitwise 更轻量，适合先在同一台 8 卡节点里试水 PD 分离。它的优势是部署简单，但扩展性受限于单机资源。
DistServe 则更强调跨节点调度和并行策略独立配置，比如 Prefill 用 TP=4，Decode 用 TP=1，从而分别优化算力和带宽。
