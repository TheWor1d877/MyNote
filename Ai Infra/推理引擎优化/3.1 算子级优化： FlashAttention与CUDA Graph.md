## FlashAttention原理
改变数据的搬运方式，不改变Attention的数学公式
标准 Attention 实现会将 N * N 的的注意力矩阵完整写入 HBM，导致显存复杂度为 
O(n^2)。FlashAttention 通过三个关键技术避免这一瓶颈：
#### 分块计算
不让中间结果落地到HBM上面，而是都在SRAM中完成

传统Attention：
```text
第1步：从 HBM 读 Q、K → 算 S = QK^T → 把 S 写回 HBM
第2步：从 HBM 读 S → 算 P = softmax(S) → 把 P 写回 HBM
第3步：从 HBM 读 P、V → 算 O = PV → 把 O 写回 HBM
```

瓶颈在于S与P的反复读写，时间复杂度O(n^2)

FlashAttention的做法：
将QKV都切开：
```text
Q: [Q₁, Q₂, Q₃, ..., Q_{T_r}]
K: [K₁, K₂, K₃, ..., K_{T_c}]
V: [V₁, V₂, V₃, ..., V_{T_c}]
```

外层循环： 遍历所有的Q块
	初始化输出 O_i = 0
	初始化统计量 m_i = -∞（最大值）, l_i = 0（归一化因子）
	内层循环遍历KV块：
		从HBM中加载Ki Vi到SRAM
		算出最后的O_ij累加到O_i中
		更新统计量
最后将Oi写回HBM中

优点：
只读QKV
只写最终结果O
中间的SP全在SRAM中，不访问HBM
时间复杂度：
O(n^2 * d / sqrt(M) )

#### 在线Softmax
分块计算的时候，每个块只能看到部分Key
为了保证最后的Softamax结果正确,使用在线Softmax
```text
对每个块 j，计算局部最大值 m_j 和局部指数和 l_j：
  m_j = max(S_j)          // 当前块的行最大值
  l_j = sum(exp(S_j - m_j))  // 当前块的归一化分母

全局 Softmax 通过递推更新：
  m_new = max(m_old, m_j)
  l_new = l_old · exp(m_old - m_new) + l_j · exp(m_j - m_new)
  O_new = (l_old · O_old · exp(m_old - m_new) + P_j · V_j · exp(m_j - m_new)) / l_new
```
这样只需一次前向遍历，无需存储完整的 n×n 矩阵

#### 重计算
反向传播时需要 P 矩阵，FlashAttention 不存储 P ，而是在 backward 时重新从 Q 、 K 计算一次。由于 SRAM 访问极快，重计算的开销远小于 HBM 存储的开销——这是典型的以计算换带宽策略。

## CUDA  Graph
在 PyTorch 中，每次调用 model.forward() 都会触发：
1. Python 解释器执行
2. C++ 前端调度
3. CUDA Runtime API 调用（cudaLaunchKernel）
4. GPU Driver 内核启动

对于短推理序列，单个 Token 生成的 Kernel 执行时间可能仅几微秒，但 CPU 端的启动开销可达 10~50 μs，CPU 成为瓶颈。(CPU 要打包参数、调用驱动、提交命令)

CUDA Graphs 允许将一系列 CUDA Kernel 的启动序列录制为一个静态图(把一串 kernel launch、memcpy依赖关系先录下来)，之后通过单次 cudaGraphLaunch 调用重放整个序列，绕过 Python/C++ 前端和 CUDA Runtime 的逐层调度。一次提交即可

Capture 阶段：跑一次真实计算，记录这个 stream 上所有 GPU 操作。
Replay 阶段：不再逐个 launch，而是直接提交整张图。
收益：CPU-GPU 交互次数大幅下降，launch 开销从“每个 kernel 付一次”变成“整张图付一次”。

CUDA Graphs 要求计算图静态——输入 tensor 的 shape 必须固定。vLLM 通过预分配固定大小的 CUDA Graph 池（覆盖常见序列长度区间）来解决动态长度问题。

CUDA Graph的价值主要在大量小Kernel + 固定形状 + 反复执行的场景
## 算子融合思想
多个小算子合并为一个 CUDA Kernel，减少 Kernel 启动次数和中间显存读写。
融合模式 1：LayerNorm + Activation
融合模式 2：RoPE + QKV 投影
融合模式 3：Attention + Add + Norm
