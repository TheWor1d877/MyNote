## block hash链条计算命中深度
hash 是链式累积的：第 i 个块的哈希是 hash(前一块的哈希, 当前块的 token)

这个语义是“连续匹配、断开即止”的根源：链式哈希让每个块的身份绑定了它的全部祖先。第 0 块不同，第 1 块的哈希就不同，第 2 块也跟着变，整条链全部失效。举个量化的例子：2400 token 的系统提示、block_size=16，总共 150 个块。如果在系统提示开头插入一个时间戳，第 0 块就变了，链式传导导致 150 个块全部不可命中；把时间戳放到末尾，可以复用 149 个块。


## block hash的淘汰策略
淘汰不是按“哈希更长”来选的，按的是 LRU，但 LRU 平手时用前缀深度做 tie-breaker。

正常淘汰逻辑：缓存满了，找一个 ref_cnt=0 的块踢掉。多个 ref_cnt=0 的块里，踢最久没被访问的

平手时怎么办：如果几个块最后访问时间一样，优先踢前缀更长的那条链的末尾块

一个请求的块在逻辑上是 `[block_0, block_1, ..., block_n]`，block_n 是链尾，hash tokens 最多。释放时如果不反转，block_0 先入队、排在更靠前；反转之后，block_n 先入队，链尾的块就排到了队头附近。

这样 LRU 队列的头部天然就是“同一时刻释放的块里，前缀最深的那一个”。淘汰时从队头取，取到的就是最长前缀的末尾块，不需要遍历比较
