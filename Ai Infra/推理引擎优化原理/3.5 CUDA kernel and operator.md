## 三层结构
```text
第一层：类别（按计算模式划分，是“文件夹”）
    └── 第二层：算子（有确定名字和数学定义的具体计算单元）
            └── 第三层：kernel（算子在特定条件下的具体执行方案）
```

## 算子类别
#### 逐元素类
输出张量的第 i 个元素，只由输入张量的第 i 个元素决定，一个进一个出，形状不变，没有元素之间互相影响
```text
【逐元素类】
  ├─ aten::add      // 两个张量逐元素相加：out[i] = a[i] + b[i]
  ├─ aten::sub      // 逐元素相减
  ├─ aten::mul      // 逐元素相乘
  ├─ aten::div      // 逐元素相除
  ├─ aten::exp      // 逐元素取 e 的幂
  ├─ aten::log      // 逐元素取对数
  ├─ aten::sqrt     // 逐元素开平方
  ├─ aten::abs      // 逐元素取绝对值
  ├─ aten::pow      // 逐元素求幂
  ├─ aten::neg      // 逐元素取负
  ├─ aten::clamp    // 逐元素截断到 [min, max] 区间
  └─ aten::add（选它展开，最基础、最常被融合）
       ├─ kernel: CPU 标量循环版          // for 循环一个一个加，兜底
       ├─ kernel: CPU SIMD 向量化版        // 用 AVX 指令一次加 8/16 个 float
       ├─ kernel: CUDA 朴素版              // 一个 GPU 线程算一个元素
       ├─ kernel: CUDA 向量化版            // 一个线程用 float4 一次算 4 个元素
       └─ kernel: CUDA 融合版（add+relu）  // 加法和激活合成一个 kernel，省一次 HBM 往返
```

#### 规约类
把多个元素折叠成一个（N 对 1），比如一行求和、求最大值、求均值
```text
【规约类】
  ├─ aten::sum      // 把所有元素加起来
  ├─ aten::mean     // 求平均值（sum / 元素个数）
  ├─ aten::max      // 求最大值
  ├─ aten::min      // 求最小值
  ├─ aten::argmax   // 求最大值所在的下标（不是值本身）
  ├─ aten::argmin   // 求最小值所在的下标
  ├─ aten::prod     // 把所有元素乘起来
  ├─ aten::var      // 求方差
  ├─ aten::std      // 求标准差
  ├─ aten::norm     // 求范数（如 L2 范数 = 平方和开根号）
  ├─ aten::cumsum   // 累加和：out[i] = a[0]+a[1]+...+a[i]
  └─ aten::sum（选它展开，规约类最基础，softmax 内部要用）
       ├─ kernel: CPU 循环累加版              // 单线程顺序加，兜底
       ├─ kernel: CUDA 单 block 行内 reduce 版 // 一个 block 负责一行，shared memory 里树形规约
       ├─ kernel: CUDA 多 block + grid-stride 版 // 行太长，拆给多个 block 各算一段再合并
       └─ kernel: CUDA 融合版（softmax 里 sum+max）// 求最大值和求和合并进一个 kernel，省一次遍历
```

#### 矩阵运算类
矩阵乘法及其变体。这是计算量最大的一类，LLM 里 90% 以上的浮点运算都在这里
```text
【BLAS类】
  ├─ aten::mm       // 2D 矩阵乘：C = A·B
  ├─ aten::bmm      // 批量矩阵乘：对 batch 里每个样本各做一次矩阵乘
  ├─ aten::mv       // 矩阵乘向量：C = A·v
  ├─ aten::linear   // 线性层：y = x·W^T + b（内部是 matmul + bias）
  ├─ aten::addmm    // bias + 矩阵乘：C = β·C + α·(A·B)
  ├─ aten::baddbmm  // 批量版 addmm
  ├─ aten::einsum   // 爱因斯坦求和，可以表达各种矩阵运算组合
  ├─ aten::outer    // 外积：两个向量生成一个矩阵
  ├─ aten::dot      // 两个向量的点积
  └─ aten::matmul（选它展开，LLM 里 FLOPs 占比最高，kernel 实现最多）
       ├─ kernel: CPU 朴素三重循环版                    // for i,j,k 直接算，好写但极慢
       ├─ kernel: CPU MKL/OneDNN 优化版                 // 分块 + SIMD + 多线程，快几十倍
       ├─ kernel: CUDA cuBLAS 大矩阵分块版              // shared memory 分块 + 寄存器复用 + Tensor Core
       ├─ kernel: CUDA cuBLAS 小矩阵专用版              // 大矩阵 kernel 启动开销太大，小矩阵换轻量 tiling
       ├─ kernel: CUDA cuBLAS 瘦长矩阵 split-K 版       // K 很大但 M/N 很小，把 K 拆开给多 block 并行
       └─ kernel: CUDA 融合版（matmul+bias+activation） // 矩阵乘结果还在片上时直接加 bias、做激活
```

#### 归一化类
把一批数值重新缩放，让它们的分布变得规整（比如均值变 0、方差变 1），防止数值过大或过小导致训练不稳定
```text
【归一化类】
  ├─ aten::layer_norm   // 按“每个样本自己的所有特征”归一化，不跨样本。Transformer 每层都用
  ├─ aten::batch_norm   // 按“整个 batch 在同一通道上的所有样本”归一化。CNN 常用
  ├─ aten::group_norm   // 把通道分组，每组内归一化。介于 layer 和 batch 之间
  ├─ aten::rms_norm     // 只除以均方根、不减均值，比 layer_norm 少一步。LLaMA 等模型用
  ├─ aten::instance_norm// 每个样本每个通道单独归一化。风格迁移常用
  └─ aten::layer_norm（选它展开，Transformer 里每层必用）
       ├─ kernel: CPU 两遍循环版                    // 第一遍求均值方差，第二遍归一化
       ├─ kernel: CUDA 朴素两 kernel 版             // kernel A 算统计量写回 HBM，kernel B 读回来归一化
       ├─ kernel: CUDA 单 kernel 行内版             // 一个 block 负责一行，shared memory 里完成统计+归一化，不落 HBM
       └─ kernel: CUDA 融合版（layer_norm+residual_add+gelu） // 残差加、归一化、激活三步合成一个 kernel
```

#### 激活函数类
激活函数是神经网络里给每个神经元输出加一个“非线性变换”的函数。没有它，多层网络叠起来还是等价于一层线性变换
```text
【Activation类】
  ├─ aten::relu      // max(0, x)，负数变 0，正数不变。最简单最常用
  ├─ aten::leaky_relu// 负数不直接变 0，而是乘一个很小的系数（如 0.01）
  ├─ aten::gelu      // 高斯误差线性单元，BERT/GPT 系列常用，比 relu 平滑
  ├─ aten::silu      // 也叫 swish，x·sigmoid(x)。LLaMA 等模型的 SwiGLU 里用
  ├─ aten::sigmoid   // 把任意实数压到 (0,1) 区间，常用来表示概率
  ├─ aten::tanh      // 把任意实数压到 (-1,1) 区间
  ├─ aten::softmax   // 把一组数变成概率分布（每项在 0~1 之间且总和为 1）
  ├─ aten::log_softmax // softmax 后再取 log，数值更稳定，常和 NLLLoss 搭配
  └─ aten::gelu（选它展开，BERT/GPT 系列最常用）
       ├─ kernel: CPU 版                // 标量循环，用 erf 或 tanh 近似
       ├─ kernel: CUDA 精确版           // 用 erf 函数，数学精确但稍慢
       ├─ kernel: CUDA tanh 近似版      // 用 tanh 近似公式，更快，精度损失可忽略
       └─ kernel: CUDA 融合版（linear+gelu） // FFN 里 Linear→GELU 合成一个 kernel，省中间张量
```

#### 卷积类
用一个小的“卷积核”（比如 3×3 的权重矩阵）在输入图像上滑动，每个位置做加权求和，提取局部特征
```text
【卷积类】
  ├─ aten::conv1d          // 一维卷积，用于序列/音频
  ├─ aten::conv2d          // 二维卷积，用于图像，CNN 最核心
  ├─ aten::conv3d          // 三维卷积，用于视频/医学图像
  ├─ aten::conv_transpose2d// 转置卷积（反卷积），用于上采样/生成模型
  ├─ aten::depthwise_conv2d// 深度可分离卷积的深度部分，每个通道单独卷。MobileNet 用
  ├─ aten::conv2d（选它展开，CNN 里最核心，kernel 实现方式最多）
       ├─ kernel: CPU 朴素 im2col + GEMM 版    // 把卷积展开成矩阵乘，复用 GEMM
       ├─ kernel: CUDA 直接卷积版              // 直接按滑动窗口算，小卷积核小通道时用
       ├─ kernel: cuDNN Winograd 版            // 3×3 小核专用，减少乘法次数，理论加速 2~4 倍
       ├─ kernel: cuDNN FFT 版                 // 大卷积核时用，把卷积变成频域乘法
       ├─ kernel: cuDNN implicit GEMM 版       // 大通道时用，不显式展开，边算边取省内存
       └─ kernel: CUDA 融合版（conv+bias+relu）// Conv-BN-ReLU 块合成一个 kernel
```

#### 视图类
不改变张量里的数值，只改变“怎么看待这块数据”——比如把 2×3 的矩阵看成 3×2、把连续的 12 个数看成 3×4、把两个张量拼在一起。
```text
【形状/视图类】
  ├─ aten::view       // 改变形状，要求内存连续，零拷贝
  ├─ aten::reshape    // 改变形状，内存不连续时会自动拷贝一份
  ├─ aten::transpose  // 交换两个维度，只改 stride，零拷贝
  ├─ aten::permute    // 按任意顺序重排所有维度，只改 stride
  ├─ aten::squeeze    // 去掉大小为 1 的维度（如 [1,3,1,5] → [3,5]）
  ├─ aten::unsqueeze  // 在指定位置插入一个大小为 1 的维度
  ├─ aten::flatten    // 把连续几个维度合并成一个
  ├─ aten::concat     // 沿某个维度把多个张量拼起来（需要真实搬运）
  ├─ aten::split      // 沿某个维度把张量切成几份
  ├─ aten::slice      // 取张量的一个子区间
  ├─ aten::expand     // 把大小为 1 的维度广播成更大（不复制数据，只改 stride）
  └─ aten::reshape（选它展开，最常用、最能体现“零拷贝”特殊性）
       ├─ 零拷贝路径：只改 size/stride 元数据，不启动计算 kernel   // 形状兼容且内存连续时走这条
       ├─ kernel: CUDA copy kernel                              // 形状不兼容、必须真实搬数据时
       └─ kernel: CPU copy kernel                               // 同上，CPU 版
```


## operator
####  Dispatch表
Dispatch表是 PyTorch 框架自身的**代码基础设施**，是 C++ 层面的一个多维查找表
在
算子被触发时，PyTorch 的 **dispatcher** 根据输入 tensor 的 device（CPU/CUDA）、dtype、是否需要 autograd 等，从该算子的 **dispatch table** 里选出优先级最高的 kernel 函数指针，然后调用它。

一个add算子的dispatch表大致如下：
```text
Operator: add.Tensor
+------------------+------------------+
| DispatchKey      | Kernel           |
+------------------+------------------+
| Autograd         | add_autograd     |
| CPU              | add_cpu_kernel   |
| CUDA             | add_cuda_kernel  |
| ...              | ...              |
+------------------+------------------+
```


## kernel
#### kernel的加载

1. **启动/预热阶段**：加载模型对应的 CUDA 模块（包含这个模型所有可能用到的 kernel 的 cubin/PTX）。
2. **第一次执行某个算子时**：该算子背后的 kernel 被首次 launch，驱动此刻把它的机器码真正搬进显存，之后常驻。
3. **后续重复调用同一个 kernel**：不再搬代码，只走 CPU 侧的提交流程。
