## 传统连续分配的致命缺陷
大模型推理的显存占用分为两部分： 模型权重与KV Cache
模型权重是静态只读的，KV Cache是动态持续增长的
权重是固定的，但 KV Cache 才是显存管理的真正噩梦——它的生命周期和长度完全不可预测，且每个请求的长度差异极大（从几十 token 到几十万 token）。

传统推理框架采用连续内存预分配策略，但是会导致严重的内存碎片问题
采用内存共享的策略，在并行采样的场景中，多个输出序列共享同一个 Prompt 前缀，但每个序列的 KV Cache 被分配在不同的连续空间中，导致相同的前缀被重复计算、重复存储，显存开销成倍增长。


在生产环境中，90% 的 LLM 服务 OOM 不是因为模型权重太大，而是因为 KV Cache 爆了。一个 70B 模型的权重约 140GB，但在 batch_size=32、max_len=4096 的并发下，KV Cache 可以轻松超过 80GB，直接撑爆单张 A100。

## PagedAttention： 操作系统的虚拟内存分页
PagedAttention 将 KV Cache 切分为固定大小的物理块（Physical Block），默认每个块存储 16 个 token 的 KV 向量。 每个请求维护一张 Block Table，逻辑上连续，物理上可以不连续。 这就是虚拟内存分页思想的核心迁移。

- 按需分配（Lazy Allocation）
初始只分配 1 个物理 KV block，每生成 1 个 token 就查表——若当前 block 已满（16/16），则从全局显存池中分配一个新物理块并更新 Block Table。请求完成时，所有物理块立即放回 block pool，下一个新请求可立即复用。

- CUDA Kernel的三大约束优化：
块级遍历： 一次加载整块（16 tokens）的 KV，实现连续内存访问，消除逐 token 随机访问的开销。
页表间接寻址：通过 block_table[logical_idx] 查物理块号，支持逻辑连续、物理不连续的 KV Cache。
局部 Softmax + 全局归一化（FlashAttention 思想）：先在 block 内部做局部 softmax 归一化，最后跨 block 合并归一化结果，避免一次性加载全量 KV 导致的显存峰值。

#### Copy-on-Write：写时复制
PagedAttention 的 Block Table 天然支持内存共享——不同序列可以将它们的逻辑块映射到同一个物理块，就像操作系统中多个进程共享同一物理页一样。
实现机制：
每个物理块维护一个 引用计数（ref_count），记录有多少个序列在共享它。
当多个序列共享相同前缀（如 System Prompt）时，它们的逻辑块指向同一个物理块，无需重复存储。
Copy-on-Write（CoW）：仅在某个序列需要写入新 token（即发生"分叉"）时，才复制该物理块并更新 Block Table，其他序列继续共享原块。


## 推理服务(vLLM)中显存的消费者
模型权重： 静态的，加载时就固定了
KVCache： 随着batch与seq长度伸缩，在给具体请求分配显存空间的时候预留
激活值： 模型前向计算过程中产生的“中间结果张量”，随 batch/序列形状波动，峰值在 Prefill，显存占用大小随着运行时候逐步迭代
CUDA Graph池/workspace： 录制时候固化，后面按需增长，在warmup之后确定显存占用大小
CUDA Graph 池是一块独立预留的显存：vLLM 为不同 batch size 预先 capture 多张图，每张图都会 reserve 自己的 buffer。这部分开销不是固定值，而是随 capture 的图数量和 batch size 档位线性增长
CUDA Graph池不是CUDAGraph图本身，而是CUDA Graph固定引用的显存地址

计算公式： 
可用显存 = gpu_memory_utilization × 总显存
KV_cache_pool = 可用显存 − 模型权重 − 激活/CUDA Graph 开销
