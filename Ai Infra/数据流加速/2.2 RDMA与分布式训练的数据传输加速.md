可以使用GDS来解决磁盘到GPU的瓶颈，但是多个节点之间的数据传输是新的瓶颈

## 分布式训练的通信场景
数据并行（Data Parallel）：每个GPU持有模型副本，处理不同数据，每轮需要all_reduce梯度
模型并行（Model/Tensor/Pipeline Parallel）：模型被切分到多个GPU，前向/后向传播中需要频繁传递激活值和梯度
混合并行：上述两种的组合，通信模式更加复杂

## RDMA的核心机制：内核旁路与零拷贝
RDMA（Remote Direct Memory Access）的本质是让一台机器的GPU/内存直接访问另一台机器的GPU/内存，全程不经过对方的CPU和操作系统。
#### 三大核心特性
- 内核旁路（Kernel Bypass）
传统网络通信需要经过操作系统的内核协议栈，而RDMA通过用户态直接访问网卡硬件，绕过内核。应用层直接调用RDMA verbs（如ibv_post_send）发起传输请求，网卡硬件自行完成数据搬运。
- 零拷贝（Zero-Copy）
数据从源端GPU显存/内存直接传输到目标端GPU显存/内存，中间不经过任何缓冲区和协议栈。CPU完全不参与数据传输，只负责下发指令。
- CPU卸载（CPU Offload）
RDMA网卡（RNIC）内置专用的传输引擎，自行处理可靠性保证、流量控制、拥塞控制等协议逻辑。CPU只需要注册内存区域、发布工作请求，之后就可以去做其他事情。

#### 通信原语
| 模式 | 描述 | 适用场景 |
|------|------|----------|
| Send/Recv | 类似传统socket，需要双方配合完成传输 | 通用通信 |
| RDMA Write | 单方发起，直接写入对端内存，对端无感知 | GPU显存直传、Checkpoint同步 |
| RDMA Read | 单方发起，直接从对端内存读取 | 参数服务器拉取权重 |

其中RDMA Write是最强大的模式——你可以让GPU A直接把梯度写入GPU B的显存，GPU B甚至不需要知道这件事正在发生，直到它去读取那块内存。

#### 实现方式
InfiniBand vs RoCE

- RoCE（RDMA over Converged Ethernet）
融合网络：在以太网上运行RDMA协议，可以使用标准以太网交换机
无损以太网：必须开启PFC（Priority Flow Control），防止拥塞丢包。RDMA没有重传机制，一旦丢包会导致传输失败
ECN标记：开启显式拥塞通知，配合DCQCN算法实现拥塞控制
MTU设置：建议设置为4096（jumbo frame），减少分片开销
网卡要求：需要支持RDMA的网卡（如Mellanox ConnectX系列、NVIDIA BlueField DPU）

#### 落地方式： NCCL
NCCL（NVIDIA Collective Communications Library）是NVIDIA提供的集合通信库，PyTorch分布式训练默认使用它。

NCCL 是 NVIDIA 的集合通信库，负责 GPU 与 GPU 之间的数据传输-1-12。它提供 all-reduce、all-gather、broadcast 等通信原语，优化的是：
- 单机内：通过 PCIe、NVLink、NVSwitch 连接多张 GPU
- 跨节点：通过 InfiniBand、RoCE 连接多台机器

NCCL会自动检测底层网络能力，不需要手动调用RDMA verbs，NCCL会帮你处理好一切。但你需要确保环境配置正确（驱动、网卡、PFC、MTU等），否则NCCL会回退到TCP，性能大打折扣。

## 传输方式维度
数据传输语义	流式（Stream）/ 消息（Message）/ 数据报（Datagram）	数据是字节流还是带边界的信息
通信原语	Send/Recv、RDMA Write、RDMA Read	谁发起、谁感知、怎么访问内存
同步方式	同步 / 异步、阻塞 / 非阻塞	调用后是否等待完成
连接方式	面向连接 / 无连接	是否需要先建连接
