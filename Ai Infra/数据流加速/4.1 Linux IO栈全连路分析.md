一次普通的 write() 系统调用，在内核中需要经历七层关卡：
```txt
┌─────────────────────────────────────────────────────────┐
│ 应用层（Application）                                     │
│   write(fd, buf, count)                                 │
├─────────────────────────────────────────────────────────┤
│ VFS 层（Virtual File System）                             │
│   虚拟文件系统抽象层，路由到具体文件系统实现                    │
├─────────────────────────────────────────────────────────┤
│ 文件系统层（File System: ext4/xfs/btrfs）                  │
│   分配 inode、更新目录项、管理 extent                      │
├─────────────────────────────────────────────────────────┤
│ Page Cache 层                                           │
│   写入内存页缓存（Dirty Page），标记为待回写                 │
├─────────────────────────────────────────────────────────┤
│ 通用块层（Generic Block Layer）                           │
│   将文件 offset 映射为逻辑块号（LBA），I/O 调度             │
├─────────────────────────────────────────────────────────┤
│ 设备驱动层（Device Driver: NVMe/SATA/SCSI）               │
│   将逻辑块号转换为物理命令，提交到硬件队列                    │
├─────────────────────────────────────────────────────────┤
│ 物理层（Physical Device: SSD/HDD/NVMe）                   │
│   闪存颗粒编程 / 磁盘磁头寻道                              │
└─────────────────────────────────────────────────────────┘
```

每一层存在的问题：

| 层级 | 典型瓶颈 | 症状 |
|------|---------|------|
| 应用层 | 序列化/反序列化开销、小 I/O 频繁系统调用 | CPU 高、syscall 多 |
| VFS 层 | 路径查找（path lookup）、权限检查 | 元数据操作慢 |
| 文件系统层 | inode 分配、日志提交（journal commit）、extent 分裂 | 元数据 I/O 高 |
| Page Cache | Dirty Page 积压、回写阻塞 | 内存抖动、writeback 延迟 |
| 通用块层 | I/O 调度器排队、请求合并失败 | await 高、队列深度大 |
| 设备驱动层 | 硬件队列满、中断亲和性差 | 队列拥堵、CPU 软中断高 |
| 物理层 | SSD GC、HDD 寻道、带宽饱和 | util 100%、吞吐上不去 |

## PageCache DirtyPage 
Page Cache 是内核用空闲内存做的"文件内容缓存"。读取文件时，内核先将数据从磁盘读入 Page Cache，应用再从 Page Cache 读取；写入文件时，内核先写入 Page Cache（标记为 Dirty Page），再由后台线程异步回写到磁盘。

Dirty Page的生命周期
```text
应用 write()
    ↓
写入 Page Cache，页标记为 Dirty
    ↓
─────────────────────────────────────
后台回写线程（writeback）异步处理：
─────────────────────────────────────
    ↓
Dirty Page 进入回写队列
    ↓
满足触发条件时，提交到块设备层
    ↓
块设备完成 I/O，页标记为 Clean
    ↓
内存不足时，Clean Page 被回收
```
