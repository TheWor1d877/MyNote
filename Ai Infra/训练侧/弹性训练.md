**弹性训练**

**1. 定义**

弹性训练是指分布式训练任务在运行过程中，能够根据集群资源的可用情况动态调整参与训练的 worker 数量，而不需要终止整个任务再重新提交。它与容错训练的区别在于：容错是在节点故障后以相同规模重启，弹性则允许训练规模在设定范围内变化。

**2. 核心机制：min 与 max**

弹性任务在启动时声明一个 worker 数量范围，例如 `--nnodes=1:4` 表示最少 1 个节点、最多 4 个节点。只要当前可用 worker 数不低于最小值，任务就能启动；运行过程中，资源增加可以扩容，资源被回收可以缩容，任务不中断。

**3. 与 rank 的关系**

每次 worker 数量发生变化，所有参与进程需要重新执行一次 rendezvous（集合通信），重新分配 rank 和 world_size。这意味着弹性训练下 world_size 不是固定值，训练代码不能硬编码依赖固定的进程总数。

**4. 弹性训练解决什么问题**

主要针对两类场景：一是使用可被抢占的实例（如竞价实例）时，资源随时可能被回收；二是集群资源动态变化时，任务可以在少量资源上先跑起来，等更多资源空闲时自动扩容，提升利用率。代价是训练脚本需要适配规模变化，例如调整 batch size 或学习率，并配合 checkpoint 在成员变更时保存和恢复状态。

**5. 与当前 checkpoint 链路的关系**

 `rank-<rank>/` 目录结构和「world_size 份 manifest 都在」的完整性判定，前提是 world_size 固定。弹性训练下 world_size 会变化，完整性判定的基准随之失效。这也是为什么一期关闭多 rank 的同时，弹性训练在当前 checkpoint 设计下同样缺乏支撑：目录与 Pod 一一对应的假设，以及固定份数的 manifest 校验，都无法直接套用到规模会变的场景。
