## 内核内存分配管理
#面试-计算机基础-复习  解释 buddy system 与 slab 分配器的原理：buddy 如何通过伙伴块的分裂与合并减少外部碎片？slab 如何在 buddy 之上减少内部碎片并缓存高频分配的对象？

buddy system 与 slab分别解决外部与内部碎片
#### buddy system
想象整个物理内存是一块大小 2^n 的连续区域，比如 1024 页。buddy 把内存按 2 的幂切成不同大小的块——1 页、2 页、4 页、8 页……一直到 1024 页。每种大小各有一条空闲链表。

你释放一个 4 页块，内核先看它的伙伴是不是也空闲。是的话，两个合并成一个 8 页块。然后继续看这个 8 页的伙伴空不空闲，空闲就再合并成 16 页……一路往上滚，直到伙伴不空闲或者到顶为止。这就是合并。

这就解决了外部碎片：因为释放时能自动把相邻的伙伴合回大块，不会留下一堆零散的小空洞。只要两块是伙伴，早晚能拼回去。

关键机制是"怎么快速找到伙伴"：因为是 2 的幂对齐，伙伴的地址可以用位运算直接算出来——把当前块地址的第 k 位翻转，就是伙伴地址。不用查表、不用遍历，一条异或就够。这是 buddy 效率高的核心。

缺点： 粒度太粗，全是2的幂

#### slab
slab 的思路是：既然这些对象大小固定、又反复创建销毁，那我干脆给每种对象预先备好一批"成型的内存槽位"，反复复用。

slab 向 buddy 要一些页（通常是一页或几页），把这一整块切成若干个大小相同的小格子，每个格子正好能放一个这种对象。这一整块就叫一个 slab。比如 task_struct 是 1KB，那一个 4KB 的 slab 就切成 4 个槽位，专门放 task_struct。
（task_struct 是 Linux 内核里描述一个进程（或线程）的核心数据结构）

内部碎片小了。槽位大小是按对象实际大小对齐切的，1KB 的对象就切 1KB，不再是一个 4KB 页只装一个。虽然还有一点点对齐浪费，但比 buddy 直接给整页小得多。
分配快了。对象是复用的，不用每次初始化；槽位拿取就是链表操作，不像 buddy 那样要分裂合并。高频创建销毁的对象——进程、文件、网络包——全都受益。
